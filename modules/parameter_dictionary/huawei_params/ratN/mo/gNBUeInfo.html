gNBUeInfo

+-gNodeBFunction
  +-gNBUeInfo

Description

This MO is used to set UE information parameters that need to be matched during UE identification on the base station side.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    gNodeBFunction
  • Relation with the gNBAbnMsg MO:
    • If the value of UeInfoIndex in the gNBAbnMsg MO is greater than 0, UeInfoIndex must be already configured in the gNBUeInfo MO.
  • Relation with the gNBUeSpecificParam MO:
    • UeInfoIndex in the gNBUeSpecificParam MO must be already configured in the gNBUeInfo MO.
  • Relation with the gNBUeCompatibleCtrl MO:
    • UeInfoIndex corresponding to UeInfoIndex in a gNBUeCompatibleCtrl MO must already be configured in a gNBUeInfo MO.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD GNBUEINFO

Use this command to add UE information.
LST GNBUEINFO

Use this command to list UE information.
RMV GNBUEINFO

Use this command to remove UE information.

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
UE Information Index

Indicates the UE information index.
UE Information Type

Indicates the UE information type. If this parameter is set to IMEISV_TAC, the UeImeisvTac parameter must be set. If this parameter is set to IMEISV_TAC_SVN, the UeImeisvTac and UeImeisvSvn parameters must be set. If this parameter is set to UE_CAPABILITY, the UeCapbOffset, UeCapbLength, and UeCapbContent parameters must be set. If there are instances with different UeInfoIndex values but with the UeCapbOffset, UeCapbLength, and UeCapbContent parameters collectively identifying the same UE, only the instance with the smallest UeInfoIndex value takes effect. If this parameter is set to UE_FEATUREVALUE, the UeFeatureValueMask and UeFeatureValueContent parameters must be set. If this parameter is set to UE_EUTRA_CAPABILITY, characteristic parameters related to the EUTRA capability need to be configured.
UE Capability Offset

Indicates the start identification position of the UE capability-related binary code streams of received by the gNodeB. It indicates the offset relative to the UE-CapabilityRAT-ContainerList IE described in 3GPP TS 38.331. For example, the value 1 indicates that the identification offset relative to UE-CapabilityRAT-ContainerList is 1 bit. This parameter is an advanced parameter. Set this parameter under the guidance of Huawei customer center.
UE Capability Length

Indicates the to-be-identified bit length of UE capability-related binary code streams received by the gNodeB. For example, the value 8 indicates eight bits. The value of UeCapbLength must match the value of UeCapbContent. If the value of UeCapbLength is greater than the actual length specified by UeCapbContent, UEs cannot be identified.This parameter is an advanced parameter. Set this parameter under the guidance of Huawei customer center.
UE Capability Content

Indicates the to-be-identified content in UE capability-related binary code streams received by the gNodeB. The parameter value is a hexadecimal number that consists of 0 to 200 characters. Byte-granularity configuration is applied. For example, if UeCapbLength is set to 8, set this parameter to FF. This parameter is an advanced parameter. Set this parameter under the guidance of Huawei customer center.
UE Type Description

Indicates the customized UE descriptions.
UE Type Allocation Code

Indicates the type allocation code (TAC) in the IMEISV of a UE. Each TAC identifies a UE model. For details about the IMEISV, see section 6.2.2 in 3GPP TS 23.003 V10.1.0 or later releases. If the UeInfoType parameter is set to IMEISV_TAC or IMEISV_TAC_SVN, this parameter must be set. When setting this parameter, ensure that the value of this parameter is consistent with the IMEISV sequence in the standard interface tracing result.
UE Software Version Number

Indicates the software version number (SVN) in the IMEISV of a UE. Each SVN identifies a software version of a UE. For details about the IMEISV, see section 6.2.2 in 3GPP TS 23.003 V10.1.0 or later releases. If the UeInfoType parameter is set to IMEISV_TAC_SVN, this parameter must be set. When setting this parameter, ensure that the value of this parameter is consistent with the IMEISV sequence in the standard interface tracing result.
UE Feature Value Content

Indicates the feature value content for the gNodeB to identify a UE. The parameter value is a hexadecimal number that consists of 0 to 32 characters, meaning a maximum of 128 bits (indicating 128 feature values). This parameter is an advanced parameter. To modify this parameter, contact Huawei Customer Service Center for technical support.
UE Feature Value Mask

Indicates the position of a valid bit in UeFeatureValueContent. If a bit field is set to 1, the corresponding bit field in UeFeatureValueContent is valid. In other cases, the bit field is invalid. The parameter value must be a 32-character hexadecimal number. This parameter is an advanced parameter. To modify this parameter, contact Huawei Customer Service Center for technical support.
Access Stratum Release

Indicates the access stratum (AS) capability supported by abnormal UEs, which corresponds to the AccessStratumRelease IE in UE-EUTRA-Capability defined in 3GPP TS 36.331. The value of this parameter complies with 3GPP specifications. For example, the value 0 indicates Release 8, the value 1 indicates Release 9, the value 2 indicates Release 10, the value 3 indicates Release 11, the value 4 indicates Release 12, the value 5 indicates Release 13, the value 6 indicates Release 14, and the value 7 indicates Release 15. Other values do not correspond to specification releases.

If this parameter is set to 255, this parameter is not used for UE match. If this parameter is set to another value, a UE matches the UE type when the parameter value is completely identical to the UE capability information.
UE Category

Indicates the UE category supported by abnormal UEs, which corresponds to the UE categories in the ue-Category, ue-Category-v1020, ue-Category-v1170, and ue-Category-v11a0 IEs in UE-EUTRA-Capability defined in 3GPP TS 36.331.

When setting this parameter, you need to combine bit values in binary format and then convert the binary number into a decimal number. The binary digit combination rule is as follows: Each bit from the right to the left stands for a UE category defined in 3GPP specifications. Bit 0 stands for category 1, bit 1 category 2, bit 2 category 3, ..., bit 9 category 10, bit 10 category 11, and bit 11 category 12. Other bits are reserved. If a bit value is 1, UEs of the corresponding UE category are defined as abnormal UEs. For example, to define UEs of categories 4 and 6 as abnormal UEs, set this parameter to 40, which is the decimal format of the binary number 101000.

If this parameter is set to 0, this parameter is not used for UE match. If this parameter is set to another value, a UE matches the UE type when the parameter value is completely identical to the UE capability information.
Feature Group Indicator

Indicates the FGIs of Release 8 or earlier supported by abnormal UEs, which correspond to the bit string in the field featureGroupIndicators in the information element (IE) UE-EUTRA-Capability in 3GPP TS 36.331. When setting this parameter, convert the binary FGI into a decimal one.

If this parameter is set to 0, this parameter is not used for UE match. If this parameter is set to another value, a UE matches the UE type when the parameter value is completely identical to the UE capability information.
E-UTRAN Band List 1

Indicates the E-UTRA band list 1, which corresponds to the fields bandEUTRA in the information element (IE) SupportedBandListEUTRA in 3GPP TS 36.331.

When setting this parameter, you need to combine bit values in binary format and then convert the binary number into a decimal number. The binary digit combination rule is as follows: Each bit from the right to the left stands for an E-UTRA band. Bit 0 stands for band 1, bit 1 band 2, bit 2 band 3, ..., and bit 31 band 32. If the value of a bit is 1, the corresponding E-UTRA band is supported by abnormal UEs. For example, if an abnormal UE supports both bands 4 and 7, the binary number indicating the E-UTRA band list is 1001000. This binary number can be converted into 72 in decimal format, which can be taken as the parameter value.

If this parameter is set to 0, this parameter is not used for UE match. If this parameter is set to another value, a UE matches the UE type when the parameter value is completely identical to the UE capability information.

DL UE Category

Indicates the downlink UE categories supported by abnormal UEs, which correspond to the following fields in UE-EUTRA-Capability defined in 3GPP TS 36.331: ue-CategoryDL-r12, ue-CategoryDL-v1260, ue-CategoryDL-v1310, ue-CategoryDL-v1330, ue-CategoryDL-v1350, ue-CategoryDL-v1430, ue-CategoryDL-v1450, ue-CategoryDL-v1460, and ue-CategoryDL-v1530.

When setting this parameter, you need to combine field values indicating the UE categories in binary format and then convert the binary number into a decimal number. The binary digit combination rule is as follows: Each bit from the right to the left stands for a UE category. Bits 0 to 16 stand for categories 0 to 16, respectively. Bits 17, 18, 19, 20, 21, 22, and 23 stand for category_n17, category_m1, category 18, category 19, category 1bis, category_m2, and category 20, respectively. Bit 29 indicates category 26. Other bits are reserved. If a bit value is 1, the corresponding UE category is supported by the UEs. For example, if a UE supports both categories 19 and 16, the binary number indicating the UE capabilities is 100010000000000000000. This binary number can be converted into 1114112 in decimal format, which can be taken as the parameter value.

If this parameter is set to 0, this parameter is not used for UE match. If this parameter is set to another value, a UE matches the UE type when the parameter value is completely identical to the UE capability information.

Bits 0 to 13 stand for category 0 to category 13, respectively. Bit 14 indicates category_n14, bit 15 indicates category_m1, bit 16 indicates category 15, bit 17 indicates category 1bis, bit 18 indicates category_n16, bit 19 indicates category_n17, bit 20 indicates category_n18, bit 21 indicates category_n19, bit 22 indicates category_n20, bit 23 indicates category_m2, bit 24 indicates category_n21, bit 25 indicates category22, ..., and bit 29 indicates category 26. For example, to define UEs of category_n14 and category 8 as abnormal UEs, set this parameter to 16640, which is the decimal format of the binary number 100000100000000.
