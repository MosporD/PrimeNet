Set Mac-hs Scheduling Parameters (SET ULOCELLMACHSPARA)

Network Element: BTS3900, BTS3900 WCDMA, BTS5900, BTS5900 WCDMA

Function

The command is used to modify the Mac-hs parameters.

Note

  • Modifying parameters does not affect ongoing services, but affects only the services that are established later.
  • If LOCELLTYPE is set to IMB_CELL, this command is invalid.
  • Parameters associated with rules are introduced to accommodate the User Experience Improvement for Lightly Loaded Cells feature. The mapping between parameters and rules is as follows: EXTRAPOWER associates with rules 5 and 6. According to the mapping between a parameter and a rule, run the DSP NODEBRULEACTIONPARA command to query the rule activation status for a cell. If the rule is activated, run the LST NODEBRULEACTIONPARA command to query the setting of Administrative State. If Administrative State is ENABLE, the parameter settings in the SET ULOCELLMACHSPARA command will not take effect. Accordingly, the NODEBRULEACTIONPARA parameter settings take effect.

RSCALLOCM Resource Allocate Method

Meaning: Indicates the Resource Allocate Method. Radio resources indicate HSDPA available power resources and code resources. Code Priority: The code resource priority allocation scheme mainly applies to scenarios where power resources are limited. In scenarios where power resources are not limited, this scheme lowers the system throughput. Power Priority: The power resource priority allocation scheme mainly applies to scenarios where code resources are limited. In scenarios where code resources are not limited, this scheme lowers the system throughput. Balance between Code and Power: The power-code balanced scheme avoids exhaustion of either type of resources, improves the resource use efficiency and improves the cell capacity.

GUI Value Range: CODE_PRI(Code Priority), POWER_PRI(Power Priority), POWERCODE_BAL(Balance between Code and Power)

Unit: None

Actual Value Range: CODE_PRI, POWER_PRI, POWERCODE_BAL

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: CODE_PRI: The code resource priority allocation scheme mainly applies to scenarios where power resources are limited. In scenarios where power resources are not limited, this scheme lowers the power resource use efficiency and thereby lowers the system throughput.

POWER_PRI: The power resource priority allocation scheme mainly applies to scenarios where code resources are limited. In scenarios where code resources are not limited, this scheme lowers the code resource use efficiency and thereby lowers the system throughput.

POWERCODE_BAL: The power-code balanced scheme strikes a balance between the code resources and power resources consumed by the cell. This avoids exhaustion of either type of resources, improves the resource use efficiency and improves the cell capacity. Compared with the code resource priority allocation scheme, the power-code balanced scheme increases the downlink load of the cell and reduces the code resource use efficiency.

SM Scheduling Method

Meaning: Indicates the HSDPA Scheduling Method. PF: The differences between channel environments of users are considered in order to ensure equity among users. Enhanced PF: This algorithm is an enhancement to PF. Channel quality is considered in order to reach high resource efficiency and gain a high system capacity. Round Robin: Scheduling opportunities are allocated among users simply and effectively on a polling basis. The system throughput is low. Max C/I: This algorithm brings about the maximum system throughput, but it cannot ensures equity between users or meet users' QoS requirements. Location based EPF: Based on the Enhanced PF algorithm, the Location based EPF algorithm considers the impact of user location. Smart EPF: In heavy load scenarios, the smart EPF algorithm increases the weight of the impact of the channel quality on the scheduling priority while moderately guaranteeing the service differentiation and user fairness. In addition, this algorithm adaptively acquires its application scenarios based on machine learning.

GUI Value Range: EPF(Enhanced PF), PF(PF), RR(Round Robin), MAXCI(Max C/I), EPF_LOC(Location based EPF), EPF_SMART(Smart EPF)

Unit: None

Actual Value Range: EPF, PF, RR, MAXCI, EPF_LOC, EPF_SMART

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: MAXCI: This algorithm brings about the maximum system throughput, but it cannot ensure equity between users or meet users' QoS requirements.

RR: Scheduling opportunities are allocated among users simply and effectively on a polling basis. Different users have the same scheduling opportunities, but users are not differentiated. In addition, it does not consider channel quality, and therefore the system throughput is low.

PF: The differences between channel environments of users are considered in order to ensure equity among users. But users are not differentiated.

EPF: Scheduling rights values cover the QoS requirements of different services. GBRs can be ensured preferentially, and equity and differentiation among users are reflected. Channel quality is considered in order to reach high resource efficiency and gain a high system capacity. This algorithm is an enhancement to PF.

EPF_LOC: Considering the EPF algorithm and user location, the users at the near of cell are scheduled with a high probability. As a result, the cell throughput increases and the throughput of cell edge users decreases.

EPF_SMART: In heavy load scenarios, the smart EPF algorithm increases the weight of the impact of the channel quality on the scheduling priority while moderately guaranteeing the service differentiation and user fairness. This increases system capacity.
