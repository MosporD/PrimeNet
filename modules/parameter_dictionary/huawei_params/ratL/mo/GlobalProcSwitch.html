+-NE

Description

The GlobalProcSwitch MO consists of the switch of automatic X2 setup, the method of automatic X2 setup, the scheduling request indication (SRI) adaptation switch, and the logical channel group profile.

Description
The Switch of X2 setup by SON

Indicates whether to enable inter-eNodeB X2 self-setup. This parameter applies only to LTE FDD and LTE TDD.
The method of X2 setup by SON

Indicates the inter-eNodeB X2 self-setup method. The value X2_OVER_OSS can be set only for Huawei eNodeBs, and the value X2_OVER_S1 can be set for eNodeBs of any vendor. This parameter applies only to LTE FDD and LTE TDD.
LCG Profile

Indicates the logical channel group configuration. Currently, four logical channel group profiles are available.

If this parameter is set to LCG_PROFILE_0, the logical channel groups are assigned as follows: Logical channel group 0 is assigned to control-plane services (SRB 1, SRB 2, and QCI-5 and QCI-69 bearers) and QCI-65 services. Logical channel group 1 is assigned to VoLTE services (QCI-1 bearers) and QCI-66 services. Logical channel group 2 is assigned to other GBR services (QCI-2, QCI-3, QCI-4 and QCI-75 bearers). Logical channel group 3 is assigned to non-GBR services and QCI-79 services.

If this parameter is set to LCG_PROFILE_1, the logical channel groups are assigned as follows: Logical channel group 0 is assigned to control-plane services, PTT voice services (QCI-65 and QCI-66 bearers), and VoLTE services (QCI-1 bearers). Logical channel group 1 is assigned to QCI-75 services and other GBR services (bearers of QCIs 2 to 4). Logical channel group 2 is assigned to high-priority non-GBR services and QCI-79 services. Logical channel group 3 is assigned to low-priority non-GBR services.

If this parameter is set to LCG_PROFILE_2, the logical channel groups are assigned as follows: Logical channel group 0 is assigned to control-plane services and QCI-65 services. Logical channel group 1 is assigned to VoLTE services, QCI-66 services, QCI-75 services, and other GBR services (bearers of QCIs 2 to 4). Logical channel group 2 is assigned to high-priority non-GBR services and QCI-79 services. Logical channel group 3 is assigned to low-priority non-GBR services. Therefore, if this parameter is set to LCG_PROFILE_2, VoLTE services must be carried by QCI-1 bearers, PTT services must be carried by QCI-65 and QCI-66 bearers, and it is recommended that bearers of QCIs 2 to 4 be not used. TDD does not support LCG_PROFILE_2.

If this parameter is set to LCG_PROFILE_3, the logical channel groups are assigned as follows: Logical channel group 0 is assigned to control-plane services (SRB 1, SRB 2, and QCI-5 and QCI-69 bearers). Logical channel group 1 is assigned to VoLTE services (QCI-1 bearers) and QCI-65 and QCI-66 services. Logical channel group 2 is assigned to other GBR services (QCI-2, QCI-3, QCI-4 and QCI-75 bearers). Logical channel group 3 is assigned to non-GBR services and QCI-79 services.

This parameter applies only to LTE FDD and LTE TDD.
RNC POOL HO RIM Switch

Indicates whether to enable or disable RAN information management (RIM) for handovers within an RNC pool. An RNC pool can be used for load balancing between RNCs. An RNC can take over a cell that was controlled by another RNC in the same pool. This parameter applies only to LTE FDD and LTE TDD.
UU Message Simultaneous Sending Switch

Indicates whether the eNodeB simultaneously sends Uu messages for security mode activation and reconfiguration. If this parameter is set to ON, the eNodeB simultaneously sends the Uu messages. If this parameter is set to OFF, the eNodeB sends the Uu messages one by one. If the eNodeB needs to query the UE capability information during initial access and the UeCapbEnquirySecurityEnhSwitch option of the ProtocolMsgOptSwitch parameter in the GlobalProcSwitch MO is selected, then the UuMsgSimulSendSwitch parameter does not take effect and the security mode activation, UE capability query, and reconfiguration are processed in sequence. This parameter applies only to LTE FDD and LTE TDD.
X2 Auto Setup Switch Via Target Operator

Indicates whether to enable the X2 interface self-setup function based on target operators. If this parameter is set to ON, the local eNodeB automatically sets up X2 interfaces with peer eNodeBs or gNodeBs of only target operators. If this parameter is set to OFF, the local eNodeB can automatically set up X2 interfaces with peer eNodeBs or gNodeBs of all operators that are not on the X2 blacklist. The X2 blacklist is configured by the X2BlackWhiteList MO. Target operators are specified by the X2AutoSetupOperator MO.
X2 Son TNL Select Mode

Indicates whether to select transport network layer (TNL) parameters based on the primary PLMN ID or selected PLMN ID contained in the SON configuration message. This parameter is used for X2 self-setup in RAN sharing scenarios. Selecting TNL parameters based on the primary PLMN ID applies only to X2 self-setup between eNodeBs provided by different vendors. For X2 self-setup between Huawei eNodeBs, selecting TNL parameters based on the selected PLMN ID is used in preference. This parameter applies only to the X2 interface between eNodeBs. This parameter applies only to LTE FDD and LTE TDD.
Choose UMTS Cell Load Info Trans Channel

Indicates the UMTS load transmission channel. The eNodeB sends RAN-INFORMATION-REQUEST PDUs to UTRAN cells to request multiple reports on the load status of UTRAN cells only when the parameter is set to BASED_ON_RIM. The function specified by the parameter value BASED_ON_ECO is temporarily unavailable. This parameter applies only to LTE FDD and LTE TDD.
S1 handover in data forwarding switch

Indicates the switch used to control the data forwarding mechanism in S1-based incoming handovers.

If the switch is turned off, uplink data forwarding and downlink data forwarding are separately determined. The target eNodeB can choose to send both the uplink and downlink destination addresses, not send the uplink and downlink destination addresses, or send only the uplink or downlink destination address to the source eNodeB.

If the switch is turned on, uplink data forwarding and downlink data forwarding are determined together. The target eNodeB can choose to send both the uplink and downlink destination addresses, not send the uplink and downlink destination addresses, or send only the downlink destination address to the source eNodeB. The target eNodeB cannot send only the uplink destination address to the source eNodeB. This parameter applies only to LTE FDD and LTE TDD.
Inter RAT Link Setup Switch

Indicates the inter-RAT link setup switch. BTS_ENODEB_LINK_SETUP_SWITCH: Indicates whether to set up a link between a BTS and an eNodeB. This option applies only to LTE FDD.
The Timer of X2 delete by SON

Indicates length of the time in which the X2 interface configuration is retained on the local and peer eNodeBs when cells served by the two eNodeBs do not have a neighbor relationship with each other. If the local eNodeB determines that no neighbor relationship is configured between cells served by the local and peer eNodeBs, the local eNodeB starts the timer defined by X2SonDeleteTimer. If no coordinated services are running over the X2 interface when the timer expires, the local eNodeB removes the X2 interface configuration. If this parameter is set to 0, the neighbor relationship-based X2 self-removal function is disabled. This parameter applies only to LTE FDD and LTE TDD.
RIM Coding Policy

Indicates the eNodeB coding scheme for Global eNodeB ID IE and Reporting Cell ID IE in the RIM message. If the EPC devices that exchange RIM messages with eNodeBs are provided by Huawei and the peer devices adopt the private coding scheme, set this parameter to Private Coding. In other cases, set this parameter to Standard Coding. This parameter applies only to LTE FDD and LTE TDD.
L2GU Handover Required With LTE Cap Switch

Indicates whether the handover request message for a handover from E-UTRAN to UTRAN or GERAN contains the UE-EUTRA-Capability information element (IE). This parameter applies only to LTE FDD and LTE TDD.
Different Operator With Same MMEC Switch

Indicates whether MMEs of different operators that share the eNodeB can be configured with the same mobility management entity code (MMEC).

If this parameter is set to OFF, MMEs of different operators that share the eNodeB cannot be configured with the same MMEC. If this parameter is set to ON, MMEs of different operators that share the eNodeB can be configured with the same MMEC.
Peer Request Based X2 Delete Switch

Indicates whether to enable the X2 automatic removal based on a request from the peer eNodeB. If this parameter is set to ON(On), this function is enabled. In this case, the local eNodeB removes the X2 interface configuration if the local eNodeB receives a RESET REQUEST message from the peer eNodeB and determines that the X2 interface is unavailable. If this parameter is set to OFF(Off), this function is disabled. This parameter applies only to LTE FDD and LTE TDD.
Receive status of UL PDCP SDUs sending switch

Indicates whether the SN STATUS TRANSFER message contains the IE "Receive Status Of UL PDCP SDUs" during an S1- or X2-based outgoing handover.

If this parameter is set to OFF, the SN STATUS TRANSFER message contains the IE "Receive Status Of UL PDCP SDUs" when the eNodeB receives out-of-order uplink PDCP packets for bearers in AM.

If this parameter is set to ON, the SN STATUS TRANSFER message contains the IE "Receive Status Of UL PDCP SDUs" when the following conditions are met: (1) The source eNodeB receives out-of-order uplink PDCP packets for bearers in AM. (2) The target eNodeB returns the uplink data forwarding address. This option applies only to LTE FDD and LTE TDD.
Protocol Message Optimization Switch

Indicates whether to optimize protocol messages sent by the eNodeB. This parameter provides the following options:

RrcSetupOptSwitch: If this option is selected, optimization of RRCConnectionSetup messages is enabled. In this case, IEs with protocol-defined default values are no longer included in the RRCConnectionSetup messages. For details about the protocol-defined default setting, see 3GPP TS 36.331. This option applies only to LTE FDD and LTE TDD.

IucsRrcRecfgMcCombSwitch: If this option is selected, the eNodeB includes the radio resource configuration and measurement configuration for a UE in one RRCConnectionReconfiguration message during initial access. This option applies only to LTE FDD and LTE TDD.

RcrpRrcRecfgMcCombSwitch: If this option is selected, the eNodeB includes the radio resource configuration and measurement configuration for a UE in one RRCConnectionReconfiguration message during RRC connection reestablishment. The option will not take effect on the interaction of RRC connection reestablishment and other signaling procedures. This option applies only to LTE FDD and LTE TDD.

RrcRecfgMcOptSwitch: If this option is selected, the cell measurement configurations with the CIO of 0 (indicated by cellIndividualOffset) are no longer included in the measurement configurations delivered to UEs. This option applies only to LTE FDD and LTE TDD.

IdleCsfbRedirectOptSwitch: If this option is selected and the preferred CSFB policy is redirection, during CSFB for UEs in idle mode, the eNodeB no longer activates the security mode or performs RRC connection reconfiguration, but directly sends a redirection message. In accordance with the security requirements of 3GPP CR (R2-1714284), this option takes effect only for redirections to UTRAN cells. This option applies only to LTE FDD and LTE TDD.

UlNasBufferSwitch: If this option is selected, the eNodeB buffers uplink NAS messages sent by the UE before the UE-associated logical S1 connection is available and sends these messages after the UE-associated logical S1 connection is available. If this option is deselected, the eNodeB releases this UE after the procedures end. This option applies only to LTE FDD and LTE TDD.

IratMeasCfgTransSwitch: If this option is selected, the Handover Required message that the eNodeB sends to a BSC contains the IE IRAT Measurement Configuration. This option applies only to LTE FDD and LTE TDD.

GeranAnrMcOptSwitch: This option controls whether measurement configuration optimization takes effect when ANR with GERAN is enabled. If this option is deselected, the optimization does not take effect. That is, when an eNodeB delivers measurement configuration to UEs to perform CGI reading for ANR with GERAN, the carrierFreqs IE can contain multiple GERAN frequencies. If this option is selected, the optimization takes effect, and the carrierFreqs IE contains only one GERAN frequency. This option applies only to LTE FDD and LTE TDD.

SRVCCHoBasedUeCapSwitch: If this option is selected, the eNodeB determines whether to trigger an SRVCC based only on the UE SRVCC capability information, not the SRVCCOperationPossible IE that the MME sends to the eNodeB. If this option is deselected, the eNodeB determines whether to trigger an SRVCC based on the SRVCCOperationPossible IE that the MME sends to the eNodeB. This option applies only to LTE FDD and LTE TDD.

L2GPLMNChooseOptSwitch: This option specifies whether to enable target PLMN ID optimization for handovers to GERAN. If this option is selected, the eNodeB takes the NCL-defined PLMN IDs and includes them in the handover request messages or RIM request messages. If this option is deselected, the optimization is not activated. This option applies only to LTE FDD and LTE TDD.

HoInRrcRecfgMcCombSwitch: If this option is selected, after a UE is handed over to a cell, the cell delivers the radio resource configuration and measurement configuration in a single RRC Connection Reconfiguration message to the UE during the resource reconfiguration procedure. This option applies only to LTE FDD and LTE TDD.

UeCapEnquiryCombSwitch: If this option is selected and a UE sends an Attach Request message to an eNodeB during initial access, the eNodeB queries capabilities of the UE immediately after the RRC connection for the UE is established. This option does not apply to subsequent UE capability query induced by the CA extended frequency band combination query. If this option is deselected and a UE sends an Attach Request message to an eNodeB during initial access, the eNodeB does not query capabilities of the UE until the MME sends a UE context setup request to the eNodeB.
