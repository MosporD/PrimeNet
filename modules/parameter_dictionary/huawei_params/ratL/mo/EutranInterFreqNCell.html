EutranInterFreqNCell

+-NE
  +-eNodeBFunction
    +-Cell
      +-EutranInterFreqNCell

Description

An EutranInterFreqNCell MO consists of the parameters related to the neighbor relationship with an inter-frequency E-UTRAN cell. These parameters include those used in measurement control for inter-frequency handovers and those in system information block type 5 (SIB5) for inter-frequency cell reselections. Inter-frequency neighboring relations can be maintained by automatic neighbor relation (ANR). Inter-frequency neighboring relationships are used in algorithms such as mobility load balancing (MLB), mobility robustness optimization (MRO).

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    Cell
  • Relation with the EutranExternalCell, CnOperator, eNodeBFunction, ENodeBSharingMode, and Cell MOs:
    • Before adding an inter-eNodeB EutranInterFreqNCell MO, ensure that the associated EutranExternalCell MO has been configured.
  • Relation with the EutranExternalCell and Cell MOs:
    • Before adding an inter-eNodeB EutranInterFreqNCell MO, ensure that the associated EutranExternalCell MO has been configured, and the NbCellFlag of the server Cell of the inter-eNodeB EutranInterFreqNCell MO must be same with the NbCellFlag of EutranExternalCell.
    • If NbCellFlag in a Cell MO is set to FALSE, and DlEarfcn in the local Cell MO belongs to an LTE FDD frequency band, the carrier frequency calculated based on DlEarfcn in the EutranExternalCell MO that represents an inter-eNodeB EutranInterFreqNCell MO must be different from the carrier frequency calculated based on DlEarfcn in the local Cell MO.
    • Before adding an inter-eNodeB inter-frequency neighboring cell, ensure that the associated EutranExternalCell MO has been configured, and the NbCellFlag of the server Cell of the inter-eNodeB EutranInterFreqNCell MO must be same with the NbCellFlag of EutranExternalCell.
  • Relation with the Cell MO:
    • Before adding an intra-eNodeB EutranInterFreqNCell MO for a serving cell, ensure that a Cell MO corresponding to this intra-eNodeB inter-frequency cell has been configured, and the parameter NbCellFlag must be set to the same value for the two cells.
    • If NbCellFlag in a Cell MO is set to FALSE, and DlEarfcn in the local Cell MO belongs to an LTE FDD frequency band, the carrier frequency calculated based on DlEarfcn in the Cell MO that represents an intra-eNodeB EutranInterFreqNCell MO must be different from the carrier frequency calculated based on DlEarfcn in the local Cell MO.
    • The CGI of the local cell must be different from that of any intra-eNodeB inter-frequency neighboring cell. A CGI is comprised of Mcc, Mnc, eNodeBId and CellId. Two CGIs are considered to be the same if they have an identical combination of the four parameters. The CGI of an inter-frequency neighboring cell is comprised of Mcc, Mnc, eNodeBId, and CellId in the EutranInterFreqNCell MO. The CGI of the local cell is comprised of Mcc and Mnc in one associated CnOperator MO, eNodeBId in the associated eNodeBFunction MO, and CellId in the Cell MO.
  • Relation with the Cell and EutranInterNFreq MOs:
    • DlEarfcn in the Cell MO corresponding to an intra-eNodeB EutranInterFreqNCell MO must be the same as DlEarfcn in an EutranInterNFreq MO.
  • Relation with the Cell and Prb MOs:
    • If NbCellFlag in a Cell MO is set to TRUE and an intra-eNodeB cell is to be added in an EutranInterFreqNCell MO for this Cell MO, Prb MO whose AnchorCarrierFlag is TRUE must be configured first for the two cells.
  • Relation with the EutranExternalCell and Prb MOs:
    • If an inter-eNodeB inter-frequency neighboring cell is to be configured using an EutranInterFreqNCell MO for a local cell whose NbCellFlag is set to TRUE, the carrier frequency identified by the combination of DlEarfcn and DlFreqOffset in the EutranExternalCell MO that the EutranInterFreqNCell MO depends on cannot be the same as the carrier frequency identified by the combination of DlEarfcn and DlFreqOffset or by DlEarfcn and DlBandWidth in the Cell corresponding to LteDlRbIndex in the Prb MO with AnchorCarrierFlag set to TRUE for the local cell.
  • Relation with the Prb MO:
    • If an intra-eNodeB inter-frequency neighboring cell is to be configured using an EutranInterFreqNCell MO for a local cell whose NbCellFlag is set to TRUE, the carrier frequency identified by the combination of DlEarfcn and DlFreqOffset or by DlEarfcn and DlBandWidth in the Cell corresponding to LteDlRbIndex in the Prb MO with AnchorCarrierFlag set to TRUE for the neighboring cell cannot be the same as the carrier frequency identified by the combination of DlEarfcn and DlFreqOffset or by DlEarfcn and DlBandWidth in the Cell corresponding to LteDlRbIndex in the Prb MO with AnchorCarrierFlag set to TRUE for the local cell.
  • Relation with the EutranInterNFreq and Prb MOs:
    • If an intra-eNodeB inter-frequency neighboring cell is to be configured using an EutranInterFreqNCell MO for a local cell whose NbCellFlag is set to TRUE, and AnchorCarrierFlag is set to TRUE in the Prb MO for the neighboring cell, then an EutranInterNfreq MO must be configured for the local cell and the frequency and frequency offset specified by DlEarfcn and DlFreqOffset in the EutranInterNfreq MO must be the same as those specified by DlEarfcn and DlFreqOffset or calculated based on DlEarfcn and DlBandWidth in the Cell corresponding to LteDlRbIndex in the Prb MO with AnchorCarrierFlag set to TRUE for the neighboring cell.
  • Relation with the CnOperator and ENodeBSharingMode MOs:
    • In intra-eNodeB scenarios, when the ENodeBSharingMode parameter in an ENodeBSharingMode MO is set to SEPARATED_FREQ_SPEC, the Mcc and Mnc parameters in the EutranInterFreqNCell MO must be the same as the Mcc and Mnc parameters in the CnOperator MO corresponding to the primary operator, respectively.
  • Relation with the CellOp, CnOperator, CnOperatorTa, and ENodeBSharingMode MOs:
    • A CellOp MO must be configured for each EutranInterFreqNCell MO that corresponds to an intra-eNodeB inter-frequency neighboring cell. If the ENodeBSharingMode parameter in the ENodeBSharingMode MO is set to SHARED_FREQ, Mcc and Mnc in such an EutranInterFreqNCell MO must be the same as the Mcc and Mnc specified in the CnOperator MO representing the primary operator. If ENodeBSharingMode is set to INDEPENDENT or SEPARATED_FREQ, Mcc and Mnc in such an EutranInterFreqNCell MO must be set to the same values as Mcc and Mnc specified in the CnOperator MO corresponding to the CellOp MO associated with this EutranInterFreqNCell MO.
  • Relation with the EutranExternalCell, EutranInterNFreq, and Cell MOs:
    • DlEarfcn in the EutranExternalCell MO corresponding to an inter-eNodeB EutranInterFreqNCell MO must be the same as DlEarfcn in an EutranInterNFreq MO.
    • In inter-eNodeB scenarios, the value of DlEarfcn in the EutranExternalCell MO associated with an EutranInterFreqNCell MO of a Cell MO must be the same as one of the values of DlEarfcn in the EutranInterNFreq MOs associated with this Cell MO and the values of DlFreqOffset and DlFreqOffset must be the same.
  • Relation with the EutranExternalCell, Cell, and Prb MOs:
    • In inter-eNodeB scenarios, if NbCellFlag in a Cell MO is set to TRUE and an EutranInterFreqNCell MO is to be added for this Cell MO, a Prb MO whose AnchorCarrierFlag is TRUE must be configured first for this Cell MO.
  • Relation with the CellOp, CnOperator, CnOperatorTa, CnOpSharingGroup, Cell, and ENodeBSharingMode MOs:
    • A CellOp MO must be configured for each EutranInterFreqNCell MO that corresponds to an intra-eNodeB inter-frequency neighboring cell. If ENodeBSharingMode in the ENodeBSharingMode MO is set to HYBRID_SHARED, Mcc and Mnc in such an EutranInterFreqNCell MO must be set to the same values as Mcc and Mnc, respectively, in the CnOperator MO referenced by PrimaryOperatorId in the CnOpSharingGroup MO for the intra-eNodeB inter-frequency neighboring cell.
  • Relation with the EutranInterFreqNCell MO:
    • The CGI specified by parameters in an EutranBlkNCell MO cannot be the same with the CGI specified by parameters in an EutranInterFreqNCell MO. The CGI consists of the MCC, MNC, eNodeB ID, and cell ID. Two CGIs are considered the same when the four items are the same. In the EutranBlkNCell MO, the CGI is specified by Mcc, Mnc, eNodeBId, and CellId. In the EutranInterFreqNCell MO, the CGI is specified by Mcc, Mnc, eNodeBId, and CellId.
  • Relation with the EutranIntraFreqNCell MO:
    • A maximum of 72*256 EutranInterFreqNCell and EutranIntraFreqNCell MOs can be configured in total in the same eNodeB when equipped with UMPTe or UMPTga board and did not equipped with UMPTg.
    • A maximum of 144*256 EutranInterFreqNCell and EutranIntraFreqNCell MOs can be configured in total in the same eNodeB.
    • A maximum of 18*256 EutranInterFreqNCell and EutranIntraFreqNCell MOs can be configured in total in the same eNodeB when equipped with LMPT board.
    • A maximum of 36*256 EutranInterFreqNCell and EutranIntraFreqNCell MOs can be configured in total in the same eNodeB when equipped with UMPTa/b board.
  • Relation with the EutranIntraFreqNCell and NODE MOs:
    • WM in the NODE MO is set to CONCURRENT, a maximum of 72*256 EutranInterFreqNCell and EutranIntraFreqNCell MOs can be configured in total in the same eNodeB.
  • Relation with the EutranIntraFreqNCell, Cell, and MDU MOs:
    • A maximum of 384 EutranInterFreqNCell and EutranIntraFreqNCell MOs can be configured in total for a Cell MO in the eNodeB when equipped with UMPT board or MDU type is MDUC or UMDU.
  • Relation with the EutranIntraFreqNCell and Cell MOs:
    • A maximum of 256 EutranInterFreqNCell and EutranIntraFreqNCell MOs can be configured in total for a Cell MO in the eNodeB when equipped with LMPT board.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Local cell ID

Indicates the cell ID of the local cell. It uniquely identifies a cell within an eNodeB.
Mobile country code

Indicates the mobile country code of the E-UTRAN neighboring cell.

The PLMN consists of the MCC and the MNC.

The MCC consists of three digits.

The MNC consists of two to three digits.

For example, if the MCC is 123 and the MNC is 45, then the PLMN ID is 12345.
Mobile network code

Indicates the mobile network code of the E-UTRAN neighboring cell.

The PLMN consists of the MCC and the MNC.

The MCC consists of three digits.

The MNC consists of two to three digits.

For example, if the MCC is 123 and the MNC is 45, then the PLMN ID is 12345.
eNodeB ID

Indicates the eNodeB ID of the inter-frequency neighboring cell. It uniquely identifies an eNodeB within a PLMN. The 28-bit E-UTRAN cell ID is comprised of the cell ID and the eNodeB ID (represented by the most significant 20 bits). The cell global identity (CGI) of an E-UTRAN cell is comprised of the E-UTRAN cell ID and the PLMN ID. For details, see 3GPP TS 36.413.
Cell ID

Indicates the local ID of the inter-frequency neighboring cell. It uniquely identifies a cell within an eNodeB. The 28-bit E-UTRAN cell ID is comprised of the cell ID (represented by the least significant eight bits) and the eNodeB ID. The cell global identity (CGI) of an E-UTRAN cell is comprised of the E-UTRAN cell ID and the PLMN ID. For details, see 3GPP TS 36.413.
Cell individual offset

Indicates the cell individual offset for the inter-frequency neighboring cell. It affects the probability of triggering inter-frequency measurement reports. A larger value of this parameter indicates a higher probability. For details, see 3GPP TS 36.331. This parameter applies only to LTE FDD and LTE TDD.
Cell offset

Indicates the offset for the inter-frequency neighboring cell, which is used in evaluation for cell reselections. A larger value of this parameter results in a lower probability of cell reselections to this neighboring cell. If this parameter is not set to dB0, it is delivered in SIB5. For details, see 3GPP TS 36.331. If this parameter is set to dB0, it is not delivered in SIB5. In this situation, UEs use 0 dB as the offset for cell reselections. For details, see 3GPP TS 36.304. This parameter applies only to LTE FDD and LTE TDD.
No handover indicator

Indicates whether handovers of UEs to the neighboring cell are prohibited. This parameter applies only to LTE FDD and LTE TDD.
No remove indicator

Indicates whether to permit or prohibit removal of the neighbor relationship by ANR. This parameter applies only to LTE FDD and LTE TDD.
Blind handover Priority

Indicates the priority of the neighboring cell during handovers. The parameter values are divided into three segments, indicating the blind-handover priority, frequency-based-handover priority, and 0. A larger value indicates a higher priority within the same segment. The parameter values 1 to 16 indicate the blind-handover priorities used only in non-frequency-priority-based blind handovers. A blind handover is a process in which the eNodeB hands over a UE to a specified neighboring cell without measurements. If this parameter is set to 0 for blind handovers, this neighboring cell cannot be selected as a target cell for blind handovers. The parameter values 17 to 32 indicate the handover priorities used when the eNodeB selects the frequencies to be delivered for measurements based on the blind handover cell configurations. These values are applicable to frequency-priority-based blind handovers and measurement-based handovers. If this parameter is set to 0, this neighboring cell cannot be selected as a target cell for frequency-priority-based handovers. This parameter applies only to LTE FDD and LTE TDD.
ANR flag

Indicates whether this neighboring cell is automatically discovered by the ANR algorithm. This parameter applies only to LTE FDD and LTE TDD.
Local cell name

Indicates the name of the local cell.
Neighbour cell name

Indicates the name of the inter-frequency neighboring cell.
Cell Measure Priority

Indicates the priority of measurement on the inter-frequency neighboring cell. The eNodeB preferentially contains the information about a neighboring cell with this priority set to HIGH_PRIORITY while delivering a measurement configuration. This parameter applies only to LTE FDD and LTE TDD.
Overlap Indicator

Indicates whether the neighboring cell is identified as a neighboring cell overlapping the local E-UTRAN cell. The default value is NO. The parameter value YES indicates that the neighboring cell is identified as a neighboring cell overlapping the local E-UTRAN cell. The parameter value NO indicates that the neighboring cell is not identified as a neighboring cell overlapping the local E-UTRAN cell.
Overlap Range

Indicates the overlapping coverage area between the local cell and a target cell for determining the location-based UE selection policy for inter-frequency MLB. This parameter applies only to LTE TDD.
High Speed Interference Avoid Flag

Indicates whether to inform adjacent low-speed neighboring cells of high-speed train passing to reduce interference to high-speed UEs when a high-speed train reaches a high-speed dedicated network cell. This parameter applies only to LTE FDD and LTE TDD.
Neighbor Cell Classification Label

Indicates the neighboring cell classification label. The parameter values FORMAL and EXTENDED represent different neighboring cell management policies. If the number of handovers to a neighboring cell reaches a predefined threshold, the parameter is set to FORMAL for this neighboring cell; otherwise, the parameter is set to EXTENDED for this neighboring cell. This parameter applies only to LTE FDD and LTE TDD.
Aggregation Attribute

Indicates the carrier aggregation attributes of the neighboring cell. This parameter applies only to LTE FDD and LTE TDD.

BlindScellCfg: If this option is selected, the neighboring cell can be configured as an SCell or PSCell in a blind manner to work with the serving cell. If the option is deselected, the blind configuration is not allowed.
Local Cell to NCell MLB PRB Thld

Indicates the PRB usage threshold used to determine whether to trigger MLB from the local cell to the neighboring cell. This parameter does not take effect when it is set to 0. This parameter applies only to LTE FDD and LTE TDD.
Local Cell to NCell MLB UE Number Thld

Indicates the threshold of the number of UEs for triggering MLB from the local cell to the neighboring cell. The value 0 indicates that this parameter is invalid. This parameter applies only to LTE FDD and LTE TDD.
NCell to Local Cell MLB UE Number Thld

Indicates the threshold of the number of UEs for triggering MLB from the neighboring cell to the local cell. The value 0 indicates that this parameter is invalid. This parameter applies only to LTE FDD and LTE TDD.
Control Mode

Indicates the control policy on ANR-related MOs, which can be defined by the user or be based on the automatic neighbor relation (ANR) algorithm. When this parameter is set to MANUAL_MODE, this MO can be modified or removed only by users. A failure message is displayed when a user adds an existing MO (with identical keywords). When this parameter is set to AUTO_MODE, this MO can be modified or removed by users or the ANR algorithm. The MO removal is successful even if the MO does not exist. If an MO does not exist, it can be added by both users and the ANR algorithm. If an existing MO is to be added, the MO is modified when a user performs the addition, but it cannot be added by the ANR algorithm. When this MO is automatically added by the ANR algorithm, this parameter is set to AUTO_MODE by default. When this MO is added by a user, this parameter can be set to either AUTO_MODE or MANUAL_MODE. This parameter applies only to LTE FDD and LTE TDD.
Overlap Indicator Extension

Indicates whether the neighboring cell is an overlapping neighboring cell of the local cell.

VIRTUAL_4T4R_OVERLAP_INDICATOR: If this option is selected, the coverage areas of this neighboring cell and the local cell overlap. If this option is deselected, the coverage areas do not overlap. This option applies only to LTE FDD.
Neighboring Cell Addition Time

Indicates the time the neighboring cell was added by ANR for the first time. In free mode, this time is the local time of the NE. In control mode, this time is the local time of the OSS when optimization suggestions are delivered. The format is YYYY-MM-DD. For example, the value 2018-01-01 indicates January 1, 2018. The value 2001-01-01 indicates that the neighboring cell was manually added. This parameter applies only to LTE FDD and LTE TDD.
