X2Interface

+-NE
  +-eNodeBFunction
    +-X2Interface

Description

An X2Interface MO consists of user-configured parameters related to an X2 interface between the local eNodeB and a neighboring eNodeB. The parameters specify information about the X2 interface and the neighboring eNodeB, including the control port bearer used for the X2 interface, the operator to which the X2 interface belongs, and the ID of the neighboring eNodeB.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    eNodeBFunction
  • Relation with the ENodeBSharingMode MO:
    • If ENodeBSharingMode in the ENodeBSharingMode MO is set to HYBRID_SHARED and CtrlMode in the X2Interface MO is set to MANUAL_MODE, CnOpSharingGroupId in the X2Interface MO must have been configured in the associated CnOpSharingGroup MO.
  • Relation with the CnOpSharingGroup MO:
    • CnOpSharingGroupId in the X2Interface MO must have been configured in the associated CnOpSharingGroup MO if CnOpSharingGroupId is not set to the invalid value 255 and CtrlMode in the X2Interface MO is set to MANUAL_MODE.
    • The operator corresponding to CnOperatorId in the X2Interface MO must have been configured in the associated CnOpSharingGroup MO if CnOpSharingGroupId is not set to the invalid value 255 and CtrlMode in the X2Interface MO is set to MANUAL_MODE.
  • Relation with the S1Interface MO:
    • S1CpBearerId in an S1Interface MO must be different from X2CpBearerId in any X2Interface MO.
  • Relation with the CPBEARER MO:
    • If CtrlMode in the X2Interface MO is set to MANUAL_MODE, a CTRLMODE in the CPBEARER MO referenced by an X2Interface MO must set to MANUAL_MODE.
    • If CtrlMode in the X2Interface MO is set to MANUAL_MODE, X2CpBearerId in an X2Interface MO must have been set in the associated CPBEARER MO, and must not have been set in the SAAL type.
  • Relation with the CnOperator MO:
    • If CtrlMode in the X2Interface MO is set to MANUAL_MODE, CnOperatorId in an X2Interface MO must have been set in the associated CnOperator MO.
  • Relation with the MPT MO:
    • The number of instances of the X2Interface MO cannot exceed 96 when the TYPE parameter in the MPT is set to LMPT.
    • The number of instances of the X2Interface MO cannot exceed 256 when the TYPE parameter in the MPT is set to UMPT and the BRDSPEC parameter is set to UMPTa/b.
    • The number of instances of the X2Interface MO cannot exceed 384 when the TYPE parameter in the MPT is set to UMPT and the BRDSPEC parameter is set to UMPTe, and other BRDSPEC parameters in all MPT MOs is set to UMPTe, UMPTa, UMPTb, or UMPTa/b.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD X2INTERFACE

Use this command to add an X2 interface.
DSP X2INTERFACE

Use this command to query the status of an X2 interface and the information about the peer base station. The information about the peer base station includes the peer base station ID and its PLMN ID. If the status of an X2 interface is abnormal, the execution result displays the information about the peer base station in the last normal connection with the local eNodeB.
DSP X2UPINFO

Use this command to query X2 user plane information.
MOD X2INTERFACE

Use this command to modify an X2 interface.
RMV X2INTERFACE

Use this command to remove an X2 interface.
RST X2INTERFACE

Use this command to reset an X2 interface.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
X2Interface ID

Indicates the X2 interface ID. If the X2 interface is set up based on the endpoint configuration mode, the value range is 40000 to 65535. If the X2 interface is set up based on the link configuration mode using the MAE or MML commands, the recommended value range is 0 to 39999.
X2 Interface CP Bearer ID

Indicates the ID of the control port bearer for the X2 interface.
CN Operator ID

Indicates the ID of the operator that owns the X2 interface.
Peer Base Station Release

Indicates the protocol release with which the peer base station connected to the local base station through the X2 interface complies. This parameter applies only to LTE FDD and LTE TDD.
Control Mode

Indicates the control mode of the X2 interface, which determines the control policies of operators and the SON functions on the X2 interface. This parameter is set by the system and cannot be modified by operators. If the X2 interface was set up by operators by using the MAE or MML commands, this parameter is set to MANUAL_MODE and operators can configure the interface. If the X2 interface was set up automatically based on the endpoint configuration mode, then: 1. This parameter is set to AUTO_MODE. 2. Operators can reset the interface and query the information about the interface. 3. Operators cannot modify or delete the interface.
Auto Config Flag

Indicates whether the X2 interface was created automatically or manually. This parameter is set by the system and cannot be modified by operators. The system sets this parameter to AUTO_CREATED when the X2 interface was created automatically using SON and to MANUAL_CREATED when the X2 interface was created manually by using the MAE or running MML commands.
CN Operator Sharing Group ID

Indicates the ID of a carrier-sharing operator group that shares the X2 Interface MO. If the eNodeB works in hybrid RAN sharing mode, set this parameter to a value within the range from 0 to 5. If the eNodeB works in independent mode, RAN sharing with common carriers mode, or RAN sharing with dedicated carriers mode, retain the default value 255, which is an invalid value.
Neighboring Base Station Type

Indicates the type of the neighboring base station to which the local base station is connected through the X2 interface. This parameter applies only to LTE FDD and LTE TDD.
Table 3 Dynamic parameters

Parameter

Description
Neighboring Base Station ID

Indicates the ID of the neighboring base station to which the local base station is connected through the X2 interface. The combination of this parameter and NbrEnbPlmnId uniquely identifies the neighboring base station around the globe. If the neighboring base station is an eNodeB, this parameter specifies the eNodeB ID. If the neighboring base station is a gNodeB, this parameter specifies the gNodeB ID. This parameter applies only to LTE FDD and LTE TDD.
Neighbor Base Station PLMN ID

Indicates the PLMN ID of the neighboring eNodeB to which the local eNodeB is connected through the X2 interface.
X2Interface state

Indicates the status of the X2 interface. If the status is normal, the X2 interface has been successfully established. If the status is abnormal, the X2 interface establishment fails.
X2Interface state abnormal reason

Indicates the reason why the X2 interface is abnormal.
Last Fault Occur Time

Indicates the time when the last X2 fault occurred. When a lower-layer link fault occurred and persisted for 18 seconds, the time that is 18 seconds after the fault occurred is recorded and taken as the parameter value. When an X2 interface setup failed for three consecutive times, the time that the X2 setup failure occurs for the third time is recorded and taken as the parameter value. The time format is YEAR-MONTH-DAY HH:MM:SS. For example, 2000-1-1 10:20:05 indicates 10:20:05 on January 1, 2000.
Query Type

Indicates the status type of X2 interfaces to be queried. If this parameter is not specified in the DSP X2INTERFACE command, information about X2 interfaces in all states is displayed in the command output. If the X2interfaceId parameter is specified in the MML command, the QueryType parameter does not take effect.
X2 User Plane Host IPv4 Address

Indicates the IPv4 address of the user-plane host of the X2 interface. This parameter applies only to LTE FDD and LTE TDD.
X2 User Plane Peer IPv4 Address

Indicates the IPv4 address of the user-plane peer of the X2 interface. This parameter applies only to LTE FDD and LTE TDD.
X2 User Plane Link State

Indicates the user-plane link status of the X2 interface. The value Abnormal indicates that the user-plane link is disconnected. The value Normal indicates that the user-plane link is connected. The value Unknown indicates that the status or the IP PM delay of the link cannot be obtained. This parameter applies only to LTE FDD and LTE TDD.
X2 User Plane Link Maximum One-Way Delay

Indicates maximum one-way link delay of the X2 user-plane. This parameter applies only to LTE FDD and LTE TDD.
X2 User Plane Link Two-Way Delay

Indicates the two-way link delay of the X2 user-plane. This parameter applies only to LTE FDD and LTE TDD.
Transmit Available Bandwidth

Indicates the available bandwidth in the sending direction detected by the function of transmission congestion detection. If the TransmitCongDelay and TransmitAvailableBw parameter values are NULL and congestion detection in X2/eX2 links in non-ideal backhaul mode for bearer coordination services is enabled, the transmission congestion detection procedure fails. The failure cause can be one of the following: 1. The IPPM session that transmission congestion detection depends on is not activated. 2. The version or boards of the peer end do not support transmission congestion detection. 3. The boards of the local end do not support transmission congestion detection. This parameter applies only to LTE FDD and LTE TDD.
Transmit Congestion Delay

Indicates the single-way transmission congestion delay detected by the function of transmission congestion detection. If the TransmitCongDelay and TransmitAvailableBw parameter values are NULL and congestion detection in X2/eX2 links in non-ideal backhaul mode for bearer coordination services is enabled, the transmission congestion detection procedure fails. The failure cause can be one of the following:

- The IPPM session that transmission congestion detection depends on is not activated.

- The version or boards of the peer end do not support transmission congestion detection.

- The boards of the local end do not support transmission congestion detection.
X2 User Plane Host IPv6 Address

Indicates the IPv6 address of the user-plane host of the X2 interface. This parameter applies only to LTE FDD and LTE TDD.
X2 User Plane Peer IPv6 Address

Indicates the IPv6 address of the user-plane peer of the X2 interface. This parameter applies only to LTE FDD and LTE TDD.
X2 Usage Meas Duration

Indicates the length of measurement duration of X2 usage from the last measurement period to the current time. For a new X2 interface set up during this period, the length of the measurement duration is from the time the X2 interface is set up to the current time. The measurement period is specified by the X2SonDeleteTimerforX2Usage parameter in the GlobalProcSwitch MO. This parameter applies only to LTE FDD and LTE TDD.
X2 Usage Statistics

Indicates the measurement value of an X2 interface during a period from the last measurement period to the current time. For an inter-eNodeB X2 interface, this parameter indicates the total number of incoming and outgoing handovers over the X2 within a measurement duration. For an EN-DC X2 interface, this parameter indicates the total number of successful additions of a gNodeB that is connected over the EN-DC X2 interface within a measurement duration. This parameter applies only to LTE FDD and LTE TDD.
X2 NSA Meas Result in Last Period

Indicates the accumulated values of measurements of NSA services over the X2 interface in the last full period. The parameter value includes results of multiple measurement items in the following sequence:

Measurements of eNodeB-initiated SgNB addition procedures:

1. Number of times the eNodeB sends SgNB Addition Request to gNodeBs

2. Number of times the eNodeB receives SgNB Addition Request Acknowledge messages from gNodeBs

3. Number of times the eNodeB sends SgNB Reconfiguration Complete messages to gNodeBs

Measurements of eNodeB-initiated SgNB modification procedures:

4. Number of times the eNodeB sends SgNB Modification Request messages to gNodeBs

5. Number of times the eNodeB receives SgNB Modification Request Acknowledge messages from gNodeBs

6. Number of times the eNodeB sends SgNB Reconfiguration Complete messages to gNodeBs

Measurements of gNodeB-initiated SgNB release procedures:

7. Number of times the eNodeB receives SgNB Release Required messages from gNodeBs

8. Number of times the eNodeB receives SgNB Release Required messages for normal releases from gNodeBs

Measurements of gNodeB-initiated inter-base-station handover procedures:

9. Number of times the eNodeB receives SgNB Change Required messages from gNodeBs

10. Number of times the eNodeB sends SgNB Change Confirm messages to gNodeBs

11. Number of times the eNodeB sends SgNB Change Refuse messages to gNodeBs

Measurements of failed UE-initiated SCG procedures:

12. Number of times the eNodeB receives SCGFailureInformationNR messages from UEs

This parameter applies only to LTE FDD and LTE TDD.
X2 NSA Meas Result in Current Period

Indicates the accumulated values of measurements of NSA services over the X2 interface in the current period. The parameter value includes results of multiple measurement items in the following sequence:

Measurements of eNodeB-initiated SgNB addition procedures:

1. Number of times the eNodeB sends SgNB Addition Request messages to gNodeBs

2. Number of times the eNodeB receives SgNB Addition Request Acknowledge messages from gNodeBs

3. Number of times the eNodeB sends SgNB Reconfiguration Complete messages to gNodeBs

Measurements of eNodeB-initiated SgNB modification procedures:

4. Number of times the eNodeB sends SgNB Modification Request messages to gNodeBs

5. Number of times the eNodeB receives SgNB Modification Request Acknowledge messages from gNodeBs

6. Number of times the eNodeB sends SgNB Reconfiguration Complete messages to gNodeBs

Measurements of gNodeB-initiated SgNB release procedures:

7. Number of times the eNodeB receives SgNB Release Required messages from gNodeBs

8. Number of times the eNodeB receives SgNB Release Required messages for normal releases from gNodeBs

Measurements of gNodeB-initiated inter-base-station handover procedures:

9. Number of times the eNodeB receives SgNB Change Required messages from gNodeBs

10. Number of times the eNodeB sends SgNB Change Confirm messages to gNodeBs

11. Number of times the eNodeB sends SgNB Change Refuse messages to gNodeBs

Measurements of failed UE-initiated SCG procedures:

12. Number of times the eNodeB receives SCGFailureInformationNR messages from UEs

This parameter applies only to LTE FDD and LTE TDD.
X2 NSA Last Meas Period End Time

Indicates the time when the X2 service measurement finishes in the last full measurement period. The measurement period is specified by the EnodeBAlgoExtSwitch.X2NsaCounterPeriod parameter. The time format is YEAR-MONTH-DAY HH:MM:SS. For example, 2000-1-1 10:20:05 indicates 10:20:05 on January 01, 2000.

This parameter applies only to LTE FDD and LTE TDD.
