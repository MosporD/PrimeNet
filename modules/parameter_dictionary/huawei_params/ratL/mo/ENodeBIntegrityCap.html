ENodeBIntegrityCap

+-NE
  +-eNodeBFunction
    +-ENodeBIntegrityCap

Description

The ENodeBIntegrityCap MO consists of the parameters related to the priorities of the eNodeB integrity protection algorithms. The integrity protection function, which consists of integrity protection and integrity check, can be used to protect data from modification by unauthorized users. This function is applicable only to RRC signaling. Four algorithms are available for integrity protection: SNOW 3G, AES, ZUC, and NULL.

Effective Scenario

Immediately

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Primary integrity algorithm

Indicates the highest-priority integrity protection algorithm supported by the eNodeB. If this parameter is set to NOT_CFG, the eNodeB skips the algorithm of this priority when selecting the integrity protection algorithm.
Second integrity algorithm

Indicates the second-priority integrity protection algorithm supported by the eNodeB. If this parameter is set to NOT_CFG, the eNodeB skips the algorithm of this priority when selecting the integrity protection algorithm.
Third integrity algorithm

Indicates the third-priority integrity protection algorithm supported by the eNodeB. If this parameter is set to NOT_CFG, the eNodeB skips the algorithm of this priority when selecting the integrity protection algorithm.
NULL Algorithm config switch

Indicates whether the eNodeB can use the null algorithm for integrity protection. If this parameter is set to Disable, UE access using the null algorithm is prohibited. If this parameter is set to Enable, UE access using the null algorithm is supported. If this parameter is set to EnableToEia0Eea0CapbOnlyUe, access of UEs with security capabilities including only EIA0 and EEA0 is allowed regardless of whether there is a parameter set to NULL in the ENodeBCipherCap MO.
