Description

A CnOperator MO consists of the ID, name, type, mobile country code (MCC), and mobile network code (MNC) of an operator. The MCC and MNC constitute a public land mobile network (PLMN) ID, which uniquely identifies the operator.

MML Command

Function
ADD CNOPERATOR

Use this command to add a CN operator. After an operator is added, a license sharing policy and the ratio of traffic that each operator can use must be specified except in the following two cases:

1) The eNodeBSharingMode parameter is set to INDEPENDENT.

2) No traffic ratio is configured for any operator.

A maximum of six operators can be added for an eNodeB. If the eNodeB is configured to work in RAN sharing with common carriers mode, RAN sharing with dedicated carriers mode, hybrid RAN sharing mode, or RAN sharing with special dedicated carriers mode but does not have the required RAN sharing license, configurations of secondary operators do not take effect. If the license control item RAN Sharing by More Operators is disabled, a maximum of four operators can share the eNodeB, configurations of other operators do not take effect, and other operators cannot use the eNodeB to provide services.

If the license control item RAN Sharing by More Operators is disabled and more than four operators are added for the eNodeB, the following principles apply when the eNodeB decides which four operators to take effect: The configuration of the primary operator takes effect first. The configurations of secondary operators take effect in the same sequence as they are added. After the eNodeB is restarted, the configuration of the primary operator takes effect first and the configurations of secondary operators take effect based on the operator IDs. The configuration of a secondary operator with a smaller operator ID takes effect in prior to that with a larger operator ID. As a result, the following situation is possible: The configurations of secondary operators with larger IDs (for example, 4 and 5) but earlier configuration time take effect while the configurations of secondary operators with smaller IDs (for example, 0 and 1) do not take effect. However, after the eNodeB is restarted, the configurations of secondary operators with the smaller IDs (for example, 0 and 1) take effect while the configurations of secondary operators with the larger IDs (for example, 4 and 5) do not take effect. In either case, two operators cannot provide services normally. In this case, the operators need to purchase the license control item RAN Sharing by More Operators.

The combination of the mobile country code (MCC) and mobile network code (MNC) uniquely identifies an operator. If the MCC or MNC is changed, the operator identified by the operator ID is changed. A maximum of six operators can be added for an eNodeB. If the license control item RAN Sharing by More Operators is disabled, a maximum of four operators can share the eNodeB, configurations of other operators do not take effect, and other operators cannot use the eNodeB to provide services.

If the license control item RAN Sharing by More Operators is disabled and more than four operators are added for the eNodeB, the following principles apply when the eNodeB decides which four operators to take effect: The configuration of the primary operator takes effect first. The configurations of secondary operators take effect in the same sequence as they are added. After the eNodeB is restarted, the configuration of the primary operator takes effect first and the configurations of secondary operators take effect based on the operator IDs. The configuration of a secondary operator with a smaller operator ID takes effect in prior to that with a larger operator ID. As a result, the following situation is possible: The configurations of secondary operators with larger IDs (for example, 4 and 5) but earlier configuration time take effect while the configurations of secondary operators with smaller IDs (for example, 0 and 1) do not take effect. However, after the eNodeB is restarted, the configurations of secondary operators with the smaller IDs (for example, 0 and 1) take effect while the configurations of secondary operators with the larger IDs (for example, 4 and 5) do not take effect. In either case, two operators cannot provide services normally. In this case, the operators need to purchase the license control item RAN Sharing by More Operators.

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
CN Operator ID

Indicates the ID of the operator.
CN Operator name

Indicates the name of the operator.
CN Operator type

Indicates the type of the operator. The operator can be the primary operator or a secondary operator. For each eNodeB, only one primary operator but more than one secondary operator can be configured.
Mobile country code

Indicates the mobile country code (MCC) of the operator.
Mobile network code

Indicates the mobile network code (MNC) of the operator. The value of this parameter is a string of two or three decimal digits.
PLMN Mode

Indicates whether the PLMN works in Isolated E-UTRAN Operation for Public Safety (IOPS) mode when the CnOperatorType parameter is set to CNOPERATOR_SECONDARY for the operator.

Only the PLMN of a secondary operator can be configured to work in IOPS mode, and only one PLMN of an eNodeB can be configured to work in IOPS mode. When the active main control board is an LMPT board, the PlmnMode parameter cannot be set to IOPS_PLMN.
Operator Function Switch

Indicates whether to enable features for the operator.

CELL_TRAFFIC_TRACE_MSG_SWITCH: After a cell tracing task is started, the eNodeB can send the CellTrafficTrace message to the MME over the S1 interface only if this option is selected. For details about the mechanism of sending the CellTrafficTrace message, see 3GPP TS 32.422.

DCN_SUPPORT_SWITCH: The operator supports access to the dedicated core network (DCN) and the MME-initiated Reroute NAS Request procedure only if this option is selected. For details about DCN, see 3GPP TS 36.413 and 3GPP TS 23.401.

MME_STRICT_SELECTION_SWITCH: Indicates whether to enable MME selection by exact GUMMEI match for UEs of the operator. A GUMMEI is comprised of a PLMN ID, an MMEGI, and an MMEC. A UE accesses a cell with the IE Registered MME. If this option is selected, the eNodeB selects an MME, whose MMEGI and MMEC totally match those indicated by the IE. If no MME meets the exact match requirement, the eNodeB selects an MME based on priorities, topologies, and loads of MMEs and the NNSFENHANCEMENTSWITCH option does not take effect. If this option is deselected, the eNodeB selects an MME using the original algorithm.

CMAS_BROADCAST_SWITCH: CMAS messages of the PLMN can be broadcast over the air interface only if this option is selected. This option takes effect only in MOCN scenarios. When CMAS is enabled, this option must be selected for at least one PLMN. This option applies only to LTE FDD and LTE TDD.

ARP_QCI_BASED_DIFF_SCH_SW: ARP- and QCI-based differentiated scheduling is enabled only if this option is selected. This option applies only to LTE FDD and LTE TDD.

UPPER_LYR_IND_NO_BROADCAST_SW: If this option is selected, the upperLayerIndication-r15 IE of this PLMN is not included in SIB2. If this option is deselected, this IE of this PLMN is included in SIB2. This option takes effect only if the UpperLayerIndicationSwitch parameter in the NsaDcMgmtConfig MO is not set to OFF. This option applies only to LTE FDD and LTE TDD.
