ServiceIfHoCfgGroup

+-NE
  +-eNodeBFunction
    +-CnOperator
      +-ServiceIfHoCfgGroup
        +-ServiceIfDlEarfcnGrp[1~8]

Description

A ServiceIfHoCfgGroup MO is an operator-specific group of policies for service-based inter-frequency handovers. Each MO of this class will be associated with a QCI. The default policy is to prohibit handovers. Operators may query the operator IDs supported by the eNodeB before configuring this MO.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    CnOperator

  • Possible children:

    ServiceIfDlEarfcnGrp[1~8]
  • Relation with the CnOperator MO:
    • CnOperatorId in a ServiceIfHoCfgGroup MO must have been set in the associated CnOperator MO.
  • Relation with the EutranInterNFreq and ServiceIfDlEarfcnGrp MOs:
    • DlEarfcn must have been set in the associated EutranInterNFreq MO when the ServiceIfDlEarfcnGrp MO associated ServiceIfHoCfgGroup's InterFreqHoState is PERMIT_HO.
  • Relation with the CnOperatorQciPara MO:
    • The ServiceIfHoCfgGroup MO referenced by the ServiceIfHoCfgGroupId parameter in the CnOperatorQciPara MO must be configured.

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
CN Operator ID

Indicates the ID of the operator. This parameter applies only to LTE FDD and LTE TDD.
Service-based inter-Freq handover policy group ID

Indicates the ID of the service-based or service-request-based inter-frequency handover policy group. This parameter applies only to LTE FDD and LTE TDD.
Inter-Freq handover state

Indicates whether to allow service-based or service-request-based inter-frequency handovers of the policy group to a specified frequency. If this parameter is set to NO_HO, service-based or service-request-based inter-frequency handovers of services with a specific QCI to a specified frequency are not allowed. If this parameter is set to PERMIT_HO, such handovers are allowed. This parameter applies only to LTE FDD and LTE TDD.
Service-based InterFreq A4 Report Waiting Timer

Indicates the length of the inter-frequency A4 measurement report waiting timer. If an inter-frequency measurement is triggered, the duration for a UE performing inter-frequency measurement must be restricted. This prevents the UE from continuously performing gap-assisted measurements when the base station does not receive measurement reports within a period, ensuring that data transmission will not be affected.

When this timer is used for coverage-based inter-frequency handovers, there are the following situations: If the value range is 10 to 20000, then this parameter applies only to LTE TDD and the actual length of the timer is equal to the configured value. If the value range is 20010 to 40000, then this parameter applies only to LTE FDD and LTE TDD and the actual length of the timer is equal to the configured value minus 20000.

When this timer is used for service-request- or carrier-attribute-based handovers, this parameter applies only to LTE FDD and LTE TDD. If the value range is 10 to 20000, the actual length of the timer is equal to the configured value. If the value range is 20010 to 40000, the actual length of the timer is equal to the configured value minus 20000.
Service-based InterFreq A4 time to trigger

Indicates the time-to-trigger for service-based inter-frequency event A4.

When the UE detects that the signal quality in the serving cell and that in at least one inter-frequency neighboring cell meets the entering condition for a service- or service request-based handover, it does not immediately send a measurement report to the eNodeB. Instead, the UE sends a report only when the signal quality meets the entering condition throughout the time-to-trigger.

This parameter helps decrease the number of occasionally triggered event reporting, the average number of handovers, and the number of incorrect handovers, preventing unnecessary handovers.

This parameter applies only to LTE TDD.
