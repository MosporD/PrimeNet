NbCellMultiPrbConfig

+-NE
  +-eNodeBFunction
    +-Cell
      +-NbCellMultiPrbConfig

Description

An NbCellMultiPrbConfig MO consists of parameters used to configure carrier policies and inter-carrier load balancing for multi-carrier NB-IoT scenarios.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    Cell
  • Relation with the PrbSchConfig MO:
    • For an NB-IoT cell, the sum of the values of the PrbUlScUsageDiffThld parameter in the NbCellMultiPrbConfig MO and the UlSubcarrierUsageOffset parameter in the PrbSchConfig MO must be less than or equal to 100.
    • For an NB-IoT cell, the sum of the values of the PrbDlScUsageDiffThld parameter in the NbCellMultiPrbConfig MO and the DlSubcarrierUsageOffset parameter in the PrbSchConfig MO must be less than or equal to 100.
  • Relation with the Cell and CellUlschAlgo MOs:
    • If the NbCellFlag parameter in the Cell MO is set to TRUE, and the NbUlSubcarrierSpacingType parameter in the CellUlschAlgo MO is set to 3dot75K or HYBRID_MODE, the NbRfCarrierStrategy parameter in the NbCellMultiPrbConfig MO cannot be set to SHARE.
  • Relation with the Cell and Prb MOs:
    • When the number of Prb instances in Cell is greater than 2, the NbRfCarrierStrategy parameter of the NbCellMultiPrbConfig in the same cell cannot be set to SEPARATE.
  • Relation with the Prb MO:
    • If the number of Prb MOs (under the same Cell MO) in which the DeployMode parameters are set to STAND_ALONE is two and the NbRfCarrierStrategy parameter in the NbCellMultiPrbConfig MO under this Cell MO is set to SHARE, the spacing between the uplink center frequencies of the PRBs specified in the preceding Prb MOs with the WorkMode parameter set to UL_DL or UL_ONLY must be an integer multiple of 15 kHz.
    • If the number of Prb MOs (under the same Cell MO) in which the DeployMode parameters are set to STAND_ALONE is two, the AnchorCarrierFlag parameter in one of the Prb MOs is set to TRUE, and the NbRfCarrierStrategy parameter in the NbCellMultiPrbConfig MO under this Cell MO is set to SHARE, then the spacing between the downlink center frequencies of the PRBs specified in the preceding Prb MOs with the WorkMode parameter set to UL_DL or DL_ONLY must be 300 kHz.
  • Relation with the Cell, Prb, SpectrumCloud, and CellRbReserve MOs:
    • When the NbCellFlag parameter in a Cell MO is set to TRUE, the NbRfCarrierStrategy parameter in the NbCellMultiPrbConfig under the same cell is set to SHARE, and under the LTE cell associated by the LteCellId of the Prb, the SpectrumCloudSwitch parameter in the SpectrumCloud MO is set to GL_SPECTRUM_CONCURRENCY, the RbRsvType parameter in a CellRbReserve MO is set to UPLINK_MODE, and the RbRsvMode parameter in the CellRbReserve MO is set to NB_RESERVED or NB_DEPLOYMENT, then if shared frequencies of ARFCNs specified by GsmArfcn and LTE RBs do not overlap, the RbRsvStartIndex and RbRsvEndIndex parameters in the CellRbReserve MO must be set in such a way that the reserved RBs are 280 kHz away from the center frequency of shared ARFCNs.
  • Relation with the Cell, Prb, CellAlgoSwitch, CellRbReserve, and CellDss MOs:
    • When the NbCellFlag parameter in a Cell MO is set to TRUE, the NbRfCarrierStrategy parameter in the NbCellMultiPrbConfig under the same cell is set to SHARE, and under the LTE cell associated by the LteCellId of the Prb, the DynSpectrumShareSwitch parameter in the CellAlgoSwitch MO is set to GLDynSpectrumShareSwitch switch on, the RbRsvType parameter in a CellRbReserve MO is set to UPLINK_MODE, and the RbRsvMode parameter in the CellRbReserve MO is set to NB_RESERVED or NB_DEPLOYMENT, then the RbRsvStartIndex and RbRsvEndIndex parameters in the CellRbReserve MO must be set in such a way that the reserved RBs are 2 RBs away from the shared RBs.
  • Relation with the Cell, CellAlgoSwitch, and Prb MOs:
    • If AnchorCarrierFlag is set to FALSE and DeployMode is set to GUARD_BAND or IN_BAND in some Prb MOs under a Cell MO for an NB-IoT cell meeting specific conditions, the COVERAGE_LEVEL_0 option of PrachCoverageLevelType must be selected in at least one of these Prb MOs. The specific conditions are as follows: The value of CellActiveState in the Cell MO is CELL_ACTIVE, the MULTI_CARRIER_ENH_SWITCH option of NbCellAlgoSwitch in the CellAlgoSwitch MO under the Cell MO is selected, the NPRACH_PRB_SELECTION_SW option of MultiCarrierOptSwitch in the NbCellMultiPrbConfig MO under the Cell MO is selected, and AnchorCarrierFlag and DeployMode in a Prb MO under the Cell MO are set to TRUE and STAND_ALONE, respectively.
    • If AnchorCarrierFlag is set to FALSE and DeployMode is set to STAND_ALONE in some Prb MOs under a Cell MO for an NB-IoT cell meeting specific conditions, the COVERAGE_LEVEL_0 option of PrachCoverageLevelType MOs must be selected in at least one of these Prb MOs. The specific conditions are as follows: The value of CellActiveState in the Cell MO is CELL_ACTIVE, the MULTI_CARRIER_ENH_SWITCH option of NbCellAlgoSwitch in the CellAlgoSwitch MO under the Cell MO is selected, the NPRACH_PRB_SELECTION_SW option of MultiCarrierOptSwitch in the NbCellMultiPrbConfig MO under the Cell MO is selected, and AnchorCarrierFlag and DeployMode in a Prb MO under the Cell MO are set to TRUE and GUARD_BAND or IN_BAND, respectively.
  • Relation with the CellAlgoSwitch, Prb, and PrbSchConfig MOs:
    • If AnchorCarrierFlag is set to FALSE and DeployMode is set to STAND_ALONE in some Prb MOs under a Cell MO for an NB-IoT cell meeting specific conditions, PagingWeight must be set to a value other than W0 in the PrbSchConfig MO under at least one of these Prb MOs. The specific conditions are as follows: The MULTI_CARRIER_ENH_SWITCH option of NbCellAlgoSwitch in the CellAlgoSwitch MO under the Cell MO is selected, the PAGING_PRB_SELECTION_SW option of MultiCarrierOptSwitch in the NbCellMultiPrbConfig MO under the Cell MO is selected, and AnchorCarrierFlag and DeployMode in a Prb MO under the Cell MO are set to TRUE and GUARD_BAND or IN_BAND, respectively.
    • If AnchorCarrierFlag is set to FALSE and DeployMode is set to GUARD_BAND or IN_BAND in some Prb MOs under a Cell MO for an NB-IoT cell meeting specific conditions, PagingWeight must be set to a value other than W0 in the PrbSchConfig MO under at least one of these Prb MOs. The specific conditions are as follows: The MULTI_CARRIER_ENH_SWITCH option of NbCellAlgoSwitch in the CellAlgoSwitch MO under the Cell MO is selected, the PAGING_PRB_SELECTION_SW option of MultiCarrierOptSwitch in the NbCellMultiPrbConfig MO under the Cell MO is selected, and AnchorCarrierFlag and DeployMode in a Prb MO under the Cell MO are set to TRUE and STAND_ALONE, respectively.
  • Relation with the CellUlschAlgo and Prb MOs:
    • When more than two Prb MO instances are configured under a Cell MO or if the NbRfCarrierStrategy parameter in the NbCellMultiPrbConfig MO under a Cell MO is set to SHARE, NbUlSubcarrierSpacingType in the CellUlschAlgo MO under this Cell MO cannot be set to 3dot75K or HYBRID_MODE.

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Local Cell ID

Indicates the local ID of a cell, which uniquely identifies the cell within an eNodeB. This parameter applies only to NB-IoT.
PRB DL Subcarrier Usage Difference Threshold

Indicates the threshold used to determine whether to trigger load balancing between carriers of a multi-carrier NB-IoT cell. This threshold is a difference in downlink subcarrier resource usage between the serving carrier and the candidate carrier. If the difference in downlink subcarrier resource usage between the carriers is greater than or equal to the sum of the values of this parameter and the DlSubcarrierUsageOffset parameter in the PrbSchConfig MO, load balancing will be triggered between the carriers. This parameter applies only to NB-IoT.
PRB DL Subcarrier Usage Threshold

Indicates the threshold used to determine whether to trigger load balancing between NB-IoT carriers. This threshold is represented by downlink subcarrier resource usage. If the downlink subcarrier resource usage of a carrier is higher than or equal to the value of this parameter, load balancing is triggered between this carrier and other carriers. If the downlink subcarrier resource usage of a carrier is lower than the value of this parameter, the eNodeB evaluates whether to trigger load balancing between this carrier and other carriers based on the difference in downlink subcarrier resource usage between carriers. If the difference condition is not met either, load balancing will not be triggered between the carriers. This parameter applies only to NB-IoT.
PRB UE Number Offset

Indicates the offset to the difference in the number of UEs between the NB-IoT carriers. This offset is used for load balancing between the NB-IoT carriers. This parameter applies only to NB-IoT.
PRB UL Subcarrier Usage Difference Threshold

Indicates the threshold used to determine whether to trigger load balancing between carriers of a multi-carrier NB-IoT cell. This threshold is a difference in uplink subcarrier resource usage between the serving carrier and the candidate carrier. If the difference in uplink subcarrier resource usage between the carriers is greater than or equal to the sum of the values of this parameter and the UlSubcarrierUsageOffset parameter in the PrbSchConfig MO, load balancing will be triggered between the carriers. This parameter applies only to NB-IoT.
PRB UL Subcarrier Usage Threshold

Indicates the threshold used to determine whether to trigger load balancing between NB-IoT carriers. This threshold is represented by uplink subcarrier resource usage. If the uplink subcarrier resource usage of a carrier is higher than or equal to the value of this parameter, load balancing is triggered between this carrier and other carriers. If the uplink subcarrier resource usage of a carrier is lower than the value of this parameter, the eNodeB evaluates whether to trigger load balancing between this carrier and other carriers based on the difference in uplink subcarrier resource usage between carriers. If the difference condition is not met either, load balancing will not be triggered between the carriers. This parameter applies only to NB-IoT.
NB-IoT RF Carrier Strategy

Indicates the RF carrier policy for an NB-IoT cell. If this parameter is set to SEPARATE_PRECEDENCE, the RF carrier separation policy is preferentially used to set up the cell. If the RRU or BBP does not support RF carrier separation, the RF carrier sharing policy is then used. If this parameter is set to SHARE, the RF carrier sharing policy is used to set up the cell. This policy requires that the RRU and BBP support RF carrier sharing. If this parameter is set to SEPARATE, the RF carrier separation policy is used to set up the cell. This policy requires that the RRU and BBP support RF carrier separation. This parameter applies only to the LTE in-band and standalone deployment modes. In other deployment modes, the RF carrier separation policy is used by default. This parameter applies only to macro and micro base stations but does not apply to LampSite base stations. This parameter applies only to NB-IoT.
Multi-Carrier Optimization Switch

Indicates whether to enable NB-IoT multi-carrier functions.

PAGING_PRB_SELECTION_SW: Indicates the carrier range for NB-IoT UEs that support R15-defined mixed operation modes to monitor paging messages. If this option is deselected, the UEs monitor paging messages on all carriers that support paging. If this option is selected, the UEs monitor paging messages on non-anchor carriers that support paging and are deployed in multi-carrier mode in compliance with 3GPP Release 15. This option is valid only when both paging on non-anchor carriers deployed in multi-carrier mode in compliance with 3GPP Release 14 and paging on non-anchor carriers deployed in multi-carrier mode in compliance with 3GPP Release 15 are enabled. For details, see 3GPP TS 36.331. This option applies only to NB-IoT.

NPRACH_PRB_SELECTION_SW: Indicates the carrier range for NB-IoT UEs that support R15-defined mixed operation modes to access the cell. If this option is deselected, the UEs can initiate random access on all carriers that support random access. If this option is selected, the UEs can initiate random access on non-anchor carriers that support random access and are deployed in multi-carrier mode in compliance with 3GPP Release 15. This option is valid only when both access on non-anchor carriers deployed in multi-carrier mode in compliance with 3GPP Release 14 and access on non-anchor carriers deployed in multi-carrier mode in compliance with 3GPP Release 15 are enabled. For details, see 3GPP TS 36.331. This option applies only to NB-IoT.

PWR_DIFF_BASED_PRB_LB_SW: Indicates whether an NB-IoT cell supports load sharing based on the power difference between carriers. If this option is selected, the cell supports load sharing based on the power difference between carriers. If this option is deselected, whether loads can be shared between carriers varies as follows: If the NB-IoT cell has two carriers, UEs at coverage level 2 can perform services only on the anchor carrier; if the NB-IoT cell has more than two carriers, UEs at coverage level 2 can be assigned to non-anchor carriers whose power difference from the anchor carrier is at least -4 dB. This option applies only to NB-IoT.
NB-IoT MPRU RF Carrier Strategy

Indicates the MPRU RF carrier policy for an NB-IoT cell. If this parameter is set to SHARE, the RF carrier sharing policy is used to set up the cell. This policy requires that the BBP and RRU support RF carrier sharing. If this parameter is set to SEPARATE, the RF carrier separation policy is used to set up the cell. This policy requires that the BBP and RRU support RF carrier separation. This parameter applies only to the LTE in-band deployment mode. In other deployment modes, the RF carrier separation policy is used by default. This parameter applies only to LampSite base stations. This parameter applies only to NB-IoT.
