PrivateBand

+-NE
  +-eNodeBFunction
    +-PrivateCaBandComb
      +-PrivateBand

Description

A PrivateBand MO consists of parameters related to a band which an eNodeB supports, in a private CA band combination.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    PrivateCaBandComb
  • Relation with the PrivateBand MO:
    • Among all frequency bands with the same PrivateCaCombId parameter value in the PrivateBand MOs, if the CombBandIndex parameter value for one of these frequency bands (for example frequency band A) is greater than that for another (for example frequency band B), the CombBandId parameter value for frequency band A must be greater than or equal to that for frequency band B.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD PRIVATEBAND

Use this command to add a band to a private CA band combination.
LST PRIVATEBAND

Use this command to list the configuration of a band in a private CA band combination.
MOD PRIVATEBAND

Use this command to modify the configuration of a band in a private CA band combination.
RMV PRIVATEBAND

Use this command to remove a band from a private CA band combination.

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Private CA Band Combination ID

Indicates the ID of a private CA band combination within an eNodeB. This parameter applies only to LTE FDD and LTE TDD.
Combination Band Index

Indicates the index of a band in the private CA band combination. This parameter applies only to LTE FDD and LTE TDD.
Combination Band ID

Indicates the number of the band. For details about band numbers, see 3GPP TS 36.101. This parameter applies only to LTE FDD and LTE TDD.
Combination Band Bandwidth

Indicates the bandwidth set supported in the band. If a bandwidth is selected, any carrier with this bandwidth in the band can be a component of the private CA band combination. Selected bandwidths must be identical to cell bandwidths supported by a UE. Otherwise, the eNodeB may mistakenly determine that a bandwidth that the UE does not support is supported in the private CA band combination, causing CA configuration failures for the UE. This parameter applies only to LTE FDD and LTE TDD.
