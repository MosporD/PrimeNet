Modify CeRachCfg Configuration (MOD CERACHCFG)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify the RACH coverage enhancement configurations.

Note

None.

Parameters

ID Name Description
LocalCellId Local Cell ID

Meaning: Indicates the local ID of a cell, which uniquely identifies a cell within an eNodeB. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~255

Unit: None

Actual Value Range: 0~255

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: L-FDD, L-TDD
CoverageLevel Coverage Level

Meaning: Indicates the coverage level of the cell. The values of this parameter correspond to 0 dB, 5 dB, 10 dB, and 15 dB coverage enhancement.

The value COVERAGE_LEVEL_0(COVERAGE_LEVEL_0) indicates 0 dB coverage enhancement. The value COVERAGE_LEVEL_1(COVERAGE_LEVEL_1) indicates 5 dB coverage enhancement. The value COVERAGE_LEVEL_2(COVERAGE_LEVEL_2) indicates 10 dB coverage enhancement. The value COVERAGE_LEVEL_3(COVERAGE_LEVEL_3) indicates 15 dB coverage enhancement. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: COVERAGE_LEVEL_0(COVERAGE_LEVEL_0), COVERAGE_LEVEL_1(COVERAGE_LEVEL_1), COVERAGE_LEVEL_2(COVERAGE_LEVEL_2), COVERAGE_LEVEL_3(COVERAGE_LEVEL_3)

Unit: None

Actual Value Range: COVERAGE_LEVEL_0, COVERAGE_LEVEL_1, COVERAGE_LEVEL_2, COVERAGE_LEVEL_3

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: L-FDD, L-TDD
ContentionResolutionTimer Timer for Contention Resolution

Meaning: Indicates the period in which a UE waits for Msg4 during a random access (RA) procedure. This timer starts when a UE initially transmits or retransmits Msg3. If the UE receives Msg4 or NACK to Msg3 before the timer expires, the timer stops. If the UE does not receive either message until the timer expires, the RA fails. In this case, the UE must re-initiate an RA procedure. For details about this parameter, see 3GPP TS 36.321. To prevent UE access failures as a result of contention resolution timer expiration caused by a large number of repetitions, it is recommended that this parameter be set to a value not less than two times the sum of the actual initial numbers of repetitions indicated by the MpdcchInitRepNum and PdschInitRepNum parameters in the EmtcCeSchCfg MO. For details about the actual initial numbers of repetitions, see 3GPP TS 36.213. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: SF80_MAC_RESOLUTION_TIMER(SF80_MAC_RESOLUTION_TIMER), SF100_MAC_RESOLUTION_TIMER(SF100_MAC_RESOLUTION_TIMER), SF120_MAC_RESOLUTION_TIMER(SF120_MAC_RESOLUTION_TIMER), SF160_MAC_RESOLUTION_TIMER(SF160_MAC_RESOLUTION_TIMER), SF200_MAC_RESOLUTION_TIMER(SF200_MAC_RESOLUTION_TIMER), SF240_MAC_RESOLUTION_TIMER(SF240_MAC_RESOLUTION_TIMER), SF480_MAC_RESOLUTION_TIMER(SF480_MAC_RESOLUTION_TIMER), SF960_MAC_RESOLUTION_TIMER(SF960_MAC_RESOLUTION_TIMER)

Unit: subframe

Actual Value Range: SF80_MAC_RESOLUTION_TIMER, SF100_MAC_RESOLUTION_TIMER, SF120_MAC_RESOLUTION_TIMER, SF160_MAC_RESOLUTION_TIMER, SF200_MAC_RESOLUTION_TIMER, SF240_MAC_RESOLUTION_TIMER, SF480_MAC_RESOLUTION_TIMER, SF960_MAC_RESOLUTION_TIMER

MML Default Value: None

Recommended Value: This parameter can be set by the eNodeB by default. The default values are as follows:

CoverageLevel is set to COVERAGE_LEVEL_0: SF480_MAC_RESOLUTION_TIMER (480)

CoverageLevel is set to COVERAGE_LEVEL_1: SF480_MAC_RESOLUTION_TIMER (480)

CoverageLevel is set to COVERAGE_LEVEL_2: SF960_MAC_RESOLUTION_TIMER (960)

CoverageLevel is set to COVERAGE_LEVEL_3: SF960_MAC_RESOLUTION_TIMER (960)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter results in a lower probability that UEs fail to receive message 4 (Msg4) because of scheduling delay, and it also leads to a larger delay for UEs to retransmit preambles. A smaller value leads to the opposite effects.

Applicable Mode: L-FDD, L-TDD
MaxNumPrbAttempt Maximum Number of Preamble Attempt

Meaning: Indicates the maximum number of preamble transmission attempts for the corresponding coverage level. For details, see 3GPP TS 36.321. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: N3_PREMB_ATTEMPT_MAX(N3_PREMB_ATTEMPT_MAX), N4_PREMB_ATTEMPT_MAX(N4_PREMB_ATTEMPT_MAX), N5_PREMB_ATTEMPT_MAX(N5_PREMB_ATTEMPT_MAX), N6_PREMB_ATTEMPT_MAX(N6_PREMB_ATTEMPT_MAX), N7_PREMB_ATTEMPT_MAX(N7_PREMB_ATTEMPT_MAX), N8_PREMB_ATTEMPT_MAX(N8_PREMB_ATTEMPT_MAX), N10_PREMB_ATTEMPT_MAX(N10_PREMB_ATTEMPT_MAX)

Unit: None

Actual Value Range: N3_PREMB_ATTEMPT_MAX, N4_PREMB_ATTEMPT_MAX, N5_PREMB_ATTEMPT_MAX, N6_PREMB_ATTEMPT_MAX, N7_PREMB_ATTEMPT_MAX, N8_PREMB_ATTEMPT_MAX, N10_PREMB_ATTEMPT_MAX

MML Default Value: None

Recommended Value: N3_PREMB_ATTEMPT_MAX(N3_PREMB_ATTEMPT_MAX)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A large value of this parameter leads to a high probability that the eNodeB correctly receives the preamble sent by the UE and a long time that a UE experiencing radio link failures must wait before the RRC connection reestablishment procedure. A small value of this parameter leads to a low probability that the eNodeB correctly receives the preamble sent by the UE and a short time that a UE experiencing radio link failures must wait before the RRC connection reestablishment procedure.

Applicable Mode: L-FDD, L-TDD
PreambleRatio Preamble Ratio

Meaning: Indicates the proportion of preambles corresponding to a coverage level to all preambles of the cell. This parameter is used to calculate the number of preambles corresponding to a coverage level. The number of preambles corresponding to a coverage level (excluding the maximum coverage level) is calculated by rounding down the value of this parameter multiplied by the total number of preambles of the cell. No preambles are allocated to a coverage level if the cell does not support this coverage level. The number of preambles corresponding to the maximum coverage level supported by the cell equals the total number of preambles subtracted by the number of preambles corresponding to other coverage levels. Therefore, the proportion of preambles corresponding to the maximum coverage level supported by the cell may be greater than the value of this parameter. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~100

Unit: %

Actual Value Range: 0~100

MML Default Value: None

Recommended Value: 25

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A large value of this parameter leads to a low probability of access collision for the corresponding coverage level and a short access delay. A small value of this parameter leads to a high probability of access collision for the corresponding coverage level and a long access delay. Modifying this parameter will change the preamble groups for eMTC. If the preamble selected by a UE accessing the network belongs to such preamble groups, preamble demodulation performance may be affected, and the random access success rate decreases for a short period.

Applicable Mode: L-FDD, L-TDD
PreambleRepetitionNum Preamble Repetition Number

Meaning: Indicates the number of repeated preamble transmissions for the corresponding coverage level. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: PRACH_REPETITION_N1(PRACH_REPETITION_N1), PRACH_REPETITION_N2(PRACH_REPETITION_N2), PRACH_REPETITION_N4(PRACH_REPETITION_N4), PRACH_REPETITION_N8(PRACH_REPETITION_N8), PRACH_REPETITION_N16(PRACH_REPETITION_N16), PRACH_REPETITION_N32(PRACH_REPETITION_N32), PRACH_REPETITION_N64(PRACH_REPETITION_N64), PRACH_REPETITION_N128(PRACH_REPETITION_N128)

Unit: subframe

Actual Value Range: PRACH_REPETITION_N1, PRACH_REPETITION_N2, PRACH_REPETITION_N4, PRACH_REPETITION_N8, PRACH_REPETITION_N16, PRACH_REPETITION_N32, PRACH_REPETITION_N64, PRACH_REPETITION_N128

MML Default Value: None

Recommended Value: This parameter can be set by the eNodeB by default. The default values are as follows:

CoverageLevel is set to COVERAGE_LEVEL_0: PRACH_REPETITION_N1(PRACH_REPETITION_N1)

CoverageLevel is set to COVERAGE_LEVEL_1: PRACH_REPETITION_N4(PRACH_REPETITION_N4)

CoverageLevel is set to COVERAGE_LEVEL_2: PRACH_REPETITION_N16(PRACH_REPETITION_N16)

CoverageLevel is set to COVERAGE_LEVEL_3: PRACH_REPETITION_N32(PRACH_REPETITION_N32)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter leads to a higher random access success rate for UEs. However, more resources are occupied. A smaller value of this parameter results in the opposite effects.

Applicable Mode: L-FDD, L-TDD
RandomPreambleRatio Random Preamble Ratio

Meaning: Indicates the proportion of random preambles corresponding to the cell coverage level to the total number of preambles for this coverage level. The number of random preambles corresponding to the cell coverage level equals the value of this parameter multiplied by the total number of preambles corresponding to the cell coverage level. Preambles are classified into random and dedicated preambles. Random preambles are used for contention-based access, and dedicated preambles are used for non-contention-based access. For details, see section 5.1.1 in 3GPP TS 36.321. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 1~100

Unit: %

Actual Value Range: 1~100

MML Default Value: None

Recommended Value: 75

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A small value of this parameter leads to a high probability of contention-based access collision, a long contention-based access delay, a high probability that dedicated preambles are allocated to non-contention-based access UEs, and a short non-contention-based access delay. A large value of this parameter leads to a low probability of contention-based access collision, a short contention-based access delay, a low probability that dedicated preambles are allocated to non-contention-based access UEs, and a long non-contention-based access delay. The service drop rate may increase if the access delay increases. Modifying this parameter will change the preamble groups for eMTC. If the preamble selected by a UE accessing the network belongs to such preamble groups, preamble demodulation performance may be affected, and the random access success rate decreases for a short period.

Applicable Mode: L-FDD, L-TDD
RachThldIncreaseCoeff RACH Threshold Increase Coefficient

Meaning: Indicates the coefficient for increasing the RACH detection threshold under the corresponding coverage level. For example, if this parameter is set to the GUI value 400, the RACH detection threshold under the current coverage level increases by four times. If this parameter is set to the GUI value -50, the RACH detection threshold under the current coverage level decreases by 0.5 times. If this parameter is set to the GUI value 0, the RACH detection threshold under the current coverage level remains unchanged. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: -100~1000

Unit: None

Actual Value Range: -1~10, step: 0.01

MML Default Value: None

Recommended Value: This parameter can be set by the eNodeB by default as follows:

0 when the CoverageLevel parameter is set to COVERAGE_LEVEL_0

0 when the CoverageLevel parameter is set to COVERAGE_LEVEL_1

400 when the CoverageLevel parameter is set to COVERAGE_LEVEL_2

400 when the CoverageLevel parameter is set to COVERAGE_LEVEL_3

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: When this parameter is set to 0, network performance is not affected.

A larger non-zero value of this parameter leads to a higher probability of missing preamble detection but a lower probability of false preamble detection. A smaller non-zero value of this parameter leads to the opposite effects.

Applicable Mode: L-FDD, L-TDD
AdaptiveRachHighLoadThld High Load Threshold for Adaptive RACH

Meaning: Indicates whether to enable eMTC RACH adaptation and the high-load threshold for triggering eMTC RACH adaptation. If this parameter is set to 255, the function does not take effect. If this parameter is set to a value other than 255 and the load is higher than the value, the function takes effect. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~100,255

Unit: %

Actual Value Range: 0~100,255

MML Default Value: None

Recommended Value: 255

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to 255, network performance is not affected.

If this parameter is set to a value other than 255: A larger value of this parameter results in a lower probability of triggering RACH adaptation and a higher probability of deterioration in control-plane KPIs, such as the random access success rate and RRC connection setup success rate, for eMTC UEs in the case of a large number of concurrent eMTC connections. A smaller value of this parameter results in a higher probability of triggering RACH adaptation and a higher probability of improving control-plane KPIs for eMTC UEs in the case of a large number of concurrent eMTC connections.

Applicable Mode: L-FDD, L-TDD

Example

To modify the CeRachCfg Configuration with the parameters as follows: Local cell ID: 0, Coverage Level: COVERAGE_LEVEL_0, Timer for Contention Resolution: SF100_MAC_RESOLUTION_TIMER, run the following command:
MOD CERACHCFG: LocalCellId=0, CoverageLevel=COVERAGE_LEVEL_0, ContentionResolutionTimer=SF100_MAC_RESOLUTION_TIMER;
