Modify WTCP Proxy Algorithm Configuration (MOD WTCPPROXYALGO)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify parameter settings related to TCP proxy algorithms.

Note

None.

Parameters

ID Name Description
LocalCellId Local cell ID

Meaning: Indicates the local ID of a cell, which uniquely identifies the cell within an eNodeB. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~255

Unit: None

Actual Value Range: 0~255

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: L-FDD, L-TDD
TcpAccelerationSwitch TCP Acceleration Switch

Meaning: Indicates whether to enable the WTCP proxy function. If an operator's network is an LTE-only network and data forwarding channels have been configured for inter-eNodeB handovers, it is recommended that this parameter be set to ON. When this parameter is set to ON, the eNodeB acts as a proxy in handling TCP packets of HTTP or HTTPS services to increase the download rate of TCP streams. When this parameter is set to OFF, the WTCP proxy function is disabled. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: OFF(OFF), ON(ON)

Unit: None

Actual Value Range: OFF, ON

MML Default Value: None

Recommended Value: OFF(OFF)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: When this parameter is set to ON, the download rate of HTTP or HTTPS services and user-perceived data rate increase, but the CPU usage of baseband processing units also increases.

When this parameter is set to OFF, the eNodeB does not act as a proxy in handling TCP packets of UEs, and network performance is not affected.

Applicable Mode: L-FDD, L-TDD
TCPStatisticsSwitch TCP Statistics Switch

Meaning: Indicates whether to enable TCP measurements. If this parameter is set to ON(ON), the eNodeB starts TCP measurements regardless of the status of the wireless TCP proxy function. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: OFF(OFF), ON(ON)

Unit: None

Actual Value Range: OFF, ON

MML Default Value: None

Recommended Value: OFF(OFF)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: L-FDD, L-TDD
MaxRttStatisticsThd Max RTT Statistic Threshold

Meaning: Indicates the threshold for measuring the maximum round trip time (RTT) among all TCP-related counters. If the RTT of TCP packets in the access network or ground links is greater than this parameter value, the RTT is not considered during the measurement of counters related to RTT delay. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 100~3000

Unit: ms

Actual Value Range: 100~3000

MML Default Value: None

Recommended Value: 300

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: L-FDD, L-TDD
MaxProxyPktNum Max Number of Proxy Packets

Meaning: Indicates the maximum number of downlink TCP packets sent by the WTCP proxy. If the number of downlink TCP packets sent by the WTCP proxy reaches the maximum value, the WTCP proxy mode is terminated. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 200~2000

Unit: None

Actual Value Range: 200~2000

MML Default Value: None

Recommended Value: 200

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A small value of this parameter leads to a large number of TCP streams that support the WTCP proxy. However, the gains for each TCP stream decrease. A large value of this parameter leads to a small number of TCP streams that support the WTCP proxy. However, the gains for each TCP stream increase.

Applicable Mode: L-FDD, L-TDD
AckSplitCount TPE ACK Split Count

Meaning: Indicates the number of split ACKs in the TCP Proxy Enhancer (TPE). If this parameter is set to 0, ACK splitting is not performed in the TPE. If this parameter is set to a non-0 value, this parameter specifies the number of ACKs generated each time ACK splitting is performed in the TPE. This parameter applies only to LTE FDD and LTE TDD.

DisuseStatement: This parameter will be deleted in later versions. Although the configuration interface in this version supports synchronization and delivery of the setting of this parameter, the system does not use this parameter. Therefore, avoid using this parameter.

GUI Value Range: 0~20

Unit: None

Actual Value Range: 0~20

MML Default Value: None

Recommended Value: 4

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A small value of this parameter leads to a small number of ACKs generated each time ACK splitting is performed in the TPE and small increase in the web page download rate. A large value of this parameter leads to a large number of ACKs generated each time ACK splitting is performed in the TPE and large increase in the web page download rate. However, congestion may occur in the window, which causes packet loss.

Applicable Mode: L-FDD, L-TDD
TcpAsSchWeightFactor TCP Acceleration Schedule Weight Factor

Meaning: Indicates the weight factor of the basic scheduling priority for TCP acceleration services. This parameter is used to guarantee such services for acceleration-involved UEs in both the uplink and downlink. If this parameter is set to 0, pre-scheduling of UEs requiring TCP acceleration does not take effect. This parameter applies only to LTE TDD.

GUI Value Range: 0~1000

Unit: None

Actual Value Range: 0~1000

MML Default Value: None

Recommended Value: 50

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to 0, TCP link setup acceleration does not take effect. A large value of this parameter leads to a high service scheduling priority during TCP link setup acceleration. In this case, the eNodeB preferentially guarantees TCP link setup, reducing the TCP link setup delay but increasing the delay of other processes. A small value of this parameter leads to a low service scheduling priority during TCP link setup acceleration. In this case, the TCP link setup delay increases, but the delay of other processes reduces.

Applicable Mode: L-TDD
TcpActiveOrderingTimer TCP Active Ordering Timer

Meaning: Indicates the length of the proactive TCP packet ordering timer.

If this parameter is set to 0, proactive TCP packet ordering does not take effect, and TCP packets are transparently transmitted.

If this parameter is set to a value greater than 0: 1. When TCP packets reach the eNodeB in order, the eNodeB directly sends these packets to UEs without buffering the packets; 2. When TCP packet disorder occurs, this timer is started, and the eNodeB resequences the disordered TCP packets before sending them to UEs. If disordered TCP packets have not reached the eNodeB when this timer expires, the eNodeB sends all buffered TCP packets to UEs. The eNodeB does not proactively order non-TCP/IP packets. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~10

Unit: ms

Actual Value Range: 0~10

MML Default Value: None

Recommended Value: The recommended value is 2.

This parameter is typically set to 0 by default, indicating that proactive TCP packet ordering is disabled. Set this parameter based on statistics on packet loss and disorder on the live network. Available network statistics show that packet disorder occurs more often than packet loss, and disordered packets reach the eNodeB within 2 ms in 80% of packet disorder cases.

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to 0, proactive TCP packet ordering does not take effect, and TCP packets are transparently transmitted.

A small value of this parameter (greater than 0) leads to a small number of cases that the eNodeB resequences disordered packets but small negative throughput gains when packets are lost. A large value of this parameter leads to a large number of cases that the eNodeB resequences disordered packets but large negative throughput gains when packets are lost. The throughput increases after the eNodeB resequences disordered packets.

Applicable Mode: L-FDD, L-TDD
WtcpEnhancementSwitch WTCP Enhancement Switch

Meaning: Indicates whether to enhance WTCP proxy.

WTCP_LOST_PACKET_SWITCH: If this option is selected, the eNodeB checks the size of the UE transmission window to prevent packet loss and does not intercept ACK responses to resent packets when the ACK responses sent by the WTCP proxy are lost. If this option is deselected, the eNodeB does not check the size of the UE transmission window and intercepts ACK responses to resent packets when ACK packets sent by the WTCP proxy are lost. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: WTCP_LOST_PACKET_SWITCH(WTCP_LOST_PACKET_SWITCH)

Unit: None

Actual Value Range: WTCP_LOST_PACKET_SWITCH

MML Default Value: None

Recommended Value: OFF(Off)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: L-FDD, L-TDD
WtcpDlRttTimer WTCP Downlink RTT Timer

Meaning: Indicates the TCP downlink RTT timer. If no ACK message for the corresponding TCP packet is received when this timer expires, scheduling acceleration over the air interface is enabled. If an ACK message for the corresponding TCP packet is received when this timer does not expire, scheduling acceleration over the air interface is disabled. If this parameter is set to 0, WTCP scheduling acceleration over the air interface does not take effect. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~20

Unit: 10ms

Actual Value Range: 0~200

MML Default Value: None

Recommended Value: 0

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A smaller value of this parameter leads to a higher probability of triggering WTCP scheduling acceleration over the air interface and greater impacts on the download rates of background UEs. A larger value of this parameter leads to a lower probability of triggering WTCP scheduling acceleration over the air interface and smaller impacts on the download rates of background UEs.

Applicable Mode: L-FDD, L-TDD
RtoProtectionBufferThld RTO Protection Buffer Threshold

Meaning: Indicates the threshold of the number of buffered WTCP packets for enabling WTCP proxy RTO protection. This parameter takes effect only if it is set to a value greater than 0. If the number of buffered WTCP packets reaches this threshold, WTCP proxy RTO protection is enabled to avoid RTO. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~20

Unit: None

Actual Value Range: 0~200, step: 10

MML Default Value: None

Recommended Value: If the cell is heavily loaded, which causes a long delay over the air interface, and the delay between the eNodeB and server is short, it is recommended that this parameter be set to 5.

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A smaller value (greater than 0) of this parameter leads to a smaller probability of RTO due to WTCP proxy but a longer ACK feedback delay during WTCP proxy. A larger value of this parameter leads to the opposite effects.

Applicable Mode: L-FDD, L-TDD

Example

To modify the WTCPPROXYALGO in a cell with the parameters as follows: Local cell ID: 0, Max RTT Statistics Threshold: 500, run the following command:
MOD WTCPPROXYALGO: LocalCellId=0, MaxRttStatisticsThd=500;
