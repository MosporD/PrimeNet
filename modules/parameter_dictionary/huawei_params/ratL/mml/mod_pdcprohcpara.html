Modify ROHC Configuration (MOD PDCPROHCPARA)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify the parameters related to ROHC. The parameters are used by the ROHC entities at the PDCP layer on the radio interface, for header compression and decompression of data packets on the user plane.

Note

None.

Parameters

ID Name Description
HighestMode ROHC Highest mode

Meaning: Indicates the operating mode of ROHC.

In Unidirectional Mode (U-Mode), packets are sent only from the compressor to the decompressor, and a feedback channel is not mandatory. Therefore, U-Mode is less reliable than Bidirectional Optimistic Mode (O-Mode) and Bidirectional Reliable Mode (R-Mode), but its feedback-induced overhead is minimum compared with the overhead in O-Mode and R-Mode. In O-Mode, the decompressor can send feedback messages to the compressor to indicate decompression failures or successful context synchronization. O-Mode is more reliable than U-Mode and requires a smaller number of feedback messages than R-Mode. In R-Mode, the reliability of context synchronization between the compressor and the decompressor is higher than that in any other mode. However, because of frequent feedback, R-Mode causes the largest amount of link overhead.

GUI Value Range: U_MODE(Unidirectional Mode), O_MODE(Bi-directional Optimistic Mode), R_MODE(Bi-Directional Reliable Mode)

Unit: None

Actual Value Range: U_MODE, O_MODE, R_MODE

MML Default Value: None

Recommended Value: O_MODE(Bi-directional Optimistic Mode)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: The setting of this parameter affects uplink ROHC reliability, uplink compression efficiency, and downlink feedback overhead as follows: (1) R_MODE and O_MODE provide higher uplink ROHC reliability than U_MODE. (2) R_MODE and O_MODE provide higher uplink compression efficiency than U_MODE. (3) R_MODE results in greater downlink feedback overheads than O_MODE, and U_MODE does not have feedback.

Applicable Mode: L-FDD, L-TDD
Profiles Compression profiles

Meaning: Indicates the compression profiles supported by the eNodeB.

Under the ROHC framework, header compression algorithms vary with protocols. Profiles define the header compression protocols (such as RTP/UDP/IP or TCP/IP), which are under the same ROHC framework, for specific types of packet streams. Each profile has a unique identifier.

As defined by LTE specifications, the eNodeB supports the following profiles: Profile 0x0001 (usage: RTP/UDP/IP; reference: RFC 3095 and RFC 4815), Profile 0x0002 (usage: UDP/IP; reference: RFC 3095 and RFC 4815), Profile 0x0003 (usage: ESP/IP; reference: RFC 3095 and RFC 4815), Profile 0x0004 (usage: IP; reference: RFC 3843 and RFC 4815), and Profile 0x0006 (usage: TCP/IP; reference: RFC 6846).

GUI Value Range: Profile0x0001(Profile0x0001), Profile0x0002(Profile0x0002), Profile0x0003(Profile0x0003), Profile0x0004(Profile0x0004), Profile0x0006(Profile0x0006)

Unit: None

Actual Value Range: Profile0x0001, Profile0x0002, Profile0x0003, Profile0x0004, Profile0x0006

MML Default Value: None

Recommended Value: Profile0x0001:On, Profile0x0002:On, Profile0x0003:On, Profile0x0004:On, Profile0x0006:On

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: The setting of this parameter affects supported compression profiles. Each profile supports one type of headers.

For headers with an unsupported type, profile 0x0000 applies. That is, headers are not compressed and are added with profile 0x0000 ROHC headers. This increases the transmission overhead over the air interface and reduces the ROHC gains.

Applicable Mode: L
RohcTcpSinrTriggerThld ROHC TCP SINR Trigger Threshold

Meaning: Indicates the SINR threshold for triggering ROHC TCP. This parameter controls the activation scope of ROHC TCP. When ROHC TCP is enabled and a UE supports ROHC TCP, the eNodeB delivers the RRC connection reconfiguration message to the UE to activate ROHC TCP if the uplink SINR of the UE periodically measured by the eNodeB reaches the threshold. In this case, the UE enters the ROHC TCP state and performs ROHC TCP compression on uplink TCP/IP packet headers. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: -5~10

Unit: dB

Actual Value Range: -5~10

MML Default Value: None

Recommended Value: 0

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A smaller value of this parameter results in a lower probability of triggering ROHC TCP and fewer UEs entering the ROHC TCP state. A larger value of this parameter results in the opposite effects. Entering and exiting the ROHC TCP state require RRC connection reconfiguration. With the number of UEs in the ROHC TCP state growing, the Uu signaling overhead and the eNodeB CPU usage increase.

Applicable Mode: L-FDD, L-TDD
RohcOptimizationSwitch ROHC Optimization Switch

Meaning: Indicates whether to enable ROHC-related optimization functions.

ROHC_FEEDBACK_ENHANCEMENT_SW: Indicates whether an eNodeB sends NACK feedback immediately after ROHC decompression failures occur in the uplink when the HighestMode parameter is set to O_MODE in the PdcpRohcPara MO. The eNodeB immediately sends NACK feedback in the previous scenario only if this option is selected. This option applies only to LTE FDD and LTE TDD.

PROFILE6_DL_OPTIMIZATION_SW: Indicates the downlink packet format when the IE "uplinkOnlyHeaderCompression" is configured. If this option is selected, profile 0 is not used in the downlink. If this option is deselected, profile 0 is used in the downlink. This option applies only to LTE FDD and LTE TDD.

GUI Value Range: ROHC_FEEDBACK_ENHANCEMENT_SW(ROHC_FEEDBACK_ENHANCEMENT_SW), PROFILE6_DL_OPTIMIZATION_SW(PROFILE6_DL_OPTIMIZATION_SW)

Unit: None

Actual Value Range: ROHC_FEEDBACK_ENHANCEMENT_SW, PROFILE6_DL_OPTIMIZATION_SW

MML Default Value: None

Recommended Value: ROHC_FEEDBACK_ENHANCEMENT_SW:On

PROFILE6_DL_OPTIMIZATION_SW:Off

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: ROHC_FEEDBACK_ENHANCEMENT_SW: If this option is selected and the HighestMode parameter is set to O_MODE in the PdcpRohcPara MO, the uplink ROHC decompression failure rate decreases and the uplink ROHC compression ratio slightly increases. Deselecting this option has no impact on network performance.

PROFILE6_DL_OPTIMIZATION_SW: If this option is selected and the IE "uplinkOnlyHeaderCompression" is configured: for UEs that do not use profile 0 to parse downlink packets, the number of lost packets decreases, the throughput increases, and the number of VoLTE service drops decreases; for UEs that use only profile 0 to parse downlink packets, the number of lost packets increases, the throughput decreases, and the number of VoLTE service drops increases; for UEs that can parse downlink packets in either way, there are no impacts. If this option is deselected and the IE "uplinkOnlyHeaderCompression" is configured, then the number of lost packets increases, the throughput decreases, and the number of VoLTE service drops increases for UEs that do not use profile 0 to parse downlink packets. If the IE "uplinkOnlyHeaderCompression" is not configured, the setting of this option has no impacts.

Applicable Mode: L-FDD, L-TDD

Example

To change the value of ROHC Highest mode to U_MODE, run the following command:
MOD PDCPROHCPARA: HighestMode=U_MODE;
