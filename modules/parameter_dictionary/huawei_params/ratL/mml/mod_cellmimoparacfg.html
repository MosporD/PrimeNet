Modify Cell Mimo Configuration (MOD CELLMIMOPARACFG)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify the parameters related to cell MIMO configuration.

Note

None.

Parameters

ID Name Description
LocalCellId Local cell ID

Meaning: Indicates the local cell ID. It uniquely identifies a cell within an eNodeB. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~255

Unit: None

Actual Value Range: 0~255

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: L-FDD, L-TDD
MimoAdaptiveSwitch MIMO Adaptive Switch

Meaning: Indicates the type of adaptive MIMO for a multi-antenna eNodeB. The values are described as follows:

NO_ADAPTIVE: A fixed MIMO transmission mode is used. That is, transition between MIMO transmission modes is not supported.

OL_ADAPTIVE: Open-loop transmission modes are adaptively selected. UEs report rank and CQI values but do not report PMI values.

CL_ADAPTIVE: Closed-loop transmission modes are adaptively selected. UEs report rank, CQI, and PMI values.

OC_ADAPTIVE: Open- or closed-loop transmission modes are adaptively selected. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: NO_ADAPTIVE(NO_ADAPTIVE), OL_ADAPTIVE(OL_ADAPTIVE), CL_ADAPTIVE(CL_ADAPTIVE), OC_ADAPTIVE(OC_ADAPTIVE)

Unit: None

Actual Value Range: NO_ADAPTIVE, OL_ADAPTIVE, CL_ADAPTIVE, OC_ADAPTIVE

MML Default Value: None

Recommended Value: NO_ADAPTIVE(NO_ADAPTIVE)

Parameter Relationship:

-Others:

  • This parameter is valid only when the BfSwitch option of the BfAlgoSwitch parameter in the CellAlgoSwitch MO is deselected.

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to NO_ADAPTIVE, the eNodeB uses the fixed MIMO transmission mode specified by the FixedMimoMode parameter for UEs in the downlink.

If this parameter is set to OL_ADAPTIVE, the eNodeB adaptively uses open-looped MIMO schemes for individual UEs. UEs report RI and CQI values but do not report PMI values to the eNodeB. Open-loop MIMO adaptation brings the highest robustness under high UE mobility among all MIMO schemes. When 2-way transmission is enabled on the network, the adaptation has no requirements on UEs. When 4-way transmission is enabled on the network, UEs must support 4-way transmission on the network to prevent significant deterioration of throughput, the service drop rate, or the access success rate.

If this parameter is set to CL_ADAPTIVE, the eNodeB adaptively uses closed-loop MIMO schemes for individual UEs. UEs report RI, PMI, and CQI values to the eNodeB. When 2-way transmission is enabled on the network, closed-loop MIMO adaptation is suitable for UEs that are static or moving in walk speed. Compared with open-loop MIMO adaptation, closed-loop MIMO adaptation increases the downlink throughput, but it decreases the uplink throughput if the uplink coding rate increases because of PMI reporting. With 2-way transmission enabled, closed-loop MIMO adaptation is dependent on UEs. If the PMI values reported by UEs are unreliable, the demodulation capability of UEs is low under closed-loop MIMO schemes, or UEs move fast such as in high-speed railway scenarios, closed-loop MIMO adaptation decreases the downlink throughput compared with open-loop MIMO adaptation. When 4-way transmission is enabled on the network, closed-loop MIMO adaptation significantly increases the downlink throughput in non-high-speed scenarios compared with the open-loop MIMO adaptation, but it decreases the uplink throughput if the uplink coding rate increases because of PMI reporting. With 4-way transmission enabled, UEs must support 4-way transmission from the network to prevent significant deterioration of throughput, service drop rate, or access success rate.

If this parameter is set to OC_ADAPTIVE, the eNodeB adaptively uses open- or closed-loop MIMO schemes for individual UEs. The eNodeB automatically switches between open- and closed-loop MIMO schemes for each UE. Open- and closed-loop MIMO adaptation is dependent on UEs. When 2-way transmission is enabled on the network, open- and closed-loop MIMO adaptation decreases the throughput compared with the open-loop MIMO adaptation if the PMI values reported by UEs are unreliable or the demodulation capability of UEs is low under closed-loop MIMO schemes. When 4-way transmission is enabled on the network, UEs must support 4-way transmission from the network to prevent significant deterioration of throughput, the service drop rate, or the access success rate.

Applicable Mode: L-FDD, L-TDD
FixedMimoMode Fixed MIMO Mode

Meaning: Indicates the fixed MIMO mode for a multi-antenna eNodeB. This parameter is valid only when MimoAdaptiveSwitch is set to NO_ADAPTIVE. There are four values.

TM2: Transmission mode 2 is always used for UEs.

TM3: Transmission mode 3 is always used for UEs.

TM4: Transmission mode 4 is always used for UEs.

TM6: Transmission mode 6 is always used for UEs. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: TM2(TM2), TM3(TM3), TM4(TM4), TM6(TM6)

Unit: None

Actual Value Range: TM2, TM3, TM4, TM6

MML Default Value: None

Recommended Value: TM3(TM3)

Parameter Relationship:

-Others:

  • This parameter is valid only when the MimoAdaptiveSwitch parameter is set to NO_ADAPTIVE.

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to TM2, transmission mode 2 is permanently applied to all UEs. UEs report CQI values but do not report RI or PMI values, and only a single data stream can be transmitted. Compared with TM3 or TM4, TM2 results in lower downlink throughput and supports only half the downlink peak data rate (with 2-way transmission enabled on the network) or even lower (with 4-way transmission enabled on the network). If a high PDCCH aggregation level is used on the network, TM2 increases the access success rate.

If this parameter is set to TM3, transmission mode 3 is permanently applied to UEs. UEs report RI and CQI values but do not report PMI values, and one or more data streams can be transmitted. Compared with TM2, TM3 results in higher downlink throughput and supports twice the downlink peak data rate (with 2-way transmission enabled on the network) or even higher (with 4-way transmission enabled on the network). If a low PDCCH aggregation level is used on the network, TM3 decreases the access success rate.

If this parameter is set to TM4, transmission mode 4 is permanently applied to UEs. UEs report RI, CQI, and PMI values, and one or more data streams can be transmitted. Compared with TM2, TM4 results in higher downlink throughput and supports twice the downlink peak data rate (with 2-way transmission enabled on the network) or even higher (with 4-way transmission enabled on the network). If a low PDCCH aggregation level is used on the network, TM4 decreases the access success rate. When 2-way transmission is enabled on the network for UEs in static scenarios or moving in walk speed, TM4 increases the downlink throughput compared with TM3, but it decreases the uplink throughput if uplink coding rate increases because of PMI reporting. With 2-way transmission enabled, TM4 is dependent on UEs. If the PMI values reported by UEs are unreliable, the demodulation capability of UEs is low under closed-loop MIMO schemes, or UEs move fast such as in high-speed railway scenarios, TM4 decreases the downlink throughput compared with TM3. When 4-way transmission is enabled on the network, TM4 significantly increases the downlink throughput in non-high-speed scenarios compared with TM3, but it decreases the uplink throughput if uplink coding rate increases because of PMI reporting. With 4-way transmission enabled, UEs must support 4-way transmission from the network to prevent significant deterioration in the throughput, service drop rate, or access success rate.

If this parameter is set to TM6, transmission mode 6 is permanently applied to UEs. UEs report PMI and CQI values but do not report RI values, and only a single data stream can be transmitted. Compared with TM3 or TM4, TM6 (similar to TM2) results in lower downlink throughput and supports only half the downlink peak data rate (with 2-way transmission enabled on the network) or even lower (with 4-way transmission enabled on the network). When 2-way transmission is enabled on the network for UEs in static scenarios or moving in walk speed, TM6 increases the downlink throughput compared with TM2, but it decreases the uplink throughput if uplink coding rate increases because of PMI reporting. With 2-way transmission enabled, TM6 is dependent on UEs. If the PMI values reported by UEs are unreliable, the demodulation capability of UEs is low under closed-loop MIMO schemes, or UEs move fast such as in high-speed railway scenarios, TM6 decreases the downlink throughput compared with TM2. When 4-way transmission is enabled on the network, TM6 significantly increases the downlink throughput in non-high-speed scenarios compared with TM2, but it decreases the uplink throughput if uplink coding rate increases because of PMI reporting. With 4-way transmission enabled, UEs must support 4-way transmission from the network to prevent significant deterioration in the throughput, service drop rate, or access success rate. In addition, when downlink frequency selective scheduling or ICIC is enabled, the downlink throughput will decrease because of resource allocation in TM6.

Applicable Mode: L-FDD, L-TDD
InitialMimoType Initial Mimo Type

Meaning: Indicates the MIMO transmission mode used during initial network access.

If this parameter is set to TM2, the MIMO transmission mode used during initial network access is TM2.

If this parameter is set to ADAPTIVE, the MIMO transmission mode used during initial network access is determined by the settings of the MimoAdaptiveSwitch and FixedMimoMode parameters. If the MimoAdaptiveSwitch parameter is set to NO_ADAPTIVE, the initial MIMO transmission mode is determined by the setting of the FixedMimoMode parameter. If the MimoAdaptiveSwitch parameter is set to OL_ADAPTIVE or OC_ADAPTIVE, the initial MIMO transmission mode is TM3. If the MimoAdaptiveSwitch parameter is set to CL_ADAPTIVE, the initial MIMO transmission mode is TM4. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: TM2(TM2), ADAPTIVE(ADAPTIVE)

Unit: None

Actual Value Range: TM2, ADAPTIVE

MML Default Value: None

Recommended Value: ADAPTIVE(ADAPTIVE)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to TM2, the eNodeB performs an additional MIMO reconfiguration procedure for a UE that initially accesses the network compared with that when this parameter is set to ADAPTIVE. Therefore, the service drop rate increases. If a high PDCCH aggregation level is selected on the network, the access success rate increases but downlink throughput decreases because only a single data stream can be transmitted.

If this parameter is set to ADAPTIVE, the eNodeB does not perform a MIMO reconfiguration procedure for a UE that initially accesses the network, compared with that when this parameter is set to TM2. Therefore, the service drop rate decreases. In addition, downlink throughput increases because one or more data streams can be transmitted. If a low PDCCH aggregation level is selected on the network, the access success rate decreases.

Applicable Mode: L-FDD, L-TDD
MimoSwitch MIMO Switch

Meaning: Indicates MIMO algorithm switches.

8T_TM9_MU-MIMO_SW: Indicates whether to enable 8T TM9 MU-MIMO. The function is enabled only if this option is selected. This option applies only to LTE FDD.

MM_SCC_TM9_MU_MIMO_SW: Indicates whether to enable TM9 MU-MIMO in a massive MIMO SCell. If this option is selected, then TM9 MU-MIMO is enabled and the massive MIMO SCell adaptively selects an MIMO mode and determines whether to perform multiple UE pairing based on the TM9 UE penetration rate and load. If this option is deselected, then TM9 MU-MIMO is disabled and the massive MIMO SCell only uses SU-MIMO. This option applies only to LTE FDD.

TM9_RANK8_SCH_OPT_SW: Indicates whether to enable TM9 rank 8 UE scheduling optimization. If this option is selected, TM9 rank 8 UE scheduling optimization is enabled. If this option is deselected, the optimization does not take effect. This option applies only to LTE TDD.

FREQ_DIFF_AMEND_SW: Indicates whether to enable frequency difference amendment in the cell. If this option is selected, frequency difference amendment is enabled. This function reduces the impact of excessive spacing between uplink and downlink center frequencies for FDD cells. This option applies only to massive MIMO cells. This option applies only to LTE FDD.

PRECISE_DL_CSI_SW: Indicates whether to enable high-precision downlink CSI in the cell. If this option is selected, this function is enabled. This option applies only to LTE FDD.

MASSIVE_MIMO_SUBBAND_BF_SW: Indicates whether to enable subband beamforming in the cell. If this option is selected, aperiodic subband feedback mode can be configured for UEs to trigger feedback and subband beamforming is enabled. This option applies only to LTE FDD.

MASSIVE_MIMO_MU_RANK_OPT_SW: Indicates whether to enable MU-MIMO rank optimization in the cell. If this option is selected, the maximum rank values that UEs can report are adaptively tuned in the cell. This option applies only to LTE FDD.

4T_TM9_ADAPTATION_SW: Indicates whether to enable TM9 adaptation in 4T cells. If this option is selected, some TM9-capable UEs are allowed to enter TM9 in 4T cells. If this option is deselected, the function does not take effect. This option applies only to LTE FDD.

GUI Value Range: 8T_TM9_MU_MIMO_SW(8T_TM9_MU-MIMO_SW), MM_SCC_TM9_MU_MIMO_SW(MM_SCC_TM9_MU_MIMO_SW), TM9_RANK8_SCH_OPT_SW(TM9_RANK8_SCH_OPT_SW), FREQ_DIFF_AMEND_SW(FREQ_DIFF_AMEND_SW), PRECISE_DL_CSI_SW(PRECISE_DL_CSI_SW), MASSIVE_MIMO_SUBBAND_BF_SW(MASSIVE_MIMO_SUBBAND_BF_SW), MASSIVE_MIMO_MU_RANK_OPT_SW(MASSIVE_MIMO_MU_RANK_OPT_SW), 4T_TM9_ADAPTATION_SW(4T_TM9_ADAPTATION_SW)

Unit: None

Actual Value Range: 8T_TM9_MU_MIMO_SW, MM_SCC_TM9_MU_MIMO_SW, TM9_RANK8_SCH_OPT_SW, FREQ_DIFF_AMEND_SW, PRECISE_DL_CSI_SW, MASSIVE_MIMO_SUBBAND_BF_SW, MASSIVE_MIMO_MU_RANK_OPT_SW, 4T_TM9_ADAPTATION_SW

MML Default Value: None

Recommended Value: 8T_TM9_MU_MIMO_SW:Off, MM_SCC_TM9_MU_MIMO_SW:Off, TM9_RANK8_SCH_OPT_SW:Off, FREQ_DIFF_AMEND_SW:Off, PRECISE_DL_CSI_SW:Off, MASSIVE_MIMO_SUBBAND_BF_SW:Off, MASSIVE_MIMO_MU_RANK_OPT_SW:Off, 4T_TM9_ADAPTATION_SW:On

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: 8T_TM9_MU_MIMO_SW: When this option is selected, the cell adaptively determines whether to enter or exit 8T TM9 MU-MIMO mode based on factors such as UE capability, channel condition, and cell load. Then, the cell schedules and pairs UEs meeting the pairing conditions for MU-MIMO, thereby increasing the cell spectral efficiency and user-perceived rate. When this option is deselected, network performance is not affected.

MM_SCC_TM9_MU_MIMO_SW: If this option is selected, user-perceived data rates improve. If this option is deselected, network performance is not affected.

TM9_RANK8_SCH_OPT_SW: If this option is selected, the eNodeB optimizes the scheduling policy for rank 8 UEs continuously performing large-packet services, which may increase the downlink UE throughput. If this option is deselected, network performance is not affected.

FREQ_DIFF_AMEND_SW: If this option is selected, user-perceived data rates increase when the spacing between uplink and downlink center frequencies is large. If this option is deselected, network performance is not affected.

PRECISE_DL_CSI_SW: If this option is selected, downlink channel information precision and user-perceived rates are improved. If this option is deselected, network performance is not affected.

MASSIVE_MIMO_SUBBAND_BF_SW: If this option is selected, the eNodeB configures and triggers UEs to report subband channel information, increasing user-perceived data rates. The uplink data rates are affected because the uplink feedback overhead is increased. If this option is deselected, network performance is not affected.

MASSIVE_MIMO_MU_RANK_OPT_SW: If this option is selected, the downlink cell data rate increases. If this option is deselected, network performance is not affected.

4T_TM9_ADAPTATION_SW: If this option is selected, some TM9-capable UEs that meet certain conditions can enter TM9 in 4T cells, which has no impact on network performance.

Applicable Mode: L-FDD, L-TDD

If the TBS index of a UE exceeds the threshold, the UE can participate in multi-user pairing. For LTE TDD, this parameter specifies the TBS index threshold for MU beamforming pairing. If the TBS index of a UE exceeds the threshold, the UE can participate in multi-user pairing. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~33

A smaller value of this parameter results in a higher probability that SU-MIMO in TM9 takes effect. In this way, the throughput gain is not obvious.

HighOrderMimoPairingStrat High Order MIMO Pairing Strategy

Meaning: Indicates the UE pairing policy for high-order MIMO. If this parameter is set to DEFAULT, UEs using rank 3 or rank 4 can be directly paired. If this parameter is set to FALLBACK_SU, UEs using rank 3 or rank 4 cannot be paired and therefore can perform only SU-MIMO. If this parameter is set to FALLBACK_RANK, UEs using rank 3 or rank 4 can be paired on condition that their current rank is reduced to rank 2. If this parameter is set to ADAPTIVE, the eNodeB determines whether to restrict codebook subsets for UEs using rank 3 or rank 4 or reduce the current rank of these UEs to rank 2 for pairing based on UE-level characteristics. This parameter applies only to LTE FDD.

GUI Value Range: DEFAULT(DEFAULT), FALLBACK_SU(FALLBACK_SU), FALLBACK_RANK(FALLBACK_RANK), ADAPTIVE(ADAPTIVE)

Unit: None

Actual Value Range: DEFAULT, FALLBACK_SU, FALLBACK_RANK, ADAPTIVE

MML Default Value: None

Recommended Value: DEFAULT

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to DEFAULT, network performance is not affected. If this parameter is set to FALLBACK_SU, downlink user-perceived rates of 4R UEs increase. If this parameter is set to FALLBACK_RANK, downlink user-perceived rates of 2R UEs increase. If this parameter is set to ADAPTIVE, downlink cell throughput increases.

Applicable Mode: L-FDD
RanSharingSchOptSwitch RAN Sharing Sch Opt Switch

Meaning: Indicates the algorithm for allocating RB resources for different operators proportionally in multi-user pairing scenarios. If this parameter is set to OFF, the eNodeB does not allocate RB resources for different operators proportionally in multi-user pairing scenarios. If this parameter is set to MU_PAIRING_RB_ALLOC, the operator-specific scheduling priority takes effect for all UEs. If this parameter is set to MU_PAIRING_RB_ALLOC_ENH, the operator-specific scheduling priority takes effect for paired UEs only. This parameter applies only to LTE TDD.

GUI Value Range: OFF(OFF), MU_PAIRING_RB_ALLOC(MU_PAIRING_RB_ALLOC), MU_PAIRING_RB_ALLOC_ENH(MU_PAIRING_RB_ALLOC_ENH)

Unit: None

Actual Value Range: OFF, MU_PAIRING_RB_ALLOC, MU_PAIRING_RB_ALLOC_ENH

MML Default Value: None

Recommended Value: OFF

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: In multi-user pairing scenarios: If this parameter is set to OFF, the actual proportion of occupied RBs for each operator is not restricted by the allocated RB resources. If this parameter is set to MU_PAIRING_RB_ALLOC, the actual proportion of occupied RBs for each operator is close to the proportion of allocated RB resources. If this parameter is set to MU_PAIRING_RB_ALLOC_ENH, the larger the number of non-paired UEs in a cell, the greater the difference between the actual proportion of occupied RBs for each operator and the proportion of allocated RB resources.

Applicable Mode: L-TDD
MuMimoPairingStrategy MU-MIMO Pairing Strategy

Meaning: Indicates the UE pairing policy for MU-MIMO.

If this parameter is set to DEFAULT, the eNodeB uses the correlation policy for UE pairing.

If this parameter is set to EPF_FIRST, the eNodeB selects UEs to be paired based on the pairing efficiency maximization policy and preferentially considers scheduling fairness.

If this parameter is set to PAIRING_EFF_FIRST, the eNodeB selects UEs to be paired based on the pairing efficiency maximization policy and preferentially considers spectral efficiency.

If this parameter is set to EPF_PAIRING_EFF_BALANCING, the eNodeB selects UEs to be paired based on the pairing efficiency maximization policy and balances the spectral efficiency and scheduling fairness.

This parameter applies only to LTE FDD.

GUI Value Range: DEFAULT(DEFAULT), EPF_FIRST(EPF_FIRST), PAIRING_EFF_FIRST(PAIRING_EFF_FIRST), EPF_PAIRING_EFF_BALANCING(EPF_PAIRING_EFF_BALANCING)

Unit: None

Actual Value Range: DEFAULT, EPF_FIRST, PAIRING_EFF_FIRST, EPF_PAIRING_EFF_BALANCING

MML Default Value: None

Recommended Value: DEFAULT(DEFAULT)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to DEFAULT, network performance is not affected.

If this parameter is set to EPF_FIRST, downlink cell throughput increases slightly and UE throughput at the cell edge decreases slightly. If this parameter is set to EPF_PAIRING_EFF_BALANCING, downlink cell throughput increases more and UE throughput at the cell edge decreases more, compared with the scenario where this parameter is set to EPF_FIRST. If this parameter is set to PAIRING_EFF_FIRST, downlink cell throughput increases further more and UE throughput at the cell edge decreases further more, compared with the scenario where this parameter is set to EPF_PAIRING_EFF_BALANCING.

Applicable Mode: L-FDD

Example

To modify parameters related to adaptive MIMO as follows: Local cell ID: 0, MIMO adaptive switch: OL_ADAPTIVE, run the following command:
MOD CELLMIMOPARACFG: LocalCellId=0, MimoAdaptiveSwitch=OL_ADAPTIVE;
