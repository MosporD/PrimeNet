Modify Cell (MOD CELL)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify a cell.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • If the current cell serves as a neighboring cell of another intra-eNodeB cell, the following parameters of the current cell cannot be modified: CellId and DlEarfcn. If the current cell has an intra-frequency neighboring cell, DlEarfcn of the current cell cannot be modified. In addition, DlEarfcn of the current cell cannot be modified to DlEarfcn of any neighboring E-UTRA frequency.

  • A Cell MO includes the cell ID and related radio frequency (RF) information. It is configured by network planning engineers based on site requirements.

  • The frequency band for an FDD cell must be one of frequency bands 1 to 14 and 17 to 21 and 23 and 25 and 28 and 29 and 31 to 32 and 50, and the frequency band for a TDD cell must be one of frequency bands 33 to 44 and 59 to 64. In specific frequency bands, the UL and DL EARFCNs of a cell must be set in compliance with the rules described in 3GPP TS 36.104.

  • When SubframeAssignment is set to 0, the TTI Bundling function cannot be enabled. Otherwise, the services will be interrupted.

  • Before changing an SFN cell to a non-SFN cell, ensure that all the CellAuxEnbBind MO bound to this cell are deleted.

  • The LTE cell resets when the Cell Reference Signal Port Number parameter is modified.

  • Check whether the UEs in the live network support the four-port CRS demodulation before changing the value of the Cell Reference Signal Port Number parameter to 4. If a UE does not support the four-port CRS demodulation, it cannot demodulate downlink signals.

  • The number of effective CRS ports for a common cell is equal to the number of working TX channels of the cell or the configured number of CRS ports, whichever is smaller.

    The number of effective CRS ports for an SFN cell is equal to the number of configured TX channels of the cell or the configured number of CRS ports, whichever is smaller.

  • The message "Configuration activation fail" may be displayed if a cell is modified when the baseband processing unit is starting up.

  • The LTE cell resets when the CrsPortMap parameter is modified.

  • If the CellRelayAlgoPara MO has been configured for a TDD cell, the Uplink Relay Subframe Ratio and Downlink Relay Subframe Ratio parameters in the CellRelayAlgoPara MO must be set to (1_10)1/10 before changing the uplink-to-downlink subframe configuration in the cell.

  • The SFN primary cell label must comply with the following format: %MCC::460%MNC::01%eNodeBId::1%CellId::0%. Otherwise, some fields cannot be correctly displayed in the result of batch query on the MAE.

  • Changing the settings of CPRICompression, UlBandWidth, and DlBandWidth may result in CPRI bandwidth insufficiency, causing the cell to become unavailable. If the CPRI bandwidth specification is not exceeded, block and then unblock the CPRI port for the cell.

  • LTE TDD cells with a bandwidth of 1.4 MHz or 3 MHz support only normal CP and do not support subframe configuration 5. These cells cannot be configured as high-speed cells. The transmit/receive mode can be set only to 1T1R, 2T2R, or 4T4R and the CPRI compression mode only to no compression for these cells. The preamble format cannot be set to 4 for LTE TDD cells with a bandwidth of 1.4 MHz. Otherwise, these cells cannot be activated.

  • In a Cell, if FddTddInd is set to CELL_TDD, and SubframeAssignment is set to SA1, then the AbsPattern in CellEicic could not have subframe 3 and subframe 8.

  • Modifying CoverageLevelType will cause cell to reset.

CoverageLevelType Coverage Level Type

Meaning: Indicates the NB-IoT cell coverage level. A maximum of three coverage levels are supported, corresponding to 0 dB, 10 dB, and 20 dB coverage enhancement. This parameter is valid only when the NbCellFlag parameter is set to TRUE.

COVERAGE_LEVEL_0: The NB-IoT cell supports 0 dB coverage enhancement only when this option is selected. This option applies only to NB-IoT.

COVERAGE_LEVEL_1: The NB-IoT cell supports 10 dB coverage enhancement only when this option is selected. This option applies only to NB-IoT.

COVERAGE_LEVEL_2: The NB-IoT cell supports 20 dB coverage enhancement only when this option is selected. This parameter applies only to NB-IoT.

Parameter Relationship:

The COVERAGE_LEVEL_1 and COVERAGE_LEVEL_2 options take effect only when the COVERAGE_EXTENSION_SWITCH option is selected. If the COVERAGE_LEVEL_1 and COVERAGE_LEVEL_2 options are selected but the COVERAGE_EXTENSION_SWITCH option is deselected, the eNodeB broadcasts the coverage level thresholds in SIB2 and allocates NPRACH resources for coverage levels 1 and 2. However, the eNodeB does not respond to the random access requests initiated by UEs at coverage levels 1 and 2.

CPRICompression CPRI Compression

Meaning: Indicates the CPRI compression type of the cell. CPRI compression is used in RRU cascading scenarios to enable more RRUs to be cascaded without changing the CPRI data rate. The parameter can be set to NO_COMPRESSION, NORMAL_COMPRESSION, ENHANCED_COMPRESSION, QUADPLEX_COMPRESSION, TRIPLEX_COMPRESSION_10M, or 3_2_COMPRESSION. The parameter value NO_COMPRESSION indicates that CPRI compression is not used. The parameter value NORMAL_COMPRESSION indicates that normal CPRI compression is used. The parameter value ENHANCED_COMPRESSION indicates that enhanced CPRI compression is used. The parameter value QUADPLEX_COMPRESSION indicates that quadruple CPRI compression is used. The parameter value TRIPLEX_COMPRESSION_10M indicates triple CPRI compression for a 10 MHz cell, which applies only to LTE FDD. The value 3_2_COMPRESSION indicates that the compression ratio of 3.2:1 is used. This compression ratio applies only to TDD cells and FDD massive MIMO cells. If the eNodeB is equipped with LBBPd boards and the CPRI data rate is 9.8 Gbit/s for LTE FDD cells or the CPRI data rate is greater than 4.9 Gbit/s for LTE TDD cells, the CPRI compression type of cells served by RRUs in the same RRU chain or ring must be the same. The LBBPc does not support CPRI compression. All types of LBBP boards do not support enhanced or quadruple CPRI compression. Only the UBBPe and UBBPg support triple CPRI compression for 10 MHz cells. Before changing the value of this parameter for a cell served by an RRU in an RRU chain or ring, ensure that all cells served by the RRUs in the chain or ring are deactivated. After the parameter value is changed, activate the cells. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: NO_COMPRESSION(No Compression), NORMAL_COMPRESSION(Normal Compression), ENHANCED_COMPRESSION(Enhanced Compression), QUADPLEX_COMPRESSION(Quadplex Compression), TRIPLEX_COMPRESSION_10M(Triplex Compression for 10M), 3_2_COMPRESSION(3.2 times Compression)

CrsPortMap CRS Antenna Port Mapping

Meaning: Indicates the mapping between a cell-specific reference signal (CRS) port and a transmit (TX) channel in an RRU. In cells with one or two TX channels, this parameter cannot be set. In cells with four or eight TX channels, this parameter can be set. As defined in 3GPP specifications, the CrsPortNum parameter can be set to CRS_PORT_1, CRS_PORT_2, or CRS_PORT_4. The value CRS_PORT_1 indicates that one CRS port (port 0) is configured. The value CRS_PORT_2 indicates that two CRS ports (ports 0 and 1) are configured.
