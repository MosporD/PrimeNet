Modify PrbSchConfig (MOD PRBSCHCONFIG)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify the settings of PRB-level scheduling parameters.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • For a NB-IoT cell, a modification to the DL_GAP_SWITCH in DlSchedulingSwitch parameter will result in automatic reset of the cell.

  • For a NB-IoT cell, a modification to the PagingWeight parameter will result in automatic reset of the cell.

  • For a NB-IoT cell, a modification to the PRB Index of DL PDCCH Carrier parameter will result in automatic reset of the cell.

  • For a NB-IoT cell, a modification to the NB-IoT DL Bitmap Size parameter will result in automatic reset of the cell.

  • For a NB-IoT cell, a modification to the NB-IoT DL Bitmap10 parameter will result in automatic reset of the cell and may lead to PDCCH resources unavailable for the carrier.

  • For a NB-IoT cell, a modification to the NB-IoT DL Bitmap30 parameter will result in automatic reset of the cell and may lead to PDCCH resources unavailable for the carrier.

MaxNumRepetitionForPaging Maximum Number of Paging Repetition

Meaning: Indicates the maximum number of paging repetitions in the NPDCCH common search space. For details about this parameter, see descriptions of the npdcch-NumRepetitionPaging IE in 3GPP TS 36.331. When this parameter is set to NULL, the maximum number of PDCCH repetitions corresponding to the maximum coverage level configured for the carrier is used as the value of the npdcch-NumRepetitionPaging IE by default. (The maximum number of PDCCH repetitions is specified by the PdcchMaxRepetitionCnt parameter in the PrbPdcchCeConfig MO.). When this parameter is set to a value other than NULL, the MaxNumRepetitionForPaging parameter value is used as the value of the npdcch-NumRepetitionPaging IE. This parameter applies only to NB-IoT.

Actual Value Range: REP_1, REP_2, REP_4, REP_8, REP_16, REP_32, REP_64, REP_128, REP_256, REP_512, REP_1024, REP_2048, NULL

MML Default Value: None

Recommended Value: REP_32(REP_32)

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: A small value of this parameter leads to a small coverage area for paging and less power consumption for UEs in idle mode. A large value of this parameter leads to a large coverage area for paging and more power consumption for UEs in idle mode.

Applicable Mode: L-NB-IOT
DlSchedulingSwitch Downlink Scheduling Switch

Meaning: Indicates whether to enable downlink scheduling for NB-IoT carriers.

DL_GAP_SWITCH: Indicates whether to enable the downlink gap function in an NB-IoT cell. If this option is selected, the downlink gap function can be started in the cell. If this option is deselected, the downlink gap function cannot be started in the cell.

GUI Value Range: DL_GAP_SWITCH(DL_GAP_SWITCH)

Unit: None

Actual Value Range: DL_GAP_SWITCH

MML Default Value: None

Recommended Value: DL_GAP_SWITCH:Off

Parameter Relationship:

-Configuration constraints:

  • The DL_GAP_SWITCH option of the DlSchedulingSwitch parameter can be selected only when the NbDlBitmapSize and NbDlBitmap10 parameter values are SF10 and 1023, respectively.
  • The DL_GAP_SWITCH option of the DlSchedulingSwitch parameter can be selected only when the NbDlBitmapSize, NbDlBitmap10, and NbDlBitmap30 parameter values are SF40, 1023, and 1073741823, respectively.

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: DL_GAP_SWITCH: When this option is selected, the downlink gap function is started in the cell. The time and frequency resources for coverage levels whose NPDCCH Rmax is greater than or equal to the downlink gap threshold are released in the gap duration of each downlink gap period for UEs at other coverage levels, preventing long service delay caused by long time of resource unavailability for UEs at other coverage levels.

Applicable Mode: L-NB-IOT
NbDlBitmapSize NB-IoT DL Bitmap Size

Meaning: Indicates the downlink subframe pattern size of an NB-IoT cell. This parameter applies only to NB-IoT.

GUI Value Range: SF10(SF10), SF40(SF40)

Unit: None

Actual Value Range: SF10, SF40

MML Default Value: None

Recommended Value: SF10(SF10)

Parameter Relationship:

-Configuration constraints:

  • When the DeployMode parameter in a Prb MO is STAND_ALONE or GUARD_BAND, the NbDlBitmapSize parameter in the associated PrbSchConfig MO must be set to SF10.
  • The DL_GAP_SWITCH option of the DlSchedulingSwitch parameter can be selected only when the NbDlBitmapSize and NbDlBitmap10 parameter values are SF10 and 1023, respectively.
  • The DL_GAP_SWITCH option of the DlSchedulingSwitch parameter can be selected only when the NbDlBitmapSize, NbDlBitmap10, and NbDlBitmap30 parameter values are SF40, 1023, and 1073741823, respectively.

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: None

Applicable Mode: L-NB-IOT
NbDlBitmap10 NB-IoT DL Bitmap10

Meaning: Indicates a 10-bit bitmap used to specify the set of downlink subframes for downlink transmission in the NB-IoT cell. The value of this parameter needs to be converted into a binary number, and the 10 least significant bits of the number are used as the bitmap, with each bit representing one subframe.

If the NB-IoT downlink subframe pattern is a configuration of 10 subframes, only this parameter is used to specify the downlink subframe configuration for the NB-IoT cell. If the NB-IoT downlink subframe pattern is a configuration of 40 subframes, this parameter indicates the first 10 subframes, and it is used together with the NbDlBitmap30 parameter to specify the downlink subframe configuration for the NB-IoT cell.

The value 0 in the bitmap indicates that the corresponding subframe is invalid for downlink transmission, and the value 1 in the bitmap indicates that the corresponding subframe is valid for downlink transmission.

For details, see 3GPP TS 36.331. This parameter applies only to NB-IoT.

GUI Value Range: 0~1023

Unit: None

Actual Value Range: 0~1023

MML Default Value: None

Recommended Value: None

Parameter Relationship:

-Configuration constraints:

  • If AnchorCarrierFlag in a Prb MO is set to TRUE and NbDlBitmapSize in the PrbSchConfig MO under the Prb MO is set to SF10, the number of "0" bits in the value of NbDlBitmap10 in the PrbSchConfig MO cannot exceed 3.
  • The DL_GAP_SWITCH option of the DlSchedulingSwitch parameter can be selected only when the NbDlBitmapSize and NbDlBitmap10 parameter values are SF10 and 1023, respectively.
  • The DL_GAP_SWITCH option of the DlSchedulingSwitch parameter can be selected only when the NbDlBitmapSize, NbDlBitmap10, and NbDlBitmap30 parameter values are SF40, 1023, and 1073741823, respectively.

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: A smaller number of subframes invalid for downlink transmission indicated by this parameter leads to less downlink loss. A larger number of subframes invalid for downlink transmission leads to the opposite effect, and PDCCH resources may fail to be allocated.

Applicable Mode: L-NB-IOT
NbDlBitmap30 NB-IoT DL Bitmap30

Meaning: Indicates a 30-bit bitmap used to specify the set of downlink subframes for downlink transmission in the NB-IoT cell. The value of this parameter needs to be converted into a binary number, and the 30 least significant bits of the number are used as the bitmap, with each bit representing one subframe.

If the NB-IoT downlink subframe pattern is a configuration of 10 subframes, this parameter is invalid. If the NB-IoT downlink subframe pattern is a configuration of 40 subframes, this parameter indicates the last 30 subframes, and it is used together with the NbDlBitmap10 parameter to specify the downlink subframe configuration for the NB-IoT cell.

The value 0 in the bitmap indicates that the corresponding subframe is invalid for downlink transmission, and the value 1 in the bitmap indicates that the corresponding subframe is valid for downlink transmission.

For details, see 3GPP TS 36.331. This parameter applies only to NB-IoT.

GUI Value Range: 0~1073741823

Unit: None

Actual Value Range: 0~1073741823

MML Default Value: None

Recommended Value: None

Parameter Relationship:

-Configuration constraints:

  • If the AnchorCarrierFlag parameter in a Prb MO is set to TRUE and NbDlBitmapSize in the PrbSchConfig MO under the Prb MO is set to SF40, the number of bits being 0 in the values of the NbDlBitmap30 and NbDlBitmap10 parameters in the PrbSchConfig MO must not exceed 12.
  • The DL_GAP_SWITCH option of the DlSchedulingSwitch parameter can be selected only when the NbDlBitmapSize, NbDlBitmap10, and NbDlBitmap30 parameter values are SF40, 1023, and 1073741823, respectively.

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: A smaller number of subframes invalid for downlink transmission indicated by this parameter leads to less downlink loss. A larger number of subframes invalid for downlink transmission leads to the opposite effect, and PDCCH resources may fail to be allocated.

Applicable Mode: L-NB-IOT

Meaning: Indicates the downlink carrier ID for the UE to receive RAR and Msg4 when the UE initiates random access on the current carrier. If this parameter is set to 65535, the UE receives RAR and Msg4 on the current carrier. This parameter is valid only for non-anchor carriers. This option applies only to NB-IoT.

GUI Value Range: 0~255,65535

Unit: None

Actual Value Range: 0~255,65535

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: None

Applicable Mode: L-NB-IOT
PagingWeight Paging Weight

Meaning: Indicates the paging weight of each carrier. For details, see 3GPP TS 36.331. If this parameter is set to W0 for all carriers including anchor and non-anchor carriers, paging is performed only on the anchor carrier. If this parameter is set to W0 for the anchor carrier and a value other than W0 for any non-anchor carrier, paging is not performed on the anchor carrier. If this parameter is set to W0 for a non-anchor carrier, this non-anchor carrier does not support paging. If this parameter is set to a value other than W0 for a carrier, the value of this parameter is used as the paging weight of the carrier. For details, see 3GPP TS 36.304. This option applies only to NB-IoT.

GUI Value Range: W1(W1), W2(W2), W3(W3), W4(W4), W5(W5), W6(W6), W7(W7), W8(W8), W9(W9), W10(W10), W11(W11), W12(W12), W13(W13), W14(W14), W15(W15), W16(W16), W0(W0)

Unit: None

Actual Value Range: W1, W2, W3, W4, W5, W6, W7, W8, W9, W10, W11, W12, W13, W14, W15, W16, W0

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: The larger the value of this parameter, the larger the paging weight of the current carrier. The smaller the value of this parameter, the smaller the paging weight of the current carrier.

Applicable Mode: L-NB-IOT
DlSubcarrierUsageOffset DL Subcarrier Usage Offset

Meaning: Indicates the offset to downlink subcarrier resource usage. This offset is used to determine whether to trigger load balancing between NB-IoT carriers.

If the difference in downlink subcarrier resource usage between the carriers is greater than or equal to the sum of the values of this parameter and the PrbDlScUsageDiffThld parameter in the NbCellMultiPrbConfig MO, load balancing will be triggered between the carriers. This parameter applies only to NB-IoT.

GUI Value Range: 0~100

Unit: %

Actual Value Range: 0~100

MML Default Value: None

Recommended Value: 15

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to an extremely large value, it is difficult to trigger load balancing between carriers, causing user experience to deteriorate for UEs served by the heavily loaded carrier. If this parameter is set to an extremely small value, load balancing between carriers will be triggered too frequently.

Applicable Mode: L-NB-IOT
UlSubcarrierUsageOffset UL Subcarrier Usage Offset

Meaning: Indicates the offset to uplink subcarrier resource usage. This offset is used to determine whether to trigger load balancing between NB-IoT carriers.

If the difference in uplink subcarrier resource usage between the carriers is greater than or equal to the sum of the values of this parameter and the PrbUlScUsageDiffThld parameter in the NbCellMultiPrbConfig MO, load balancing will be triggered between the carriers. This parameter applies only to NB-IoT.

GUI Value Range: 0~100

Unit: %

Actual Value Range: 0~100

MML Default Value: None

Recommended Value: 15

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to an extremely large value, it is difficult to trigger load balancing between carriers, causing user experience to deteriorate for UEs served by the heavily loaded carrier. If this parameter is set to an extremely small value, load balancing between carriers will be triggered too frequently.

Applicable Mode: L-NB-IOT

Example

To modify PRB non-coverage-level-specific scheduling parameters in the cell with the parameters as follows: Local cel0l ID: 0, PRB ID : 0, Maximum Number of Paging Repetition : REP_64, run the following command:
MOD PRBSCHCONFIG: LocalCellId=0, PrbId=0, MaxNumRepetitionForPaging=REP_64;
