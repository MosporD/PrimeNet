Modify Configurations of Coverage-Level-Specific Downlink Scheduling for PRBs (MOD PRBDLSCHCEALGO)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify coverage-level-specific parameters related to the downlink scheduling algorithm for PRB carriers of an NB-IoT cell.

Note

None.

Parameters

ID Name Description
LocalCellId Local Cell ID

Meaning: Indicates the local ID of a cell. It uniquely identifies a cell within an eNodeB. This parameter applies only to NB-IoT.

GUI Value Range: 0~255

Unit: None

Actual Value Range: 0~255

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: L-NB-IOT
PrbId PRB ID

Meaning: Indicates the NB-IoT PRB ID. It uniquely identifies a PRB within a cell. This parameter applies only to NB-IoT.

GUI Value Range: 0~255

Unit: None

Actual Value Range: 0~255

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: L-NB-IOT
CoverageLevel Coverage Level

Meaning: Indicates the UE's coverage level. The value 0 indicates 0 dB coverage enhancement; the value 1 indicates 10 dB coverage enhancement; and the value 2 indicates 20 dB coverage enhancement. This parameter applies only to NB-IoT.

GUI Value Range: COVERAGE_LEVEL_0(COVERAGE_LEVEL_0), COVERAGE_LEVEL_1(COVERAGE_LEVEL_1), COVERAGE_LEVEL_2(COVERAGE_LEVEL_2)

Unit: None

Actual Value Range: COVERAGE_LEVEL_0, COVERAGE_LEVEL_1, COVERAGE_LEVEL_2

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: L-NB-IOT
DlInitialTransRptCount DL Initial Transmission Repetition Count

Meaning: Indicates the PDSCH initial transmission repetition times for UEs corresponding to a certain coverage level. This parameter applies only to NB-IoT.

GUI Value Range: REP_1(REP_1), REP_2(REP_2), REP_4(REP_4), REP_8(REP_8), REP_16(REP_16), REP_32(REP_32), REP_64(REP_64), REP_128(REP_128), REP_192(REP_192), REP_256(REP_256), REP_384(REP_384), REP_512(REP_512), REP_768(REP_768), REP_1024(REP_1024), REP_1536(REP_1536), REP_2048(REP_2048)

Unit: None

Actual Value Range: REP_1, REP_2, REP_4, REP_8, REP_16, REP_32, REP_64, REP_128, REP_192, REP_256, REP_384, REP_512, REP_768, REP_1024, REP_1536, REP_2048

MML Default Value: None

Recommended Value: This parameter can be set by the eNodeB by default as follows:

REP_1 when the CoverageLevel parameter is set to 0

REP_1 when the CoverageLevel parameter is set to 1

REP_16 when the CoverageLevel parameter is set to 2

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter indicates a larger number of initial repetition times, thereby consuming more time-domain resources. A smaller value of this parameter results in the opposite effects. When there is a large number of UEs and the coverage level is high, setting this parameter to a large value increases the delay, resource usage, and congestion.

Applicable Mode: L-NB-IOT
DlInitialMcs Downlink Initial MCS

Meaning: Indicates the initial downlink MCS index of UEs of a coverage level. This parameter applies only to NB-IoT.

GUI Value Range: MCS_0(MCS_0), MCS_1(MCS_1), MCS_2(MCS_2), MCS_3(MCS_3), MCS_4(MCS_4), MCS_5(MCS_5), MCS_6(MCS_6), MCS_7(MCS_7), MCS_8(MCS_8), MCS_9(MCS_9), MCS_10(MCS_10), MCS_11(MCS_11), MCS_12(MCS_12), MCS_13(MCS_13)

Unit: None

Actual Value Range: MCS_0, MCS_1, MCS_2, MCS_3, MCS_4, MCS_5, MCS_6, MCS_7, MCS_8, MCS_9, MCS_10, MCS_11, MCS_12, MCS_13

MML Default Value: None

Recommended Value: This parameter can be set by the eNodeB by default as follows:

MCS_10 when the CoverageLevel parameter is set to 0

MCS_1 when the CoverageLevel parameter is set to 1

MCS_0 when the CoverageLevel parameter is set to 2

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter leads to a larger initial downlink MCS index. A smaller value of this parameter leads to a smaller initial downlink MCS index.

Applicable Mode: L-NB-IOT
UuMessageWaitingTimer Uu Message Waiting Timer

Meaning: Indicates the timer governing the period the eNodeB waits for a Uu response message from a UE. If the timer expires, the eNodeB initiates to release the UE. If this parameter is set to 0, the UuMessageWaitingTimer parameter in the ENodeBConnStateTimer MO, rather than this parameter, takes effect. If this parameter is set to 1 to 200, this parameter takes effect. This parameter applies only to NB-IoT.

GUI Value Range: 0~200

Unit: s

Actual Value Range: 0~200

MML Default Value: None

Recommended Value: When the timer is used, the recommended value is as follows:

CoverageLevel is set to 0: 35

CoverageLevel is set to 1: 45

CoverageLevel is set to 2: 65

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: The setting of this parameter affects how long the eNodeB will wait for a Uu response message from the UE. If this parameter is set to a small value and the UE does not send the response message yet, the eNodeB regards that the Uu response message times out. If this parameter is set to a large value, the eNodeB continues waiting for a response message from the UE when it does not receive the response message due to an exception. When the waiting time is too long, additional system resources are occupied.

Applicable Mode: L-NB-IOT
DlSchDurationProportion Proportion of Downlink Scheduling Duration

Meaning: Indicates the proportion of downlink scheduling duration for a specific coverage level. This parameter applies only to NB-IoT.

GUI Value Range: 5~100

Unit: %

Actual Value Range: 5~100

MML Default Value: None

Recommended Value: 100

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter leads to a larger number of downlink scheduling occasions and higher resource consumption. A smaller value of this parameter leads to the opposite effects.

Applicable Mode: L-NB-IOT
PwrDiffThld Power Difference Thld

Meaning: Indicates the threshold of the power difference between the non-anchor and anchor carriers at a specific coverage level. When the result of non-anchor carrier power minus anchor carrier power is less than this threshold, UEs at this specific coverage level cannot be assigned to a downlink-only carrier for services. If this parameter is set to -128, carrier assignment for UEs is not restricted by power difference. This parameter is valid only for non-anchor carriers. This parameter applies only to NB-IoT.

GUI Value Range: -128,-12~3

Unit: dB

Actual Value Range: -128,-12~3

MML Default Value: None

Recommended Value: This parameter can be set by the system by default. The default value is as follows:

-12 when the CoverageLevel parameter is set to 0

-12 when the CoverageLevel parameter is set to 1

-4 when the CoverageLevel parameter is set to 2

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter leads to higher required non-anchor power and fewer carriers meeting the requirement but a smaller impact on rates after the assignment. A smaller value of this parameter leads to lower required non-anchor power and more carriers meeting the requirement but a larger rate decrease after the assignment. If the power is insufficient, service drops occur.

Applicable Mode: L-NB-IOT
DlAmcMcsAdjustStep DL AMC MCS Adjustment Step

Meaning: Indicates the MCS adjustment step used in downlink AMC based on path loss difference. If this parameter is set to 0 for a coverage level, downlink AMC based on path loss difference does not take effect for the coverage level. This parameter applies only to NB-IoT.

GUI Value Range: 0~400

Unit: None

Actual Value Range: 0~40, step: 0.1

MML Default Value: None

Recommended Value: 10

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: With a given DlAmcPlAdjustStep parameter value, a smaller value of the DlAmcMcsAdjustStep parameter results in slower MCS adjustment and more conservative downlink MCS selection, and a larger the value of this parameter results in faster MCS adjustment and more aggressive downlink MCS selection.

Applicable Mode: L-NB-IOT
DlAmcPlAdjustStep DL AMC Path Loss Adjustment Step

Meaning: Indicates the path loss adjustment step used in downlink AMC based on path loss difference. If this parameter is set to 0, the downlink MCS index is adjusted at the step specified by the DlAmcMcsAdjustStep parameter in each downlink scheduling occasion for UEs at the coverage level where downlink AMC based on path loss difference has taken effect. The adjustment does not stop until the conditions for stopping the adjustment are met. This parameter applies only to NB-IoT.

GUI Value Range: 0~500

Unit: 0.1dB

Actual Value Range: 0~50

MML Default Value: None

Recommended Value: This parameter can be set by the system by default. The default value is as follows:

100 when the CoverageLevel parameter is set to COVERAGE_LEVEL_0

30 when the CoverageLevel parameter is set to COVERAGE_LEVEL_1

30 when the CoverageLevel parameter is set to COVERAGE_LEVEL_2

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: With a given DlAmcMcsAdjustStep parameter value, a smaller value of the DlAmcPlAdjustStep parameter results in slower path loss difference compensation and more aggressive downlink MCS selection, and a larger value of this parameter results in faster path loss difference compensation and more conservative downlink MCS selection.

Applicable Mode: L-NB-IOT

Example

To modify PrbDlSchCeAlgo DlInitialTransRptCount to REP_4:
MOD PRBDLSCHCEALGO: LocalCellId=2, PrbId=2, CoverageLevel=COVERAGE_LEVEL_0, DlInitialTransRptCount=REP_4;
