Modify CellRachCECfg Configuration in an NB-IoT Cell (MOD CELLRACHCECFG)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify coverage-level-specific RACH configurations in an NB-IoT cell.

Note

None.

Parameters

ID Name Description
LocalCellId Local Cell ID

Meaning: Indicates the local ID of a cell, which uniquely identifies a cell within an eNodeB.

GUI Value Range: 0~255

Unit: None

Actual Value Range: 0~255

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: L
CoverageLevel Coverage Level

Meaning: Indicates the cell coverage level for random access. The value COVERAGE_LEVEL_0 indicates coverage level 0. The value COVERAGE_LEVEL_1 indicates coverage level 1. The value COVERAGE_LEVEL_2 indicates coverage level 2. This parameter applies only to NB-IoT.

GUI Value Range: COVERAGE_LEVEL_0(COVERAGE_LEVEL_0), COVERAGE_LEVEL_1(COVERAGE_LEVEL_1), COVERAGE_LEVEL_2(COVERAGE_LEVEL_2)

Unit: None

Actual Value Range: COVERAGE_LEVEL_0, COVERAGE_LEVEL_1, COVERAGE_LEVEL_2

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: L-NB-IOT
ContentionResolutionTimer Contention Resolution Timer

Meaning: Indicates the length of the timer that governs the period in which a UE waits for message 4 (Msg4) during a random access (RA) procedure. This timer starts when a UE initially sends or resends message 3 (Msg3). This timer stops when the UE receives Msg4 or NACK to Msg3 within the length of the timer. If the UE does not receive either message until the timer expires, the RA fails, and the UE must reinitiate an RA procedure. It is recommended that this parameter be set to a relatively large value (such as PP_16) when a large number of UEs are initiating random access simultaneously or there is a large number of high-coverage-level UEs (the average number of high-coverage-level UEs performing random access per second is 0.5 or more or the uplink or downlink subcarrier resource usage reaches 65% or more). PP_1 indicates one PDCCH period, PP_2 indicates two PDCCH periods, and so on. This parameter applies only to NB-IoT.

GUI Value Range: PP_1(PP_1), PP_2(PP_2), PP_3(PP_3), PP_4(PP_4), PP_8(PP_8), PP_16(PP_16), PP_32(PP_32), PP_64(PP_64)

Unit: None

Actual Value Range: PP_1, PP_2, PP_3, PP_4, PP_8, PP_16, PP_32, PP_64

MML Default Value: None

Recommended Value: PP_64(PP_64)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter leads to a lower probability that UEs fail to receive Msg4 because of scheduling delay, and it also leads to a longer delay for UEs to retransmit preambles. A smaller value leads to the opposite effects.

Applicable Mode: L-NB-IOT
MaxNumPreambleAttempt Maximum Number of Preamble Attempt

Meaning: Indicates the maximum number of preamble transmissions for random access attempts at the corresponding cell coverage level. This parameter applies only to NB-IoT.

GUI Value Range: REP_3(REP_3), REP_4(REP_4), REP_5(REP_5), REP_6(REP_6), REP_7(REP_7), REP_8(REP_8), REP_10(REP_10)

Unit: None

Actual Value Range: REP_3, REP_4, REP_5, REP_6, REP_7, REP_8, REP_10

MML Default Value: None

Recommended Value: REP_4(REP_4)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter leads to a higher probability that the eNodeB correctly receives preambles sent by UEs in the cell at the corresponding coverage level, but a longer time for random access. A smaller value of this parameter leads to a lower probability that the eNodeB correctly receives preambles sent by UEs in the cell at the corresponding coverage level, but a shorter time for random access.

Applicable Mode: L-NB-IOT
EdtContentionResTimer EDT Contention Resolution Timer

Meaning: Indicates the timer governing the period in which a UE waits for Msg4 after sending Msg3 for EDT to the eNodeB during an RA procedure initiated by the UE using contention-based PRACH resources. This timer starts when a UE initially transmits or retransmits Msg3. If the UE receives Msg4 or NACK to Msg3 before the timer expires, the timer stops. If the timer expires, the RA fails. In this case, the UE must reinitiate an RA procedure.

If a large number of UEs initiate access concurrently, a large number of UEs are at high coverage levels, or the EdtDlDataWaitingTimer parameter in the CellEdtConfig MO is set to a large value, you are advised to set the EdtContentionResTimer parameter to a larger value and enable early contention resolution. This parameter applies only to NB-IoT.

GUI Value Range: PP_1(PP_1), PP_2(PP_2), PP_3(PP_3), PP_4(PP_4), PP_8(PP_8), PP_16(PP_16), PP_32(PP_32), PP_64(PP_64)

Unit: None

Actual Value Range: PP_1, PP_2, PP_3, PP_4, PP_8, PP_16, PP_32, PP_64

MML Default Value: None

Recommended Value: PP_64(PP_64)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter results in a lower probability that a UE fails to receive Msg4 or the MCE for early contention resolution due to scheduling delay, and a longer delay for the UE to retransmit the preamble. A smaller value of this parameter results in the opposite effects.

Applicable Mode: L-NB-IOT
RaResponseWindowSize RA Response Window Size

Meaning: Indicates the random access response (RAR) window size. This parameter can be set to different values for different coverage levels of a cell. This parameter applies only to NB-IoT.

GUI Value Range: PP2(PP2), PP3(PP3), PP4(PP4), PP5(PP5), PP6(PP6), PP7(PP7), PP8(PP8), PP10(PP10)

Unit: None

Actual Value Range: PP2, PP3, PP4, PP5, PP6, PP7, PP8, PP10

MML Default Value: None

Recommended Value: This parameter can be set by the eNodeB by default as follows:

PP10(PP10) when the CoverageLevel parameter is set to COVERAGE_LEVEL_0

PP10(PP10) when the CoverageLevel parameter is set to COVERAGE_LEVEL_1

PP10(PP10) when the CoverageLevel parameter is set to COVERAGE_LEVEL_2

The RAR window size should allow RAR resource allocation to at least one UE. The recommended value varies as follows:

When DlInitialMcs in the PrbDlSchCeAlgo MO is set to MCS_0, it is recommended that RaResponseWindowSize be set to a value not less than the result of PdcchMaxRepetitionCnt (in the PrbPdcchCeConfig MO)/8 + 4 ms + 4 x DlInitialTransRptCount (in the PrbDlSchCeAlgo MO).

When DlInitialMcs in the PrbDlSchCeAlgo MO is set to MCS_1, it is recommended that RaResponseWindowSize be set to a value not less than the result of PdcchMaxRepetitionCnt (in the PrbPdcchCeConfig MO)/8 + 4 ms + 3 x DlInitialTransRptCount (in the PrbDlSchCeAlgo MO).

When DlInitialMcs in the PrbDlSchCeAlgo MO is set to MCS_2, MCS_3, or MCS_4, it is recommended that RaResponseWindowSize be set to a value not less than the result of PdcchMaxRepetitionCnt (in the PrbPdcchCeConfig MO)/8 + 4 ms + 2 x DlInitialTransRptCount (in the PrbDlSchCeAlgo MO).

When DlInitialMcs in the PrbDlSchCeAlgo MO is set to MCS_5 or above, it is recommended that RaResponseWindowSize be set to a value not less than the result of PdcchMaxRepetitionCnt (in the PrbPdcchCeConfig MO)/8 + 4 ms + 1 x DlInitialTransRptCount (in the PrbDlSchCeAlgo MO).

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A smaller value of this parameter results in a smaller RAR window size and a lower access success rate. A larger value of this parameter results in a larger RAR window size and a higher access success rate.

Applicable Mode: L-NB-IOT

Example

To modify the CELLRACHCECFG configuration in a NB-IoT Cell with the parameters as follows: Local cell ID: 0, Coverage Level: COVERAGE_LEVEL_0, Contention Resolution Timer: PP_1, run the following command:
MOD CELLRACHCECFG: LocalCellId=0, CoverageLevel=COVERAGE_LEVEL_0, ContentionResolutionTimer=PP_1;
