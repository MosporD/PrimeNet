Modify Neighboring UTRAN Frequency (MOD UTRANNFREQ)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify the configuration of a neighboring UTRAN frequency.

Note

This is a high-risk MML command, and therefore exercise caution when executing this command.

CellReselPriority Cell reselection priority

Meaning: Indicates the cell reselection priority of the neighboring UTRAN frequency. The value 0 indicates the lowest priority. The UE decides whether to reselect a neighboring cell on the UTRAN frequency based on the value of this parameter and the absolute priority of the serving cell.

If the value of this parameter is larger than the absolute priority of the serving cell, the UE starts measurements on neighboring cells on the UTRAN frequency; then if the signal quality of some neighboring cells meets the related conditions, the UE starts cell reselection.

If the value of this parameter is smaller than the absolute priority of the serving cell, the UE starts the measurements only when the signal quality of the serving cell is poor; then if the signal quality of some neighboring cells meets the related conditions, the UE starts cell reselection. Frequencies used for different RATs must be assigned different cell reselection priorities. For details, see 3GPP TS 36.331. This parameter applies only to LTE FDD and LTE TDD.

Unit: None

Actual Value Range: 0~7

MML Default Value: None

Recommended Value: 1

Parameter Relationship:

-Others:

  • If CellReselPriorityCfgInd is set to NOT_CFG, CellReselPriority does not need to be set.

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A larger value of this parameter leads to a higher probability of starting measurements on neighboring cells on the UTRAN frequency and also a higher probability of reselection to a neighboring cell on the frequency.

OffsetFreq Frequency offset

Meaning: Indicates the frequency offset of the cell on the UTRAN frequency. It determines the probability of triggering measurement reports for events B1 and B2. For details, see 3GPP TS 36.331. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: -15~15

Unit: dB

Actual Value Range: -15~15

MML Default Value: None

Recommended Value: 0

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: Triggering condition for event B1: Mn + Ofn - Hys > Thresh.

Triggering condition for event B2: Ms + Hys < Thresh1 and Mn + Ofn - Hys > Thresh2.

In the conditions, Ms denotes the measurement result of the serving cell; Mn denotes the measurement result of the neighboring cell; Ofn denotes the frequency-specific offset of the neighboring cell; Thresh denotes the threshold for event B1; Thresh1 and Thresh2 denote the thresholds for event B2; Hys denotes the hysteresis for the corresponding event.

A smaller Ofn makes it more difficult to trigger events B1 and B2, which delays handovers and affects user experience. A larger Ofn makes it easier to trigger events B1 and B2, which increases handover decision errors and ping-pong handovers.

Applicable Mode: L-FDD, L-TDD

If this parameter is set to BOOLEAN_TRUE, the UTRAN frequency is a shared frequency, and the shared operator information must be checked on the OSS before all neighboring UTRAN cells are added. If this parameter is set to BOOLEAN_FALSE, the UTRAN frequency is not a shared frequency, and the shared operator information does not need to be checked on the OSS before all neighboring UTRAN cells are added. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: BOOLEAN_FALSE(False), BOOLEAN_TRUE(True)

Unit: None

Actual Value Range: BOOLEAN_FALSE, BOOLEAN_TRUE

MML Default Value: None

Recommended Value: BOOLEAN_TRUE(True)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to BOOLEAN_TRUE, the UTRAN frequency is a shared frequency, and operator information of neighboring UTRAN cells on the shared frequency must be checked on the OSS before the neighboring UTRAN cells are added.

If this parameter is set to BOOLEAN_FALSE, the UTRAN frequency is a non-shared frequency, and operator information of neighboring UTRAN cells on the non-shared frequency does not need to be checked on the OSS before the neighboring UTRAN cells are added, which avoids OSS congestion. Neighboring UTRAN cells on the non-shared UTRAN frequency can be added directly without the shared operator information delivered from the OSS, thereby accelerating neighboring cell addition and avoiding neighboring cell loss caused by OM channel exceptions.

Applicable Mode: L-FDD, L-TDD

SrvccPriority SRVCC Service Priority

Meaning: Indicates the single radio voice call continuity (SRVCC) priority of the neighboring UTRAN frequency, this is, the priority for the neighboring UTRAN frequency to carry SRVCC services. During coverage-based inter-RAT SRVCC-based CS service handovers with UtranFreqLayerMeasSwitch being on, the eNodeB selects and delivers the neighboring UTRAN frequencies based on the SRVCC priorities when starting measurements. The eNodeB preferentially delivers the UTRAN frequency with the highest SRVCC priority to measure. If this parameter is set to Priority_0, this neighboring UTRAN frequency is not prioritized. A larger number in the parameter value indicates that the neighboring UTRAN frequency has a higher SRVCC priority. This parameter applies only to LTE FDD and LTE TDD.
