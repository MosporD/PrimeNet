Modify UeCompat (MOD UECOMPAT)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify the configurations of a group of parameters for UE-type-specific differentiated handling of UEs.

Note

  • In a UeCompat MO, all switch-type parameters take effect only when the UeSpecificConfigIndex parameter is set to 0.

  • If the UeSpecificConfigIndex parameter in this command is to set to a value greater than 0, the parameter value must be specified following the guidance of Huawei technical support. Run this command only under the guidance of Huawei technical support.

  • If a switch-type parameter or option is associated with one or more UeSpecificPara MOs and the UeSpecificPara MO with the ConfigValue parameter value indicating that the switch is ON is associated with at least one UeCompat MO, this UeSpecificPara MO functions as a whitelist switch. The eNodeB enables the function controlled by the parameter or option only for whitelisted UEs that access the network after this MO is set.

  • t is recommended that customers and Huawei technical support not execute MML commands that trigger the following scenarios:

    1. If multiple UeCompat MOs with different UeInfoType parameter values match the same UE model, the eNodeB matches the UE model only with one of the UEInfoType parameter values. The parameter values for UE matching are prioritized as follows: IMEISV_TAC > IMEISV_TAC_SVN > UE_CAPABILITY

    2. If multiple UeCompat MOs with the UeInfoType parameter set to UE_CAPABILITY match the same UE model, only the UeCompat MO with the smallest UeCapIndex parameter value takes effect.

    (3) If multiple UeSpecificPara MOs with the same combination of MoId, ParaId, and ParaBitId parameter values are configured for the same UE model, only the UeSpecificPara MO with the smallest UeSpecificConfigIndex parameter value takes effect for such UEs on the network.

    The following is an example of the parameter validation rule:

    If the following three conditions are met, a UE-specific configuration is a whitelist switch:

    - Two UeSpecificPara MOs are associated with one switch-type parameter or option.

    - The ConfigValue parameter value in one of the UeSpecificPara MOs indicates that the switch is on, and the ConfigValue parameter value in the other MO indicates that the switch is off.

    - The UeSpecificPara MOs are associated with two UeCompat MOs matching the same UE model.

    After such UEs access the network, the UeSpecificPara MO with the smallest UeSpecificConfigIndex parameter value takes effect for the UEs. If the UeSpecificPara MO indicates that the UE-specific-configuration switch is off, the UEs are blacklisted. Otherwise, the UEs are whitelisted.

    (4) If a blacklist or whitelist parameter is configured in both the UeCompat and UeSpecificPara MOs for the same UE model, only the UeCompat MO takes effect.

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If some UEs on the network do not support some features and thereby network KPIs are affected, turning on corresponding switches can disable related features on defective UEs and therefore the KPIs are improved.

INTERMODE_FREQ_MEAS_OFF: If this option is selected, the number of RRC connection reestablishments of defective UEs decreases and the UEs cannot perform inter-duplex-mode handovers, thereby increasing the possibility of service drops. Deselecting this option has no impact on network performance.

INTER_FREQ_HO_SWITCH_OFF: If this option is selected, the number of times such UEs experience handover failures decreases, the inter-frequency handover success rate increases, the service drop rate decreases, and the ratio of the number of RRC connection reestablishments to the number of UE access procedures increases. Deselecting this option has no impact on network performance.

UL_EVSC_SWITCH_OFF: If this option is selected, uplink EVSC is disabled for blacklisted UEs and speech quality is not affected for these UEs. If this option is deselected, UEs may perform uplink EVSC, improving speech quality in the uplink.

MIMO_4T_HANDOVER_SET: If this option is selected, the eNodeB transfers incompatible UEs (service-drop UEs) identified in a 4T cell to inter-frequency cells operating on 2T-cell frequencies through blind redirection. This decreases the service drop rate of the 4T cell. If this option is deselected, the service drop rate of such UEs deteriorates in the 4T cell.

WTCP_SWITCH_OFF: If the TcpAccelerationSwitch parameter is set to ON and this option is selected, WTCP does not take effect for defective UEs. In this case, the number of service drops decreases and the data rate in the initial TCP phase decreases. If the TcpAccelerationSwitch parameter is set to ON and this option is deselected, WTCP can take effect for defective UEs. In this case, the number of service drops increases and the data rate in the initial TCP phase increases. If the TcpAccelerationSwitch parameter is set to OFF, the setting of this option has no impact on network performance.

Meaning: Indicates whether to whitelist some features.

CA_SRS_ONLY_SWITCH_ON: Indicates whether to enable the SCell polling sending SRS function for specified UEs. When this function is enabled, the SCell sends only SRSs instead of data in the uplink CA scenario. When multiple SCells exist, the SCells send SRSs in a polling manner. This function is enabled only if this option is selected. This option applies only to LTE FDD and LTE TDD.

UL_EVSC_SWITCH_ON: Indicates whether to enable the function of uplink EVSC for specified UEs. This function is enabled only if this option is selected. This option applies only to LTE FDD and LTE TDD.

This option applies only to LTE FDD and LTE TDD.

If this option is deselected, no differentiated measures are taken for the specified UEs. This option applies only to LTE FDD and LTE TDD.

Impact on Radio Network Performance: A larger value of this parameter results in more inter-frequency measurement objects that can be delivered over the Uu interface. The number of inter-frequency measurement objects that a UE can measure also depends on the UE capability. According to 3GPP specifications, an NSA UE in the DC state can measure at least a total of 13 inter-frequency measurement objects. If this parameter is set to a value larger than 13, compatibility problems may occur and UEs may become abnormal. A smaller value of this parameter results in fewer inter-frequency measurement objects that can be delivered over the Uu interface. If some inter-frequency and inter-RAT measurement objects are not delivered, measurement-related algorithms may be affected. For example, handover algorithms may be affected, and accordingly the inter-frequency and inter-RAT handover success rates may be affected. Other measurement-related algorithms cannot obtain necessary frequency measurement information.

Applicable Mode: L-FDD, L-TDD

Example

To modify the UE compatibility parameters with an index of 0 and change the value of UE Information Type to IMEISV_TAC and the value of Imeisv Tac to 1, run the following command:
MOD UECOMPAT: Index=0, UeInfoType=IMEISV_TAC, ImeisvTac=1;
