Add a Non-Anchor Carrier for an NB-IoT Cell (ADD NONANCHORPRB)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to add a non-anchor carrier for an NB-IoT cell.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

Adding a non-anchor carrier will cause the cell to automatically restart.

Before adding a non-anchor carrier for an NB-IoT cell, check that an anchor carrier has been added for this NB-IoT cell. If an anchor carrier has not been added, the non-anchor carrier cannot be added.

Before adding a non-anchor carrier, plan the working mode of the BBP and the proportion of resources for each RAT.

If a non-anchor carrier is going to be deployed in LTE in-band mode, RBs must be reserved in the LTE cell associated with the in-band carrier in advance. If no RB is reserved, adding the non-anchor carrier will cause the LTE cell to restart.

If an NB-IoT cell does not have carriers deployed in in-band mode and the non-anchor carrier is to be deployed in in-band mode, an activated LTE cell will be preferentially selected for the non-anchor carrier deployment.

When the total number of carriers is greater than two for a cell, UlSchRbAllocOptSw of the UlSchExtSwitch parameter in the CellAlgoSwitch MO will be turned on for this cell. When the total number of carriers is less than or equal to two for a cell, UlSchRbAllocOptSw of the UlSchExtSwitch parameter in the CellAlgoSwitch MO will be turned off for this cell.

This command is not applicable to LampSite base stations.

When this command is used, the LteUlRbIndex and LteDlRbIndex parameters cannot be set to 255. Otherwise, the command execution will fail.

When this command is used, UlEarfcnCfgInd is set to CFG by default.

NonAnchorCarrierDeployMode Non-Anchor Carrier Deployment Mode

Meaning: Indicates the NB-IoT PRB deployment mode. The value R13_STAND_ALONE indicates that idle spectrum adjacent to LTE spectrum is used to deploy the NB-IoT PRB, and the uplink and downlink PRB frequency offsets are set in compliance with 3GPP Release 13. The value R14_STAND_ALONE indicates that idle spectrum adjacent to LTE spectrum is used to deploy the NB-IoT PRB, and the uplink and downlink PRB frequency offsets are set in compliance with 3GPP Release 14. The value GUARD_BAND indicates that the guard band of LTE is used to deploy the NB-IoT PRB. The value IN_BAND indicates that LTE RB resources are used to deploy the NB-IoT PRB. As a result, fewer RB resources are available to LTE. This parameter applies only to NB-IoT.

The uplink EARFCN range of Band 111 is 32111 to 32160 and that of Band 222 is 31111 to 31160.
  • Among the Prb MOs with the same LocalCellId setting: (1) The DlEarfcn parameter must be set to different values in the Prb MOs in which the LteDlRbIndex parameter is set to an invalid value and the WorkMode parameter is set to UL_DL or DL_ONLY. (2) The DlEarfcn parameter must be set to different values in the Prb MOs in which the WorkMode parameter is set to UL_DL or UL_ONLY.   • Among the Prb MOs with the same LocalCellId setting: (1) The DlEarfcn parameter must be set to different values in the Prb MOs in which the LteDlRbIndex parameter is set to an invalid value and the WorkMode parameter is set to UL_DL or DL_ONLY. (2) The DlEarfcn parameter must be set to different values in the Prb MOs in which the WorkMode parameter is set to UL_DL or UL_ONLY. Specifically, if the UlEarfcnCfgInd parameter in a Prb MO is set to CFG and the LteUlRbIndex parameter in this Prb MO is set to an invalid value, the UL EARFCN of the corresponding PRB is specified by the UlEarfcn parameter in this Prb MO; if the UlEarfcnCfgInd parameter in a Prb MO is not set to CFG and the WorkMode and LteDlRbIndex parameters in this Prb MO are set to UL_DL and an invalid value, respectively, the UL EARFCN of the corresponding PRB is automatically calculated based on the values of the DlEarfcn and DlFreqOffset parameters in this Prb MO given that the system is symmetrical in the uplink and downlink.
  • The differences between the uplink frequencies of the PRBs specified in the Prb MOs in which the LocalCellId parameters are set to the same value, the WorkMode parameters are set to UL_DL or UL_ONLY, and the DeployMode parameters are set to STAND_ALONE must not be greater than the result of 20 MHz minus 200 kHz.
  • If the number of Prb MOs in which the LocalCellId parameters are set to the same value and the DeployMode parameters are set to STAND_ALONE are greater than two, the spacing between the uplink center frequencies of the PRBs specified in the Prb MOs in which the WorkMode parameters are set to UL_DL or UL_ONLY must be an integer multiple of 15 kHz.

ReferenceSignalPwr Reference Signal Power

Meaning: Indicates the reference signal power of the sector equipment for the PRB (the precision of converting dBm to mW is 0.01 mW). For details, see 3GPP TS 36.213. In accordance with 3GPP specifications, the reference signal power offset of a non-anchor carrier relative to the anchor carrier of a multi-carrier NB-IoT cell can be -12 dB, -10 dB, -8 dB, -6 dB, -4 dB, -2 dB, 0 dB, or 3 dB. If the actual offset (the difference between the configured reference signal power values of the two carriers) is different from the protocol-specified values, the protocol-specified value closest to and greater than the actual offset is delivered in a Uu message. If the actual offset is greater than 3 dB, the value 3 dB is delivered in a Uu message. For details, see 3GPP TS 36.331. This parameter applies only to NB-IoT.

GUI Value Range: -600~500

Unit: 0.1dBm

Actual Value Range: -60~50

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

NbRfCarrierStrategy NB-IoT RF Carrier Strategy

Meaning: Indicates the RF carrier policy for an NB-IoT cell. If this parameter is set to SEPARATE_PRECEDENCE, the RF carrier separation policy is preferentially used to set up the cell. If the RRU or BBP does not support RF carrier separation, the RF carrier sharing policy is then used. If this parameter is set to SHARE, the RF carrier sharing policy is used to set up the cell. This policy requires that the RRU and BBP support RF carrier sharing. If this parameter is set to SEPARATE, the RF carrier separation policy is used to set up the cell. This policy requires that the RRU and BBP support RF carrier separation. This parameter applies only to the LTE in-band and standalone deployment modes. In other deployment modes, setup on a separate carrier is used by default. This parameter applies only to macro and micro base stations and does not apply to LampSite base stations. This parameter applies only to NB-IoT.
