Modify eNodeB Timer Configuration (MOD ENODEBCONNSTATETIMER)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify the eNodeB connection state timers.

Note

None.

Parameters

ID Name Description
S1MessageWaitingTimer S1 Message Waiting Timer

Meaning: Indicates the timer governing the period that the eNodeB waits for a response message from the MME when the UE is running non-QCI1 services. If the UE is running services with a QCI of 1, the S1MsgWaitingTimerQci1 parameter controls the period that the eNodeB waits for a response message from the MME.

GUI Value Range: 1~200

Unit: s

Actual Value Range: 1~200

MML Default Value: None

Recommended Value: 20

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: The setting of this parameter affects how long the eNodeB will wait for a response message from the MME. If this parameter is set to a small value, the eNodeB waits for a period shorter than the transmission time required by a response message from the MME. If this parameter is set to a large value, the eNodeB waits for a long period for a response message that may not be received from the MME due to a fault. As a result, resources are wasted. To prevent this, you are advised to retain the default value.

Applicable Mode: L
X2MessageWaitingTimer X2 Message Waiting Timer

Meaning: Indicates the length of the timer governing the period in which the eNodeB waits for an X2 response message from a peer eNodeB when a UE is not performing any QCI-1 service. If the eNodeB performs an X2-based handover for a UE performing a QCI-1 service, the period is determined by the value of the X2MessageWaitingTimerQci1 parameter.

GUI Value Range: 1~200

Unit: s

Actual Value Range: 1~200

MML Default Value: None

Recommended Value: 20

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to a small value, the base station may regard that the response message times out when the peer base station has not sent the response message yet. If this parameter is set to a large value, the base station continues waiting for a response message from the peer base station when it has not received any response message due to a fault. As a result, resources are wasted. You are advised to retain the default value to avoid the preceding situations.

Applicable Mode: L-FDD, L-TDD

BearerActivityThd Bearer Activity Threshold

Meaning: Indicates the threshold used to determine bearer activity. The eNodeB consistently monitors the consecutive no-transmission duration for each bearer. If the duration for a bearer is less than or equal to the threshold, the eNodeB determines that the bearer is active. If this parameter is set to 65535, the eNodeB does not determine bearer activity for performance counter measurement. This parameter applies only to LTE FDD and LTE TDD.

GUI Value Range: 0~80,65535

Unit: 50ms

Actual Value Range: 0~4000,65535

MML Default Value: None

Recommended Value: 80

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A smaller value of this parameter results in a higher probability that the eNodeB regards a bearer as inactive at the bearer release, and therefore smaller values of counters that indicate the number of abnormal releases of active E-RABs and the number of abnormal releases of active UE contexts. A larger value of this parameter results in the opposite effects. If this parameter is set to 65535, the eNodeB does not determine bearer activity for performance counter measurement. The number of abnormal releases of active E-RABs and the number of abnormal releases of active UE contexts are identical to the number of abnormal releases of E-RABs and the number of abnormal releases of UE contexts without distinguishing whether there is data transmission, respectively. All releases are counted into the counters related to active bearers and UE contexts.

Applicable Mode: L-FDD, L-TDD
RrcReestActivityThld RRC Reestablishment Activity Threshold

Meaning: Indicates the switch that controls the measurement optimization of service drops for UEs in the active state and the threshold based on which the eNodeB determines whether RRC connection reestablishments are for UEs in the active state.

When this parameter is used as the switch: If this parameter is set to a value other than 0, the measurement optimization is enabled, and the eNodeB collects statistics on services drops for UEs in the active state at the PDCP layer. If this parameter is set to 0, the measurement optimization is disabled, and the eNodeB collects statistics on service drops for UEs in the active state at the MAC layer. You are advised to set this parameter to a value other than 0 only in network swapping scenarios.

When this parameter is used as the threshold: If this parameter is set to a value other than 0, the eNodeB consistently monitors how long a UE consecutively does not transmit or receive data. If the duration is shorter than the threshold, the eNodeB determines that an RRC connection reestablishment for the UE is an RRC connection reestablishment for a UE in the active state. If this parameter is set to 0, the eNodeB does not determine the UE active state for performance counter measurements related to RRC connection reestablishment.

This parameter applies only to LTE FDD.

GUI Value Range: 0~10

Unit: s

Actual Value Range: 0~10

MML Default Value: None

Recommended Value: 0

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: When this parameter is used as the switch:

If this parameter is set to a value other than 0, the number of abnormal releases of active E-RABs decreases.

If this parameter is set to 0, network performance is not affected.

When this parameter is used as the threshold:

If this parameter is set to 0, the eNodeB does not measure the number of RRC connection reestablishments for UEs in the active state. The number of RRC connection reestablishments for UEs in the active state is zero.

If this parameter is set to a value other than 0, a smaller value of this parameter results in a higher probability that the eNodeB determines that a UE consecutively does not transmit or receive data, a higher probability that an RRC connection reestablishment for the UE is determined as an RRC connection reestablishment for a UE in the inactive state, and smaller values of counters related to RRC connection reestablishments for UEs in the active state. A larger value of this parameter results in the opposite effects.

Applicable Mode: L-FDD
EcidWaitingTimer E-CID Waiting Timer

Meaning: Indicates the length of the timer that controls how the eNodeB responds to an E-CID-based positioning request message after receiving the message from the E-SMLC. Before the timer expires, if the eNodeB has already collected all E-CID measurement results, the eNodeB immediately responds to the request. If the timer expires, the eNodeB sends all measurement results that are already collected to the E-SMLC, or responds to the E-SMLC with a failure if the eNodeB does not collect any measurement result. This parameter applies only to LTE FDD and LTE TDD.

Unit: ms

Actual Value Range: 500~60000

MML Default Value: None

Recommended Value: 6000

Parameter Relationship:

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to a large value, the E-CID measurement waiting time is long for some measurement objects. As a result, the positioning fails because the eNodeB and E-SMLC cannot cooperate. If this parameter is set to a small value, some UEs do not complete all E-CID measurements and the E-CID measurement results are insufficient. This may even cause E-CID positioning failures.

To modify the S1MessageWaitingTimer: 20s, X2MessageWaitingTimer: 20s, UuMessageWaitingTimer: 35s, RrcReestActivityThld:10s , run the following command:
