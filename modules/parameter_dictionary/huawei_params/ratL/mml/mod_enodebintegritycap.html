Modify eNodeB Integrity Protection Algorithm Priority (MOD ENODEBINTEGRITYCAP)

Network Element: BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE

Function

Use this command to modify the priorities of the eNodeB integrity protection algorithms.

Note

None.

Parameters

ID Name Description
PrimaryIntegrityAlgo Primary integrity algorithm

Meaning: Indicates the highest-priority integrity protection algorithm supported by the eNodeB. If this parameter is set to NOT_CFG, the eNodeB skips the algorithm of this priority when selecting the integrity protection algorithm.

GUI Value Range: Snow3G(SNOW 3G Algorithm), AES(AES Algorithm), ZUC(ZUC Algorithm), NOT_CFG(NOT_CFG)

Unit: None

Actual Value Range: Snow3G, AES, ZUC, NOT_CFG

MML Default Value: None

Recommended Value: AES(AES Algorithm)

Parameter Relationship:

-Configuration constraints:

  • In the ENodeBIntegrityCap MO, the PrimaryIntegrityAlgo, SecondIntegrityAlgo, and ThirdIntegrityAlgo parameters must be set to different values except NOT_CFG.
  • Not all the PrimaryIntegrityAlgo, SecondIntegrityAlgo, and ThirdIntegrityAlgo parameters in the ENodeBIntegrityCap MO are set to NOT_CFG.

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: If this parameter is set to NOT_CFG, the eNodeB skips the algorithm of this priority when selecting the integrity protection algorithm. If the integrity protection algorithm list that the eNodeB supports and integrity protection algorithms that the UE supports have no intersection, the security mode configuration fails for the UE, resulting in an E-RAB setup failure or handover failure.

Applicable Mode: L

Actual Value Range: Snow3G, AES, ZUC, NOT_CFG

MML Default Value: None

Recommended Value: Snow3G(SNOW 3G Algorithm)

GUI Value Range: Snow3G(SNOW 3G Algorithm), AES(AES Algorithm), ZUC(ZUC Algorithm), NOT_CFG(NOT_CFG)

NullAlgo NULL Algorithm config switch

Meaning: Indicates whether the eNodeB can use the null algorithm for integrity protection. If this parameter is set to Disable, UE access using the null algorithm is prohibited. If this parameter is set to Enable, UE access using the null algorithm is supported. If this parameter is set to EnableToEia0Eea0CapbOnlyUe, access of UEs with security capabilities including only EIA0 and EEA0 is allowed regardless of whether there is a parameter set to NULL in the ENodeBCipherCap MO.

GUI Value Range: Disable(Disable NULL Algorithm), Enable(Enable NULL Algorithm), EnableToEia0Eea0CapbOnlyUe(NULLAlgo To Eia0Eea0CapbOnlyUe)

Unit: None

Actual Value Range: Disable, Enable, EnableToEia0Eea0CapbOnlyUe

MML Default Value: None

Recommended Value: EnableToEia0Eea0CapbOnlyUe(NULLAlgo To Eia0Eea0CapbOnlyUe)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: According to 3GPP TS 33.401, eNodeBs should allow operators to disable the null algorithm. If this parameter is set to Disable, UE access using the null algorithm is prohibited regardless of whether the access is for an emergency call. If this parameter is set to EnableToEia0Eea0CapbOnlyUe, UE access using the null algorithm is prohibited when the UE supports the integrity protection or encryption algorithm.

Applicable Mode: L

Example

To modify the priorities of the eNodeB integrity protection algorithms with the parameters follows: PrimaryIntegrityAlg: AES, SecondIntegrityAlg: ZUC, ThirdIntegrityAlg: Snow3G, run the following command:
MOD ENODEBINTEGRITYCAP: PrimaryIntegrityAlgo=AES, SecondIntegrityAlgo=ZUC, ThirdIntegrityAlgo=Snow3G;
