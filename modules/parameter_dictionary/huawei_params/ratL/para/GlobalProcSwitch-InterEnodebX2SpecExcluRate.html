Meaning

Indicates the proportion of the maximum number of X2 interfaces exclusive to inter-eNodeB X2 interfaces in X2 self-removal based on dynamic sharing of the X2 specification. The maximum number of X2 interfaces exclusive to inter-eNodeB X2 interfaces is the round-up value of the product of this parameter value and the maximum total number of X2 interfaces. If X2 self-removal based on dynamic sharing of the X2 specification is enabled and the maximum number of X2 interfaces not exclusive to inter-eNodeB X2 interfaces is insufficient for EN-DC X2 interfaces, self-setup EN-DC X2 interfaces cannot occupy the X2 interface resources exclusive to inter-eNodeB X2 interfaces.

If the peer ID is not configured correctly during manual X2 setup or this parameter value is changed, then EN-DC X2 interfaces may occupy the X2 interface resources exclusive to inter-eNodeB X2 interfaces, and X2 self-removal based on dynamic sharing of the X2 specification cannot automatically remove EN-DC X2 interfaces that occupy the X2 interface resources exclusive to inter-eNodeB X2 interfaces. In this case, it is recommended that EN-DC X2 interfaces be manually removed or EN-DC X2 self-removal be enabled.

This parameter is valid only when the BASED_ON_SPEC_DYNAMIC_SHARING option of the X2SonDeleteSwitch parameter in the GlobalProcSwitch MO is selected. This parameter applies only to LTE FDD and LTE TDD.

Caution

If X2 self-removal based on dynamic sharing of the X2 specification is enabled, the maximum number of X2 interfaces exclusive to inter-eNodeB X2 interfaces decreases, and the number of X2 interfaces that are set up reaches its maximum value, then EN-DC X2 self-setup will trigger inter-eNodeB X2 self-removal. In this case, handover services over the removed X2 interfaces are interrupted and eNodeB KPIs may deteriorate. If the maximum number of X2 interfaces exclusive to inter-eNodeB X2 interfaces increases, fewer X2 interface resources can be occupied by EN-DC X2 interfaces and the eNodeB cannot set up X2 interfaces with more gNodeBs to perform NSA services.
Validation of Modification

The parameter modification takes effect after the transport path is automatically reestablished.
Impact on Radio Network Performance

If X2 self-removal based on dynamic sharing of the X2 specification is enabled, a smaller value of this parameter results in a smaller maximum number of X2 interfaces exclusive to inter-eNodeB X2 interfaces and a larger number of X2 interface resources that can be occupied by EN-DC X2 interfaces. When an X2 interface is triggered to be removed, handover services over this interface are interrupted. As a result, eNodeB KPIs, such as the service drop rate, the number of S1-based handovers, and handover delay, may deteriorate. A larger value of this parameter results in a larger maximum number of X2 interfaces exclusive to inter-eNodeB X2 interfaces and a smaller number of X2 interface resources that can be occupied by EN-DC X2 interfaces. As a result, X2 interfaces may not be set up with new gNodeBs, affecting NSA services.
