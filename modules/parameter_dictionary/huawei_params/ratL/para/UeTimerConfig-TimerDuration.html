Recommended Value

This parameter can be set by the system by default. The default value is as follows:

If TimerType is set to NB_CL0_UE_INACTIVITY_TIMER, then: 20

If TimerType is set to NB_CL1_UE_INACTIVITY_TIMER, then: 20

If TimerType is set to NB_CL2_UE_INACTIVITY_TIMER, then: 20

The recommended value of this parameter varies with the NB-IoT cell deployment mode when the TimerType parameter is set to NB_CL0_UE_INACTIVITY_TIMER, NB_CL1_UE_INACTIVITY_TIMER, or NB_CL2_UE_INACTIVITY_TIMER. The recommended value is as follows:

20 for standalone or LTE guard band deployment scenarios; 30 for LTE in-band deployment scenarios

Impact on Radio Network Performance

NB_CL0_UE_INACTIVITY_TIMER: A smaller timer length results in earlier RRC connection releases for NB-IoT UEs at coverage level 0 without performing services, more frequent RRC connection setup requests, and better KPIs such as the service drop rate due to more normal RRC connection releases. A larger timer length results in later RRC connection releases for NB-IoT UEs at coverage level 0 without performing services, longer online duration in which radio resources are occupied, and worse KPIs such as the service drop rate due to fewer normal RRC connection releases.

NB_CL1_UE_INACTIVITY_TIMER: A smaller timer length results in earlier RRC connection releases for NB-IoT UEs at coverage level 1 without performing services, more frequent RRC connection setup requests, and better KPIs such as the service drop rate due to more normal RRC connection releases. A larger timer length results in later RRC connection releases for NB-IoT UEs at coverage level 1 without performing services, longer online duration in which radio resources are occupied, and worse KPIs such as the service drop rate due to fewer normal RRC connection releases.

NB_CL2_UE_INACTIVITY_TIMER: A smaller timer length results in earlier RRC connection releases for NB-IoT UEs at coverage level 2 without performing services, more frequent RRC connection setup requests, and better KPIs such as the service drop rate due to more normal RRC connection releases. A larger timer length results in later RRC connection releases for NB-IoT UEs at coverage level 2 without performing services, longer online duration in which radio resources are occupied, and worse KPIs such as the service drop rate due to fewer normal RRC connection releases.
