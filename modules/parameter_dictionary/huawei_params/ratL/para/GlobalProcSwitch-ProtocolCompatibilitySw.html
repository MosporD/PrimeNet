Protocol Compatibility Switch

MO GlobalProcSwitch
Parameter ID ProtocolCompatibilitySw
Parameter Name

Protocol Compatibility Switch
NE

BTS3900, BTS3900 LTE, BTS5900, BTS5900 LTE
MML Command

MOD GLOBALPROCSWITCH

LST GLOBALPROCSWITCH
Meaning

Indicates whether the eNodeB applies compatibility handling to the protocol-defined procedures. This parameter provides the following options:

CaGapMeasPriOffSwitch: Indicates whether the eNodeB preferentially deletes the inter-frequency measurement configuration after a UE reports event A4 for configuring an SCell. When the UE supports only 2CC CA, the eNodeB preferentially sends an A4-related measurement configuration deletion message if this option is selected. If this option is deselected, the eNodeB sends the SCell configuration message to the UE before sending an A4-related measurement configuration deletion message to the UE. This option applies only to LTE FDD and LTE TDD.

CaHoReqWithR9ConfigSwitch: Indicates whether the handover request message sent from the source eNodeB during a handover carries the IEs sourceOtherConfig-r9 and ue-ConfigRelease-r9. If this option is selected, the message carries these IEs. If this option is deselected, the message does not carry these IEs. This option applies only to LTE FDD and LTE TDD.

AntennaFullConfigSwitch: Indicates whether the full configuration function takes effect. When a UE complying with 3GPP Release 10 initiates a handover and the handover request message contains the IE antennaInfo-r10, the setting of this option affects the IEs contained in the handover command message. If this option is selected, the handover command message contains IEs antennaInfo-r8 and fullconfig-r9. If this option is deselected, the handover command message contains only the IE antennaInfo-r10. This option applies only to LTE FDD and LTE TDD.

DrxConfigMsgSwitch: Indicates whether the eNodeB includes the DRX-Config IE in the RRC Connection Setup message. The messages contain this IE only if this option is selected. This option applies only to LTE FDD and LTE TDD.

MultiplexingTabSelSwitch: Indicates the type of the HARQ multiplexing table used by UEs. If this option is selected, the UEs send HARQ feedback in multiplexing mode according to HARQ-ACK Multiplexing Tables 10.1.3-2, 10.1.3-3, and 10.1.3-4 in 3GPP TS 36.213. This option applies only to LTE TDD.

SCellModCaMeasRmvSwitch: Indicates whether to delete CA or DC A2 and A6 measurement configuration (A3 measurement configuration for a PSCell) of the UE before changing or deleting the SCell of the UE. If this option is selected, upon receiving an A2 or A6 measurement report (A3 measurement report for a PSCell) from a UE, the eNodeB sends an A2- and A6-related measurement configuration deletion message (A3-related measurement configuration deletion message for a PSCell) to the UE before changing or deleting the SCell of the UE. If this option is deselected, upon receiving the measurement report from a UE, the eNodeB does not send the measurement configuration deletion message to the UE before changing or deleting the SCell of the UE. This option applies only to LTE FDD and LTE TDD.

HoCfgReleaseJudgeSwitch: Indicates whether the target eNodeB checks if the release version of the configuration used by the UE from the source eNodeB is later than that of the target eNodeB in an inter-eNodeB handover. When the following conditions are met: (1) The target eNodeB receives a handover request message from the source eNodeB; (2) The release version of the IE ue-ConfigRelease-r9 contained in the message is later than that of the target eNodeB or the message contains an IE that the target eNodeB does not support, the target eNodeB regards that the release version of the configuration used by the UE is later than that of the target eNodeB and includes the IE fullconfig-r9 in the HandoverCommand message if this option is selected. In the preceding scenario, the target eNodeB does not include the IE fullconfig-r9 in the HandoverCommand message if this option is deselected. This option applies only to LTE FDD and LTE TDD.

ScellIndexLimitSwitch: Indicates the index value assigned to an SCell for a UE. If this option is selected, the index value assigned cannot exceed the maximum number of CCs that can be aggregated for the UE. If this option is deselected, the index value assigned can be any one in the entire SCell index value range. This option applies only to LTE FDD and LTE TDD.

HoWithSccMimoModifySwitch: Indicates the method for configuring the MIMO mode of the SCell for the SCell configuration during handovers. If this option is selected, the MIMO mode of the SCell is configured based on UE status in the initial access. If this option is deselected, the MIMO mode of the SCell is configured based on UE status in the handover. This option applies only to LTE FDD and LTE TDD.

ForbidHighCapabilitySwitch: Indicates whether the eNodeB forbids capabilities beyond the UE protocol version for defective UEs that comply with 3GPP Release 10 or later. Some defective UEs may report capabilities beyond the UE protocol version. If this option is deselected, capabilities beyond the UE protocol version are allowed to take effect on the eNodeB. If this option is selected, the eNodeB ignores capabilities beyond the UE protocol version that are reported by the UEs. This option applies only to LTE FDD and LTE TDD.

UlNasCrossHoCacheSwitch: Indicates whether an eNodeB saves an uplink NAS message in the buffer when a handover process and the message cross. When this option is selected, the eNodeB saves the uplink NAS message in the buffer and then sends it to the MME after the handover finishes. When this option is deselected, the eNodeB does not save the message in the buffer. This option applies only to LTE FDD and LTE TDD.

SCellBlindA2Switch: Indicates whether the eNodeB delivers the A2 measurement configuration for SCells to a CA UE after configuring an SCell for the UE in CA-group-based configuration mode in a blind manner. The eNodeB delivers the measurement configuration only if this option is selected. The A2 threshold is always -140 dBm, which is the minimum 3GPP-defined value. This option applies only to LTE FDD and LTE TDD.

DrxActiveStatusJudgeOptSwitch: Indicates that the eNodeB evaluates whether subframe n is in DRX active time at the n-5 subframe, whether to receive CQI/PMI/RI/PTI reports on PUCCH at subframe n, and whether to handle false PUCCH detections at subframe n for UEs complying with 3GPP Release 11 or later. If this option is deselected, for UEs complying with 3GPP Release 11 or later, the eNodeB evaluates whether subframe n is in DRX active time at the n-4 subframe. Then, the eNodeB determines whether to receive CQI/PMI/RI/PTI reports on PUCCH at subframe n. If this option is selected, for UEs complying with 3GPP Release 11 or later, the eNodeB evaluates whether subframe n is in DRX active time also at the n-5 subframe. Then, the eNodeB determines whether to receive CQI/PMI/RI/PTI reports on PUCCH at subframe n and whether to handle false PUCCH detections at subframe n. For details, see section 5.7 in 3GPP TS 36.321. This option applies only to LTE FDD and LTE TDD.

MfbiMeasurementControlSwitch: Indicates the switch to control the delivery of inter-frequency measurement configurations in multi-band scenarios. If this option is selected and the carrier frequency belongs to multiple operating bands, the eNodeB delivers only one frequency in the measurement configuration. If this option is deselected, the eNodeB delivers all possible frequencies in the measurement configuration in the preceding scenario. This option applies only to LTE FDD and LTE TDD.

HighSpeedR14Switch: Indicates whether to enable the 3GPP Release 14 high speed function. If the option is selected and the HighSpeedFlag parameter in the Cell MO is set to HIGH_SPEED or ULTRA_HIGH_SPEED, the eNodeB includes the 3GPP Release 14 high-speed-related IEs in the system information, handover command, and SCC configuration messages and the 3GPP Release 14 high speed function takes effect. If this option is deselected, the eNodeB does not include the IEs in these messages and the function does not take effect. This option applies only to LTE FDD and LTE TDD.

NrCapabilityParallelQuerySw: Indicates whether to enable parallel query of the NR capability. If this option is selected, the eNodeB queries both the NR and EUTRA-NR capabilities using a single UECapabilityEnquiry message during a UE capability query procedure. If this option is deselected, the eNodeB queries either the NR or EUTRA-NR capability using a single UECapabilityEnquiry message. This option applies only to LTE FDD and LTE TDD.

NsaS1ProcedureConflCompatSw: If this option is deselected, the eNodeB responds to the following messages sent from an MME with a procedure processing failure with the cause value "Interaction with other procedure" during an NSA DC procedure: E-RAB SETUP REQUEST, E-RAB MODIFY REQUEST, E-RAB RELEASE COMMAND, and UE CONTEXT MODIFICATION REQUEST. If this option is selected, the eNodeB can process these messages and respond with a success during an NSA DC procedure. This option applies only to LTE FDD and LTE TDD.

GtpuExtensionHeaderV1530Sw: Indicates whether the eNodeB complies with 3GPP TS 29.281 V15.3.0 or later in terms of the setting of the Next Extension Header Type field in the GTP-U Extension Header. If this option is selected, the eNodeB complies with 3GPP TS 29.281 V15.3.0 or later. When the extension header type is Long PDCP PDU Number, the eNodeB sets the Next Extension Header Type field to the binary number 00000011. If this option is deselected, the eNodeB does not comply with 3GPP TS 29.281 V15.3.0 or later. When the extension header type is Long PDCP PDU Number, the eNodeB sets the Next Extension Header Type field to the binary number 10000010. This option applies only to LTE FDD and LTE TDD.

NrB1MeasOptSw: Indicates whether to enable the eNodeB not to configure measurement gaps in NR B1 measurement configurations delivered to an NSA UE and whether to combine the RRC connection reconfiguration messages for the NR B1 measurement removal and SCG addition procedures for an NSA UE. If this option is selected, the eNodeB does not configure measurement gaps in NR B1 measurement configurations and combines the RRC connection reconfiguration messages for the NR B1 measurement removal and SCG addition procedures. If this option is deselected, the eNodeB configures measurement gaps in NR B1 measurement configurations and does not combine the RRC connection reconfiguration messages for the NR B1 measurement removal and SCG addition procedures. This option applies only to LTE FDD and LTE TDD.

LteNrCapbParallelQuerySw: Indicates whether the eNodeB can query the E-UTRAN, NR, and EUTRAN-NR DC capabilities of an NSA-DC-capable UE through a single UE capability query message. If this option, the NrCapabilityParallelQuerySw option of the ProtocolCompatibilitySw parameter in the GlobalProcSwitch MO, and the CaBandCombQueryOptSwitch option of the ProtocolMsgOptSwitch parameter in the GlobalProcSwitch MO are all selected, the eNodeB can query these capabilities at a time through a single UE capability query message. If this option is deselected, the eNodeB cannot query these capabilities at a time through a single UE capability query message. This option applies only to LTE FDD and LTE TDD.

DrbIdIncrementalAllocSwitch: Indicates whether to enable incremental DRB ID allocation. The range of DRB IDs is 1 to 32. When the eNodeB sets up a new DRB, there are the following situations: If this option is deselected, the eNodeB searches for the smallest unused ID started from 1 and allocates it to the new DRB. If this option is selected, the eNodeB searches for the unused ID following the maximum used DRB ID and allocates it to the new DRB. For a non-NB-IoT UE, an intra-cell handover is triggered when the new DRB ID is greater than or equal to 26. After the handover, the eNodeB allocates the DRB ID started from 1 again. For an NB-IoT UE, the UE release is triggered when the eNodeB receives a new DRB setup request and the allocated DRB ID reaches the maximum value 32.

HoDrbCompatibilitySwitch: Indicates whether the eNodeB is compatible with the handover request in which DRB information is contained in the "SourceRB-ConfigSN-NR-r15" IE but not in the "DRB-ToAddModList" IE. The eNodeB is compatible with such a handover request only if this option is selected. This parameter does not take effect for an LMPT board. This option applies only to LTE FDD and LTE TDD.

CaScellRemovalSwitch: Indicates whether the base station removes an SCell that fails be configured for a CA UE during a dedicated bearer setup procedure for the UE. Assume that an SCell fails to be configured for a CA UE during a dedicate bearer setup procedure. If this option is selected, the base station removes the SCell that fails to be configured. If this option is deselected, the base station does not remove the SCell that fails to be configured. This option applies only to LTE FDD and LTE TDD.

NrGapFrameOffsetRoundDownSw: During gap-assisted measurements of NR frequencies, the gap offset is calculated based on the frame offset and the NR SSB offset. If this option is selected, the conversion from frame offset to radio frame is based on the round-down principle. If this option is deselected, the conversion from frame offset to radio frame is based on the round-off principle. This option applies only to LTE FDD and LTE TDD.

Disuse statement: DrbIdIncrementalAllocSwitch: This option will be deleted in later versions. Although the configuration interface in this version still supports synchronization and delivery of the setting of this option, the system no longer uses this option. Therefore, avoid using this option.

Impact on Radio Network Performance

CaGapMeasPriOffSwitch: If this option is selected, the eNodeB preferentially deletes the inter-frequency measurement configuration. In this case, if the cell reported by a UE fails to be configured as an SCell, the UE does not try other cells within the current measurement period. As a result, entry into the CA state is delayed, affecting UE throughput. If this option is deselected, the UE tries more than one cell during SCell configuration within the current measurement period. Therefore, the UE can quickly enter CA, and UE throughput increases. However, if the UE has compatibility problems, the service drop rate increases.

CaHoReqWithR9ConfigSwitch: If this option is deselected, the target eNodeB may consider that necessary IEs are missing from the handover request, and therefore the handover fails. The handover success rate decreases. If this option is selected, the handover compatibility is enhanced. As a result, the handover success rate increases, the number of RRC connection reestablishments drops, and the service drop rate decreases.

AntennaFullConfigSwitch: If the handover command message contains the IE fullconfig-r9, the UE restores PDCP, RLC, MAC, and PHY to their default values. This causes packet loss during the handover and affects UE performance.

DrxConfigMsgSwitch: If this option is deselected, there is no impact except a 0.2% decrease in the success rate of RRC connection setup on a specific network where top UEs exist. If this option is selected, KPIs may deteriorate because UEs do not support the IE DRX-Config. Therefore, this option is deselected by default.

MultiplexingTabSelSwitch: If this option is selected, for 3GPP Release 10 UEs that do not fully support multiplexing according to HARQ-ACK Multiplexing Tables 10.1.3-2, 10.1.3-3, and 10.1.3-4 in 3GPP TS 36.213, the IBLER decreases and the throughput increases. For 3GPP Release 10 UEs that support multiplexing mode according to HARQ-ACK Multiplexing Tables 10.1.3-2, 10.1.3-3, and 10.1.3-4 in 3GPP TS 36.213, the IBLER slightly increases and the throughput decreases.

SCellModCaMeasRmvSwitch: If this option is selected, A2 and A6 measurement configuration for the SCC (A3 measurement configuration for the PSCell) of a CA UE is deleted before the SCell is changed. This ensures that the previous measurement configuration can be automatically deleted by the UE and prevents service drops due to repeated measurement configurations.

HoCfgReleaseJudgeSwitch: When the target eNodeB receives a HandoverPreparationInformation message from the source eNodeB and the target eNodeB determines that the release version of the configuration used by the UE is later than that of the target eNodeB, the target eNodeB includes the IE fullconfig-r9 in the HandoverCommand message if this option is selected. In this case, the UE applies default PDCP, RLC, MAC, and physical channel configurations. This may cause packet losses during the handover, affecting UE performance. In the preceding scenario, if this option is deselected, the target eNodeB does not include IE fullconfig-r9 in the HandoverCommand message. In this case, after the handover, the UE uses an IE that the target eNodeB does not support, which is not consistent with the target eNodeB configuration. This may cause exceptions such as a service drop or RRC connection reestablishment, affecting user experience.

ScellIndexLimitSwitch: If this option is selected, there is a possibility that the eNodeB adds and removes SCells with the same index value in A6-based SCell changes and handovers with SCell configuration. In this case, if the UE has incompatibility issues, the signaling procedure fails and the eNodeB cannot add an SCell for the UE.

HoWithSccMimoModifySwitch: If this option is selected, the MIMO mode of the SCell in SCell configuration for handovers is configured based on UE status in the initial access. In this case, the SCell can quickly use spatial multiplexing, and the downlink data rate of the SCell does not change or increases. However, if UEs have incompatibility issues, the service drop rate increases. Deselecting this option has no impact on network performance.

ForbidHighCapabilitySwitch: If this option is deselected and some defective UEs cannot fully support capabilities beyond the UE protocol version, the network KPIs are affected. If this option is selected, the eNodeB ignores and disables capabilities beyond the UE protocol version that are reported by the UEs, improving the cell KPIs.

UlNasCrossHoCacheSwitch: Selecting this option may decrease the handover success rate and the number of MME-induced service drops. Deselecting this option results in the opposite effects.

SCellBlindA2Switch: If this option is selected, the eNodeB delivers the A2 measurement configuration for SCells to a CA UE after configuring an SCell for the UE in CA-group-based configuration mode in a blind manner. If the UE has incompatibility issues, the SCell synchronization measurement depends on measObject of the SCC. This avoids that the SCell of the CA UE cannot work properly and improves UE throughput.

DrxActiveStatusJudgeOptSwitch: If this option is selected, the eNodeB also evaluates whether subframe n is in DRX active time 5 ms in advance. If subframe n is in a sleep period, the eNodeB does not receive CQI/PMI/RI/PTI reports on PUCCH. If the eNodeB evaluates whether subframe n is in a sleep period 5 ms in advance and subframe n is in DRX active time 4 ms in advance, the eNodeB receives CQI/PMI/RI/PTI reports on PUCCH and handles false PUCCH detections. As a result, uplink packet loss decreases but the uplink PUCCH performance deteriorates slightly. If this option is deselected, the UE does not send CQI/PMI/RI/PTI reports on PUCCH if the UE evaluates that subframe n is in a sleep period 5 ms in advance based on 3GPP specifications. If the eNodeB evaluates that subframe n is in DRX active time 4 ms in advance, the eNodeB receives CQI/PMI/RI/PTI reports on PUCCH but does not handle false PUCCH detections. This causes state inconsistency between the eNodeB and UE, which results in packet loss. It is recommended that this option be selected when the penetration rate of UEs complying with 3GPP Release 11 or later is high.

MfbiMeasurementControlSwitch: If this option is selected, the eNodeB does not deliver multiple measurement objects of the same carrier frequency in multi-band scenarios so that the measurement configuration can carry more effective information. In multi-frequency scenarios, this helps improve measurement effectiveness and therefore increase the handover success rate. If this option is deselected, the eNodeB may delivery two EARFCNs of the same carrier frequency in multi-band scenarios, which may cause UE malfunctions.

HighSpeedR14Switch: If this option is selected, the 3GPP Release 14 high speed function is enabled, improving user experience of high-speed UEs complying with 3GPP Release 14. If this option is deselected, network performance is not affected.

NrCapabilityParallelQuerySw: If this option is selected, the UE capability query procedure is shortened. However, the total size of the EUTRA-NR and NR capability information may exceed the maximum signaling size. If this option is deselected, the eNodeB queries the EUTRA-NR and NR capabilities separately and the signaling size does not exceed the maximum size. However, the UE capability query procedure is prolonged.

NsaS1ProcedureConflCompatSw: If this option is selected, the eNodeB can handle S1 procedure conflicts, increasing the E-RAB setup success rate, E-RAB release success rate, E-RAB modification success rate, and UE context modification success rate. If this option is deselected and the MME does not support parallel processing, E-RAB setup, release, and modification, and UE context modification will fail in case of procedure conflicts, decreasing the E-RAB setup success rate, E-RAB release success rate, E-RAB modification success rate, and UE context modification success rate.

GtpuExtensionHeaderV1530Sw: If this option is selected and the peer base station does not support the GTP-U extension header type of Long PDCP PDU Number, the peer base station does not discard the data packets (forwarded to it) with the extension header during handovers. This does not affect network performance. If this option is selected and the peer base station supports the GTP-U extension header type of Long PDCP PDU Number in a way that does not comply with 3GPP TS 29.281 V15.3.0 and later, the UE PDCP layer will postpone the sending of the data forwarded to the UE to the application layer during a handover or NSA DC SCell change. As a result, UE throughput decreases for a short period. If this option is deselected and the peer base station does not support the GTP-U extension header type of Long PDCP PDU Number, the peer base station discards the data packets (forwarded to it) with this extension header during handovers. As a result, UE throughput decreases for a short period.

NrB1MeasOptSw: If this option is selected, the latency on SCG addition for NSA-DC-capable UEs decreases. If this option is deselected, network performance is not affected.

LteNrCapbParallelQuerySw: If this option is selected, the eNodeB can query the E-UTRAN, NR, and EUTRAN-NR DC capabilities of an NSA-DC-capable UE through a single UE capability query procedure. In this case, the access latency for the NSA-DC-capable UE can be shortened. However, exceptions occur when some UEs receive the query messages, leading to KPI deterioration. If this option is deselected, the eNodeB query these capabilities separately, extending the querying duration.

DrbIdIncrementalAllocSwitch: When a DRB is repeatedly removed and then set up, there are the following situations: If this option is selected, for non-NB-IoT UEs, the number of intra-cell handovers increases; for NB-IoT UEs, the number of abnormal releases increases. If this option is deselected, network performance is not affected.

HoDrbCompatibilitySwitch: If this option is selected, the eNodeB is compatible with the handover request in which DRB information is contained in the "SourceRB-ConfigSN-NR-r15" IE but not in the "DRB-ToAddModList" IE. During an X2-based handover, the target eNodeB sends a response indicating a handover preparation success. In this case, the handover preparation success rate increases. If this option is deselected, the eNodeB is not compatible with the handover request in which DRB information is contained in the "SourceRB-ConfigSN-NR-r15" IE but not in the "DRB-ToAddModList" IE. During an X2-based handover, the target eNodeB sends a response indicating a handover preparation failure.

CaScellRemovalSwitch: If this option is selected and the eNodeB fails to configure an SCell, the eNodeB proactively removes this SCell to ensure that the bearer setup would not fail again because of this SCell during the next reconfiguration procedure. If this option is deselected, there is no impact.
