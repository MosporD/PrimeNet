Parameter Name

HO and E-RAB Conflict Processing Strategy
NE

MML Command

MOD GLOBALPROCSWITCH

LST GLOBALPROCSWITCH
Meaning

Indicates the policy for handling conflicts between handover-related procedures and bearer-related procedures. A handover-related procedure refers to as an X2- or S1-based handover preparation phase. A bearer-related procedure refers to as a bearer setup, modification, or deletion procedure. If this parameter is set to HO_FLOW_FIRST, the eNodeB processes the handover-related procedure first when a conflict occurs. If this parameter is set to ERAB_FLOW_FIRST, the eNodeB performs as follows when a conflict occurs: 1. If the handover is not for CSFB, or an SRVCC procedure conflicts with a QCI-1 bearer release procedure, the eNodeB processes the bearer-related procedure first. 2. If the handover is for CSFB, or an SRVCC procedure conflicts with another bearer-related procedure, the eNodeB processes the handover-related procedure first. If this parameter is set to ONLY_X2_HO_ERAB_FLOW_FIRST, the eNodeB processes the bearer-related procedure first only when an X2-based handover-related procedure and a bearer-related procedure conflict. When an S1-based handover-related procedure and a bearer-related procedure conflict, the eNodeB processes the handover-related procedure first. This parameter applies only to LTE FDD and LTE TDD.

Impact on Radio Network Performance

If this parameter is set to HO_FLOW_FIRST, the eNodeB preferentially processes the handover-related procedure. When the MME cannot handle the conflict, setting this parameter to HO_FLOW_FIRST decreases the E-RAB setup, modification, or removal success rate, thereby decreasing the VoLTE call success rate. If this parameter is set to ERAB_FLOW_FIRST and the eNodeB receives a bearer-related procedure in the event of a handover, the eNodeB cancels the handover and processes the bearer-related procedure first. In this case, the UE cannot be handed over in time, increasing the service drop rate and decreasing the handover success rate. However, when the MME cannot handle conflicts between handover-related procedures and bearer-related procedures, setting this parameter to ERAB_FLOW_FIRST increases the E-RAB setup, modification, or removal success rate, thereby increasing the VoLTE call success rate. If this parameter is set to ONLY_X2_HO_ERAB_FLOW_FIRST, the eNodeB processes the bearer-related procedure first only when an X2-based handover-related procedure and a bearer-related procedure conflict. In this case, the UE cannot be handed over in time, increasing the service drop rate and decreasing the handover success rate. However, when the MME cannot handle conflicts between handover-related procedures and bearer-related procedures, setting this parameter to ONLY_X2_HO_ERAB_FLOW_FIRST partially increases the E-RAB setup, modification, or removal success rate, thereby increasing the VoLTE call success rate.
