Meaning

Indicates the interval at which the eNodeB controls the downlink UE-AMBR. When this parameter is set to AMBR_50_MS(AMBR_50_MS), AMBR_100_MS(AMBR_100_MS), AMBR_200_MS(AMBR_200_MS), or AMBR_500_MS(AMBR_500_MS), the eNodeB controls the downlink UE-AMBR at an interval of 50, 100, 200, or 500 ms in downlink scheduling. When this parameter is set to AMBR_1000_MS(AMBR_1000_MS), the eNodeB does not control the UE-AMBR. This parameter applies only to LTE FDD and LTE TDD.

Recommended Value

When the downlink UE-AMBR is set to a small value and the network is not congested, you are advised to adjust the AMBR control period, with the maximum value being AMBR_500_MS(500ms). In scenarios where the downlink UE-AMBR is not to be controlled, you are advised to set this parameter to AMBR_1000_MS(1000ms). In other scenarios, the value AMBR_50_MS(50ms) is recommended.

Impact on Radio Network Performance

In multi-user scenarios, a larger value of this parameter results in a higher speed at which small-packet services of downlink AMBR-restricted UEs are scheduled, a shorter wait time for these UEs during scheduling, and therefore a higher user-perceived downlink data rate.

When the period is set to 1000 ms, the eNodeB does not perform downlink AMBR control over UEs.

If the downlink AMBR control period is set to a large value, single-user TCP packet injection may cause the TCP service send window to become unstable. As a result, the incoming traffic volume is insufficient and UE throughput decreases.
