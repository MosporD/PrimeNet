Meaning

Indicates the policy based on which intra-RAT event-triggered ANR and event-triggered ANR with NR add neighbor relationships to NRTs.

If this parameter is set to BASED_NCL, intra-RAT event-triggered ANR and event-triggered ANR with NR add neighbor relationships to NRTs based on NCLs.

If this parameter is set to NOT_BASED_NCL, intra-RAT event-triggered ANR and event-triggered ANR with NR add neighbor relationships to NRTs based on CGIs reported by UEs instead of based on information in NCLs. This parameter applies only to LTE FDD and LTE TDD.

Impact on Radio Network Performance

When PCIs are appropriately planned and the eNodeB or gNodeB capacity is small, you are advised to set this parameter to BASED_NCL. This is because, in such a scenario, the NCL is reliable and will not lead to inappropriate neighbor relationships. Adding neighbor relationships based on the NCL can reduce the number of Uu signaling messages and make neighbor relationship addition more quickly when the neighbor relationships are added for the first time.

When PCIs are not appropriately planned and the eNodeB or gNodeB capacity is large, you are advised to set this parameter to NOT_BASED_NCL. This is because, in such a scenario, the NCL is not reliable and will lead to inappropriate neighbor relationships. If the neighbor relationship is added for the first time, the number of Uu signaling messages increases. This ensures neighbor relationship correctness, decreases the possibility of falsely reporting PCI confusion alarms, increases the intra-RAT intra-frequency and inter-frequency handover success rates, and increases the DC SCell configuration success rate.
