SUBIF

TRANSPORT
  +-SUBIF

Description

The SUBIF MO is the sub-interface associating the virtual routing and forwarding (VRF) and Ethernet Like interface. The Ethernet Like interface includes the Ethernet port and Ethernet trunk.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the VRF MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The VRF instance used by a SUBIF MO must have been configured.
  • Relation with the DEVIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If PT in a DEVIP MO is set to SUBIF, the SUBIF MO that uses the same VRF instance as the DEVIP MO must have been configured.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If PT in a DEVIP MO is not set to SUBIF or LOOPINT, the SUBIF MO cannot be configured.
  • Relation with the IFIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If PT in an IFIP MO is set to SUBIF, the SUBIF MO that uses the same VRF instance as the IFIP MO must have been configured.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If PT in an IFIP MO is not set to SUBIF, the SUBIF MO cannot be configured.
  • Relation with the TUNNEL MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]A TUNNEL MO and a SUBIF MO cannot both be configured.
  • Relation with the VLANCLASS MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]A VLANCLASS MO and a SUBIF MO cannot both be configured.
  • Relation with the ETHTRKLNK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If PT in a SUBIF MO is set to ETH, and the corresponding ETHPORT MO has joined an ETHTRK MO, the SUBIF MO cannot be added.
  • Relation with the PORTSECURITY MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]An ETHPORT MO on which a SUBIF MO depends must meet either of the following conditions: (1) The corresponding PORTSECURITY MO is not configured. (2) The corresponding PORTSECURITY MO has been configured, and its SWITCH is set to ENABLE.
  • Relation with the ETHTRK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If PT in a SUBIF MO is set to ETHTRK, the corresponding ETHTRK MO must have been configured.
  • Relation with the PACKETFILTER MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If PT in a PACKETFILTER MO is set to SUBIF, the corresponding SUBIF MO must have been configured.
  • Relation with the VLANMAP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If a SUBIF MO has been configured, VLANMODE in the VLANMAP MO cannot be set to VLANGROUP.
  • Relation with the HAGRP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In one logical protection group, SN in an HAGRP MO must be the same as SN in a SUBIF MO.
  • Relation with the PPPLNK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]A PPPLNK MO and a SUBIF MO cannot both be configured.
  • Relation with the MPGRP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]An MPGRP MO and a SUBIF MO cannot both be configured.
  • Relation with the MDU MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If TYPE in an MDU MO is set to MDUC, the SUBIF MO must meet the following conditions: Cabinet No., Subrack No., and Slot No. are set to the same values as those in the MDU MO; PN is set to a value within the range of 0 to 2.
  • Relation with the GTRANSPARA MO:
    • [Co-MPT, NodeB, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to NEW, the SUBIF MO cannot be configured.
  • Relation with the GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]The number of SUBIF MOs is 0 when the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured.
