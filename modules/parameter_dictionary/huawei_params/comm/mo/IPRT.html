IPRT

TRANSPORT
  +-IPRT

Description

The IPRT MO refers to the routing table, which is used for data forwarding. It can be manually configured.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the DEVIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If an IPRT MO and a DEVIP MO are in the same routing domain, NEXTHOP in the IPRT MO must be different from IP in the DEVIP MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If an IPRT MO and a DEVIP MO are on the same network segment and are in the same routing domain, NEXTHOP in the IPRT MO cannot be set to the broadcast IP address for the DEVIP MO. That is, in the IP address consisting of NEXTHOP in the IPRT MO and MASK in the DEVIP MO, the network IDs cannot be all 0s and the host IDs cannot be all 1s.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and IFT in an IPRT MO are set to IF and TUNNEL, respectively, DSTIP in the IPRT MO must be different from IP in a DEVIP MO in the same routing domain.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and IFT in an IPRT MO are set to IF and TUNNEL, respectively, the logical AND-operation result of DSTIP and DSTMASK in the IPRT MO must be different from IP in a DEVIP MO in the same routing domain and from the logical AND-operation result of IP and MASK in a DEVIP MO.
  • Relation with the DEVIP, IFIP, and GTRANSPARA MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If MODELSELECT of GTRANSPARA is set to TRADITION and an IPRT MO and a DEVIP MO whose PT is set to ETH, ETHTRK, SUBIF, or ETHCI are in the same routing domain, NEXTHOP in the IPRT MO must be on the same network segment as IP in the DEVIP MO. In addition, CN, SRN, SN, and SBT in the DEVIP MO must be the same as CN, SRN, SN, and SBT in the IPRT MO, respectively. If MODELSELECT of GTRANSPARA is set to HOSTGW and an IPRT MO and an IFIP MO whose PT is set to ETH, ETHTRK, SUBIF, or ETHCI are in the same routing domain, NEXTHOP in the IPRT MO must be on the same network segment as IP in the IFIP MO. In addition, CN, SRN, SN, and SBT in the IFIP MO must be the same as CN, SRN, SN, and SBT in the IPRT MO, respectively.
  • Relation with the IFIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If an IPRT MO and an IFIP MO are on the same network segment and are in the same routing domain, NEXTHOP in the IPRT MO cannot be set to the broadcast IP address for the IFIP MO. That is, in the IP address consisting of NEXTHOP in the IPRT MO and MASK in the IFIP MO, the network ID cannot be all 0 and the host ID cannot be all 1.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and IFT in an IPRT MO are set to IF and TUNNEL, respectively, DSTIP in the IPRT MO must be different from IP in an IFIP MO in the same routing domain.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and IFT in an IPRT MO are set to IF and TUNNEL, respectively, the logical AND-operation result of DSTIP and DSTMASK in the IPRT MO must be different from IP in an IFIP MO in the same routing domain and from the logical AND-operation result of IP and MASK in an IFIP MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If an IPRT MO and an IFIP MO are in the same routing domain, NEXTHOP in the IPRT MO must be different from IP in the IFIP MO.
  • Relation with the IPRT MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the same routing domain, a maximum of one IPRT MO whose DSTIP and DSTMASK are both set to 0.0.0.0 can be configured on a BS.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]A maximum of 150 IPRT MOs can be configured on a board.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Each IPRT MO must have a unique combination of CN, SRN, SN, SBT, VRFIDX, DSTIP, DSTMASK, RTTYPE, IFT, IFNO, and NEXTHOP.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the same routing domain, a maximum of two IPRT MO whose DSTIP, DSTMASK, and PREF are the same can be configured on a BS.
  • Relation with the OMCH MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If an IPRT MO and an OMCH MO are in the same routing domain, NEXTHOP in the IPRT MO must be different from IP in the OMCH MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BRT in an OMCH MO is set to YES, before configuring the RTIDX in this OMCH MO, ensure that the IPRT MO in the same routing domain for the OMCH MO have been configured. That is, in the same routing domain, the IPRT MOs whose RTIDX is the same as RTIDX in the OMCH MO must have been configured.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BINDSECONDARYRT in an OMCH MO is set to YES, before configuring the SECONDARYRTIDX in this OMCH MO, ensure that the IPRT MO in the same routing domain for the OMCH MO have been configured. That is, in the same routing domain, the IPRT MOs whose RTIDX is the same as SECONDARYRTIDX in the OMCH MO must have been configured.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and IFT in an IPRT MO are set to IF and TUNNEL, DSTIP in an IPRT MO must be different from IP in an OMCH MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BEAR is set to IPv4 and BRT is set to YES in an OMCH MO, in the same routing domain, the IPRT MOs whose RTIDX is the same as RTIDX in the OMCH MO must have been configured. If the RTTYPE is set to IF, the IFT cannot be set to IPOA.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BEAR is set to IPv4 and BINDSECONDARYRT is set to YES in an OMCH MO, in the same routing domain, the IPRT MOs whose RTIDX is the same as SECONDARYRTIDX in the OMCH MO must have been configured. If the RTTYPE is set to IF, the IFT cannot be set to IPOA.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]IFT in the IPRT MO bound to an OMCH MO cannot be AIRLNK.
    • [Co-MPT, NodeB]If BEAR is set to ATM and BRT is set to YES in an OMCH MO, there must be an IPRT MO in the same routing domain with the OMCH MO, the combination of RTIDX, CN, SRN, SN and SBT in this IPRT MO must be the same as the combination of RTIDX, CN, SRN, SN and SBT in the OMCH MO. The RTTYPE must be set as IF and IFT must be set to IPOA in the IPRT MO.
  • Relation with the TUNNEL MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and IFT are set to IF and TUNNEL, respectively in an IPRT MO, IFNO in the IPRT MO must be the same as TUNNELID in the associated TUNNEL MO.
  • Relation with the PPPLNK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If RTTYPE and IFT in an IPRT MO are set to IF and TUNNEL, DSTIP in an IPRT MO must be different from LOCALIP in an PPPLNK MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB]If RTTYPE and IFT are set to IF and PPP, respectively in an IPRT MO, IFNO in the IPRT MO must be the same as PPPLNKN in the associated PPPLNK MO.
  • Relation with the MPGRP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If RTTYPE and IFT in an IPRT MO are set to IF and TUNNEL, DSTIP in an IPRT MO must be different from LOCALIP in an MPGRP MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB]If RTTYPE and IFT are set to IF and MPGRP, respectively in an IPRT MO, IFNO in the IPRT MO must be the same as MPGRPN in the associated MPGRP MO.
  • Relation with the GTRANSPARA MO:
    • [Co-MPT, NodeB, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to NEW, the IPRT MO cannot be configured.
  • Relation with the MDU MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]When TYPE in the MDU MO is set to MDUC, the IPRT MO must meet the following conditions: RTIDX is set to a value in the range of 0 to 127; RTTYPE is set to NEXTHOP.
  • Relation with the MPT, GTMU, and OMCH MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB]When a GTMU MO with TYPE set to GTMU exists, and an MPT MO with TYPE set to UMPT does not exist, and only one OMCH MO exists, for any two IPRT MOs of a base station in the same routing domain, if their RTIDX is set to a value different from that of RTIDX or SECONDARYRTIDX in the OMCH MO, and RTTYPE and IFT in any one of the IPRT MO are set to IF and TUNNEL, respectively, DSTIP in the two IPRT MOs must be set to different values.
    • When a GTMU MO with TYPE set to GTMU exists, and an MPT MO with TYPE set to UMPT does not exist, and more than one OMCH MO exists, for any two IPRT MOs of a base station in the same routing domain, if their RTIDX is set to a value different from that of RTIDX or SECONDARYRTIDX in the OMCH MO with FLAG set to MASTER and is set to a value different from that of RTIDX or SECONDARYRTIDX in the OMCH MO with FLAG set to SLAVE, and RTTYPE and IFT in any one of the IPRT MO are set to IF and TUNNEL, respectively, DSTIP in the two IPRT MOs must be set to different values.
    • When a GTMU MO with TYPE set to GTMU does not exists, or an MPT MO with TYPE set to UMPT exists, or an OMCH MO does not exist, for any two IPRT MOs of a base station in the same routing domain, if RTTYPE and IFT in any one of the IPRT MO are set to IF and TUNNEL, respectively, DSTIP in the two IPRT MOs must be set to different values.
  • Relation with the GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]The number of IPRT MOs must be less than or equal to 132 when the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured.
  • Relation with the MPT and OMCH MOs:
    • [gNodeB]When an MPT MO with TYPE set to UMPT exists, or an OMCH MO does not exist, for any two IPRT MOs of a base station in the same routing domain, if RTTYPE and IFT in any one of the IPRT MO are set to IF and TUNNEL, respectively, DSTIP in the two IPRT MOs must be set to different values.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD IPRT

Use this command to add a static IP route.
DSP IPRT

Use this command to query the information about all IP routes.

Use this command to list the information about all the static IP routes.
MOD IPRT

Use this command to modify the configuration of an IP route.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Route Index

Indicates the index of an IP route.
Cabinet No.

Indicates the cabinet number of the board where the IP route is located.
Subrack No.

Indicates the subrack number of the board where the IP route is located.
Slot No.

Indicates the slot number of the board where the IP route is located.
Subboard Type

Indicates the type of sub-board on the board where the IP route is established.
Port Type

Indicates the port type.
Port No.

Indicates the port number.
Route Type

Indicates the type of route. If this parameter is set to NEXTHOP, all the IP packets that meet the route direction are first forwarded to the specified next hop IP address. If this parameter is set to IF, all the IP packets that meet the route direction are first forwarded to the specified egress port.
VRF Index

Indicates the index of a VRF instance. UMTS currently supports the default routing domain only (the VRF index is 0).
Destination IP

Indicates the destination IP address of the route.
Mask

Indicates the subnet mask for the destination IP address of the route.
Next Hop IP

Indicates the IP address of the next hop.
Peer IP

Indicates the peer IP address of the link on the air interface. Only the UMPT, LMPT and UMDU support IP routes whose Port Type is Air Link.
MTU Switch

Indicates the switch for configuring the maximum transmission unit (MTU).
Maximum Transmission Unit

Indicates the MTU on a link. The smaller one between this value and the MTU on the Ethernet port takes effect for the base station.
Preference

Indicates the priority of the routing entry. A smaller parameter value indicates a higher priority.
Description Info

Indicates the description about the destination of the route.
Table 3 Dynamic parameters

Parameter

Description
Protocol

Indicates the type of the IP route. A static host route is a manually configured route with the subnet mask set to 255.255.255.255. A static gateway route is a manually configured route, in which the subnet mask is not set to 255.255.255.255. A dynamic host route is a dynamically generated route with the subnet mask set to 255.255.255.255. A dynamic gateway route is a dynamically generated route, in which the subnet mask is not set to 255.255.255.255.
Actual Port Type

Indicates the port type.
Actual Port No.

Indicates the actual port number.
