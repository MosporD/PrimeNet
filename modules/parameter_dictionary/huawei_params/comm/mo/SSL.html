SSL

TRANSPORT
  +-SSL

Description

The SSL MO defines the configuration information about the Secure Sockets Layer (SSL), which includes the configuration of the SSL connection and the query of SSL version supported by an NE.

Effective Scenario

Not involved

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the TLSPOLICY MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If a TLSPOLICY MO does not exist, it cannot be referenced.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
DSP SSLCPB

Use this command to query the Secure Sockets Layer (SSL) version supported by an NE. The version information provides the SSL connection capability of the NE.
DSP SSLERRINFO

Use this command to query the error information about the Secure Sockets Layer (SSL) connection.
DSP SSLRENEGO

Use this command to query SSL renegotiation records, including the SSL renegotiation time, source IP address, destination IP address, receive port, and SSL renegotiation result.
LST SSLCONF

Use this command to list the configuration parameter attributes of SSL.
SET CERTFILE

Use this command to configure NE certificate files to be loaded. The files are the root certificate, certificate revocation list (CRL), certificate chain, public key, and private key. These certificate files are used for digital connection authentication during the Secure Sockets Layer (SSL) handshake. This command can be used to remove the certificates for the certificate revocation list(CRL),certificate chains, and private key password.
SET CONNTYPE

Use this command to set the type of connection between an NE and a client.
SET RRUSECPOLICY

Use this command to set the RRU/AAU authentication mode configured on the BBU during Secure Sockets Layer (SSL) handshakes.
SET SSLAUTHMODE

Use this command to set the authentication mode for the NE to be used during the Secure Sockets Layer (SSL) handshake.
SET SSLCONF

Use this command to set configurations of the SSL.

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Connection Type

Indicates the connection type supported by the NE. Compatible connection mode indicates that the NE supports both the common connection mode and the SSL connection mode. When the connection type is set to ALL(Compatible Connection), NE security risks will be increased if a client accesses the NE in the plaintext mode. Set this parameter to a proper value.
Authentication Mode

Indicates the authentication mode of the SSL connection. If Authentication Mode is set to NONE(Verify None), it indicates that the NE does not need to verify the certificate on the MAE or LMT. If Authentication Mode is set to PEER(Verify Peer Certificate), the NE must verify the certificate of the MAE or LMT during SSL connection setup. If the certificate verification fails, the SSL connection cannot be set up. When the authentication mode is set to NONE(Verify None), NEs will not verify the peer certificate, so that unauthorized clients are more likely to access NEs. Set this parameter to a proper value.
Renegotiation Switch

Indicates Whether the NE supports the SSL renegotiation.
Renegotiation Interval

Indicates Minimum interval between two consecutive SSL renegotiations supported by the NE.
Lowest Cipher Suite Level

Indicates the lowest security level of the SSL cipher suite used by an SSL connection. Reducing the lowest level of cipher suites may increase system security risks. Set this parameter to a proper value.
TLS/SSL Version

Indicates the TLS or SSL version supported by the NE.TLS(Transport Layer Security). The TLS1.2 and TLS1.3 version are enabled eternally in the system, and therefore they cannot be disabled currently. You are not advised to use SSL3.0, TLS1.0 and TLS1.1 because they have security risks.
RRU Authentication Mode

Indicates the authentication mode of the SSL connection via the BBU eCPRI port. If this parameter is set to NONE(Verify None), the RRU can use anonymous authentication to establish a link with the BBU after the first TLS bidirectional authentication between the BBU and the RRU fails. If this parameter is set to PEER(Verify Peer Certificate), the NE must verify the certificate of the RRU eCPRI port during SSL connection setup. If the certificate verification fails, SSL the SSL connection cannot be set up. If this parameter is set to NONE(Verify None), the NE will not verify the peer certificate, so that unauthorized clients are more likely to access the NE. Please set this parameter to a proper value.
RRU Huawei Certificate Authentication Switch

Indicates whether an RRU can use the Huawei certificate for mutual authentication with a BBU. If this switch is turned on, the RRU can use the Huawei certificate to establish connections with the BBU. If this switch is turned off, the RRU cannot use the Huawei certificate to establish connections with the BBU.
Policy ID

Indicates the ID of a TLS configuration policy.
