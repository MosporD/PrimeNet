CFMMA

TRANSPORT
  +-CFMMD
    +-CFMMA
      +-CFMLOCALMEP[0~32]
      +-CFMMEP[0~32]
      +-CFMRMEP[0~64]

Description

The CFMMA MO, a Maintenance Association (MA) for connectivity check (CC), is a set of maintenance points in a maintenance domain (MD). The MA is identified by MD name and MA name.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    CFMMD

  • Possible children:

    CFMLOCALMEP[0~32];CFMMEP[0~32];CFMRMEP[0~64]
  • Relation with the CFMMA MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In a CFMMA MO, if BNDVLAN is set to YES, VLANID in the CFMMA MO must be different from that in other CFMMA MOs.
  • Relation with the CFMMEP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When adding a CFMMEP MO to an ETHPORT MO that belongs to an ETHTRK MO, CCMINTL in the CFMMD MO containing the CFMMEP MO in the ETHTRK MO must be greater than CCMINTL in the CFMMD MO containing the CFMMEP MO in the ETHTRKLNK MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When adding a CFMMEP MO to an ETHTRK MO that an ETHPORT MO belongs to it, CCMINTL in the CFMMD MO containing the CFMMEP MO in the ETHTRK MO must be greater than CCMINTL in the CFMMD MO containing the CFMMEP MO in the ETHTRKLNK MO.
  • Relation with the CFMLOCALMEP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When adding a CFMLOCALMEP MO to an ETHPORT MO that belongs to an ETHTRUNK MO, CCMINTL in the CFMMD MO containing the CFMLOCALMEP MO in the ETHTRUNK MO must be greater than CCMINTL in the CFMMD MO containing the CFMLOCALMEP MO in the ETHTRUNKLNK MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When setting the TRANSCFGMODE in the GTRANSPARA MO to NEW and adding a CFMLOCALMEP MO to an ETHTRUNK MO that an ETHPORT MO belongs to it, CCMINTL in the CFMMD MO containing the CFMLOCALMEP MO in the ETHTRUNK MO must be greater than CCMINTL in the CFMMD MO containing the CFMLOCALMEP MO in the ETHTRUNKLNK MO.
  • Relation with the HAGRP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to OLD, SN in an HAGRP MO must be the same as that in a CFMMA MO in one logical protection group.
  • Relation with the GTRANSPARA MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If MODELSELECT of GTRANSPARA is set to TRADITION and OAMTYPE of GTRANSPARA is set to ITU_T_Y1731, the length of MANAME in the CFMMA MO cannot exceed 13 characters.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If MODELSELECT of GTRANSPARA is set to TRADITION and OAMTYPE of GTRANSPARA is set to ITU_T_Y1731, MANAME in the CFMMA MO must be different from each other.
  • Relation with the GTRANSPARAGW and GTRANSPARA MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If MODELSELECT of GTRANSPARA is set to HOSTGW and OAMTYPE of GTRANSPARAGW is set to ITU_T_Y1731, the length of MANAME in the CFMMA MO cannot exceed 13 characters.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If MODELSELECT of GTRANSPARA is set to HOSTGW and OAMTYPE of GTRANSPARAGW is set to ITU_T_Y1731, MANAME in the CFMMA MO must be different from each other.
  • Relation with the MDU MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If TYPE in an MDU MO is set to MDUC, the CFMMEP MO must meet the following conditions: Cabinet No., Subrack No., and Slot No. are set to the same values as those in the MDU MO; BNDVLAN is set to YES.
  • Relation with the GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]The number of CFMMA MOs must be less than or equal to 8 when the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured.
