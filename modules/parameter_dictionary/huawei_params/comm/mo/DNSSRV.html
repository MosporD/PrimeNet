DNSSRV

TRANSPORT
  +-DNSSRV

Description

This MO is used to configure information for a DNS server.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the DNSSRV MO:
    • [Co-MPT, eNodeB, gNodeB]When the IPVER parameter in the DNSSRV MO is set to IPv6, the DNSCIP6 and DNSSIP6 parameters in two DNSSRV MOs cannot be totally the same.
    • [Co-MPT, eNodeB, gNodeB]The DNSSRV MO with parameter IPVER set to IPv6 cannot be configured.
    • [Co-MPT, eNodeB, gNodeB]When the IPVER parameter in the DNSSRV MO is set to IPv4, the DNSCIP4 and DNSSIP4 parameters in two DNSSRV MOs in the same VRF domain cannot be totally the same.
    • [Co-MPT, eNodeB, gNodeB]A maximum of 4 DNSSRV MOs can be configured on a BS.
  • Relation with the DEVIP and GTRANSPARA MOs:
    • [Co-MPT, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to OLD and IPVER is set to IPv4, DNSCIP4 in a DNSSRV MO must be the same as IP in an existing DEVIP MO, and PT in a DEVIP MO is not set to PPP or MPGRP or ETHCI.
  • Relation with the IPADDR6 MO:
    • [Co-MPT, eNodeB, gNodeB]When the IPVER parameter in the DNSSRV MO is set to IPv6, the DNSCIP6 parameter in the DNSSRV MO must be the IPADDR6 MO configured in the same routing domain of the base station.
    • [Co-MPT, eNodeB, gNodeB]The DNSSIP6 parameter in the DNSSRV MO must be different from the IPV6 parameter in the IPADDR6 MO in the same routing domain.
  • Relation with the DEVIP MO:
    • [Co-MPT, eNodeB, gNodeB]The DNSCIP4 parameter in all DNSSRV MOs must be configured on the same board.
    • [Co-MPT, eNodeB, gNodeB]The DNSSIP4 parameter in the DNSSRV MO must be different from the IP parameter in the DEVIP MO in the same routing domain.
  • Relation with the IPADDR4, IPADDR6, LOOPBACK, and INTERFACE MOs:
    • [Co-MPT, eNodeB, gNodeB]The DNSCIP4 and DNSCIP6 parameters in all DNSSRV MOs must be configured on the same board.
  • Relation with the OMCH MO:
    • [Co-MPT, eNodeB, gNodeB]The DNSSIP6 parameter in the DNSSRV MO must be different from the IP6 parameter in the OMCH MO in the same routing domain.
    • [Co-MPT, eNodeB, gNodeB]The DNSSIP4 parameter in the DNSSRV MO must be different from the IP parameter in the OMCH MO in the same routing domain.
  • Relation with the IPADDR4, INTERFACE, and GTRANSPARA MOs:
    • [Co-MPT, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to NEW and IPVER is set to IPv4, DNSCIP4 in a DNSSRV MO must be the same as IP in an existing IPADDR4 MO, and PT in the INTERFACE MO referenced by IPADDR4 is not set to PPP or MPGRP or ETHCI.
  • Relation with the LOCALIP MO:
    • [Co-MPT, eNodeB, gNodeB]IP in a LOCALIP MO must be different from DNSSIP4 in a DNSSRV MO in the same routing domain.
  • Relation with the IPADDR4 MO:
    • [Co-MPT, eNodeB, gNodeB]The DNSSIP4 parameter in the DNSSRV MO must be different from the IP parameter in the IPADDR4 MO in the same routing domain.
  • Relation with the PMTUCFG MO:
    • [Co-MPT, eNodeB, gNodeB]If MODE in the PMTUCFG MO is set to ACTIVE, PORTNO cannot be the same as the PN in a DNSSRV MO of IPVER is set to IPv6.
  • Relation with the MPGRP MO:
    • [Co-MPT, eNodeB]The DNSSIP4 parameter in the DNSSRV MO must be different from the LOCALIP parameter in the MPGRP MO in the same routing domain.
  • Relation with the PPPLNK MO:
    • [Co-MPT, eNodeB]The LOCALIP parameter in the PPPLNK MO must be different from the DNSSIP4 parameter in the DNSSRV MO in the same routing domain.
  • Relation with the WLOCALIP MO:
    • [Co-MPT, eNodeB]The IP parameter in the WLOCALIP MO must be different from the DNSSIP4 parameter in DNSSRV.
  • Relation with the GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]The number of DNSSRV MOs is 0 when the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured.
  • Relation with the NODE MO:
    • [Co-MPT]An DNSSRV MO cannot be configured on a PRODUCTTYPE MO with PRODUCTTYPE set to DBS3900 DCU or DBS5900 DCU.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD DNSSRV

Use this command to add a DNS server.
DSP DNS

Use this command to query the DNS information of a base station.
LST DNSSRV

Use this command to list the configurations of DNS servers.
MOD DNSSRV

Use this command to modify a DNS server.
RMV DNSSRV

Use this command to remove a DNS server.
STR DNS

Use this command to start a DNS resolution.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
DNS SERVER ID.

Indicates the DNS server ID.
VRF Index

Indicates the index of a VRF instance. UMTS currently supports the default routing domain only (the VRF index is 0).
IP Version

Indicates the IP protocol version.
DNS Client IPv4

Indicates the IPv4 address of the DNS client.
DNS Server IPv4

Indicates the IPv4 address for the DNS server.
DNS Client IPv6

Indicates the IPv6 address of the DNS client.
DNS Server IPv6

Indicates the IPv6 address for the DNS server.
DNS Server Port No.

Indicates the number of the port on the DNS server. The port number must be the same as that configured on the peer DNS server.
DSCP

Indicates the DSCP of the DNS packet.
Table 3 Dynamic parameters

Parameter

Description
Initial Domain Name

Indicates the initial domain name during a DNS query.
Fully Qualified Domain Name

Indicates the full domain name returned by the DNS server during a DNS query.
IP

Indicates the IP address returned by the DNS server during a DNS query.
DNS Server

Indicates the IP address of the DNS server used during a DNS query.
Resolution Result

Indicates whether the DNS resolution succeeds. If the value of this parameter is Success, the DNS of the initial domain name is successfully resolved. If the value of this parameter is Fail, the DNS of the initial domain name fails to be resolved.
Fail Reason

Indicates the cause of the failed DNS resolution.
Resolution Time

Indicates the time of the DNS resolution.
