IPROUTE4

TRANSPORT
  +-IPROUTE4

Description

An IPROUTE4 MO defines a static IPv4 route, which is used for data forwarding by configuring a routing table.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the IPADDR4 MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If an IPROUTE4 MO and an IPADDR4 MO are in the same routing domain, NEXTHOP in the IPROUTE4 MO must be different from IP in the IPADDR4 MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If an IPROUTE4 MO and an IPADDR4 MO are on the same network segment and are in the same routing domain, NEXTHOP in the IPROUTE4 MO cannot be set to the broadcast IP address for the IPADDR4 MO. That is, in the IP address consisting of NEXTHOP in the IPROUTE4 MO and MASK in the IPADDR4 MO, the network IDs cannot be all 0s and the host IDs cannot be all 1s.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and PT in an IPROUTE4 MO are set to IF and TUNNEL, respectively, DSTIP in the IPROUTE4 MO must be different from IP in an IPADDR4 MO in the same routing domain.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and PT in an IPROUTE4 MO are set to IF and TUNNEL, respectively, the logical AND-operation result of DSTIP and DSTMASK in the IPROUTE4 MO must be different from IP in an IPADDR4 MO in the same routing domain and from the logical AND-operation result of IP and MASK in an IPADDR4 MO.
  • Relation with the IPROUTE4 MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the same routing domain, a maximum of one IPROUTE4 MO whose DSTIP and DSTMASK are both set to 0.0.0.0 can be configured on a BS.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Each IPROUTE4 MO must have a unique combination of VRFIDX, DSTIP, DSTMASK, RTTYPE, PT, PORTID, and NEXTHOP.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the same routing domain, a maximum of two IPROUTE4 MO whose DSTIP, DSTMASK, and PREF are the same can be configured on a BS.
    • [Co-MPT, eNodeB, gNodeB]In the same routing domain, if RTTYPE is set to IF and PT is set to INTERFACE in an IPROUTE4 MO, DSTIP, DSTMASK, and PREF in any two IPROUTE4 MOs cannot be set to the same values.
    • [Co-MPT, eNodeB, gNodeB]In the same routing domain, if RTTYPE and PT in an IPROUTE4 MO are set to IF and INTERFACE, respectively, the IPROUTE4 MO cannot form active and standby routes with an IPROUTE4 MO whose RTTYPE is set to NEXTHOP or with an IPROUTE4 MO whose RTTYPE is set to IF but PT is not set to INTERFACE.
  • Relation with the OMCH MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If an IPROUTE4 MO and an OMCH MO are in the same routing domain, NEXTHOP in the IPROUTE4 MO must be different from IP in the OMCH MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and PT in an IPROUTE4 MO are set to IF and TUNNEL, DSTIP in an IPROUTE4 MO must be different from IP in an OMCH MO in the same routing domain.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BEAR is set to IPv4 and BRT is set to YES in an OMCH MO, in the same routing domain, the IPROUTE4 MOs whose RTIDX is the same as RTIDX in the OMCH MO must have been configured. If the RTTYPE is set to IF, the PT cannot be set to IPOA.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BRT in an OMCH MO is set to YES, before configuring the RTIDX in this OMCH MO, ensure that the IPROUTE4 MO in the same routing domain for the OMCH MO have been configured. That is, in the same routing domain, the IPROUTE4 MOs whose RTIDX is the same as RTIDX in the OMCH MO must have been configured.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BINDSECONDARYRT in an OMCH MO is set to YES, before configuring the SECONDARYRTIDX in this OMCH MO, ensure that the IPROUTE4 MO in the same routing domain for the OMCH MO have been configured. That is, in the same routing domain, the IPROUTE4 MOs whose RTIDX is the same as SECONDARYRTIDX in the OMCH MO must have been configured.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BEAR is set to IPv4 and BINDSECONDARYRT is set to YES in an OMCH MO, in the same routing domain, the IPROUTE4 MOs whose RTIDX is the same as SECONDARYRTIDX in the OMCH MO must have been configured. If the RTTYPE is set to IF, the PT cannot be set to IPOA.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]PT in the IPROUTE4 MO bound to an OMCH MO cannot be AIRLNK.
    • [Co-MPT, NodeB]If BEAR is set to ATM and BRT is set to YES in an OMCH MO, there must be an IPROUTE4 MO in the same routing domain with the OMCH MO, the RTIDX in this IPROUTE4 MO must be the same as the RTIDX in the OMCH MO. The RTTYPE must be set as IF and PT must be set to IPOA in the IPROUTE4 MO.
  • Relation with the BACKTUNNEL MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If RTTYPE and PT are set to IF and TUNNEL, respectively in an IPROUTE4 MO, PORTID in the IPROUTE4 MO must be the same as PORTID in the associated BACKTUNNEL MO.
  • Relation with the IPADDR4 and INTERFACE MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the same routing domain, the IP address specified by NEXTHOP in the IPROUTE4 MO must be on the same network segment as the IP address specified by IP in the IPADDR4 MO that is configured on an INTERFACE MO with PT set to ETH, ETHTRK, or ETHCI.
  • Relation with the PPPLNK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If RTTYPE and PT are set to IF and PPP, respectively in an IPROUTE4 MO, PORTID in the IPROUTE4 MO must be the same as PORTID in the associated PPPLNK MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB]If RTTYPE and PT in an IPROUTE4 MO are set to IF and TUNNEL, DSTIP in an IPROUTE4 MO must be different from LOCALIP in an PPPLNK MO.
  • Relation with the MPGRP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If RTTYPE and PT are set to IF and MPGRP, respectively in an IPROUTE4 MO, PORTID in the IPROUTE4 MO must be the same as PORTID in the associated MPGRP MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB]If RTTYPE and PT in an IPROUTE4 MO are set to IF and TUNNEL, DSTIP in an IPROUTE4 MO must be different from LOCALIP in an MPGRP MO.
  • Relation with the GTRANSPARA MO:
    • [Co-MPT, NodeB, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to OLD, the IPROUTE4 MO cannot be configured.
  • Relation with the INTERFACE MO:
    • [Co-MPT, eNodeB, gNodeB]In the same routing domain, if RTTYPE and PT in an IPROUTE4 MO are set to IF and INTERFACE, respectively, the INTERFACE MO corresponding to PORTID in the IPROUTE4 MO must have been configured.
  • Relation with the IPSECBINDITF, IPSECPOLICY, and IKEPEER MOs:
    • [Co-MPT, eNodeB, gNodeB]If RTTYPE is set to IF and PT is set to INTERFACE in an IPROUTE4 MO, the INTERFACE MO specified by PORTID cannot be bound to the IPSECPOLICY MO that references an IKEPEER MO with REDUNDANCYFLAG set to SLAVE and IPVERSION set to IPV6.
    • [Co-MPT, eNodeB, gNodeB]In an IKEPEER MO referenced by an IPSECBINDITF MO, if REDUNDANCYFLAG is set to SLAVE and IPVERSION is set to IPV6, and if an IPROUTE4 MO with RTTYPE set to IF and PT set to INTERFACE has been configured on the master IPSECBINDITF MO, the total number of configured IPROUTE4 MOs and all slave IPSECBINDITF MOs (with active IPSECBINDITF MOs configured with IPROUTE4 MOs in the same IPSec redundancy group) cannot exceed 150.
  • Relation with the IPSECBINDITF MO:
    • [Co-MPT, eNodeB, gNodeB]If RTTYPE in an IPROUTE4 MO is set to IF, the INTERFACE MO corresponding to PORTID in the IPROUTE4 MO must be configured with an IPSECBINDITF MO.
  • Relation with the IPSECBINDITF and IPSECPOLICY MOs:
    • [Co-MPT, eNodeB, gNodeB]If RTTYPE is set to IF and PT is set to INTERFACE in an IPROUTE4 MO, ACLTYPE in the IPSECPOLICY MO that is bound to the same IPSECBINDITF MO as this interface must be set to IPV4 or IPV4+IPV6.
  • Relation with the MPT and OMCH MOs:
    • [gNodeB]When an MPT MO with TYPE set to UMPT exists, or an OMCH MO does not exist, for any two IPROUTE4 MOs of a base station in the same routing domain, if RTTYPE and PT in any one of the IPROUTE4 MO are set to IF and TUNNEL, respectively, DSTIP in the two IPROUTE4 MOs must be set to different values.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD IPROUTE4

Use this command to add a static IPv4 route.
DSP IPROUTE4

Use this command to query the information about all the static IPv4 routes.
LST IPROUTE4

Use this command to list the information about all the static IP routes.
MOD IPROUTE4

Use this command to modify the configuration of a static IPv4 route.
RMV IPROUTE4

Use this command to remove a static IPv4 route.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Route Index

Indicates the index of an IPv4 route.
VRF Index

Indicates the index of a VRF instance. UMTS currently supports the default routing domain only (the VRF index is 0).
Destination IP

Indicates the destination IP address of the IPv4 route.
Mask

Indicates the destination subnet mask of the IPv4 route.
Route Type

Indicates the type of an IPv4 route. The value NEXTHOP indicates that IP packets transmitted through the route are forwarded to a specified next-hop IP address. The value IF indicates that IP packets transmitted through the route are forwarded to a specified outbound interface.
Next Hop IP

Indicates the next-hop IP address.
Port Type

Indicates the type of the port.
Port ID

Indicates the port ID of an IPv4 route.
Peer IP

Indicates the peer IP address of an air interface link. Only UMPT/LMPT/UMDU boards for LTE support IP routes of the air interface link type.
MTU Switch

Indicates the MTU configuration switch.
Maximum Transmission Unit

Indicates the maximum transmission unit of a transmission link. The smaller value between this parameter value and the maximum transmission unit configured for interface corresponding to the routed interface prevails on the base station.
Preference

Indicates the priority of the routing entry. A smaller parameter value indicates a higher priority.
User Label

Indicates the user-defined information.
Table 3 Dynamic parameters

Parameter

Description
Cabinet No.

Indicates the cabinet number of the board to which an IPv4 route belongs.
Subrack No.

Indicates the subrack number of the board to which an IPv4 route belongs.
Slot No.

Indicates the slot number of the board to which an IPv4 route belongs.
Actual Port Type

Indicates the type of the actual port.
Actual Port No.

Indicates the number of the actual port. When the actual port type is Ethernet trunk, the actual port number indicates the port ID of the Ethernet trunk. When the actual port type is tunnel, the actual port number indicates the port ID of the backplane tunnel.
Route Protocol

Indicates the type of the router entry of an IPv4 route. A static host route is a manually configured route with the subnet mask set to 255.255.255.255. A static gateway route is a manually configured route with the subnet mask not being 255.255.255.255. A direct host route is a dynamically generated IPv4 route with the subnet mask being 255.255.255.255. A direct gateway route is a dynamically generated IPv4 route with the subnet mask not being 255.255.255.255.
Valid State

Indicates the validity state of an IPv4 route.
