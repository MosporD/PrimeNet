IPPATHRT

TRANSPORT
  +-IPPATHRT

Description

The IPPATHRT MO enables data to be forwarded on different paths according to the source IP address. This MO is used to carry services with various QoS requirements on the networks with different QoS features. An IP path route and an IP path work together to implement the function of hybrid transport. The IPPATHRT MO takes effect only in LTE.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the DEVIP, IFIP, and GTRANSPARA MOs:
    • [Co-MPT, eGBTS, eNodeB]If MODELSELECT of GTRANSPARA is set to TRADITION, the value of SRCIP in an IPPATHRT MO must be the same as the IP address in a configured DEVIP MO that meets both of the following conditions: (1) The DEVIP MO is in the same routing domain as the IPPATHRT MO. (2) The port type in the DEVIP MO is set to ETH, ETHTRK, LOOPINT, or SUBIF. If MODELSELECT of GTRANSPARA is set to HOSTGW, the value of SRCIP in an IPPATHRT MO must be the same as the IP address in a configured DEVIP MO that meets both of the following conditions: (1) The DEVIP MO is in the same routing domain as the IPPATHRT MO. (2)The IFIP MO is in the same routing domain as the IPPATHRT MO, the port type in the IFIP MO is set to ETH, ETHTRK, or SUBIF.
    • [Co-MPT, eGBTS, eNodeB]On the board to which the IP address specified by SRCIP in an IPPATHRT MO belongs, there must be an IP address that is on the same network segment and in the same routing domain as the IP address specified by NEXTHOPIP and these two IP addresses cannot be the same.
  • Relation with the IPADDR4 and INTERFACE MOs:
    • [Co-MPT, eGBTS, eNodeB]The value of SRCIP in an IPPATHRT MO must be the same as that of IP in an IPADDR4 MO in the same routing domain, and the IPADDR4 MO must be configured on the INTERFACE MO with PT set to ETH, ETHTRK, or LOOPINT.
    • [Co-MPT, eGBTS, eNodeB]NEXTHOPIP in an IPPATHRT MO cannot be set to a broadcast IP address of the network segment where the IPADDR4 MO on the egress port is located, and Network ID and Host ID cannot be all 0 or all 1.
  • Relation with the IPADDR4 MO:
    • [Co-MPT, eGBTS, eNodeB]If an IPADDR4 MO and an IPPATHRT MO are in the same routing domain, IP in the IPADDR4 MO must be different from NEXTHOPIP in the IPPATHRT MO.
  • Relation with the DEVIP MO:
    • [Co-MPT, eGBTS, eNodeB]NEXTHOPIP in an IPPATHRT MO cannot be set to a broadcast IP address of the network segment where the DEVIP MO on the egress port is located, and Network ID and Host ID cannot be all 0 or all 1.
    • [Co-MPT, eGBTS, eNodeB]If a DEVIP MO and an IPPATHRT MO are in the same routing domain, IP in the DEVIP MO must be different from NEXTHOPIP in the IPPATHRT MO.
  • Relation with the IPADDR4, INTERFACE, LOOPBACK, and GTRANSPARA MOs:
    • [Co-MPT, eGBTS, eNodeB]On the board to which the IP address specified by SRCIP in an IPPATHRT MO belongs, there must be an IP address that is on the same network segment and in the same routing domain as the IP address specified by NEXTHOPIP and the latter two IP addresses cannot be the same.
  • Relation with the OMCH MO:
    • [Co-MPT, eGBTS, eNodeB]In the same routing domain, IP in an OMCH MO must be different from NEXTHOPIP in an IPPATHRT MO.
  • Relation with the IFIP MO:
    • [Co-MPT, eGBTS, eNodeB]NEXTHOPIP in an IPPATHRT MO cannot be set to a broadcast IP address of the network segment where the IFIP MO on the egress port is located, and Network ID and Host ID cannot be all 0 or all 1.
    • [Co-MPT, eGBTS, eNodeB]If an IFIP MO and an IPPATHRT MO are in the same routing domain, IP in the IFIP MO must be different from NEXTHOPIP in the IPPATHRT MO.
  • Relation with the MDU MO:
    • [Co-MPT, eGBTS, eNodeB]When TYPE in the MDU MO is set to MDUC, the IPPATHRT MO cannot be configured.
  • Relation with the SRCIPROUTE4 MO:
    • [Co-MPT, eNodeB]An SRCIPROUTE4 MO and an IPPATHRT MO cannot both be configured.
  • Relation with the SRCIPRT MO:
    • [Co-MPT, eNodeB]An SRCIPRT MO and an IPPATHRT MO cannot both be configured.
  • Relation with the GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]The number of IPPATHRT MOs is 0 when the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured.
  • Relation with the NODE MO:
    • [Co-MPT]An IPPATHRT MO cannot be configured on a PRODUCTTYPE MO with PRODUCTTYPE set to DBS3900 DCU or DBS5900 DCU.
  • Relation with the GTPU MO:
    • A static route with the same value must be configured for the GTP-U packets carried on the IP path before the IPPATHRT function is enabled.

Function

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
VRF Index

Indicates the index of a VRF instance. UMTS currently supports the default routing domain only (the VRF index is 0).
Source IP

Indicates the source IP address of an IP path route. The source IP address must be the same as the configured device IP address.
Destination IP

Indicates the destination IP address of an IP path route.
Transport Resource Type

Indicates the type of transport resource carried on an IP path route. The value HQ indicates high-quality transport resources, and the value LQ indicates low-quality transport resources.
Next Hop IP

Indicates the next-hop IP address of an IP path route. The next-hop IP address and the configured device IP address must be on the same network segment, but cannot be the same.
