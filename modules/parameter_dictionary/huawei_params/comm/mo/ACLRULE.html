ACLRULE

TRANSPORT
  +-ACL
    +-ACLRULE

Description

An ACLRULE MO is used to define the rules in an access control list (ACL). The BS identifies and classifies the data flows based on the rules.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    ACL
  • Relation with the PACKETFILTERING MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If ACLAUTOSWITCH is set to OFF, and FM in a PACKETFILTERING MO is set to ADV_ACL, and ACLTYPE in a PACKETFILTERING MO is set to IPV4, at least one ACLRULE MO which is created manually is included in the ACL MO corresponding to ACLID.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If FM in a PACKETFILTERING MO is set to L2_ACL, at least one ACLRULE MO is included in the ACL MO corresponding to ACLID.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In a PACKETFILTERING MO, if ACLAUTOSWITCH is set to ON, manually added ACL rules cannot be numbered from 50000 to 59999 because those ACL rule IDs are used by automatically created ACL rules. That is, RULEID cannot be set to any value from 50000 to 59999 for a manually created ACL rule. In the ACLRULE MO, if the value of AUTOCFGFLAG for an ACL rule is MANUAL_CREATED, this ACL rule is manually created.
  • Relation with the ACLRULE MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Each ACLRULE MO with CTRLMODE set to MANUAL_MODE in one ACL MO must have a unique configuration. Two ACLRULE MOs have the same configuration if the following values are the same in the two MOs: calculation result of SIP and SWC by using a wildcard; calculation result of DIP and DWC by using a wildcard; values of ACTION, PT, SMPT, SOP, SPT1, SPT2, DMPT, DOP, DPT1, DPT2, MDSCP, DSCP, and MFRG.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Each ACLRULE MO in one ACL MO must have a unique configuration. Two ACLRULE MOs have the same configuration if the following condition is met: The two ACLRULE MOs have the same combination of ACTION, VLANIDOP, VLANID1, and VLANID2.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]A maximum of 16 ACLRULE MOs can be configured in one ACL MO when ACLID in the ACLRULE MO is within the range of 4000 to 4999.

    • [NodeB]A maximum of 24 ACLRULE MOs can be configured in one ACL MO.
    • [eGBTS]A maximum of 128 ACLRULE MOs can be configured in one ACL MO.
  • Relation with the IPSECPOLICY MO:

Function

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
ACL ID

Indicates the ID of the access control list (ACL) to which an ACL rule belongs.
Rule ID

Indicates the ID of an ACL rule. The values 1 to 65535 indicate ACL rules manually configured by users or automatically generated for packet filtering. (When the value of ACL Rule Automatic Setup and Deletion Switch of packet filtering is ON, IDs from 50000 to 59999 cannot be used for manually configured ACL rules and are used for automatically generated ACL rules for packet filtering only.) The values 65431 to 65536 indicate the ACL rules automatically generated during DHCP detection. The values 70000 to 79999 indicate ACL rules automatically generated for packet filtering in endpoint configuration mode. The values 80000 to 89999 indicate ACL rules automatically generated for IPsec in endpoint configuration mode.
Action

Indicates the action taken on the data that matches an ACL rule. When an ACL rule is bound to packet filtering, the base station allows the data that matches the rule to transmit if this parameter is set to PERMIT, and discards the data if this parameter is set to DENY. When an ACL rule is referenced by an IPSec policy, the base station encrypts or decrypts the data that matches the rule if this parameter is set to PERMIT, and does not encrypt or decrypt the data if this parameter is set to DENY.
Protocol Type

Indicates the protocol type of the data to which an ACL rule is applied.
Source IP Address

Indicates the source IP address of data to which an ACL rule is applied. To add an ACL rule that is applicable to data of all source IP addresses, set this parameter to 0.0.0.0.
Source Wildcard

Indicates the wildcard of a source IP address. The wildcard is used to determine which bits can be neglected when IP address matching is being performed. It can be considered as the inverse of the corresponding subnet mask.
Match Source Port

Indicates whether to check the source port number of each data stream before applying an ACL rule.
Source Port Operate

Indicates the filtering condition for a source port. If this parameter is set to OP_LT, the ACL rule is applied to the data stream whose source port number is smaller than or equal to the configured port number. If this parameter is set to OP_GT, the ACL rule is applied to the data stream whose source port number is larger than or equal to the configured port number. If this parameter is set to OP_EQ, the ACL rule is applied to the data stream whose source port number is equal to the configured port number. If this parameter is set to OP_NEQ, the ACL rule is applied to the data stream whose source port number is not equal to the configured port number. If this parameter is set to OP_RANGE, the ACL rule is applied to the data stream whose source port number is within the configured range. OP_NEQ is available only for the LMPT, UMPT, UMDU, UTRPc, UCCU and SMPT.
Source Port 1

Indicates the source port number used when SMPT is set to YES. If SOP is set to OP_RANGE, this parameter indicates the smallest source port number. If SOP is not set to OP_RANGE, this parameter indicates a specific source port number.
Source Port 2

Indicates the source port number used when SMPT is set to YES. If SOP is set to OP_RANGE, this parameter indicates the largest source port number. This parameter is valid only when SOP is set to OP_RANGE.
Destination IP Address

Indicates the destination IP address of data to which an ACL rule is applied. To add an ACL rule that is applicable to data of all destination IP addresses, set this parameter to 0.0.0.0.
Destination Wildcard

Indicates the wildcard of a destination IP address. The wildcard is used to determine which bits can be neglected when IP address matching is being performed. It can be considered as the inverse of the corresponding subnet mask.
Match Destination Port

Indicates whether to check the destination port number of each data stream before applying an ACL rule.
Destination Port Operate

Indicates the filtering condition for the destination port. This parameter is valid only when DMPT is set to YES. If this parameter is set to OP_LT, the ACL rule is applied to the data stream whose destination port number is smaller than or equal to the configured port number. If this parameter is set to OP_GT, the ACL rule is applied to the data stream whose destination port number is larger than or equal to the configured port number. If this parameter is set to OP_EQ, the ACL rule is applied to the data stream whose destination port number is equal to the configured port number. If this parameter is set to OP_NEQ, the ACL rule is applied to the data stream whose destination port number is not equal to the configured port number. If this parameter is set to OP_RANGE, the ACL rule is applied to the data stream whose destination port number is within the configured range. This parameter can be set to OP_NEQ only for the LMPT, UMPT, UMDU, UTRPc, UCCU, and SMPT.
Destination Port 1

Indicates the destination port number used when DMPT is set to YES. If DOP is set to OP_RANGE, this parameter indicates the smallest destination port number. If DOP is not set to OP_RANGE, this parameter indicates a specific destination port number.
Destination Port 2

Indicates the destination port number used when DMPT is set to YES. If DOP is set to OP_RANGE, this parameter indicates the largest destination port number. This parameter is valid only when DOP is set to OP_RANGE.
Match DSCP

Indicates whether to check the DSCP of each data stream before applying the ACL rule.
DSCP

Indicates the differentiated services code point (DSCP).
Match Fragment Message

Indicates whether to match the fragment message. The ACL rules for matching fragment messages apply to only packet filtering and does not apply to the IPSec function. When this parameter is set to NO, whether a packet is fragmented is not checked. When this parameter is set to YES, this rule applies only to the middle and last fragments but does not apply to the first fragment or packets that are not fragmented.
Control Mode

Indicates whether an object can be modified or deleted by the system. The value MANUAL_MODE means that only the user can modify or delete the object. The value AUTO_MODE means only the system can modify or delete the object.
VLAN ID Operate

Indicates the filter criteria for VLAN IDs. This parameter is valid only when the ACL ID ranges from 4000 to 4999. When this parameter is set to OP_EQ, only the VLAN ID specified by VLANID1 is a valid. When this parameter is set to OP_RANGE, all the VLAN IDs within the range of VLANID1 to VLANID2 are valid. When this parameter is set to OP_NOVLAN, only packets without VLAN tags are valid.
VLAN ID 1

Indicates the ID of a VLAN to which service data belongs. When Source Port Operate is set to OP_EQ, this parameter specifies the ID of the matching VLAN. When Source Port Operate is set to OP_RANGE, this parameter specifies the smallest ID of the matching VLANs.
VLAN ID 2

Indicates the ID of a VLAN to which service data belongs. When Source Port Operate is set to OP_RANGE, this parameter specifies the largest ID of the matching VLANs. This parameter is valid only when Source Port Operate is set to OP_RANGE.
Auto Config Flag

Indicates whether the object is created by the system. MANUAL_CREATED means that the object is configured by the user manually. AUTO_CREATED means that the object is created by the system.
