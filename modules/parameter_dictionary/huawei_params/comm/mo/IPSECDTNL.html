IPSECDTNL

TRANSPORT
  +-IPSECDTNL

Description

An IPSECDTNL MO consists of the parameters related to an IPSec tunnel pair, such as the IPSec policies and BFD sessions referenced by the IPSec tunnel pair. An IPSec tunnel pair, that is, two IPSec tunnels between the BS and two security gateways (SeGWs), enhances the transmission security between the BS and the core network (CN) or between the BS and the MAE. In implementation, if an IPSec tunnel becomes faulty and the other tunnel is detected to be normal, the BS automatically switches over to the other tunnel and resumes secure transmission with the CN or MAE.

Immediately

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD IPSECDTNL

Use this command to add an IPSec tunnel pair. An IPSec tunnel pair, that is, two IPSec tunnels between the BS and two security gateways (SeGWs), enhances the transmission security between the BS and the core network (CN) or between the BS and the MAE. When the BFD detection switch is set to on, an IPSec tunnel pair uses two BFD sessions to detect the status of the primary and secondary IPSec tunnels, respectively. One BFD session used to detect the status of the primary IPSec tunnel, and the other used to detect that of the secondary IPSec tunnel. If the BFD detection result for the IPSec tunnel in use shows that the SeGW is unreachable or the associated IPSec security associations (SAs) are abnormal, the other IPSec tunnel takes over automatically and resumes secure transmission if it is detected to be normal and the associated IPSec SAs are normal. When the BFD detection switch is set to off, an IPSec tunnel pair determines the status of the primary and secondary IPSec tunnels according to the IPSec SA status. If the SA status of an IPSec tunnel being used becomes faulty and that of the other tunnel is detected to be normal, the base station automatically switches over to the other tunnel and resumes secure transmission with the CN or MAE. IPSec SAs corresponding to all the ACL rules in the ACL referenced by an IPSec tunnel are considered normal only when these IPSec SAs are successfully negotiated. When the Narrow Down Switch parameter in the IPSECPOLICY MO is set to ON, it is considered that an ACL rule in the ACL referenced by this IPSECPOLICY MO succeeds in negotiating an IPSec SA as long as only one IPSec SA is successfully negotiated.
DSP IPSECDTNL

Use this command to query the information about an IPSec tunnel pair.
LST IPSECDTNL

Use this command to list the information about an IPSec tunnel pair.
MOD IPSECDTNL

Use this command to modify the configuration of an IPSec tunnel pair.
RMV IPSECDTNL

Use this command to remove an IPSec tunnel pair.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
IPSec Dual Tunnel ID

Indicates the ID of the IPSec tunnel pair. It uniquely identifies a pair of primary and secondary IPSec tunnels.
Master Policy Group Name

Indicates the name of the primary IPSec policy group.
Master IPSec Sequence No.

Indicates the ID of the primary IPSec policy. The primary IPSec tunnel uses the primary IPSec policy, which is identified by this parameter and the MSPGN parameter together.
Slave Policy Group Name

Indicates the name of the secondary IPSec policy group.
Slave IPSec Sequence No.

Indicates the ID of the secondary IPSec policy. The secondary IPSec tunnel uses the secondary IPSec policy, which is identified by this parameter and the SSPGN parameter together.
BFD Detect Switch

Indicates whether to enable the BFD function. When this parameter is set to OFF, the NE does not enable the BFD function. When this parameter is set to ON, the NE enables the BFD function.
Master Tunnel's BFD Session ID

Indicates the ID of the BFD session referenced by the primary IPSec tunnel.
Slave Tunnel's BFD Session ID

Indicates the ID of the BFD session referenced by the secondary IPSec tunnel.
IPSec Dual Tunnel Switch Back

Indicates whether services can be switched back to the primary tunnel from the secondary tunnel after the former recovers in IPSec dual-tunnel scenarios. When this parameter is set to OFF, the NE does not enable the IPSec dual-tunnel switch back function. When this parameter is set to ON, the NE enables the IPSec dual-tunnel switch back function. If the secondary tunnel that carries services becomes faulty and the primary tunnel is working properly, services are switched to the primary tunnel immediately regardless of the setting of this parameter.
IPSec Switch Back Wait Time

Indicates the period from the time the primary tunnel recovers to the time services are switched back to the primary tunnel in the case that services have been switched to the secondary tunnel after the primary tunnel is faulty in IPSec dual-tunnel scenarios. If the user runs the MOD IPSECDTNL command to change the value of this parameter during a back switchover, the changed value does not take effect until the next back switchover. The primary tunnel must keep working properly during the switchover. If the primary tunnel is disconnected, the time counting restarts. It is recommended that this parameter be set to a value greater than 10s to prevent ping-pong switchovers due to intermittent disconnection of the primary tunnel.
Table 3 Dynamic parameters

Parameter

Description
Current Used IPSec Policy

Indicates the IPSec policy in use. If the primary IPSec tunnel is used, the IPSec policy in use is the primary IPSec policy. If the slave IPSec tunnel is used, the IPSec policy in use is the slave IPSec policy.

Indicates the total number of switchovers between the primary and secondary IPSec tunnels.
Master or Slave Switchover Information

Indicates specific information about switchovers between the primary and secondary IPSec tunnels. This parameter provides information about at most 10 switchovers.
