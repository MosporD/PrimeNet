AAL2NODE

TRANSPORT
  +-AAL2NODE

Description

An AAL2 node is used to trigger the establishment of an Access Link Control Application Part (ALCAP) node. The ALCAP is a generic name for the transport signaling protocol used to set up and release transport bearers. Functions such as ALCAP protocol processing, data configuration, status query, and resource management are performed through communication between the transport layer and the external modules based on the ALCAP.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the MDU MO:
    • [Co-MPT, NodeB, eGBTS]When TYPE in the MDU MO is set to MDUC, the AAL2NODE MO cannot be configured.
  • Relation with the AAL2NODE MO:
    • [Co-MPT, NodeB]Before adding an AAL2 node whose BELONG and FLAG are set to SLAVE and MASTER, or MASTER and SLAVE, respectively, ensure that the AAL2NODE MO whose BELONG and FLAG are set to MASTER and MASTER, respectively has been configured if NT in the AAL2NODE MO is set to LOCAL.
    • [Co-MPT, NodeB]Before adding an AAL2 node whose BELONG and FLAG are set to SLAVE and SLAVE, respectively, ensure that the AAL2NODE MO whose BELONG and FLAG are set to SLAVE and MASTER, respectively has been configured if NT in the AAL2NODE MO is set to LOCAL.
    • [Co-MPT, NodeB]Each AAL2NODE MO must have a unique value of ADDR.
    • [Co-MPT, NodeB]Each AAL2NODE MO must have a unique SAALLNK MO.
  • Relation with the AAL2PATH MO:
    • [Co-MPT, NodeB]If NT in an AAL2PATH MO is set to LOCAL, the AAL2NODE MO that meets the following conditions must have been configured: (1) BELONG and FLAG are both set to MASTER and MASTER; (2) NT is set to LOCAL.
    • [Co-MPT, NodeB]If NT in an AAL2PATH MO is set to HUB, the AAL2NODE MO whose NT is set to HUB must have been configured.
  • Relation with the SAALLNK MO:
    • [Co-MPT, NodeB]Before adding an AAL2NODE MO, ensure that SAALNO in an SAALLNK MO is the same as LN in the AAL2NODE MO under the same BS.
  • Relation with the AAL2ADJNODE MO:
    • [Co-MPT, NodeB]ADDR in an AAL2NODE MO must be different from that in an AAL2ADJNODE MO.
    • [Co-MPT, NodeB]An AAL2NODE MO and an AAL2ADJNODE MO cannot use the same SAALLNK MO.
    • [Co-MPT, NodeB]Before adding an AAL2ADJNODE MO, ensure that an AAL2NODE MO whose NT is set to HUB has been configured.
  • Relation with the CPBEARER MO:
    • [Co-MPT, NodeB]When BEARTYPE in a CPBEARER MO is set to SAAL, the associated SAALLNK MO cannot be used by an AAL2NODE MO. That is, LINKNO in the CPBEARER MO must be different from LN in the AAL2NODE MO.
  • Relation with the GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]The number of AAL2NODE MOs is 0 when the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
SAAL Link No.

Indicates the SAAL link number of an AAL2 node.
ATM Address

Indicates the ATM address of an AAL2 node. The value of this parameter is a string of 40 hexadecimal characters with or without the prefix H' (or h'). For example, this parameter can be set to H'3902030405060708090001020304050607080900 or 3902030405060708090001020304050607080900. The ATM address must begin with 39, 45, 47, or 49 to comply with the protocol.
Node Type

Indicates the type of an AAL2 node. If this parameter is set to LOCAL, the AAL2 node is used to control the local services on the BS. If this parameter is set to HUB, the AAL2 node is used to control services of the lower-level BS cascaded to the hub BS.
Belong Flag

Indicates the type of controller to which an AAL2 node is connected. The controller is either a master controller or a slave controller.
Transport Channel Flag

Indicates the transport channel of an AAL2 node, which can be master or slave.
