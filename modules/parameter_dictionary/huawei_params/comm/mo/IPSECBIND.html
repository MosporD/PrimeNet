IPSECBIND

TRANSPORT
  +-IPSECBIND

Description

This MO indicates the binding relationship between the IP Security (IPSec) policy group and the port. An IPSec tunnel is negotiated to protect the data streams on a port only after an IPSec policy group is bound to the port.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the IPSECDTNL and GTRANSPARA MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to OLD, in an IPSECDTNL MO, the active and standby IPSECPOLICY MOs must be bound to ports; the active and standby IPSECPOLICY MOs must be bound to two different IPSECBIND MOs, and the SPGN values in the two IPSECBIND MOs are the same as the SPGN values in the active and standby IPSECPOLICY MOs, respectively.
  • Relation with the IPSECPOLICY MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The IPSECPOLICY MO associated with an IPSECBIND MO must have been configured.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]CTRLMODE in the IPSECBIND MO must be set to the same value as CTRLMODE in the corresponding IPSECPOLICY MO.
  • Relation with the ETHTRKLNK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Before configuring an IPSECBIND MO on an ETHPORT MO, ensure that the ETHPORT MO has not been added to an ETHTRK MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Before binding an IPSECPOLICY MO to an ETHTRK MO, ensure that an ETHTRKLNK MO is configured in the ETHTRK MO.
  • Relation with the ETHTRK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Before binding an IPSECPOLICY MO to an ETHTRK MO, ensure that the ETHTRK MO is configured.
  • Relation with the PORTSECURITY MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Before adding an IPSECBIND MO, ensure that SWITCH in the PORTSECURITY MO on the bound Ethernet port is set to ENABLE.
  • Relation with the HAGRP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In one logical protection group, SN in an HAGRP MO must be the same as that in an IPSECBIND MO.
  • Relation with the IPSECBIND MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]One IPSECPOLICY MO can be bound to only one port.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Only one or less IPSECBIND MO can be configured on a port with CTRLMODE set to MANUAL_MODE.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Only one or less IPSECBIND MO can be configured on a port with CTRLMODE set to AUTO_MODE.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]A maximum of six IPSECBIND MOs can be automatically created in a base station.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]A maximum of six IPSECBIND MOs can be manually created in a base station.
  • Relation with the IKEPEER and IPSECPOLICY MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When the REDUNDANCYFLAG parameter in the IKEPEER MO referenced by the IPSECPOLICY MO is set to SLAVE and the slave and master IKEPEER MOs are configured in different IPSECPOLICY MOs, the IPSECPOLICY MO of the slave IKEPEER MO can be added to this board when the following conditions are met:
    • The IPSECPOLICY MO of the master IKEPEER MO to which this slave IKEPEER MO corresponds must have been added to a board.
    • The IPSECBIND MOs of the master and slave IKEPEER MOs must be configured in the same cabinet, subrack, and slot.
    • [Co-MPT, NodeB, eNodeB, gNodeB]The IPVERSION in the IKEPEER MO referred by the IPSECBIND MO can be only set to IPV4.
  • Relation with the ACLRULE and IPSECPOLICY MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The maximum of ACLRULE MOs with ACTION set to PERMIT which are referenced by IPSECBIND on a transmission board is 264.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The maximum of ACLRULE MOs with ACTION set to PERMIT which are referenced by IPSECBIND on a main control board is 512.
  • Relation with the BBP and CASCADEPORT MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]On a UBBP or LCOP board, if in the CASCADEPORT MO, the PN parameter is set to 6 and the PM parameter is set to SCPRI/SRIO or AUTO, this board cannot be configured with the IPSECBIND MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]On a UBBP or LCOP board, if the CASCADEPORT MO in which the PN parameter is set to 6 does not exist, this board cannot be configured with the IPSECBIND MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]On a UBBP or LCOP board, if in the CASCADEPORT MO, the PN parameter is set to 6 and the PM parameter is set to 1*40GE, and PT in the IPSECBIND MO for this board is set to ETH, PN can only be set to 0 in the IPSECBIND MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]On a UBBP or LCOP board, if in the CASCADEPORT MO, the PN parameter is set to 6 and the PM parameter is set to 4*10GE, and PT in the IPSECBIND MO for this board is set to ETH, PN can only be set to 0, 1, 2, or 3 in the IPSECBIND MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]On a UBBP board, if in the CASCADEPORT MO, the PN parameter is set to 6 and the PM parameter is set to 1*100GE, and PT in the IPSECBIND MO for this board is set to ETH, PN can only be set to 0 in the IPSECBIND MO.
  • Relation with the GTRANSPARA MO:
    • [Co-MPT, NodeB, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to NEW, the IPSECBIND MO cannot be configured.
  • Relation with the ETHCIPORT MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]Before binding an IPSECPOLICY MO to an ETHCIPORT MO, ensure that the ETHCIPORT MO is configured.
  • Relation with the MDU MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If TYPE in an MDU MO is set to MDUC, the IPSECBIND MO must meet the following conditions: Cabinet No., Subrack No., and Slot No. are set to the same values as those in the MDU MO; SBT is set to BASE_BOARD; PT is set to ETH; PN is set to a value within the range 0 to 2.
  • Relation with the MPT, ACLRULE, and IPSECPOLICY MOs:
    • [Co-MPT, eNodeB, gNodeB]When an MPT MO with TYPE set to LMPT exists, and an MPT MO with TYPE set to UMPT does not exist, the maximum of ACLRULE MOs with ACTION set to PERMIT which are referenced by IPSECBIND on one board is 128.
  • Relation with the HAGRP, MPT, ACLRULE, and IPSECPOLICY MOs:
    • [Co-MPT, eNodeB, gNodeB]When an MPT MO with TYPE set to LMPT exists and the LMPT board is not in an HAGRP MO, the maximum of ACLRULE MO with ACTION set to PERMIT which are referenced by IPSECBIND MO on the LMPT board is 128.
  • Relation with the ACLRULE, IPSECPOLICY, GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]When the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured, the maximum of ACLRULE MOs with ACTION set to PERMIT which are referenced by IPSECBIND on one board is 128.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD IPSECBIND

Use this command to bind an IPSec policy group to a port. IPSec tunnels are negotiated to protect the data streams flowed through a port only after an IPSec policy group is bound to the port.
DSP IKEMSGSTAT

Use this command to query statistics on Internet Key Exchange (IKE) messages.
DSP IKESA

Use this command to query the status of the IKE Security Association (SA).
DSP IKESTAT

Use this command to query basic information about an Internet Key Exchange (IKE) Security Association (SA).
DSP IKEV1EXCHSTAT

Use this command to query status information about an Internet Key Exchange version 1 (IKEv1) exchange.
DSP IKEV2EXCHSTAT

Use this command to query status information about an Internet Key Exchange version 2 (IKEv2) exchange.
DSP IPSECSA

Use this command to query the status of the IPSec SA.
DSP IPSECSADELSTAT

Use this command to query statistics on an IP Security (IPSec) SA.
LST IPSECBIND

Use this command to list the binding relation between the IPSECBIND MO and the port.
RMV IPSECBIND

Use this command to remove the binding of an IPSec policy group to a port. The execution of this command terminates the protection mechanism applied to the data streams flowed through the port.
