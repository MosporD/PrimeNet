BFD

TRANSPORT
  +-BFD

Description

A BFD MO consists of the parameters related to a Bidirectional Forwarding Detection (BFD). BFDs are used to quickly identify faults on a channel.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the BFD MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If two BFD MOs are in the same routing domain, DSTIP in one BFD MO must be different from SRCIP or DSTIP in the other BFD MO.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]MYDISCREAMINATOR in one BFD MO must be different from MYDISCREAMINATOR in the other BFD MO.
  • Relation with the IPADDR4 MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If a BFD MO and an IPADDR4 MO are in the same routing domain, DSTIP in the BFD MO must be different from IP in the IPADDR4 MO.
    • [gNodeB]SRCIP in a BFD MO to be added must have been configured, SRCIP in the BFD MO must be the same as IP in the IPADDR4 MO in the same routing domain.
  • Relation with the LOCALIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If a BFD MO and a LOCALIP MO are in the same routing domain, DSTIP in the BFD MO must be different from IP in the LOCALIP MO.
  • Relation with the OMCH MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If a BFD MO and an OMCH MO are in the same routing domain, DSTIP in the BFD MO must be different from IP in the OMCH MO.
  • Relation with the IPSECDTNL and IPSECPOLICY MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the default routing domain, in an IPSECDTNL MO, SRCIP in the BFD MOs for the active and standby tunnels must be the same as LOCALIP in the IKEPEER MOs of the active and standby IPSECPOLICY MOs, respectively; DSTIP in the BFD MOs for the active and standby tunnels must be the same as REMOTEIP in the IKEPEER MOs of the active and standby IPSECPOLICY MOs, respectively.
  • Relation with the IPSECDTNL MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Before adding an IPSECDTNL MO, ensure that the BFD MOs for the active and standby tunnels of the IPSECDTNL MO have been configured. That is, in the same routing domain the BFD MOs whose BFDSN is the same as MBFDSN and SBFDSN in the IPSECDTNL MO, respectively must have been configured.
  • Relation with the BFDKEYCHAIN MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When BFDAUTHSW in the BFD MO is set to ON, the BFDKEYCHAIN MO instance used by a BFD MO must have been configured.
  • Relation with the BFDKEY MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When BFDAUTHSW in the BFD MO is set to ON, the BFDKEY MO instance used by a BFD MO must have been configured.
  • Relation with the IPADDR4, MPGRP, PPPLNK, and GTRANSPARA MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB]SRCIP in a BFD MO to be added must have been configured, SRCIP in the BFD MO must be the same as any of the following: LOCALIP in the PPPLNK MO in the same routing domain, or LOCALIP in the MPGRP MO, or IP in the IPADDR4 MO.
  • Relation with the PPPLNK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If a BFD MO and a PPPLNK MO are in the same routing domain, DSTIP in the BFD MO must be different from LOCALIP in the PPPLNK MO.
  • Relation with the MPGRP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If a BFD MO and an MPGRP MO are in the same routing domain, DSTIP in the BFD MO must be different from LOCALIP in the MPGRP MO.
  • Relation with the WLOCALIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]IP in the WLOCALIP MO must be different from DSTIP in the BFD MO in the default routing domain.
  • Relation with the GTRANSPARA MO:
    • [Co-MPT, eNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to OLD, the BFD MO cannot be configured.
  • Relation with the GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]The number of BFD MOs must be less than or equal to 16 when the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD BFD

Use this command to add a Bidirectional Forwarding Detection (BFD). BFD, a protocol for fast link fault detection, provides a low-overhead and short-duration method of detecting link failures.
DSP BFD

Use this command to query the status of a BFD.
LST BFD

Use this command to list the configuration of a BFD.
MOD BFD

Use this command to modify the configuration of a BFD.
RMV BFD

Use this command to remove a BFD.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Session ID

Indicates the ID of a BFD.
VRF Index

Indicates the index of a VRF instance. UMTS currently supports the default routing domain only (the VRF index is 0).
Source IP

Indicates the source IP address of a BFD. The source IP address of a BFD must be a device IP address of a specified board (for example, the IP address of an Ethernet port or a port that carries a PPP link or MP group) or a logical IP address (for example, the IP address of a loopback port), but cannot be set to the same value as the IP address of a remote maintenance channel or a negotiated IP address. Note that a BFD cannot be configured as a single-hope session if its source IP address is a logical IP address.
Destination IP

Indicates the destination IP address of a BFD. The destination IP address must be a valid IP address, and cannot be set to 0.0.0.0 or any existing IP addresses in the system. If Virtual Router Redundancy Protocol (VRRP) is used in the network, two BFDs must be configured with the destination IP addresses set to the active and standby physical IP addresses of the virtual router, respectively.
My Discriminator

Indicates the local discriminator of a BFD session. The local discriminator must be the same as the peer discriminator.
Hop Type

Indicates the hop type of a BFD. The single-hop BFD is used to perform point-to-point detection at the data link layer, and often used in layer 2 networking scenarios. The multi-hop BFD is used to perform end-to-end connectivity checks at the transport layer, and often used in layer 3 networking scenarios.
Min TX Interval

Indicates the minimum interval at which a BFD transmits control packets.
Min RX Interval

Indicates the minimum interval at which a BFD receives control packets.
Detection Multiplier

Indicates the detection multiplier of a BFD.
Session Catalog

Indicates the type of a BFD. If this parameter is set to MAINTENANCE, this BFD is used only for continuity check (CC). If this parameter is set to RELIABILITY, the BFD is used to trigger route interlock. Route interlock enables the standby route to take over once the active route becomes faulty, and therefore prevents service interruption caused by route failures.
DSCP

Indicates the Differentiated Services Code Point (DSCP). The priority has a positive correlation with the value of this parameter.
Protocol Version

Indicates the protocol version of a BFD session.
BFD Authentication Switch

Indicates whether a BFD supports BFD authentication. You are advised to enable the BFD Authentication Switch.
BFD Authentication Algorithm

Indicates the algorithm used during BFD authentication.
BFD Authentication Key Chain ID

Indicates the ID of a configured BFD key chain.
