IKECFG

TRANSPORT
  +-IKECFG

Description

The IKECFG MO is used to define basic IKE configuration such as the IKE local name and IKE keepalive duration.

Effective Scenario

Not involved

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the PACKETFILTERING and INTERFACE MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If IPSECBINDMODE in the IKECFG MO is set to ALL, the ITFTYPE of the INTERFACE MO associated with a PACKETFILTERING MO which ACLTYPE is set to IPV4 must be set to NORMAL.
  • Relation with the PACKETFILTERING MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When IPSECBINDMODE in an IKECFG MO is set to ALL, PT in a PACKETFILTERING MO is set to INTERFACE, and ACLTYPE is set to IPV4, and PORTID in the PACKETFILTERING MO is set to the same value as ITFID in an INTERFACE MO, ITFTYPE in the INTERFACE MO must be set to NORMAL.
  • Relation with the SECURITYHOST, IPADDR4, INTERFACE, and GTRANSPARA MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When IPSECBINDMODE in an IKECFG MO is set to ALL, at least one INTERFACE MO with ITFTYPE set to NORMAL and VRFIDX set to 0 must exist on the physical port, on which an INTERFACE MO corresponding to the IPADDR4 MO referenced by the SECURITYHOST MO is located.
  • Relation with the GTRANSPARA MO:
    • [Co-MPT, NodeB, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to OLD, the IPSECBINDMODE in the IKECFG MO must be set to SINGLE.
  • Relation with the GTRANSPARA and IPSECDTNL MOs:
    • [Co-MPT, NodeB, eNodeB, gNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to NEW and IPSECBINDMODE in the IKECFG MO is set to ALL, the IPSECDTNL MO cannot be configured.
  • Relation with the IPSECBINDITF and INTERFACE MOs:
    • [Co-MPT, NodeB, eNodeB, gNodeB]If IPSECBINDMODE in the IKECFG MO is set to ALL, the ITFTYPE of the INTERFACE MO associated with an IPSECBINDITF MO with parameter CTRLMODE set to MANUAL_MODE must be set to NORMAL.
  • Relation with the MPT, IPSECBINDITF, and INTERFACE MOs:
    • [Co-MPT, eNodeB]When TYPE in the MPT MO is set to LMPT and IPSECBINDMODE in the IKECFG MO is set to ALL, a maximum of four INTERFACE MOs with ITFTYPE set to VLAN can be configured on the physical ports corresponding to the INTERFACE MOs with ITFTYPE set to NORMAL, to which all the IPSECBINDITF MOs on the same board are bound.
    • [Co-MPT, eNodeB]When TYPE in the MPT MO is set to LMPT and IPSECBINDMODE in the IKECFG MO is set to SINGLE, a maximum of four IPSECBINDITF MOs that are carried on the INTERFACE MOs with ITFTYPE set to VLAN can be configured on the same board.

Parameter

Description
Local Name

Indicates the IKE local name.
Interval for Sending Keepalive Packets

Indicates the interval for sending keepalive packets. When this parameter is set to 0, keepalive packets are not sent. When this parameter is not set to 0, check the timer for waiting for keepalive packets on the peer end. It is recommended that the timer length be greater than or equal to a value three times of this parameter value.

Indicates the timeout duration for waiting for the keepalive packets. If this parameter is set to 0, keepalive packets are not sent.

Indicates the interval for sending network address translation (NAT) keepalive packets. This parameter is valid only when the NAT traversal function of IPsec is enabled.
DSCP

Indicates the DSCP for IKE negotiation packets.
IPSec Redundancy Switch Back

Indicates whether to allow a switchback to the master IKE peer after its negotiation recovers when the IPSec redundancy function is enabled.

If this parameter is set to OFF, the base station automatically stops the negotiation with the master IKE peer (IPv4 or IPv6) when the negotiation with the master IKE peer fails and the negotiation with a slave IKE peer succeeds. In this case, the IKE negotiation failure alarm for the master IKE peer is not cleared. If the negotiation with a slave IKE peer succeeds previously but fails now, and if the negotiation with the slave IKE peer with the lowest priority still fails, the negotiation with the master IKE peer is started immediately even if this parameter is set to OFF. After the negotiation with the master IKE peer succeeds, the system immediately switches back to the master IKE peer and clears the IKE negotiation failure alarm for the master IKE peer.

If this parameter is set to ON, the negotiation with the master IKE peer (IPv4 or IPv6) does not stop when the negotiation with the master IKE peer fails and services are switched to a slave IKE peer. In this case, the IKE negotiation failure alarm for the master IKE peer is cleared only when the negotiation with the master IKE peer succeeds. If the negotiation with the master IKE peer succeeds but the negotiation with a slave IKE peer fails, the system immediately switches services back to the master IKE peer. If the negotiation with a slave IKE peer succeeds, the system switches back to the master IKE peer after the specific timer expires. (The timer length is the sum of the IPSec switchback wait time and the random IPSec switchback delay.) If you run the SET IKECFG command to forbid the switchback when the master and slave IKE peers are being switched (in the switchback wait period), the system immediately stops the negotiation of the primary channel.

If this parameter is set to IPV4_ON+IPV6_OFF, the IPv4 switchback is enabled but the IPv6 switchback is disabled. This option is valid only for the UMPT/UMDU board that supports IPv6.

If this parameter is set to IPV4_OFF+IPV6_ON, the IPv4 switchback is disabled but the IPv6 switchback is enabled. This option is valid only for the UMPT/UMDU board that supports IPv6.
IPSec Redundancy Switch Back Wait Time

Indicates the duration before a switchover from the slave IKE peer to the master IKE peer in the IPSec redundancy function. If the master IKE peer that has been switched over to the slave IKE peer due to failed negotiation succeeds in the negotiation again, the duration from the negotiation success to the back switchover equals the duration specified by this parameter plus a random delay generated with the IPSec Redundancy Switch Back Random Delay Time parameter specified. If the SET IKECFG command is executed to modify the value of this parameter during a back switchover, the modified value does not take effect until the next back switchover.
IPSec Redundancy Switch Back Random Delay Time

Indicates the random delay before a switchover from the slave IKE peer to the master IKE peer in the IPSec redundancy function. When this parameter is set to N, a random delay that ranges from 0 to N is added to the duration before a back switchover. When this parameter is set to 0, no random delay is added to the duration before a back switchover. If the master IKE peer that has been switched over to the slave IKE peer due to failed negotiation succeeds in the negotiation again, the duration from the negotiation success to the back switchover equals the duration specified by the IPSec Redundancy Switch Back Wait Time parameter plus a random delay generated with this parameter specified. If the SET IKECFG command is executed to modify the value of this parameter during a back switchover, the modified value does not take effect until the next back switchover.
IPSec Redundancy Switchover Wait Time

Indicates the duration before a switchover from the master IKE peer to the slave IKE peer in the IPSec redundancy function. If a master IKE peer fails the negotiation, the slave IKE peer initiates negotiation after a period that equals the duration specified by this parameter plus a random delay generated with the IPSec Redundancy Switchover Random Delay Time parameter specified. If the SET IKECFG command is executed to modify the value of this parameter during the slave IKE peer negotiation, the modified value does not take effect until the next switchover.
IPSec Redundancy Switchover Random Delay Time

Indicates the random delay before a switchover from the masker IKE peer to the slave IKE peer in the IPSec redundancy function. If a master IKE peer fails the negotiation, the slave IKE peer initiates negotiation after a period that equals the duration specified by the IPSec Redundancy Switchover Wait Time parameter plus a random delay generated with this parameter specified. When this parameter is set to N, a random delay that ranges from 0 to N is added to the duration before the negotiation. When this parameter is set to 0, no random delay is added to the duration before the negotiation. If the SET IKECFG command is executed to modify the value of this parameter during the slave IKE peer negotiation, the modified value does not take effect until the next switchover.
IPSec Bind Mode

Indicates the binding mode of an IPsec policy group, which can be global mode and single-interface mode. The two modes are mutually exclusive. In global mode, an IPsec policy group and packet filtering policies can be bound only to a normal interface, and the IPsec and packet filtering policies take effect on the normal interface and all VLAN subinterfaces in the default routing domain of the physical port to which the normal interface belongs. In single-interface mode, the IPsec policies take effect only on the interface bound to the IPsec policy group and packet filtering policies take effect only on the interface bound to the packet filtering policies. This parameter is valid only for IPv4 IPsec and packet filtering policies.
