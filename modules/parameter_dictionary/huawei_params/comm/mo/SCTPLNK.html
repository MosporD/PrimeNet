SCTPLNK

TRANSPORT
  +-SCTPLNK

Description

An SCTPLNK MO consists of parameters related to a Stream Control Transmission Protocol (SCTP) link. The SCTP link is used to carry signaling.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the SCTPLNK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the same routing domain, each SCTPLNK MO must have a unique combination of LOCIP or SECLOCIP (SECLOCIP is not set to 0.0.0.0), PEERIP or SECPEERIP (SECPEERIP is not set to 0.0.0.0), LOCPORT, and PEERPORT.
    • [Co-MPT, eNodeB, gNodeB]In the same routing domain, each SCTPLNK MO must have a unique combination of LOCIP6 or SECLOCIP6, PEERIP6 or SECPEERIP6, LOCPORT, and PEERPORT. Neither SECLOCIP6 nor SECPEERIP6 can be set to 0::0.
    • [Co-MPT, eNodeB, gNodeB]On a BS, the total number of SCTPLNK MOs must be less than or equal to 1024.
    • [Co-MPT, eNodeB, gNodeB]In an SCTPLNK MO, LOCIP6 must be set to a globally scoped unicast address.
    • [NodeB]The SCTPLNK MO of IPv6 cannot been configured.
  • Relation with the OMCH MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the same routing domain, PEERIP in an OMCH MO must be different from LOCIP and SECLOCIP in an SCTPLNK MO.
  • Relation with the CPBEARER MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BEARTYPE in a CPBEARER MO is set to SCTP, an SCTPLNK MO whose SCTPNO is the same as LINKNO in the CPBEARER MO must have been configured.
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If BEARTYPE in the CPBEARER MO is set to SCTP, CTRLMODE must be set to the same value as CTRLMODE that is associated with the SCTPLNK MO.
  • Relation with the PPPLNK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]In the same routing domain, PEERIP in a PPPLNK MO must be different from LOCIP and SECLOCIP in an SCTPLNK MO.
  • Relation with the MPGRP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]In the same routing domain, PEERIP in an MPGRP MO must be different from LOCIP and SECLOCIP in an SCTPLNK MO.
  • Relation with the EPGROUP, SCTPHOST, and SCTPPEER MOs:
    • [Co-MPT, NodeB, eNodeB, gNodeB]The SCTP configurations of EndPoint conflict with the configurations of a manually configured SCTPLNK MO. The following two groups of four-tuple parameters must be different: One group of four-tuple parameters consists of the following parameters: SIGIP1V4 or SIGIP2V4 (when the value of SIGIP2V4 is not 0.0.0.0) in the SCTPHOST MO with IPVERSION set to IPv4 in the EPGROUP MO, PN, SIGIP1V4 or SIGIP2V4 (when the value of SIGIP2V4 is not 0.0.0.0) in the SCTPPEER MO with IPVERSION set to IPv4 in the EPGROUP MO, PN. The other group of four-tuple parameters consists of the following parameters: LOCIP or SECLOCIP (when the value of SECLOCIP is not 0.0.0.0) in the SCTPLNK MO whose CTRLMODE is set to MANUAL_MODE, PEERIP or SECPEERIP (when the value of SECPEERIP is not 0.0.0.0), LOCPORT, PEERPORT.
    • [Co-MPT, eNodeB, gNodeB]In the same routing domain, when SCTPHOST MO and SCTPPEER MO are configured in one EPGROUP MO simultaneously and their IP version are IPv6, the SIGIP1V6 or SIGIP2V6(SIGIP2V6 is not set to 0::0), PN of SCTPHOST MO and the SIGIP1V6 or SIGIP2V6(SIGIP2V6 is not set to 0::0), PN of SCTPPEER MO cannot conflict with the SCTPLNK MO's four-tuple parameters.
    • [Co-MPT, eNodeB, gNodeB]The SCTP configurations of EndPoint conflict with the configurations of a manually configured SCTPLNK MO. The following two groups of four-tuple parameters must be different: One group of four-tuple parameters consists of the following parameters: SIGIP1V6 or SIGIP2V6 (when the value of SIGIP2V6 is not 0::0) in the SCTPHOST MO with IPVERSION set to IPv6 in the EPGROUP MO, PN, SIGIP1V6 or SIGIP2V6 (when the value of SIGIP2V6 is not 0::0) in the SCTPPEER MO with IPVERSION set to IPv6 in the EPGROUP MO, PN. The other group of four-tuple parameters consists of the following parameters: LOCIP6 or SECLOCIP6 (when the value of SECLOCIP6 is not 0::0) in the SCTPLNK MO whose CTRLMODE is set to MANUAL_MODE, PEERIP6 or SECPEERIP6 (when the value of SECPEERIP6 is not 0::0), LOCPORT, PEERPORT.
  • Relation with the MDU MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]When TYPE in the MDU MO is set to MDUC, a maximum of 384 SCTPLNK MOs can be configured.
    • [Co-MPT, eGBTS, eNodeB]When TYPE in the MDU MO is set to MDUC, the SCTPLNK MO of IPv6 cannot be configured.
  • Relation with the PPPLNK, MPGRP, DEVIP, and GTRANSPARA MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB]When TRANSCFGMODE in the GTRANSPARA MO is set to OLD, before adding an SCTPLNK MO with CTRLMODE set to MANUAL_MODE, ensure that the MPGRP or PPPLNK MO that has the same VRF Index as the SCTPLNK MO has been configured. Alternatively, ensure that the DEVIP MO, MPGRP MO, or PPPLNK MO that meets both of the following conditions has been configured: (1) The DEVIP MO, MPGRP MO, or PPPLNK MO is in the same routing domain as the SCTPLNK MO. (2) LOCIP or SECLOCIP in the SCTPLNK MO is the same as IP in the DEVIP MO, LOCALIP in the MPGRP MO, or LOCALIP in the PPPLNK MO. The first and the second local IP addresses of an SCTP link must be configured on the same subrack, if the two IP addresses are not on the same board, the subboard type of the host IP addresses must be BASE_BOARD, and the bearing port type must be ETH, ETHTRK, or LOOPINT.
  • Relation with the PPPLNK, MPGRP, IPADDR4, and GTRANSPARA MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB]When TRANSCFGMODE in the GTRANSPARA MO is set to NEW and an SCTPLNK MO with CTRLMODE set to MANUAL_MODE is configured, either of the following is true: 1. There must be the following parameters that have the same values as LOCIP or SECLOCIP in the SCTPLNK MO and these IP addresses are in the same routing domain: IP in the IPADDR4 MO; LOCALIP in the MPGRP MO; LOCALIP in the PPPLNK MO. 2. There must be either the MPGRP MO with LOCALIP set to 0.0.0.0 or the PPPLNK MO with LOCALIP set to 0.0.0.0.
  • Relation with the IPADDR4, PPPLNK, MPGRP, INTERFACE, LOOPBACK, and GTRANSPARA MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB]When TRANSCFGMODE in the GTRANSPARA MO is set to NEW and CTRLMODE is set to MANUAL_MODE and SECLOCIP is valid in an SCTPLNK MO, the IPADDR4 MOs for LOCIP and SECLOCIP of this MO must be configured on the same subrack, if the two IP addresses are not on the same board, the subboard type of the host IP addresses must be BASE_BOARD, and the bearing port type must be ETH, ETHTRK, or LOOPINT.
  • Relation with the IPADDR6 MO:
    • [Co-MPT, eNodeB, gNodeB]LOCIP6 in an SCTPLNK MO with CTRLMODE set to MANUAL_MODE must be the same as IPV6 in an existing IPADDR6 MO in the same routing domain.
    • [Co-MPT, eNodeB, gNodeB]SECLOCIP6 in an SCTPLNK MO with CTRLMODE set to MANUAL_MODE must be 0:0:0:0:0:0:0:0 or IPV6 in an IPADDR6 MO in the same routing domain.
  • Relation with the TUNNELITF MO:
    • [Co-MPT, eNodeB, gNodeB]LOCALIP6 in a TUNNELITF MO with CTRLMODE set to MANUAL_MODE must be different from LOCIP6 and SECLOCIP6 in an SCTPLNK MO with IPVERSION set to IPv6 in the same routing domain.
  • Relation with the IPADDR6, INTERFACE, and LOOPBACK MOs:
    • [Co-MPT, eNodeB]When CTRLMODE is set to MANUAL_MODE and SECLOCIP6 is valid in an SCTPLNK MO, the IPADDR6 MOs for LOCIP6 and SECLOCIP6 of this MO must be configured on the same board.
  • Relation with the GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]The number of SCTPLNK MOs must be less than or equal to 4 when the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured.
  • Relation with the NODE MO:
    • [Co-MPT]An SCTPLNK MO cannot be configured on a PRODUCTTYPE MO with PRODUCTTYPE set to DBS3900 DCU or DBS5900 DCU.
  • Relation with the DEVIP and GTRANSPARA MOs:
    • [gNodeB]When TRANSCFGMODE in a GTRANSPARA MO is set to OLD, before adding an SCTPLNK MO with CTRLMODE set to MANUAL_MODE, ensure that the DEVIP MO that meets both of the following conditions has been configured: (1) The DEVIP MO is in the same routing domain as the SCTPLNK MO. (2) LOCIP or SECLOCIP in the SCTPLNK MO is the same as IP in the DEVIP MO.
  • Relation with the IPADDR4 and GTRANSPARA MOs:
    • [gNodeB]When TRANSCFGMODE in a GTRANSPARA MO is set to NEW, before adding an SCTPLNK MO with CTRLMODE set to MANUAL_MODE, ensure that the IPADDR4 MO that meets both of the following conditions has been configured: (1) The IPADDR4 MO is in the same routing domain as the SCTPLNK MO. (2) LOCIP or SECLOCIP in the SCTPLNK MO is the same as IP in the IPADDR4 MO.

Description
Link No.

Indicates the number of the SCTP link. The value of SCTPNO in the SCTPLNK MOs configured by users ranges from 0 to 65535. The value of SCTPNO in the SCTPLNK MOs configured by the system ranges from 70000 to 79999.

Subrack No.

Indicates the subrack number of the SCTP link.
Slot No.

Indicates the slot number of the SCTP link.

Indicates the maximum stream number of the SCTP link.
Control Mode

Indicates whether an object can be modified or deleted by the system. The value MANUAL_MODE means that only the user can modify or delete the object. The value AUTO_MODE means only the system can modify or delete the object. The NR does not support MANUAL_MODE.
First Local IP Address

Indicates the first local IP address of the SCTP link.
Second Local IP Address

Indicates the second local IP address of the SCTP link.
Local SCTP Port No.

Indicates the local port number of the SCTP link.
First Peer IP Address

Indicates the first peer IP address of the SCTP link.
Second Peer IP Address

Indicates the second peer IP address of the SCTP link.
Peer SCTP Port No.

Indicates the peer port number of the SCTP link.
RTO Min Value

Indicates the minimum RTO value for an SCTP link. A smaller value of this parameter indicates a shorter period required for checking link connectivity. The new RTO ranges from the minimum RTO value to the maximum RTO value.
RTO Max Value

Indicates the maximum RTO value of an SCTP link. A larger value indicates a longer period required for checking link connectivity.
RTO Initial Value

Indicates the initial RTO value of an SCTP link. A larger value indicates a longer period required for checking link connectivity.
RTO Alpha Value

Indicates the RTO alpha value of an SCTP link. A larger value indicates less sensitivity to the link delay.
RTO Beta Value

Indicates the RTO beta value of an SCTP link. A larger value indicates more sensitivity to the link delay.
Heart-beat Interval

Indicates the heartbeat interval for an SCTP link. The heartbeat check is independently initiated by each end of an association and then confirmed by the peer end through the HB ACK packet. When no services are carried, a link disconnection is determined if the number of heartbeat check attempts reaches the maximum retransmission attempts on an association but the HB ACK packet is not received from the peer end.
Max Association Retransmission

Indicates the maximum number of retransmissions for the SCTP association. When the number of retransmissions for the association exceeds the value of this parameter, the SCTP link is disconnected and a link failure alarm is reported.
Max Path Retransmission

Indicates the maximum number of retransmissions over a path. When the number of retransmissions over a path exceeds the value of this parameter, the path is regarded as failed if no heartbeat acknowledgment is received. If multiple paths are used, path switching is automatically performed.
Checksum Algorithm Type

Indicates the type of checksum algorithm. The checksum algorithms at both ends of an SCTP link must be the same.
Switch Back Flag

Indicates whether the SCTP link switches back to the primary path when it is restored and reachable. If the primary path is not reachable, the SCTP link switches to the secondary path. When this parameter is set to ENABLE, the SCTP link switches to the primary path if the primary path is restored and reachable. When this parameter is set to DISABLE and the primary path is restored and reachable, the SCTP link does not switch back to the primary path if the secondary path is also reachable, and the SCTP link switches back to the primary path if the secondary path is unreachable.
Heart-beat Times When Switch Back

Indicates the number of heartbeats to be detected before the transmission switches back to the primary path. After the primary path is restored, the transmission switches back to the primary path when the number of heartbeats detected reaches this value.
Block Flag

Indicates whether the SCTP link is blocked or not.
SACK Timeout

Indicates the time interval that one end of an SCTP link has to wait before it can send an SACK message in response to the reception of data. A larger value of this parameter indicates a longer time interval between the reception of data and the sending of the corresponding SACK message.
Description Info

Indicates the peer description information of the SCTP link.
Auto Config Flag

Indicates whether the object is created by the system. MANUAL_CREATED means that the object is configured by the user manually. AUTO_CREATED means that the object is created by the system. The NR does not support MANUAL_CREATED.
VRF Index

Indicates the index of a VRF instance. UMTS currently supports the default routing domain only (the VRF index is 0).
IP Version

Indicates the IP protocol version.
First Local IPv6 Address

Indicates the first local IPv6 address of an IPv6 SCTP link.
Second Local IPv6 Address

Indicates the second local IPv6 address of an IPv6 SCTP link.
First Peer IPv6 Address

Indicates the first peer IPv6 address of an IPv6 SCTP link.
Second Peer IPv6 Address

Indicates the second peer IPv6 address of an IPv6 SCTP link.
Maximum SCTP PDU Size

Indicates the maximum size of an IPv4 SCTP PDU (Protocol Data Unit). It specifies the maximum length of an SCTP PDU (excluding the IP header) transmitted on an SCTP link. If the value of this parameter is greater than the size of the IP layer MTU of the base station or intermediate transmission equipment, SCTP packets are fragmented at the IP layer. This causes a large number of fragments and affects the transmission efficiency of the intermediate transmission equipment.
DTLS Policy ID

Indicates the sequence number of a DTLS configuration policy. The parameter takes effect only in NR.
DTLS Connection Policy

Indicates the DTLS connection policy. DTLS_ONLY indicates that the local end uses only DTLS connections. If the peer end does not support or is not configured with DTLS, the negotiation fails. DTLS_PRIORITY indicates that the local end attempts to establish a DTLS connection for the first time. If the peer end does not support or is not configured with DTLS, the local end uses the SCTP connection. If this parameter is set to DTLS_PRIORITY, the security is reduced. Therefore, you are advised not to set this parameter to DTLS_PRIORITY. This parameter applies only to NR.
SCTP Authentication Chunk List

Indicates the list of SCTP chunk types for which the local end requires the peer end to support authentication. The IDs of SCTP chunks that can be authenticated by the base station are 0, and 3 to 9. For details, see RFC4895 and RFC4960. Currently, SCTP block authentication is supported only in DTLS over SCTP scenarios. This parameter applies only to NR.
