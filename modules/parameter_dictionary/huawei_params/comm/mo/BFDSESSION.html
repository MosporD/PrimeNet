BFDSESSION

TRANSPORT
  +-BFDSESSION

Description

A BFDSESSION MO consists of the parameters related to a Bidirectional Forwarding Detection (BFD) session. BFD sessions are used to quickly identify faults on a channel.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    TRANSPORT
  • Relation with the BFDSESSION MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If two BFDSESSION MOs are in the same routing domain, DSTIP in one BFDSESSION MO must be different from SRCIP or DSTIP in the other BFDSESSION MO.
  • Relation with the IFIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If a BFDSESSION MO and an IFIP MO are in the same routing domain, DSTIP in the BFDSESSION MO must be different from IP in the IFIP MO.
  • Relation with the DEVIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If a BFDSESSION MO and a DEVIP MO are in the same routing domain, DSTIP in the BFDSESSION MO must be different from IP in the DEVIP MO.
  • Relation with the LOCALIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If a BFDSESSION MO and a LOCALIP MO are in the same routing domain, DSTIP in the BFDSESSION MO must be different from IP in the LOCALIP MO.
  • Relation with the OMCH MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]If a BFDSESSION MO and an OMCH MO are in the same routing domain, DSTIP in the BFDSESSION MO must be different from IP in the OMCH MO.
  • Relation with the IPSECDTNL and IPSECPOLICY MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In an IPSECDTNL MO, SRCIP in the BFDSESSION MOs for the active and standby tunnels must be the same as LOCALIP in the IKEPEER MOs of the active and standby IPSECPOLICY MOs, respectively; DSTIP in the BFDSESSION MOs for the active and standby tunnels must be the same as REMOTEIP in the IKEPEER MOs of the active and standby IPSECPOLICY MOs, respectively.
  • Relation with the IPSECDTNL MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]Before adding an IPSECDTNL MO, ensure that the BFDSESSION MOs for the active and standby tunnels of the IPSECDTNL MO have been configured. That is, in the same routing domain the BFDSESSION MOs whose BFDSN is the same as MBFDSN and SBFDSN in the IPSECDTNL MO, respectively must have been configured.
  • Relation with the BFDKEYCHAIN MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When BFDAUTHSW in the BFDSESSION MO is set to ON, the BFDKEYCHAIN MO instance used by a BFDSESSION MO must have been configured.
  • Relation with the BFDKEY MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When BFDAUTHSW in the BFDSESSION MO is set to ON, the BFDKEY MO instance used by a BFDSESSION MO must have been configured.
  • Relation with the DEVIP, MPGRP, PPPLNK, IFIP, and GTRANSPARA MOs:
    • [Co-MPT, NodeB, eGBTS, eNodeB]SRCIP in a BFDSESSION MO to be added must have been configured. That is: (1) If MODELSELECT of GTRANSPARA is set to TRADITION, for the BFDSESSION MO, DEVIP MO, PPPLNK MO, and MPGRP MO configured on the same board, SRCIP in the BFDSESSION MO must be the same as any of the following: IP in the IFIP MO in the same routing domain, LOCALIP in the PPPLNK MO, and LOCALIP in the MPGRP MO. (2) If MODELSELECT of GTRANSPARA is set to HOSTGW, for the BFDSESSION MO, IFIP MO, PPPLNK MO, and MPGRP MO configured on the same board, SRCIP in the BFDSESSION MO must be the same as any of the following: IP in the IFIP MO in the same routing domain, LOCALIP in the PPPLNK MO, and LOCALIP in the MPGRP MO.
  • Relation with the PPPLNK MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If a BFDSESSION MO and a PPPLNK MO are in the same routing domain, DSTIP in the BFDSESSION MO must be different from LOCALIP in the PPPLNK MO.
  • Relation with the MPGRP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]If a BFDSESSION MO and an MPGRP MO are in the same routing domain, DSTIP in the BFDSESSION MO must be different from LOCALIP in the MPGRP MO.
  • Relation with the WLOCALIP MO:
    • [Co-MPT, NodeB, eGBTS, eNodeB]IP in the WLOCALIP MO must be different from DSTIP in the BFDSESSION MO in the default routing domain.
  • Relation with the GTRANSPARA MO:
    • [Co-MPT, eNodeB]If TRANSCFGMODE in the GTRANSPARA MO is set to NEW, the BFDSESSION MO cannot be configured.
  • Relation with the GTMU, MPT, and APPLICATION MOs:
    • [Co-MPT, eGBTS]The number of BFDSESSION MOs must be less than or equal to 16 when the Application MO with AT set to GBTS and the GTMU MO with TYPE set to GTMU are configured but the MPT MO with TYPE set to UMPT is not configured.
  • Relation with the DEVIP, IFIP, and GTRANSPARA MOs:
    • [gNodeB]SRCIP in a BFDSESSION MO to be added must have been configured. That is: (1) If MODELSELECT of GTRANSPARA is set to TRADITION, for the BFDSESSION MO and DEVIP MO configured on the same board, SRCIP in the BFDSESSION MO must be the same as any of the following: IP in the IFIP MO in the same routing domain. (2) If MODELSELECT of GTRANSPARA is set to HOSTGW, for the BFDSESSION MO and IFIP MO configured on the same board, SRCIP in the BFDSESSION MO must be the same as any of the following: IP in the IFIP MO in the same routing domain.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD BFDSESSION

Use this command to add a Bidirectional Forwarding Detection (BFD) session. BFD, a protocol for fast link fault detection, provides a low-overhead and short-duration method of detecting link failures.
DSP BFDSESSION

Use this command to query the status of a BFD session.
LST BFDSESSION

Use this command to list the configuration of a BFD session.
MOD BFDSESSION

Use this command to modify the configuration of a BFD session.
RMV BFDSESSION

Use this command to remove a BFD session.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Cabinet No.

Indicates the cabinet No. to which a BFD session belongs.
Subrack No.

Indicates the subrack No. to which a BFD session belongs.
Slot No.

Indicates the slot No. to which a BFD session belongs.
Session ID

Indicates the ID of a BFD session. The session ID plus 1 is the local discriminator of the BFD session. The local discriminator must be consistent with the configuration at the peer end.
VRF Index

Indicates the index of a VRF instance. UMTS currently supports the default routing domain only (the VRF index is 0).
Source IP

Indicates the source IP address of a BFD session. The source IP address of a BFD session must be a device IP address of a specified board (for example, the IP address of an Ethernet port or a port that carries a PPP link or MP group) or a logical IP address (for example, the IP address of a loopback port), but cannot be set to the same value as the IP address of a remote maintenance channel or a negotiated IP address. Note that a BFD session cannot be configured as a single-hope session if its source IP address is a logical IP address.
Destination IP

Indicates the destination IP address of a BFD session. The destination IP address must be a valid IP address, and cannot be set to 0.0.0.0 or any existing IP addresses in the system. If Virtual Router Redundancy Protocol (VRRP) is used in the network, two BFD sessions must be configured with the destination IP addresses set to the active and standby physical IP addresses of the virtual router, respectively.
Hop Type

Indicates the hop type of a BFD session. The single-hop BFD session is used to perform point-to-point detection at the data link layer, and often used in layer 2 networking scenarios. The multi-hop BFD session is used to perform end-to-end connectivity checks at the transport layer, and often used in layer 3 networking scenarios.
Min TX Interval

Indicates the minimum interval at which a BFD session transmits control packets.
Min RX Interval

Indicates the minimum interval at which a BFD session receives control packets.
Detection Multiplier

Indicates the detection multiplier of a BFD session.
Session Catalog

Indicates the type of a BFD session. If this parameter is set to MAINTENANCE, this BFD session is used only for continuity check (CC). If this parameter is set to RELIABILITY, the BFD session is used to trigger route interlock. Route interlock enables the standby route to take over once the active route becomes faulty, and therefore prevents service interruption caused by route failures.
DSCP

Indicates the Differentiated Services Code Point (DSCP). The priority has a positive correlation with the value of this parameter.
Protocol Version

Indicates the protocol version of a BFD session.
BFD Authentication Switch

Indicates whether a BFD session supports BFD authentication. You are advised to enable the BFD Authentication Switch.
BFD Authentication Algorithm

Indicates the algorithm used during BFD authentication.
BFD Authentication Key Chain ID

Indicates the ID of a configured BFD key chain.
