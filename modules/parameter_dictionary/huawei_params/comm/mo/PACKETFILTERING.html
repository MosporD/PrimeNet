PACKETFILTERING

TRANSPORT
  +-PACKETFILTERING

Description

The PACKETFILTERING MO indicates the filtering of IP packets. The system first obtains the header information about the packets received by NEs, compares the information with the preset ACL rules, and then forwards or discards the packets according to the comparison results. The header information involves the numbers of protocols carried at the IP layer, source addresses and destination addresses of the packets, and source ports and destination ports of the packets.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD PACKETFILTERING

Use this command to add a packet filtering policy object. A packet filtering policy object binds an ACL to a physical port so that IP packets that are received on the physical port can be filtered by the ACL.
DSP PACKETFILTERING

Use this command to query the statistics of the packets that are matched with the ACL rules after the packet filtering policy is bound to the Ethernet port.
LST PACKETFILTERING

Use this command to list the configurations of all packet filtering policy objects.
MOD PACKETFILTERING

Use this command to modify the settings of packet filtering policy.
RMV PACKETFILTERING

Use this command to remove a packet filtering policy object.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Packet Filtering ID

Indicates the ID of the packet filtering policy.
Filter Mode

Indicates the packet filtering policy mode. The NE can filter packets based on the advanced ACL or layer-2 ACL.
ACL Type

Indicates the type of the ID of the access control list.
Port Type

Indicates the port type on which the packet filtering policy depends.
Port ID

Indicates the port ID or interface ID. When Port Type is set to Interface, this parameter indicates the interface ID. When Port Type is set to other values, this parameter indicates the port ID. When Port Type is set to Interface, the following are true: if IPsec Policy Group Binding Mode in the IKECFG MO is set to ALL, packet filtering policies can be bound only to a normal interface and take effect on the normal interface and all VLAN subinterfaces in the default routing domain of the physical port to which the normal interface belongs; if IPsec Policy Group Binding Mode in the IKECFG MO is set to SINGLE, packet filtering policies take effect only on the interface bound to the IPsec policies.
ACL ID

Indicates the ID of an ACL. The value of this parameter ranges from 3000 to 4999. A value in the range of 3000 to 3999 indicates that the ACL rules in this ACL are advanced ACL rules. A value in the range of 4000 to 4999 indicates that the ACL rules in this ACL are layer 2 ACL rules.
Match Behavior

Indicates whether to permit or reject access of the data that does not match the ACL rule. If this parameter is set to PERMIT, data that does not match the ACL rule is allowed to pass. If this parameter is set to DENY, data that does not match the ACL rule is discarded.
ACL Rule Automatic Setup and Deletion Switch

Indicates whether to enable automatic setup of advanced ACL rules for packet filtering policy. When this switch is turned on, the system creates advanced ACL rules that match the following items in the ACL group referenced by the packet filtering policy object: OM data flows, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, and PKI data flows. When the MOD PACKETFILTERING command is executed to change the value of this parameter from ON to OFF, the system will automatically delete the automatically created advanced ACL rules in the ACL group referenced by the packet filtering policy object.
OMCH Peer IP Limit Switch

Indicates whether the peer IP address is limited by the ACL rules that have been automatically generated for the OM channel when the ACL rule automatic setup and deletion function is enabled. When this parameter is set to ON(ON), the peer IP address must be the IP address of the MAE. In this case, if any one of the NetEco, TraceServer, and NIC is independently deployed, the ACL rules must be manually configured before the preceding device can access the base station.
