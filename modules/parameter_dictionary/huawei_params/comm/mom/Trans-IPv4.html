IPv4 MOM Description

This section describes the functions and concepts of IPv4. It also provides the managed object model (MOM) views and describes the managed objects (MOs) related to IPv4.

Functions and Concepts

Figure 1 shows the generic protocol stack for IPv4 transmission on a base station. Transport protocol layers are divided into the control plane and user plane for processing signaling and user data, respectively. The control plane uses Stream Control Transmission Protocol (SCTP) links, and the user plane uses Internet Protocol (IP) paths.

The fundamental protocol part, control plane, and user plane provide the transport bearer service for the application layer. For principles of transport protocol layers, see the corresponding feature parameter description document for each RAT.

Figure 1 Generic protocol stack for IPv4 transmission on a base station
MOs related to IPv4 transmission can be configured in endpoint mode and in link mode.
  • In link mode, a conventional transmission configuration mode, the control-plane bearer Stream Control Transmission Protocol (SCTP) link and the user-plane bearer Internet Protocol (IP) path must be configured for a transmission link. The port information is negotiated by two ends on the transmission link.
  • In endpoint mode, the two ends of a transmission link must be configured, for example, IP addresses. If the endpoint mode is used, the system automatically creates SCTP links and IP paths based on the port information.

Table 1 describes the MOs related to IPv4 transmission.
Table 1 MOs related to IPv4 transmission

Protocol Layer

Configuration Mode

MO

Description

Data link layer

Endpoint mode and link mode

ETHPORT
  • This MO defines an Ethernet port for connection to an NE.
  • This MO includes parameters such as the speed, duplex mode, port attribute, ARP proxy flag, and maximum transmission unit (MTU).
  • The duplex mode and port attribute must be negotiated with the peer end.

ETHTRK/ETHTRUNK

This MO defines an Ethernet trunk. An Ethernet trunk binds multiple Ethernet ports into a trunk, achieving load sharing and enhancing transmission reliability.

VLANMAP
This MO defines the next-hop VLAN mapping and is used to attach different VLAN tags to the data packets according to their next-hop IP addresses. The mapping modes are classified into single VLAN and VLAN group:
  • In single VLAN mode, next-hop IP addresses are directly mapped to VLAN tags.
  • In VLAN group mode, next-hop IP addresses are mapped to VLAN groups and then to VLAN tags in the VLAN groups based on the differentiated services code points (DSCPs) and types of data packets.

VLANCLASS
This MO defines VLAN priority mapping and is used to map VLAN tags based on traffic types of services. There are two mapping modes:
  • If the traffic type is user data, VLAN tags are mapped based on the DSCPs of user data packets.
  • If the traffic type is not user data, VLAN tags are mapped based on the traffic type.

DSCPMAP

This MO defines the mapping between a DSCP and a VLAN priority. If no VLAN priority is specified when a VLANMAP MO is configured, the VLAN priority is specified for user data based on mapping rules defined in the DSCP2VLANPRI MO.

DSCP2PCPMAP

This MO defines the table of mappings between DSCPs and VLAN priorities. The corresponding DSCP2PCPMAP MO must be specified when an INTERFACE MO is configured.

SUBNETVLAN

This MO defines a subnet VLAN mapping by attaching a VLAN tag to a data packet based on its source or destination IP address. For details on the procedures for dividing VLANs and tagging VLANs, see the corresponding feature parameter description document.

E1T1

This MO defines an E1 or T1 port for connecting to the transport network and consists of parameters such as line coding scheme and frame format for the port.

PPPLNK

This MO defines a Point-to-Point Protocol (PPP) link. PPP is usually used for setting up a direct connection between two nodes and provides functions such as connection authentication and header compression.

MPGRP

This MO defines a Multi-Link Point-to-Point Protocol (MLPPP) link, which enables spread spectrum communication between multiple PPP links.

Network layer

Endpoint mode and link mode

DEVIP/IPADDR4

This MO defines the device IP address of an IP port. Before configuring this MO, ensure that the associated ETHPORT MO has been configured. The DEVIP/IPADDR4 MO defines the following IP addresses:

  • Device IP address used by an SCTP link or IP path on an S1 or X2 interface
  • Device IP address of an OM channel

IPRT/IPROUTE4
  • This MO defines a static IP route. A routing table is configured to implement data forwarding.
  • During the configuration of the control plane and user plane of an S1 or X2 interface, IP routes to the peer end are required.
  • During the configuration of an S1 or X2 interface, IP routes are not required when a base station is connected to the core network or another base station through a layer 2 network. However, IP routes are required when a base station is connected to the core network or another base station through a layer 3 network.
  • During the configuration of an OM channel, IP routes are not required when a base station is connected to the EMS through a layer 2 network, but are required when a base station is connected to the EMS through a layer 3 network. IP routes are also required if route binding is disabled for the OM channel.

SRCIPRT/SRCIPROUTE4

This MO defines source-based routing, which is a type of policy-based routing and is used to configure a static IP route based on the source address to implement data forwarding.

Source-based routing takes precedence over destination-based routing. The destination-based routing is used only when no route can be found based on the source-based routing.

LOOPBACK

This MO defines a loopback interface, which is a virtual interface. A loopback interface can be configured with a loopback IP address.

INTERFACE

This MO is used to configure IP-layer interfaces, classify these interfaces into normal interfaces and VLAN subinterfaces, and configure IP addresses and packet filtering.

RSCGRP

These MOs define the transmission resource group. If there are no passing-by data flows, a user-defined transmission resource group is not required.

Transport/Application layer

Link mode

SCTPLNK

This MO defines an SCTP link for the control plane.

CP CPBEARER

This MO defines bearers for the control ports at the application layer.

IPPATH
  • This MO defines an IP path for the user plane of an S1 or X2 interface.
  • If an IP path needs to be added to a user-defined transmission resource group, set the RSCGRPID parameter in the IPPATH MO to the value of the RSCGRPID parameter in the user-defined RSCGRP MO.

Endpoint mode

EPGROUP

This MO defines a transmission node resource set, which can be a set of control-plane endpoints, a set of user-plane endpoints, or a set of control- and user-plane endpoints.

SCTPHOST

This MO defines information of an SCTP host. During establishment of the control plane, an SCTP link is automatically set up based on the configured SCTP host and SCTP peer. When the security self-setup function is enabled on an SCTP host, a security host must be configured for the SCTP host. One SCTP host IP address can reference only one security host.

SCTPPEER

This MO defines information of an SCTP peer. In X2 self-setup scenarios, this MO can be automatically generated. In other scenarios, this MO must be manually configured. In security scenarios, if an IPsec address is configured in this MO, IPsec negotiation is automatically set up between the SCTP host end and the SCTP peer end.

USERPLANEHOST

This MO defines information of a user-plane host. During self-setup of the user plane, a user-plane link is automatically set up based on the user-plane host and user-plane peer. The user-plane host and user-plane peer can be manually configured or automatically generated.

USERPLANEPEER

This MO defines information of a user-plane peer and can be manually configured or automatically generated.

Endpoint mode and link mode

OMCH

This MO defines a maintenance channel between a base station and an EMS. The EMS manages and maintains the base station through the maintenance channel.

NOTE:
  1. During the configuration of an OM channel:
    • If only one OM channel is required, configure only the active OM channel.
    • If active and standby OM channels are required, configure both an active OM channel and a standby OM channel. The system preferentially uses the active OM channel. If the active OM channel is faulty, the base station switches to the standby OM channel as required by the EMS.
    The active/standby role of an OM channel is specified by the FLAG parameter.
  2. MOs related to VLANs must be configured in VLAN networking scenarios.
