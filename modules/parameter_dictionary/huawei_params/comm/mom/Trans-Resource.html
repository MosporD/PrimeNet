Transmission Resource Management MOM Description

This section describes the functions and concepts related to transport resource management. It also provides the managed object model (MOM) view and describes the managed objects (MOs) related to transport resource management.

Functions and Concepts

Quality of service (QoS) in network communications is a mechanism that guarantees an expected level of performance in the packet loss rate, delay, jitter, and bandwidth. QoS provides different service qualities based on different requirements.

Transport resources are one type of resources on the access network. The transport resource management function manages transport resources based on QoS requirements.

Transport resource management involves transport resource configuration and mapping, transport load control, and transport congestion control. The radio resource management (RRM) algorithms that are closely related to transport resource management include air interface resource scheduling algorithm and air interface load control algorithm. The transport resource management algorithm policies must be consistent with the RRM algorithm policies to the greatest extent. Figure 1 shows the overall structure of transport resource management. Transport resource management is described as follows:
  • Transport resource configuration and mapping
    The principles of transport resource configuration and mapping are as follows:
    • Transport resources include physical ports, transport resource groups, and IP paths. By properly configuring these transport resources, more refined and accurate bandwidth management is achieved.
    • Transport resource mapping implements differentiated transmission by mapping traffic types to differentiated service code points (DSCPs) based on transmission requirements (for example, requirements for the delay, jitter, and packet loss rate).
  • Transport load control
    Transport load control applies when transport resources are limited. It aims to provide differentiated services (DiffServ), ensure fairness among UEs, and increase transport bandwidth usage and network capacity without affecting service quality. Transport load control involves the following functions:
    • Transport admission control: Services are admitted based on the transport load. By allocating transport resources to UEs, a base station manages transport bandwidth and controls the load on transport bandwidth.
    • Transport resource preemption: After an initial admission attempt fails, high-priority services can access the network by preempting the transport resources of low-priority services.
    • Transport overload control: This function can be used to rapidly enhance transport stability when transport resources are overloaded.
    • Transport load reporting: When the transport load is excessively high, the transport layer reports the load status to the module for load balancing on the air interface or the base station starts transport overload control.
  • Transport congestion control

    The transport network quality may fluctuate frequently. In this situation, transport dynamic flow control estimates available bandwidth on the transport network and dynamically adjusts the bandwidth of base station interface boards based on the transport network quality information provided by IP PM. When the transport network quality is good, the base station gradually increases the bandwidth. When the quality is poor, the base station decreases the bandwidth to prevent congestion.

    A base station implements dynamic transport flow control on each transport resource group by using the following functions:
    • Transport differentiated flow control involves traffic shaping of transport resource groups, queue scheduling of transport resource groups, and back pressure algorithms. This function provides UEs with DiffServ while ensuring fairness. When a base station interface board is congested, this function can be used to ensure the quality of non-flow-controllable services by transmitting these services preferentially. In addition, the rates of non-real-time services are limited to achieve differentiated allocation of bandwidth among services.
    • Dynamic bandwidth adjustment estimates transport bandwidth and provides bandwidth information for transport differentiated flow control and transport admission control. If the dynamic TX bandwidth adjustment function is enabled, the TX bandwidth is adjusted according to the automatic bandwidth adjustment parameters (Packet Loss Ratio Down Threshold and Delay Variation Down Threshold). If the traffic exceeds the configured bandwidth, the bandwidth can be appropriately adjusted to avoid data loss.
    • IP PM is a Huawei proprietary function. It performs end-to-end performance monitoring to obtain network quality information such as the traffic volume, packet loss rate, delay, and jitter. IP PM improves system performance by enhancing system maintainability and testability.
    NOTE:
    Transport congestion control applies to user-plane services.

MOs related to transport resource management are described as follows in terms of transport load control and transport congestion control:
  • Transport load control
    MOs related to transport load control include DIFPRI, TACALG, TLDRALG, and TOLCALG.
    • DIFPRI defines a mapping between traffic types and DSCPs. This MO supports different transport paths based on DSCPs. Traffic can be classified into signaling, OM, and IP clock.
    • TACALG defines a transport admission control algorithm.
    • TLDRALG defines the transport load status of a base station. The reported transport load status is used as the input for the load balancing algorithm.
    • TOLCALG defines a transport overload control (OLC) algorithm.
    • DLFLOWCTRLPARA (in the old model)/IPDLFLOWCTRLPARA (in the new model) defines the configuration for the downlink flow control algorithm on a NodeB.
    • ULFLOWCTRLPARA (in the old model)/IPULFLOWCTRLPARA (in the new model) defines the configuration for the uplink flow control algorithm on a NodeB.
  • Transport congestion control
    MOs related to transport congestion control include PRI2QUE (in the old model)/DSCP2QUEMAP (in the new model), RSCGRP (in the old model)/IPRSCGRP (in the new model), RSCGRPALG (in the old model)/IPRSCGRPALG (in the new model), LR (in the old model)/PORTLR (in the new model), and IPPMSESSION.
    • PRI2QUE (in the old model)/DSCP2QUEMAP (in the new model) defines a mapping between system internal queues and transport bearer priorities represented by DSCPs. Queue 0 has the highest priority.
    • RSCGRP (in the old model)/IPRSCGRP (in the new model) defines the configuration information of a transport resource group. This MO consists of the resource group ID, traffic-related parameters, and other parameters.
    • IP2RSCGRP (in the old model)/IP2IPRSCGRP (in the new model) defines a mapping between a destination IP address of passing-by data and a transport resource group. The MO is used to guarantee the QoS of bound service flows in the target network segment by binding these service flows to a transport resource group. The mapping between IP addresses and transport resource groups is configured only when base stations are cascaded.
    • RSCGRPALG (in the old model)/IPRSCGRPALG (in the new model) defines algorithms related to a transport resource group. The MO consists of the transport resource group ID and algorithm parameters.
    • LR (in the old model)/PORTLR (in the new model) defines the transmission data rate configuration on a physical port. This MO consists of the port number, rate limitation algorithm switch, and traffic-related parameters.
    • IPPMSESSION defines an IP PM session. IP PM monitors the quality of transport links, such as the delay, jitter, and packet loss rate. The monitoring results are used as the input for dynamic flow control.
    • UDT defines a user data type and is used to support differentiated user data types including gold, silver, and bronze.
    • UDTPARAGRP defines a group of user data type parameters and is used to support the parameter groups for differentiated user data types including gold, silver, and bronze. Each parameter group is uniquely identified by a group ID and includes parameters such as the data priority, activity factor, primary transport resource type, primary port load threshold, and primary-to-secondary port load ratio threshold.
