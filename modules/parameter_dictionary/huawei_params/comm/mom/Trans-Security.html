Transmission Security MOM Description

This section describes the functions and concepts of IEEE 802.1X-based access control, IPsec, packet filtering, and IP attack defense policy. It also provides the managed object model (MOM) view of and the managed objects (MOs) related to transmission security.

Functions and Concepts

IEEE 802.1X-based Access Control

IEEE 802.1X-based access control involves the following:
  • Authentication client (a device to be authenticated): initiates an IEEE 802.1X-based access control procedure.
  • Authentication access equipment (such as a LAN switch): receives and transmits authentication messages between base stations and the authentication server at the MAC layer.
  • Authentication server: performs authentication on clients by using various authentication mechanisms or methods. In an LTE system, a commonly used authentication server is a Remote Authentication Dial-In User Service (RADIUS) server.
In IEEE 802.1X-based access control, Extensible Authentication Protocol over LAN (EAPoL) messages, which contain digital certificates of a base station, are transmitted to the RADIUS server. The RADIUS server performs authentication on the base station by using a Huawei-issued root certificate configured on the server. After the authentication server authenticates the base station and authorizes the controlled port, data can pass through the controlled port in the authorized state. This ensures that only authorized users can access the network. For details on digital certificates, see PKI MOM Description.

IPsec

IPsec is a security scheme in which operators define security policies. A security policy specifies a type of packets that need to be protected and how they should be protected. By sharing security policies, the base station can communicate with the peer end in secure mode. Concepts related to IPsec are described as follows:
  • Access control list (ACL) rule and ACL
    • An ACL rule defines a type of IP packets that need to be protected. The base station determines the packets to be protected according to ACL rules.
    • ACL rules are arranged into ACLs for convenient management. One ACL may contain multiple ACL rules.
  • IPv6 access control list (ACL6) rule and ACL6
    • An ACL6 rule defines a type of IPv6 packets that need to be protected. The base station determines the packets to be protected according to ACL6 rules.
    • ACL6 rules are arranged into ACL6s for convenient management. One ACL6 may contain multiple ACL6 rules.
  • IPsec policy and IPsec security association (SA)
    • An IPsec policy defines the protection mechanism that is used to protect a type of packets.
    • The base station shares an IPsec policy with the peer end by establishing an IPsec SA during an Internet Key Exchange (IKE) negotiation. An IPsec SA is a logical connection and has a lifetime.
  • IKE is a protocol used by the local and peer ends to establish SAs and perform identity authentication.
    • IKE SAs support two status detection mechanisms: keep-alive detection and dead peer detection (DPD). In keep-alive detection, detection packets are sent periodically. In DPD, detection packets are sent only when there is no IPsec traffic. If a base station is configured with both keep-alive detection and DPD, only keep-alive detection takes effect.
    • There are two methods of identity authentication: digital-certificate-based authentication and PSK-based authentication. PSK is short for pre-shared key. For details on digital-certificate-based authentication, see PKI MOM Description. For details on PSK-based authentication, see Transmission Security Overview.

Packet Filtering

Packet filtering is a process in which a base station accepts or discards packets according to ACL/ACL6 rules. This prevents unauthorized users from accessing the base station and implements the firewall function.

Both IPsec and packet filtering use ACL/ACL6 rules but for different purposes.
  • In IPsec, ACL/ACL6 rules are used to determine whether outgoing packets are allowed to enter the IPsec tunnel. Only the packets allowed to enter the IPsec tunnel are encrypted.
  • In packet filtering, ACL/ACL6 rules are used to determine whether incoming packets are allowed to be received by a base station. If they are not allowed to be received, the base station discards them.

IP Attack Defense Policy

An IP attack defense policy specifies the global configuration related to Address Resolution Protocol (ARP) spoofing, strict ARP learning, illegal packet detection, and neighbor discovery (ND) spoofing.
  • In ARP spoofing, an attacker maliciously tampers with the ARP table on equipment by using ARP spoofing packets, and user packets cannot be forwarded.
  • In strict ARP learning, a base station learns only the ARP request packets sent by itself and the ARP response packets sent by the peer end.
  • Illegal packets refer to the packets filtered out in packet filtering.
  • In ND spoofing, an attacker maliciously tampers with the ND table on equipment by using ND spoofing packets, and user packets cannot be forwarded.

MOs Related to IEEE 802.1X-based Access Control

MOs related to IEEE 802.1X-based access control are described as follows:
  • DOT1X (in the old model)/DOT1XAUTH (in the new model) defines the parameters required for IEEE 802.1X-based authentication for base stations. When a base station accesses a network supporting the IEEE 802.1X protocol, IEEE 802.1X-based access control is performed based on the parameter settings.

MOs Related to IPsec

MOs related to ACL define the types of packets that need to be protected. These MOs are described as follows:
  • ACLRULE/ACLRULE6 defines an ACL rule. An ACL rule determines a type of IP packets that need to be protected. ACLRULE is the MO used in IPv4 transmission. ACLRULE6 is the MO used in IPv6 transmission.
  • ACL/ACL6 defines an ACL. An ACL contains one or more ACL rules. ACL is the MO used in IPv4 transmission. ACL6 is the MO used in IPv6 transmission.
MOs related to IKE define the local parameters, algorithms, and common parameters for IKE interactions. These MOs are described as follows:
  • IKECFG defines the common parameters used in IKE interactions between the base station and peer end.
  • IKEPROPOSAL defines an IKE proposal, which includes the algorithms used in IKE interactions.
  • IKEPEER defines an IKE peer and consists of interconnection parameters used in IKE interactions between the base station and the peer end.
MOs related to IPsec SA define the ACL index, IKE peer index, and IPsec proposal index for an IPsec tunnel, and the physical port on which a group of IPsec policies take effect. These MOs are described as follows:
  • IPSECPROPOSAL defines an IPsec proposal. This MO includes the encapsulation mode, authentication algorithm, and encryption algorithm used in IPsec interactions.
  • IPSECPOLICY defines an IPsec policy. An IPsec policy specifies the protection mechanism that is used to protect a type of packets. This MO includes an ACL ID, IPsec proposal name, and IKE peer name. Before adding an IPSECPOLICY MO, ensure that the ACL, IPSECPROPOSAL, and IKEPEER MOs have been configured, which are associated with theACLID, PROPNAME, and PEERNAME parameters in the IPSECPOLICY MO, respectively.
  • IPSECBIND (in the old model) defines a binding relationship between an IPsec policy group and a physical port. The MO specifies the physical port where an IPsec policy group is to be used. IPSECBIND is the MO used in IPv4 transmission.
  • IPSECBINDITF (in the new model) defines a binding relationship between an IPsec policy group and an interface. The MO specifies the interface where an IPsec policy group is to be used.
  • IPSECDTNL defines the IPsec policies and Bidirectional Forwarding Detection (BFD) sessions for the primary and secondary tunnels in an IPsec tunnel pair. An IPsec tunnel pair consists of two IPsec tunnels between the base station and SeGWs. The tunnel pair enhances reliability of secure transmission between the base station and the core network, EMS, or clock server. If one IPsec tunnel becomes faulty and the other tunnel works properly, the base station automatically switches to the normal tunnel to continue secure transmission with the core network, EMS, or clock server.

MOs Related to Packet Filtering

MOs related to packet filtering are described as follows:
  • ACLRULE/ACLRULE6 defines an ACL rule. An ACL rule determines a type of IP packets that need to be protected.
  • ACL/ACL6 defines an ACL. An ACL contains one or more ACL rules.
  • PACKETFILTER defines an IP packet filtering policy. A base station obtains the header information about the packets received or to be transmitted, compares the information with the preset ACL rules, and then forwards or discards the packets according to the packet filtering policy. The header information includes the upper-layer protocol number, the source and destination addresses of each packet, and the source and destination ports of each packet.

IP Attack Defense Policy

MOs related to IP attack defense policy are described as follows:
  • IPGUARD defines attack defense policies used at the MAC and IP layers, attack alarm switches, and attack alarm thresholds.
  • FLOODDEFEND defines the flood attack defense function and related alarm parameters. If the local end receives excessive flood packets from the peer end, the local end will spend a large number of resources processing these packets and therefore cannot provide services normally.
  • PINGFILTER (in the old model)/PINGFILTER6 (in the new model) defines ping filtering entries in whitelist mode (you can ping the network segment or the host specified in this MO on a base station) or in blacklist mode (you cannot ping the network segment or host specified in this MO on a base station). The ping filtering mode can be set by running the SET PINGFILTERMODE command.
