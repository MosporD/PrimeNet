Add Flood Attack Defense and Alarm Parameters (ADD FLOODDEFEND)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a configuration of the flood attack defense and excessive flood packet alarm for a specific type of flood packet.

Note

  • Only one FLOODDEFEND object can be configured for each type of flood packet.

  • The configuration of the FLOODDEFEND object takes effect only on boards with Ethernet ports.

  • If both DFDSW and ALMSW are set to ENABLE, it is recommended that the alarm threshold be set to a value smaller than the defend threshold. With this setting, when the RX rate of flood packets exceeds the alarm threshold, the ALM-25950 Base Station Being Attacked is reported. If the alarm threshold is greater than the defend threshold, the ALM-25950 Base Station Being Attacked is not reported.

  • It is recommended that the TCP and UDP flood attack thresholds of the UMPT/UMDU board do not exceed 3600 pps. It is recommended that the TCP and UDP flood attack thresholds of the WMPT/GTMUc board not exceed 720 pps. It is recommended that the TCP and UDP flood attack thresholds of the LMPT board not exceed 290 pps. It is recommended that the TCP and UDP flood attack defense threshold for the UTRP (with the subboard type as UEOC, UQEC, or UTRPc), UCCU, and UBBP boards be less than or equal to 720 packets per second.

  • The eCPRI-supported boards do not support the TCP flood attack defense function.

  • This command can be used to enable the flood attack defense for a specific type of packet. If the flood attack defense is not configured for a specific type of packet, the defense against SCTP flood attacks is disabled and the defense against ARP, ICMP, TCP, SYN, UDP, ICMP6, ND, and PTB flood attacks is enabled by default. The default flood attack defense thresholds are 64 pps for ARP and SYN packets, 128 pps for ICMP packets, 2048 pps for TCP and UDP packets, 768 pps for ICMP6 packets, and 256 pps for ND and PTB packets. By default, the flood attack alarm function for ICMP6/ND/PTB packets is enabled. The default flood attack alarm thresholds are 384 for ICMP6 packets, 192 for ND and PTB packets.

  • It is recommended that the ARP spoofing detection function and the ARP flood attack defense function not be used simultaneously. If the two functions are enabled simultaneously, the ARP Spoofing Alarm Threshold parameter in the IP firewall attack defense policy should be set to a value smaller than the Alarm Threshold parameter or default value for ARP flood attack defense. Otherwise, ARP spoofing alarms cannot be reported.

  • When the system is performing heavy traffic services (such as downloading software versions, uploading a large number of logs, and tracing a large number of UEs), it is recommended that the flood attack defense function be disabled. If this function is required, it is recommended that the defense threshold and alarm threshold be increased.

  • Only the UMPT, SMPT, UMDU, GTMUc, UTRPc, UTRPa, UCCU, and CSPU boards support the defense against SCTP flood attacks.

  • [Co-MPT,eGBTS]The GTMUb does not support FLOODDEFEND.

Parameters

ID Name Description
FLDTYPE Flood Type

Meaning: Indicates the type of the flood packet. If the control bits are all 0 or both the Synchronize bit and No More Data bit are 1 in TCP packets, the packets are directly discarded and flood attack defense is not performed. SYN packets refer to packets whose Synchronize bit is 1 and Acknowledgement bit is 0. When the defenses against attacks of the SYN and TCP packets are both enabled but the SYN packet data rate does not reach the flood attack defense threshold for SYN packets, the flood attack defense threshold for TCP packets is used to trigger the defense. When the data rate of some SYN packets reaches the flood attack defense threshold for SYN packets, this threshold is used to trigger the defense against the attack of these SYN packets and the flood attack defense threshold for TCP packets is used to defend against the attack of SYN packets of which the rate does not reach the flood attack defense threshold for SYN packets.

Disuse statement: In the later versions, the value SCTP_INIT (SCTP_INIT) will be removed from the value range of this parameter. In the current version, this value can still be configured but the value does not take effect. Therefore, you are not advised to use the value SCTP_INIT (SCTP_INIT).

GUI Value Range: ARP(ARP), ICMP(ICMP), TCP(TCP), SYN(SYN), UDP(UDP), SCTP_INIT(SCTP_INIT), SCTP(SCTP), ICMP6(ICMP6), ND(ND), PTB(PTB)

Unit: None

Actual Value Range: ARP, ICMP, TCP, SYN, UDP, SCTP_INIT, SCTP, ICMP6, ND, PTB

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
DFDSW Defend Switch

Meaning: Indicates whether to enable the protection against excessive flood packets.

GUI Value Range: DISABLE(Disable), ENABLE(Enable)

Unit: None

Actual Value Range: DISABLE, ENABLE

MML Default Value: DISABLE(Disable)

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
DFDTHD Defend Threshold

Meaning: Indicates the threshold for starting the protection against excessive flood packets. If the DFDSW parameter is set to ENABLE, the system discards the extra packets when the RX rate of flood packets exceeds the threshold. It is recommended that the difference between Defend Threshold and Alarm Threshold is greater than 3% of Defend Threshold.

GUI Value Range: 1~4096

Unit: packet/s

Actual Value Range: 1~4096

MML Default Value: None

Recommended Value: If FLDTYPE is set to ARP or SYN, the recommended value is 64.

If FLDTYPE is set to ICMP, the recommended value is 128.

If FLDTYPE is set to TCP or UDP, the recommended value is 2048.

If FLDTYPE is set to SCTP, the recommended value is 1024.

If FLDTYPE is set to ICMP6, the recommended value is 768.

If FLDTYPE is set to ND, the recommended value is 256.

If FLDTYPE is set to PTB, the recommended value is 256.

Parameter Relationship:

-Others:

  • [Co-MPT, NodeB, eNodeB, gNodeB]In the FLOODDEFEND MO, if FLDTYPE is set to ARP, DFDTHD ranges from 1 to 512.
  • In the FLOODDEFEND MO, if FLDTYPE is set to ICMP or SYN, DFDTHD ranges from 1 to 1024.
  • In the FLOODDEFEND MO, if FLDTYPE is set to TCP or UDP, DFDTHD ranges from 1 to 4096.
  • In the FLOODDEFEND MO, if FLDTYPE is set to SCTP, DFDTHD ranges from 384 to 2048.
  • In the FLOODDEFEND MO, if FLDTYPE is set to ICMP6, DFDTHD ranges from 384 to 1280.
  • In the FLOODDEFEND MO, if FLDTYPE is set to ND or PTB, DFDTHD ranges from 128 to 512.

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
ALMSW Alarm Switch

Meaning: Indicates whether to report an alarm when the local end receives excessive flood packets from the peer end.

GUI Value Range: DISABLE(Disable), ENABLE(Enable)

Unit: None

Actual Value Range: DISABLE, ENABLE

MML Default Value: DISABLE(Disable)

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
ALMTHD Alarm Threshold

Meaning: Indicates the threshold for the excessive flood packet alarm. If the ALMSW parameter is set to ENABLE, the system measures the RX rate of flood packets every 10 seconds. If the measured value exceeds the threshold, an excessive flood packet alarm is reported. The alarm is cleared if the RX rate of flood packets keeps below the threshold for five consecutive minutes. It is recommended that the difference between Defend Threshold and Alarm Threshold is greater than 3% of Defend Threshold.

GUI Value Range: 1~4096

Unit: packet/s

Actual Value Range: 1~4096

MML Default Value: None

Recommended Value: If FLDTYPE is set to ARP or SYN, the recommended value is 32. If FLDTYPE is set to ICMP, the recommended value is 64. If FLDTYPE is set to TCP or UDP, the recommended value is 1024. If FLDTYPE is set to SCTP, the recommended value is 768. If FLDTYPE is set to ICMP6, the recommended value is 384. If FLDTYPE is set to ND, the recommended value is 192. If FLDTYPE is set to PTB, the recommended value is 192.

Parameter Relationship:

-Others:

  • [Co-MPT, NodeB, eNodeB, gNodeB]In the FLOODDEFEND MO, if FLDTYPE is set to ARP, ALMTHD ranges from 1 to 512.
  • In the FLOODDEFEND MO, if FLDTYPE is set to ICMP or SYN, ALMTHD ranges from 1 to 1024.
  • In the FLOODDEFEND MO, if FLDTYPE is set to TCP or UDP, ALMTHD ranges from 1 to 4096.
  • In the FLOODDEFEND MO, if FLDTYPE is set to SCTP, ALMTHD ranges from 384 to 2048.
  • In the FLOODDEFEND MO, if FLDTYPE is set to ICMP6, ALMTHD ranges from 384 to 1280.
  • In the FLOODDEFEND MO, if FLDTYPE is set to ND or PTB, ALMTHD ranges from 128 to 512.

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N

Example

To add a configuration with the parameters as follows: Flood Type: ARP, Defend Switch: ENABLE, Alarm Switch: ENABLE, run the following command:
ADD FLOODDEFEND: FLDTYPE=ARP, DFDSW=ENABLE, ALMSW=ENABLE;
