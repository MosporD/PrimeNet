Add IPv4 Route (ADD IPROUTE4)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a static IPv4 route.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Active/standby routes indicate routes with the same destination IP address and subnet mask but different priorities in the same routing domain.

  • In the same routing domain, the route to be bound to a remote maintenance channel should be on a different network segment from any other route that is not bound to any remote maintenance channel.

  • In the same routing domain, the destination IP address of an IP route must be on a different network segment from any IPv4 address on the board. In the same routing domain, the two IP addresses are on the same network segment if the following conditions are met: (IPValueA & IPMaskA == IPValueB & IPMaskB) and (IPMaskA == IPMaskB). & indicates the bitwise logical AND operation.

  • The route with both the destination IP address and subnet mask set to 0.0.0.0 is a default route. Do not configure a default route as it may result in exceptions when a transport device uses the Virtual Router Redundancy Protocol (VRRP).

  • If the bear type of a remote maintenance channel is IPv4, do not set the destination IP address to 0.0.0.0 for the route bound to the remote maintenance channel. Otherwise, broadcast storms may occur. If the bear type of a remote maintenance channel is ATM, do not set the destination IP address to 0.0.0.0 for the route bound to the remote maintenance channel.

  • Equal-cost routes are not supported. Equal-cost routes are two routes that have the same destination IP address, subnet mask, and priority in the same routing domain. If equal-cost routes are used, SCTP links may be disconnected. If the physical outbound ports of equal-cost routes are different, service admission, flow control, and traffic statistics on the transmission resource group may be inaccurate.

  • If an IPPATHRT and an IPROUTE4 have the same destination IP address but different next hop IP addresses, the IPPATHRT has a higher priority than the IPROUTE4.

  • System specifications: A base station supports a maximum of 150 IPv4 routes.

  • Board specifications: A board supports a maximum of 150 IPv4 routes.

  • In the same routing domain, two routes that have the same destination network segment and are not bound to any remote maintenance channels should have different priorities.

  • In the same routing domain, two IPv4 routes that have the same destination IP address and subnet mask and which are not bound to remote maintenance channels must be on the same board. It is recommended that the two IPv4 routes have different priorities.

  • In the same routing domain, it is not recommended that an IP route which is not bound to remote maintenance channels and the routes bound to remote maintenance channels have the same destination IP address and subnet mask. If the IP route and a route that is bound to the active remote maintenance channel having the same destination IP address and subnet mask are on the same board, the IP route will be disabled.

  • The MTU can be configured only for the UMPT, UMDU, LMPT, UTRPc, UCCU, UBBPe (excluding UBBPe15), UBBPei, UBBPep, UBBPem, LCOP, UBBPex2, UBBPf0, UBBPf1, UBBPg1, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7 and UBBPg9 boards.

  • In secure networking scenarios, the outer layer can be fragmented only for encrypted packets.

  • The parameter Maximum Transmission Unit is invalid if the ping packet specifies the outgoing port.

  • This operation may interrupt the services or OM channels. It is recommended that you determine whether to enable the automatic configuration data rollback function depending on scenarios. For details, see the help of the CFM CB command.

  • In backplane-based co-transmission scenarios, if the destination IP address of the host tunnel route configured for the RAT providing the co-transmission port is the same as the IP address of the peer device on the same layer 2 network, an IP address conflict will occur on the peer device.

  • [Co-MPT,NodeB,eGBTS,eNodeB]If an error message indicating an IP address conflict is displayed when you set the next hop IP address, search the existing IP addresses in the system that may conflict with the next hop IP address by running the following commands: LST IPADDR4, DSP IPADDR4, LST OMCH, DSP OMCH, LST PPPLNK, DSP PPPLNK, LST LOCALIP, DSP LOCALIP, LST MPGRP, DSP MPGRP, LST IPROUTE4, and DSP IPROUTE4. The conflicting IP address may be an IPv4 Address, local IP address of a remote maintenance channel, local IP address of a PPP link, IP address for local maintenance, local IP address of an MP group, or next hop IP address of an IPv4 route.

  • [Co-MPT,NodeB,eNodeB,gNodeB]After an IPADDR4 MO is configured, the system automatically generates a direct gateway route. A direct gateway route takes precedence over other routes. Therefore, after an IPROUTE4 MO is configured, if the network address part of the destination IP address of the IPROUTE4 MO is the same as that of the direct gateway route, the IPROUTE4 MO is invalid.

  • [Co-MPT,eNodeB,gNodeB]Active/standby mode and load sharing mode are not supported between two routes whose Port Type is Air Link or between a route whose Port Type is Air Link and a route of another type.

  • [Co-MPT,eNodeB,gNodeB]Currently, only the UMPT, LMPT, and UMDU boards all in LTE mode support IPv4 routes whose Port Type is Air Link. The corresponding service links can be established only between the main control board and the baseband processing board.

  • [Co-MPT,eNodeB,gNodeB]If the RST APP command is executed to reset the APP that uses the route with Port Type set to AIRLNK, this route becomes unavailable. The route takes effect only when the UE accesses the network again.

  • [Co-MPT,eNodeB,gNodeB]Peer IP and destination IP address of the route whose Port Type is Air Link cannot be the same as any existing IP address in this base station. The destination IP address of the route cannot be the same as Peer IP of the route. This constraint needs to be configured by users.

  • [Co-MPT,eNodeB,gNodeB]Peer IP of the route whose Port Type is Air Link must be valid, and it cannot be a broadcast IP address or multicast IP address.

  • [Co-MPT,eNodeB,gNodeB]The route whose Port Type is Air Link does not support route interlock or BFD reliability detection.

  • [eNodeB,gNodeB]If an LMPT serves as the main control board, the IPv4 route whose Port Type is not Air Link but whose Route Type is IF(Exit Interface) can be successfully configured but cannot take effect.

  • [eNodeB,gNodeB]The route with both the destination IP address and subnet mask set to 0.0.0.0 is a default route.

  • [Co-MPT,eGBTS]In the GTMUb/GTMUc a maximum of 132 IPv4 routes can be configured on the board.

  • [gNodeB]If an error message indicating an IP address conflict is displayed when you set the next hop IP address, search the existing IP addresses in the system that may conflict with the next hop IP address by running the following commands: LST IPADDR4, DSP IPADDR4, LST OMCH, DSP OMCH, LST LOCALIP, DSP LOCALIP, LST IPROUTE4, and DSP IPROUTE4. The conflicting IP address may be an IPv4 Address, local IP address of a remote maintenance channel, IP address for local maintenance, or next hop IP address of an IPv4 route.

FORCEEXECUTE Support Forcible Execution

Meaning: Indicates whether a forcible change of an IPv4 route is made. When this parameter is set to NO(No), the system checks whether the change affects upper-layer services. If the change affects upper-layer services, the forcible change will fail. When this parameter is set to YES(Yes), the system does not check whether the change affects upper-layer services. Upper-layer services include the following: active/standby OM channel (OMCH), DNS service (DNSSRV), security link (IKEPEER), certificate issuance (CA), CRL update (CRLTSK), IP clock link (IPCLKLINK), NTP (NTPC), Abis CP/Iub CP/S1 CP/X2 CP/M2 CP/ECO CP/eX2 CP/SO CP/uX2 CP/Xw CP/gNBCUX2 CP/gNBCUNg CP/gNBCUXn CP (SCTPLNK/SCTPPEER), and Abis UP/IP path of an unknown service type/Iub UP/uX2 UP/S1 UP/X2 UP/eX2 UP/Xw UP/gNBCUX2 UP/gNBCUS1 UP/gNBCUNg UP/gNBCUXn UP (IPPATH/USERPLANEPEER). This parameter is invalid when a WMPT, LMPT, GTMUb, or GTMUc serves as the main control board.

Pay attention to the following when using this parameter:

1. The system checks whether a forcible change of an IP route affects upper-layer services based on the configuration data instead of based on the actual running status of these services.

2. If an NE is configured with an SRCIPROUTE4, PPPLNK, or MPGRP MO, the system does not check whether a forcible change of an IPv4 route affects upper-layer services.

3. If Port Type is set to IPOA(IP Over ATM Interface) or AIRLNK(Air Link) for the IPv4 route to be added or removed, the system does not check whether the addition or removal affects upper-layer services.

4. If Port Type is set to IPOA(IP Over ATM Interface) or AIRLNK(Air Link) for both the IPv4 routes before and after the modification, the system does not check whether the modification affects upper-layer services.

5. If Port Type is set to IPOA(IP Over ATM Interface) or AIRLNK(Air Link) for an IPv4 route, the system does not check whether the IPv4 route forms a pair of equal-cost routes with another route and whether the IPv4 route is included in the network segment of another route.

Example

To add an IPv4 Route with the parameters as follows: RTIDX:0, DSTIP:"192.168.101.0", DSTMASK:"255.255.255.0", RTTYPE:NEXTHOP, NEXTHOP:"192.168.100.1", MTUSWITCH:OFF, run the following command:
ADD IPROUTE4: RTIDX=0, DSTIP="192.168.101.0", DSTMASK="255.255.255.0", RTTYPE=NEXTHOP, NEXTHOP="192.168.100.1", MTUSWITCH=OFF;
