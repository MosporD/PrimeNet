Add IPv6 ACL Rule (ADD ACLRULE6)

Network Element: BTS3900, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a rule to an IPv6 access control list (ACL).

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • [Co-MPT,eNodeB,gNodeB]Before running this command, ensure that the associated IPv6 ACL has been configured.

  • [Co-MPT,eNodeB,gNodeB]In the same IPv6 ACL, the source or destination IPv6 address range as well as the source or destination port number range of different IPv6 ACL rules that have the same IPv6 ACL ID and different IPv6 ACL rule IDs cannot have any inclusion or overlapping relationships. Otherwise, the IPv6 ACL rules conflict.

  • [Co-MPT,eNodeB,gNodeB]When applied to data, ACL rules in one IPv6 ACL are used one by one in ascending order of rule ID.

  • [Co-MPT,eNodeB,gNodeB]If the UMPTa/UMPTb/UMDU is the main control board, a maximum of 1536 ACLRULE MOs and ACLRULE6 MOs can take effect on a BS. If the UMPTe is the main control board, a maximum of 2048 ACLRULE MOs and ACLRULE6 MOs can take effect on a BS. If the UMPTg/UMPTga is the main control board, a maximum of 6092 ACLRULE MOs and ACLRULE6 MOs can take effect on a BS.

  • [Co-MPT,eNodeB,gNodeB]System specifications: If a UMPTa/UMPTb/UMDU is used as the main control board, a base station supports a maximum of 320 IPv6 ACL rules. If a UMPTe is used as the main control board, a base station supports a maximum of 512 IPv6 ACL rules. If a UMPTg/UMPTga is used as the main control board, a base station supports a maximum of 584 IPv6 ACL rules. If a UMPTe/UMPTg/UMPTga is used as the main control board, a maximum of 320 manually configured IPv6 ACL rules are supported.

  • [Co-MPT,eNodeB,gNodeB]Board specifications: The UMPTa/UMPTb/UMDU supports a maximum of 320 IPv6 ACL rules, all of which can be manually configured IPv6 ACL rules. The UMPTe supports a maximum of 512 IPv6 ACL rules, among which a maximum of 320 IPv6 ACL rules can be manually configured IPv6 ACL rules. The UMPTg/UMPTga supports a maximum of 584 IPv6 ACL rules, among which a maximum of 320 IPv6 ACL rules can be manually configured IPv6 ACL rules. In IPSec scenarios, if IPVERSION in the IKEPEER MO is set to IPv4, the UMPTa/UMPTb/UMDU board supports a maximum of 264 IPv6 ACL rules with ACTION set to PERMIT. The UMPTe board supports a maximum of 512 IPv6 ACL rules with ACTION set to PERMIT. The UMPTg/UMPTga board supports a maximum of 512 IPv6 ACL rules with ACTION set to PERMIT. In IPSec scenarios, if IPVERSION in the IKEPEER MO is set to IPv6, the UMPTa/UMPTb/UMDU board supports a maximum of 320 IPv6 ACL rules with ACTION set to PERMIT. The UMPTe board supports a maximum of 456 IPv6 ACL rules with ACTION set to PERMIT. The UMPTg/UMPTga board supports a maximum of 584 IPv6 ACL rules with ACTION to PERMIT. In the packet filtering scenario, the UMPT/UMDU board supports a maximum of 64 IPv6 ACL rules.

  • [Co-MPT,eNodeB,gNodeB]An IPv6 ACL rule takes effect on the board where an IPv6 ACL takes effect. If the ACL6 object does not take effect on any board because it does not have a bearer (packet filtering policy or IPsec policy group binding interface) the ACLRULE6 object will also not take effect.

  • [Co-MPT,eNodeB,gNodeB]If an ACL6 MO is referenced by an IPSECPOLICY MO, the ACL6 MO cannot be configured with multiple ACLRULE6 MOs of the permit type that have inclusive relationships. Otherwise, any of the following may occur: IPsec SA negotiation fails; IPsec SA negotiation succeeds but is deleted later; different IPsec SA negotiation results are obtained when the narrow down switch is turned on.

  • [Co-MPT,eNodeB,gNodeB]If an ACLRULE6 MO is referenced by an IPSECPOLICY MO of the IPv6 type in IPsec scenarios, neither Source Port Operate nor Destination Port Operate in the ACLRULE6 MO can be set to OP_NEQ (Not Equivalent).

  • [Co-MPT,eNodeB,gNodeB]If an ACLRULE6 MO is referenced by an IPSECPOLICY of the IPv6 type in IPsec scenarios, Match DSCP in the ACLRULE6 MO cannot be set to YES (Yes).

  • [Co-MPT,eNodeB,gNodeB]In IPSec scenarios, if an IPv6 ACL rule list with configuration conflicts described in the preceding two notes exists and is referenced by an IPSECPOLICY MO, exceptions such as IPSec SA negotiation failures and frequent switchovers may occur on the device (depending on the peer configurations).

  • [Co-MPT,eNodeB,gNodeB]If an IPv6 ACL rule used by an IPSec policy has Protocol Type set to a non-IP type, Match Source Port set to Yes, or Match Destination Port set to Yes, ensure that the IPv6 ACL rule contains PMTU data flows. Otherwise, PMTU data flows will be discarded and PMTU discovery will fail.

SOP Source Port Operate

Meaning: Indicates the filter criteria for a source port. If this parameter is set to OP_LT, the ACL rule is applied to the data stream whose source port number is smaller than or equal to the configured port number. If this parameter is set to OP_GT, the ACL rule is applied to the data stream whose source port number is larger than or equal to the configured port number. If this parameter is set to OP_EQ, the ACL rule is applied to the data stream whose source port number is equal to the configured port number. If this parameter is set to OP_NEQ, the ACL rule is applied to the data stream whose source port number is not equal to the configured port number. If this parameter is set to OP_RANGE, the ACL rule is applied to the data stream whose source port number is within the configured range.

GUI Value Range: OP_LT(Less or Equal), OP_GT(Greater or Equal), OP_EQ(Equivalent), OP_NEQ(Not Equivalent), OP_RANGE(Range)

FORCEEXECUTE Support Forcible Execution

Meaning: Indicates whether a forcible change of an IPv6 ACL rule is made. When this parameter is set to NO(No), the system checks whether the change affects upper-layer services. If the change affects upper-layer services, the forcible change will fail. When this parameter is set to YES(Yes), the system does not check whether the change affects upper-layer services. Upper-layer services include the following: active OM channel (OMCH), DNS service (DNSSRV), certificate authority (CA), CRL update (CRLTSK), IP clock link (IPCLKLINK), NTP (NTPC), ABIS CP/IUB CP/S1 CP/X2 CP/M2 CP/ECO CP/eX2 CP/SO CP/UX2 CP/XW CP/gNBCUX2 CP/gNBCUNg CP/gNBCUXn CP (SCTPLNK/SCTPPEER), and ABIS UP/IPPATH of unknown service type/IUB UP/UX2 UP/S1 UP/X2 UP/eX2 UP/XW UP/gNBCUX2 UP/gNBCUS1 UP/gNBCUNg UP/gNBCUXn UP (USERPLANEPEER).Only the change of the IPv6 ACL rule that is manually configured with Protocol Type set to IPv6 and Match DSCP set to NO in IPsec networking is checked.

Pay attention to the following when using this parameter:

1. The system checks whether a forcible change affects upper-layer services based on the configuration data instead of based on the actual running status of these services.

2. If an NE is configured with an SRCIPROUTE6 MO, the system does not check whether a forcible change of an IPv6 ACL rule affects upper-layer services.

Example

To add an IPv6 ACL rule with the parameters as follows: IPv6 ACL ID: 3000, IPv6 Rule ID: 10, Protocol Type: IP6, Source IPv6 Address: 2001:DB8::1, Source Address Prefix Length: 32, Destination IPv6 Address: 2001:DB8::2, Destination Address Prefix Length: 32, Match DSCP: YES, DSCP: 25, run the following command: 
ADD ACLRULE6: ACLID=3000, RULEID=10, PT=IP6, SIP="2001:DB8::1", SPFXLEN=32, DIP="2001:DB8::2", DPFXLEN=32, MDSCP=YES, DSCP=25;
