Add IPSec Dual Tunnel (ADD IPSECDTNL)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add an IPSec tunnel pair. An IPSec tunnel pair, that is, two IPSec tunnels between the BS and two security gateways (SeGWs), enhances the transmission security between the BS and the core network (CN) or between the BS and the MAE. When the BFD detection switch is set to on, an IPSec tunnel pair uses two BFD sessions to detect the status of the primary and secondary IPSec tunnels, respectively. One BFD session used to detect the status of the primary IPSec tunnel, and the other used to detect that of the secondary IPSec tunnel. If the BFD detection result for the IPSec tunnel in use shows that the SeGW is unreachable or the associated IPSec security associations (SAs) are abnormal, the other IPSec tunnel takes over automatically and resumes secure transmission if it is detected to be normal and the associated IPSec SAs are normal. When the BFD detection switch is set to off, an IPSec tunnel pair determines the status of the primary and secondary IPSec tunnels according to the IPSec SA status. If the SA status of an IPSec tunnel being used becomes faulty and that of the other tunnel is detected to be normal, the base station automatically switches over to the other tunnel and resumes secure transmission with the CN or MAE. IPSec SAs corresponding to all the ACL rules in the ACL referenced by an IPSec tunnel are considered normal only when these IPSec SAs are successfully negotiated. When the Narrow Down Switch parameter in the IPSECPOLICY MO is set to ON, it is considered that an ACL rule in the ACL referenced by this IPSECPOLICY MO succeeds in negotiating an IPSec SA as long as only one IPSec SA is successfully negotiated.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • If the BFD detection switch has been turned on, ensure that the SeGWs also support the BFD function before running this command; otherwise, the configuration of the IPSec tunnel pair does not take effect.

  • The master and slave IPsec policies referenced by the IPsec tunnel pair must be configured. In addition, the IPsec policies must be bound to ports and one IPsec policy can be bound to only one port.

  • If the BFD detection switch has been turned on, ensure that the primary and secondary BFD sessions have been configured for the IPSec tunnel pair to be added before running this command. In addition, ensure that the source and destination IP addresses of either BFD session are the same as the local and peer IP addresses in the IKEPEER object that is referenced by the IPSec policy of the associated IPSec tunnel respectively in the same routing domain.

  • When the BFD detection switch has been turned on, the local IP address cannot be set to 0.0.0.0 for the IKEPEER object that is referenced by the primary or secondary IPSec policy of each IPSec tunnel pair.

  • Two IPSec policies of the same IPSec tunnel pair must reference the same ACL, and the ACL cannot be referenced by any other IPSec policies.

  • An IPSec policy can be referenced only by one IPSec tunnel pair.

  • The encapsulation mode must be set to TUNNEL for the IPSec proposal that is referenced by the primary or secondary IPSec policy of each IPSec tunnel pair.

  • For an IPSec tunnel pair, the IKE peers associated with the primary and secondary IPSec policies must be different from each other.

  • An automatically created IPSECPOLICY MO does not support IPSec tunnel pair.

  • System specifications: If the UMPT/UMDU/LMPT/GTMUb/GTMUc is the main control board, a maximum of 50 IPSec tunnel pairs can be configured, if the WMPT is the main control board, a maximum of 6 IPSec tunnel pairs can be configured.

  • Board specifications: A maximum of 50 IPSec tunnel pairs can be configured on a UMPT/UMDU/LMPT/UTRPc/UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9.

  • IPSec tunnel pair cannot coexist with master/slave IKE peers.

  • After an IKE peer that supports IKEv2 redirection is configured, the IPSECDTNL MO cannot be configured. After an IPSECDTNL MO is configured, the IKE peer that supports IKEv2 redirection cannot be configured.

  • It is recommended that the IPSec Switch Back Wait Time parameter be set to a value greater than 10s to prevent ping-pong switchovers due to intermittent disconnection of the primary tunnel.

IPSECSWITCHBACK IPSec Dual Tunnel Switch Back

Meaning: Indicates whether services can be switched back to the primary tunnel from the secondary tunnel after the former recovers in IPSec dual-tunnel scenarios. When this parameter is set to OFF, the NE does not enable the IPSec dual-tunnel switch back function. When this parameter is set to ON, the NE enables the IPSec dual-tunnel switch back function. If the secondary tunnel that carries services becomes faulty and the primary tunnel is working properly, services are switched to the primary tunnel immediately regardless of the setting of this parameter.

GUI Value Range: OFF(Off), ON(On)

Unit: None

MML Default Value: OFF(Off)

Recommended Value: OFF(Off)

Parameter Relationship: None

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
IPSECSWITCHBACKTM IPSec Switch Back Wait Time

Meaning: Indicates the period from the time the primary tunnel recovers to the time services are switched back to the primary tunnel in the case that services have been switched to the secondary tunnel after the primary tunnel is faulty in IPSec dual-tunnel scenarios. If the user runs the MOD IPSECDTNL command to change the value of this parameter during a back switchover, the changed value does not take effect until the next back switchover. The primary tunnel must keep working properly during the switchover. If the primary tunnel is disconnected, the time counting restarts. It is recommended that this parameter be set to a value greater than 10s to prevent ping-pong switchovers due to intermittent disconnection of the primary tunnel.

Example

To add an IPSec tunnel pair with the parameters as follows: IPSec Dual Tunnel ID: 0, Master Policy Group Name: PolicyGroup1, Master IPSec Sequence No.: 1, Slave Policy Group Name: PolicyGroup1, Slave IPSec Sequence No.: 2, BFD Detect Switch: ON, Master Tunnel's BFD Session ID: 10, Slave Tunnel's BFD Session ID: 20, IPSec Dual Tunnel Switch Back: ON, IPSec Switch Back Wait Time: 180, run the following command:
ADD IPSECDTNL: DUALID=0, MSPGN="PolicyGroup1", MSPSN=1, SSPGN="PolicyGroup1", SSPSN=2, BFDDTCTSW=ON, MBFDSN=10, SBFDSN=20, IPSECSWITCHBACK=ON, IPSECSWITCHBACKTM=180;
