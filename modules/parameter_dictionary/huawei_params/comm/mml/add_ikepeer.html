Add IKE Peer (ADD IKEPEER)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add an Internet Key Exchange (IKE) peer.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Before running this command, ensure that the associated IKE security proposal already exists.

  • System specifications: If a WMPT/GTMU/LMPT is used as the main control board, a maximum of 100 IKE peers can be configured for a base station. If a UMPTa/UMPTb/UMDU is used as the main control board, a maximum of 264 IKE peers can be configured for a base station. If a UMPTe is used as the main control board, a maximum of 392 IKE peers can be configured for a base station. If a UMPTg/UMPTga is used as the main control board, a maximum of 520 IKE peers can be configured for a base station. If a UMPT/UMDU is used as the main control board, a maximum of 256 IPv4 IKE peers and a maximum of 128 IPv6 IKE peers can be manually configured for a base station.

  • Board specifications: A UMPTa/UMPTb/UMDU supports the IKE peer specifications of 264. A UMPTe supports the IKE peer specifications of 392. A UMPTg/UMPTga supports the IKE peer specifications of 520. A UMPTa/UMPTb/UMDU supports a maximum of 264 IPv4 IKE peers, and a maximum of 128 IPv6 IKE peers. A UMPTe supports a maximum of 392 IPv4 IKE peers, and a maximum of 392 IPv6 IKE peers. A UMPTg/UMPTga supports a maximum of 392 IPv4 IKE peers, and a maximum of 520 IPv6 IKE peers. A UTRPc supports a maximum of 264 IKE peers. An LMPT/UCCU/UBBPe (excluding the UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9 supports a maximum of 100 IKE peers.

  • When the security is setup automatically, it is not recommended to configure the LOCALIP of the IKEPEER by running this command. If this IP is configured, it must be on the same physical port with the LOCIKEIPV4 of the security host.

  • IPSec tunnel pair cannot coexist with master/slave IKE peers.

  • Before configuring a slave IKE peer, ensure that the master IKE peer specified by the Master Peer Name parameter must exist.

  • The priorities of slave IKE peers corresponding to one master IKE peer must differ.

  • A master or slave IKE peer can be referenced by only one IPSec policy.

  • The Redundancy Flag parameter in the IKE peer referenced by the security host or security peer must be set to NONE(Non-redundancy).

  • After an IKE peer that supports IKEv2 redirection is configured, the IPSECDTNL MO cannot be configured. After an IPSECDTNL MO is configured, the IKE peer that supports IKEv2 redirection cannot be configured.

  • After IKEv2 Redirect Switch is set to ON in an IKE peer, this IKE peer can be referenced by only one IPSECPOLICY MO.

  • The redirection IP address sent by the peer end to the base station must be different from the Remote IP Address parameter in the IKE peer or the IP address that has been used by the base station. Otherwise, the redirection fails. The Remote IP Address parameter configured in an IKE peer cannot be the currently used redirection IP address sent by the peer to the base station.

  • The IKE peer takes effect on the board together with the IPSECBIND bearer MO. That is, the IKE peer does not take effect on any board when being configured, and takes effect on the board when the bearer MO (IPSECBIND) is configured.

  • User-configured IKE peers count in the specifications of automatically setup IKE peers even if the user-configured IKE peers are not referenced by any bearer.

  • [Co-MPT,NodeB,eNodeB,gNodeB]When the LOCALIP parameter under the IKE peer is set to 0.0.0.0, the IPRT MO or IPROUTE4 MO must be configured with its destination IP address set in same network segment as the peer IP address besides the SRCIPRT MO or SRCIPROUTE4 MO.

  • [Co-MPT,NodeB,eNodeB,gNodeB]If multiple IPv4 addresses on the same network segment are configured on an interface, the local IPv4 address in the IKEPEER object must be configured. Otherwise, IKE negotiation may fail.

  • [Co-MPT,eNodeB,gNodeB]The IPv6 IPSec redundancy switchover is performed based on the configured IKE peer priorities, regardless of the route priorities.

IPSECPREFRGSW IPSec PreFragment Switch

Meaning: Indicates whether packets can be fragmented before being encrypted. If this parameter is set to OFF and the IPVERSION parameter is set to IPv4 for an IKE peer, the IPv4 traffic is not fragmented, and the IPv6 traffic is fragmented based on the maximum MTU capability of the internal ports. If IPVERSION is set to IPv6 for an IKE peer, the internal system sets the MTU used by IPv4 and IPv6 traffic to the board maximum capability and fragments packets based on the board maximum capability.

If this parameter is set to ON, packets are fragmented before being encrypted. If the IPVERSION parameter is set to IPv4 for an IKE peer, IPv4 and IPv6 packets are fragmented based on the MTU value of the IKE peer. If the IPVERSION of the IKE peer is set to IPv6, IPv4 and IPv6 traffic is fragmented based on the MTU4 and MTU6 values of the tunnel interface, respectively.

GUI Value Range: OFF(Off), ON(On)

Unit: None

Actual Value Range: OFF, ON

MML Default Value: OFF(Off)

Recommended Value: OFF(Off)

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
MTU Maximum Transmission Unit

Meaning: Indicates the MTU of IPv4 or IPv6 before packets are encrypted when the IP protocol version of an IKE peer is IPv4. This parameter takes effect for both IPv4 and IPv6 traffic when the ACL type of the IPsec policy that references the IKE peer is IPv4+IPv6.

If the length of a packet before encryption exceeds the value of this parameter, the system fragments the packet based on the value of this parameter and then encrypts the fragmented packet. If the length of the encrypted packet exceeds the value of MTU in the ETHPORT MO, ETHCIPORT MO, ETHTRK MO, IPRT MO, IPROUTE4 MO, and INTERFACE MO, the encrypted packet will be fragmented again based on the MTU of the ETHPORT MO, ETHCIPORT MO, ETHTRK MO, IPRT MO, IPROUTE4 MO, or INTERFACE MO.

GUI Value Range: 46~9000

Unit: byte

Actual Value Range: 46~9000

MML Default Value: 1380

Recommended Value: 1380

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: If this parameter is set to an excessively large value, a packet is segmented for a second time within the system, which reduces the transmission performance. If this parameter is set to an excessively small value, the number of fragmented packets increases, increasing the encryption times. Moreover, this also reduces the effective payload of transmission. As a result, the bandwidth cannot be efficiently used, and transmission performance decreases.

Applicable Mode: G, U, L, N

Example

Example 1: To add an IKE peer with the parameters as follows: IKE Peer Name: ike, IKE Proposal ID: 10, Version: IKE_V1, Exchange Mode: AGGRESSIVE, IP Version: IPV4, Local ID Type: IPV4, Remote IP Address: 192.168.5.6, Pre-shared Key: *****, DPD Mode: PERIODIC, Local IP Address: 0.0.0.0, Redundancy Flag: SLAVE, Master Peer Name: master, Priority: 1, Certificate Source: CERTMK, Certificate File Name: eNodeBCert.pem, IPSec PreFragment Switch: OFF, run the following command: 
ADD IKEPEER: PEERNAME="ike", PROPID=10, IKEVERSION=IKE_V1, EXCHMODE=AGGRESSIVE, IPVERSION=IPV4, IDTYPE=IPV4, REMOTEIP="192.168.5.6", PKEY="*****", DPD=PERIODIC, LOCALIP="0.0.0.0", REDUNDANCYFLAG=SLAVE, MASTERPEERNAME="master", PRIORITY=1, CERTSOURCE=CERTMK, CERTNAME="eNodeBCert.pem", IPSECPREFRGSW=OFF;

Example 2: To add an IKE peer with the parameters as follows: IKE Peer Name: ikepeer, IKE Proposal ID: 1, Version: IKE_V2, IP Version: IPV4, Local ID Type: IPV4, Remote IP Address: 192.168.1.8, Pre-shared Key: *****, DPD Mode: PERIODIC, Local IP Address: 0.0.0.0, Redundancy Flag: NONE, Certificate Source: APPCERT, IPSec PreFragment Switch: OFF, run the following command: 
ADD IKEPEER: PEERNAME="ikepeer", PROPID=1, IKEVERSION=IKE_V2, IPVERSION=IPV4, IDTYPE=IPV4, REMOTEIP="192.168.1.8", PKEY="*****", DPD=PERIODIC, LOCALIP="0.0.0.0", REDUNDANCYFLAG=NONE, CERTSOURCE=APPCERT, IPSECPREFRGSW=OFF;

Example 3: To add an IKE peer with the parameters as follows: IKE Peer Name: ikepeer2, IKE Proposal ID: 1, Version: IKE_V2, IP Version: IPV4, Local ID Type: FQDN, Remote IP Address: 192.168.1.8, Pre-shared Key: *****, DPD Mode: PERIODIC, Local IP Address: 0.0.0.0, Redundancy Flag: NONE, Certificate Source: APPCERT, IPSec PreFragment Switch: OFF, run the following command: 
ADD IKEPEER: PEERNAME="ikepeer2", PROPID=1, IKEVERSION=IKE_V2, IPVERSION=IPV4, IDTYPE=FQDN, REMOTEIP="192.168.1.8", PKEY="*****", DPD=PERIODIC, LOCALIP="0.0.0.0", REDUNDANCYFLAG=NONE, CERTSOURCE=APPCERT, IPSECPREFRGSW=OFF;

Example 4: To add an IKE peer with the parameters as follows: IKE Peer Name: ikepeer6, IKE Proposal ID: 1, Version: IKE_V2, IP Version: IPV6, Local ID Type: IPV6, Pre-shared Key: *****, DPD Mode: PERIODIC, Certificate Source: APPCERT, run the following command: 
ADD IKEPEER: PEERNAME="ikepeer6", PROPID=1, IKEVERSION=IKE_V2, IPVERSION=IPV6, IDTYPE=IPV6,  PKEY="*****", DPD=PERIODIC, CERTSOURCE=APPCERT;
