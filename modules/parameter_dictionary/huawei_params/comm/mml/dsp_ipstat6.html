Display Statistical Information About IPv6 Packet (DSP IPSTAT6)

Network Element: BTS3900, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 LTE, BTS5900 5G

Function

Use this command to list the statistical information about IPv6 transmitted and received IP packets.

Note

  • [Co-MPT,eGBTS,eNodeB,gNodeB]Statistical information about IPv6 packet can be configured on a UMPT/UMDU.

  • [Co-MPT,eNodeB,gNodeB]When multiple VRF instances are configured on the UMPTg board, the number of IPv6 packets discarded by the UMPTg due to replay detection in all virtual routing domains is displayed in the default routing domain. This value is 0 for all non-default routing domains.

  • [Co-MPT,eNodeB,gNodeB]In the IPv4 and IPv6 IPsec hybrid scenario, packet statistics in all encryption directions are calculated based on the plaintext IP version, and packet statistics in all decryption directions are calculated based on the ciphertext IP version.

  • [Co-MPT,eNodeB,gNodeB]The maximum number of IPv6 packets discarded due to replay detection by the UMPTg per second is 65535. When the number of replayed IPv6 packets received per second is greater than 65535, the query result is less than the number of actually discarded replayed IPv6 packets.

  • [Co-MPT,eNodeB,gNodeB]Packets entering the IPSec module in the encryption direction are in plain text. Statistics are collected in all encryption directions based on the inner layer (encryption service IP protocol version + virtual routing domain).

  • [Co-MPT,eNodeB,gNodeB]Packets entering the IPSec module in the decryption direction are in cipher text. Statistics are collected in all decryption directions based on the outer layer (IKE tunnel IP protocol version + virtual routing domain).

  • [Co-MPT,eNodeB,gNodeB]The number of fragments that are discarded due to incomplete fragment reassembly within the timeout period is counted in the reassembly timeout statistics. The number of fragments discarded due to abnormal fragmentation or exceeding the board reassembly specifications is counted in the reassembly exception statistics. The UMPTg does not support the measurement of reassembly timeout and reassembly exception separately. The value of reassembly timeout packets is constantly 0, and reassembly timeout packets are counted in the statistics of reassembly exception packets.
