Add CRL-Updating Task (ADD CRLTSK)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a task of periodically updating a CRL.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • If the same CRL file has been loaded for a BS, running this command does not add any CRL record.

  • If the CRL is obtained using LDAP, the distinguish name in the LDAP server must be correctly set.

  • Board specifications: A UMPT/UMDU/LMPT/GTMUc/UTRPc/UCCU/UBBPe series (except UBBPe15)/LCOP/UBBPf series/UBBPF series/UBBPg series board supports a maximum of 6 periodic CRL updating tasks.

  • System specifications: If the WMPT/UMPT/UMDU/LMPT/GTMUc is the main control board, a maximum of 6 tasks of periodically updating CRLs can be configured.

  • When the ADD FTPSCLTDPORT command is executed to set FTP Server IP Address to 0.0.0.0, the corresponding destination port cannot take effect in the CRLTSK MO. If the non-default port needs to be used, run the ADD FTPSCLTDPORT command to configure the specified IP address.

  • When the Using CRL's Next Update parameter is set to DISABLE(Disable), it is recommended that the CRL Updating Period parameter in the CRLTSK MO be set to a period shorter than the interval between the effective date and next update date of the certificate file.

  • The file size of the CRL to be downloaded must be less than 2 MB. The size of a CRL in PEM format must be less than 256 KB.

  • If no source IP address is specified for the base station, the base station uses the effective local OM IP address (you can run the DSP OMCH command to query this IP address) to establish a connection. When active and standby OM channels are configured for a base station, it is recommended that users ensure connectivity from the local IP addresses of both the active and standby OM channels to that of the server. If a source IP address is specified for the base station but the source IP address is not the IP address of the board specified by the CERTDEPLOY MO, the base station fails to connect to the CRL server.

  • When setting the Minimum DH Length parameter for an NE, ensure that the value of this parameter is less than or equal to that configured on the peer device or ensure that the value of this parameter is DH_0 (adaptive Diffie-Hellman algorithm). Otherwise, the authentication between the NE and its peer device will fail and the CRL cannot be obtained.

  • If you have run the RMV CRL or ADD CRLTSK command, wait two minutes before running this command to obtain the CRL. Otherwise, the CRL may fail to be obtained.

  • When adding a CRLTSK object, ensure that the CA configuration for the issuer of the CRL file to be downloaded exist on the NE, or that the trust certificate and valid certificate chain for the issuer exist on the NE, thereby preventing CRL loading failures.

  • When adding a CRLTSK object, ensure that the TLSPOLICY used by CRLTSK exist on the NE.

MINDHLEN Minimum DH Length

Meaning: Indicates the minimum length of the Diffie-Hellman (DH) group allowed on the NE side when SSL connection is used and the peer certificate is authenticated. If the length of the DH key sent by the peer end is less than the value of this parameter when the DH is used as the key exchange algorithm in the algorithm set for authentication and negotiation, the SSL connection-based negotiation fails. The longer the DH key, the higher the security. When the value of this parameter is set to DH_0, peer SSL connection-based negotiation succeeds in spite of the DH key length.

Disuse statement: In later versions, the values DH_0, DH_512, and DH_1024 will be removed from the value range of this parameter. In the current version, this value can still be configured and take effect. Therefore, you are not advised to use the values DH_0(DH_0), DH_512(DH_512), and DH_1024(DH_1024).

GUI Value Range: DH_0(Adaptive Diffie-Hellman algorithm), DH_512(512-bit Diffie-Hellman group), DH_1024(1024-bit Diffie-Hellman group), DH_2048(2048-bit Diffie-Hellman group), DH_3072(3072-bit Diffie-Hellman group), DH_4096(4096-bit Diffie-Hellman group)

Unit: None

Actual Value Range: DH_0, DH_512, DH_1024, DH_2048, DH_3072, DH_4096

MML Default Value: DH_2048(2048-bit Diffie-Hellman group)

Recommended Value: DH_2048(2048-bit Diffie-Hellman group)

TLSSECCSSW TLS Secure Cipher Suite Switch

Meaning: Indicates the TLS security algorithm switch. When the switch is off, it is compatible with non-AEAD (Authenticated Encryption with Associated Data) and non-PFS (Perfect Forward Secrecy) weak security algorithm sets, which poses a security risk. When the switch is turned on, TLS does not support weak security algorithm sets other than AEAD and non-PFS, and only negotiates the security algorithm set. This parameter is invalid when a WMPT serves as the main control board. If this parameter is set to ON, the switch actually takes effect from OFF.

Unit: None

Example

To add a periodic task of obtaining the CRL with the parameters as follows: IP Version: IPV4, IP Address: 192.168.23.112, Using CRL's Next Update: DISABLE, Task ID: 0, Access Method: FTP, File Name: basestation.crl, Source IP: 0.0.0.0, Slave IP Address: 192.168.21.110, run the following command:
ADD CRLTSK: IPVERSION=IPV4, IP="192.168.23.112", ISCRLTIME=DISABLE, TSKID=0, CRLGETMETHOD=FTP, FILENAME="basestation.crl", SIP="0.0.0.0", SLVIP="192.168.21.110";
