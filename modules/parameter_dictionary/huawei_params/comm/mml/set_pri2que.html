Set Mapping from Priority to Inner Queue (SET PRI2QUE)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to set the mapping between the transport bearer priority (only DSCP is supported) and the inner queue.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • The lowest priorities of queues 0 through 6, ranging from PRI0 corresponding to queue 0 to PRI6 corresponding to queue6, are configured in descending sequence. That is, the priorities of neighboring queues should meet the following requirement: The value of PRI(x) is greater than or equal to that of PRI(x+1).

  • If the lowest priorities of neighboring queues x and x+1 are the same, that is, the values of PRI(x) and PRI(x+1) are the same, it indicates that no priority corresponds to queue x+1.

  • The SET DIFPRI and SET PRI2QUE commands can be used together to query the mapping between: (1) signaling priority and inner scheduling queue; (2) OM priority and inner scheduling queue.

  • When the transmission resource group that carries the low-level OM data becomes congested and the backpressure switch (see the notes of the SET RSCGRPALG command.) is turned on, the transmission rate of the low-level OM data decreases until the congestion is relieved.

  • [Co-MPT,eNodeB,gNodeB]For LTE and NR, the MOD UDTPARAGRP and SET PRI2QUE commands reflect the mapping between the service priority and the inner scheduling queue.

Parameters

ID Name Description
VRFIDX VRF Index

Meaning: Indicates the index of a VRF instance. UMTS currently supports the default routing domain only (the VRF index is 0).

Disuse statement: This parameter will be deleted in later versions. To mitigate the risk, it is recommended that this parameter not be used.

GUI Value Range: 0~7

Unit: None

Actual Value Range: 0~7

MML Default Value: None

Recommended Value: 0

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
PRI0 PriOfQue0

Meaning: Indicates the lowest priority of queue 0. If the Differentiated Services Code Point (DSCP) value of a service packet is greater than or equal to this parameter value, the service packet is assigned to queue 0.

Disuse statement: This parameter will be deleted in later versions. In the current version, this parameter can be configured and takes effect when the Transmission Configuration Mode parameter in the GTRANSPARA MO is set to OLD, and this parameter cannot be configured and is replaced by the DSCP parameter in the DSCP2QUERFF MO when the Transmission Configuration Mode parameter in the GTRANSPARA MO is set to NEW. Therefore, avoid using this parameter.

GUI Value Range: 0~63

Unit: None

Actual Value Range: 0~63

MML Default Value: None

Recommended Value: 48

Parameter Relationship:

-Configuration constraints:

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In a PRI2QUE MO, PRI0 must be greater than or equal to PRI1.

Service Interrupted After Modification: No (And no impact on the UE in idle mode)

Impact on Radio Network Performance: A lower priority of the real-time service queue leads to the preemption of non-real-time services by excessive real-time-services. A higher priority of real-time service queue leads to degrading of real-time services to the non-real-time service queue, resulting in the preemption of real-time services by non-real-time services.

Example

To set the priority of a queue with the parameters as follows: VRF Index: 0, PriOfQue0: 48, PriOfQue1: 40, PriOfQue2: 32, PriOfQue3: 24, PriOfQue4: 16, PriOfQue5: 8, PriOfQue6: 0, run the following command:
SET PRI2QUE: VRFIDX=0, PRI0=48, PRI1=40, PRI2=32, PRI3=24, PRI4=16, PRI5=8, PRI6=0;
