Start Cross Feeder Test (STR CROSFEEDTST)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to detect a crossed feeder connection. Crossed feeder connection is a wiring error in twisted pair cabling where both the main and diversity in a sector are incorrectly connected to different antennas at both sides.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • This command applies to the scenario where RF modules are in 2T2R mode. If this command is executed in other scenarios, the result may be incorrect.

  • This command does not apply to the scenario where all antennas of one sector are connected to another sector.

  • This test is an offline test and the execution of this command interrupts services. Running this command on a multi-mode RF module of a multi-mode BS or on RF modules of different modes that share the antenna system will interrupt services of both modes.

  • The VSWR test has a great impact on the precision of this test because the VSWR will cause a gain loss. You are advised to perform a high-precision VSWR test before running this command. If the VSWR is greater than 2.5, you are not advised to run this command.

  • In the scenario where a filter is configured in the antenna system, the STFREQ and ETFREQ parameters in this command must be set to the start frequency and end frequency of the filter, respectively.

  • 1. A crossed feeder connection test must involve two or more sectors (cells) working in the same frequency band and the total number of antennas in these sectors must be greater than or equal to 3.

    (1) The crossed feeder connection test is not supported if only one or no sector in the specified list has been configured.

    (2) The crossed feeder connection test is not supported if an omnidirectional antenna is configured in the base station.

    (3) A crossed feeder connection test does not involve cells served by multiple RRUs/RFUs or distributed cells.

    (4) A crossed feeder connection test does not involve sectors with their equipment configured in beam mode.

    (5) A crossed feeder connection test does not involve a frequency band if the involved sectors are configured with different numbers of antennas working in the same frequency band.

    (6) A crossed feeder connection test does not involve unavailable RF modules.

    (7) A crossed feeder connection test does not involve RF modules which do not support crossed feeder connection tests.

    (8) A crossed feeder connection test involves an antenna only if the channel of the antenna can both transmit and receive data.

  • If the user specifies the start frequency and end frequency, the base station selects frequencies in the intersection of the RF module capability and the frequency band (between the start frequency and end frequency) to perform tests. If a specific frequency is not manually specified, the BTS selects a frequency to perform a test according to the intersection set of the RF module support capability and the preconfigured granted downlink frequency band. You can run the ADD AUTHDLFREQRANGE command to configure the granted downlink frequency band. If the granted downlink frequency band is not configured, the BTS selects a frequency to perform a test according to the RF module support capability. However, this may cause the BTS to use an ungranted frequency to perform a test.

  • A crossed feeder connection test fails if the transmit power of an RF module is abnormal.

  • If crossed feeder connections are detected, you need to check whether an external filter or narrowband filter equipment exists in the antenna system first.

  • "Unknown" in the cross feeder test result means that indicates that the system cannot determine whether the cross feeder connection exists. In this case, you need to manually check the connection.

  • [eNodeB,gNodeB]This command does not apply to RRU working in TDL_IR protocol.

Output Description

Field Description

Sector No.

Indicates the number of the sector. If sectors are not configured, the value of this parameter is NULL.

RESULT

Indicates the result of the cross feeder test.

Frequency Band

Indicates the frequency band supported by sector antennas.

Cabinet No.

Indicates the cabinet number of the RRU or RFU where the TX channel is located.

Subrack No.

Indicates the subrack number of the RRU or RFU where the TX channel is located.

Slot No.

Indicates the slot number of the RRU or RFU where the TX channel is located.

TX Channel No.

Indicates the number of the TX channel of the RRU or RFU.
