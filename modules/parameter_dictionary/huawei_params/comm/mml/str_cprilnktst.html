Start CPRI Link Performance Test (STR CPRILNKTST)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to start the performance test on a CPRI link. After the performance test is performed on a CPRI link, the performance test results will be reported, including the valid performance test period, actual loopback type, number of errored seconds, number of severely errored seconds, number of unavailable seconds, and number of bit errors. These results are used to check the quality of the CPRI link.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Command Restrictions:

    The CPRI link loopback does not support the ring topology, RHUB board, or branch chain/ring on the RHUB.

    The CPRI link performance test can be started only between two adjacent nodes.

    Only one CPRI link performance test can be performed on a chain/ring at a time.

    The CPRI link performance test and loopback set must be performed on the same segment of a CPRI link.

    Before starting the CPRI link performance test, you must block all downstream boards (including the lower-level node) that can be blocked on the CPRI link to be tested. In separate-MPT scenarios using the CPRI MUX feature, you must also block all downstream boards (including the lower-level node) that can be blocked on the CPRI link to be tested on the converged party side.

    In separate-MPT scenarios using the CPRI MUX feature, the CPRI link performance test for the converging chain/ring cannot be started on the converged side.

    If the CPRI link performance test results contain "The operation timed out", the status of links on the control and service planes of all downlink boards on the CPRI link to be tested is unknown. Only after the performance test period specified by users ends, the boards can restore to the status before the CPRI link performance test, and a new CPRI link performance test can be started.

    Before starting a CPRI link performance test, ensure that loopback has been set on the CPRI link and the remaining loopback time is greater than or equal to 1 minute. If RRUs are directly connected to a BBU, set the loopback in the network management system (NMS) connecting to the base station. If RRUs are connected to a BBU through other devices, such as an optical transport network (OTN) device, set loopback in the NMS connecting to these devices. If loopback is not set, the CPRI link performance test is invalid.

    A new CPRI link performance test can be started 10s after the STR CPRILNKTST command output is displayed.

    If the CPRI port on the specified upper-level node is blocked or a breakpoint is set on this node, a CPRI link performance test cannot be started.

    If an operation such as blocking the CPRI port on an upper-level node is performed and the CPRI link is disconnected after a CPRI link performance test is started, the test results may be inaccurate.

    Some boards do not support the command. If this command is executed on these boards, an error message will be displayed. To test the performance of a CPRI link on these boards, check the SFP- and CPRI-related alarms such as ALM-26232 BBU Optical Module Transmit/Receive Fault, ALM-26234 BBU CPRI Interface Error, and ALM-26233 BBU CPRI Optical Interface Performance Degraded.

    The eCPRI protocol does not support the CPRI link performance test.

  • Impact on System:

    After the CPRI link performance test is started, the maintenance links of all downlink boards (including the lower-level board) on the CPRI link to be tested will be interrupted.

    After a CPRI link performance test starts, if links cannot be established for the associated boards or the established links cannot work at the maximum CPRI line rate, run the STR CPRILBRNEG command to initiate negotiation.

Output Description

Field Description

UpperLevelNodeCabinetNo

Indicates the cabinet number of the upper-level node of a CPRI link.

UpperLevelNodeSubrackNo

Indicates the subrack number of the upper-level node of a CPRI link.

UpperLevelNodeSlotNo

Indicates the slot number of the upper-level node of a CPRI link.

UpperLevelNodePortNo

Indicates the port number of the upper-level node of a CPRI link.

UpperLevelNodeSubPortNo

Indicates the subport number of the upper-level node of a CPRI link.

LowerLevelNodeCabinetNo

Indicates the cabinet number of the lower-level node of a CPRI link.

LowerLevelNodeSubrackNo

Indicates the subrack number of the lower-level node of a CPRI link.

LowerLevelNodeSlotNo

Indicates the slot number of the lower-level node of a CPRI link.

ValidTestPeriod(s)

Indicates the valid performance test period of a CPRI link. If CPRI link loopback is in progress, set this parameter to the smaller value between the remaining CPRI link loopback time minus 10 and the CPRI link performance test period minus 10, ensuring that the CPRI link performance test can be completed before the CPRI link loopback ends. If CPRI link loopback has ended, set this parameter to the CPRI link performance test period minus 10.

ActualLoopbackType

Indicates the actual loopback type during the CPRI link performance test. The value of this parameter can be Serial Loopback, Parallel Loopback, Logic Loopback, or No Loopback. The value Serial Loopback indicates that the loopback point is in the serial domain of the SERDES chip in the CPRI port on the loopback device. The value Parallel Loopback indicates that the loopback point is in the parallel domain of the SERDES chip in the CPRI port on the loopback device. The value Logic Loopback indicates that the loopback point is in the user logic implementation component (FPGA/ASIC chip) in the CPRI port on the loopback device. Loopback types vary depending on device types. The system automatically selects loopback nearest to the CPRI port on the loopback device. The serial loopback is nearest to the CPRI port, the parallel loopback is nearer to the CPRI port, and the logical loopback is furthest from the CPRI port.

ErroredSecondNumber

Indicates the number of errored seconds in the performance test period of a CPRI link. If bit errors occur or the port fails to properly receive or transmit data within a second, this second is an errored second.

SeverelyErroredSecondNumber

Indicates the number of severely errored seconds in the performance test period of a CPRI link. If the bit error rate is greater than the value of Severely Errored Second Threshold or the port fails to properly receive or transmit data within a second, this second is a severely errored second.

UnavailableSecondNumber

Indicates the number of unavailable seconds (UASs) in the performance test period of a CPRI link. If 10 consecutive SESs occur on a CPRI link, UASs start from the first SES. If 10 consecutive non-SESs occur over on the CPRI link, UASs stop at the first non-SES.

BitErrorNumber

Indicates the number of bit errors in the performance test period of a CPRI link.
