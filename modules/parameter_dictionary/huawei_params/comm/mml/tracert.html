Trace Route (TRACERT)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to start route tracing. Route tracing obtains the information about the gateways on the host-to-destination route by sending test packets on the route. By running this command, you can check whether the route is reachable and locate the position where a network connection failure occurs.

Note

  • You can press Ctrl+Q or run the STP PATHCHK command to stop running the TRACERT command.

  • The PING, PING6, TRACERT, TRACERT6, CFMTRACE, CFMPING, and UDPECHO commands cannot be executed simultaneously on one board.

  • If the source IP address is not specified, it must be the configured device IP address or IPv4 address or the local IP address of the remote maintenance channel. You can run the LST DEVIP, LST IPADDR4 and LST OMCH commands to query these two types of IP addresses, respectively.

  • If a destination IP address elicits no response during route tracing but can be pinged, check and remove redundant IP addresses on the egress port, which are on the same network segment as the planned IP address.

  • In TRACERT packets, "*" indicates that the detection expires, "!" indicates that the port is unreachable, "!N" indicates that the network is unreachable, "!Y" indicates that the IP address is unreachable, "!P" indicates the protocol is unavailable, "!S" indicates that the source route fails, and "!H" indicates that the host is unreachable.

  • If the destination IP address is used to search for the outbound interface or next hop, TRACERT detection is not performed.

  • If the base station is only configured with the source IP route, the source IP address must be specified.

  • In backplane transmission scenarios, the next-hop IP address cannot be displayed for the backplane in the output of the TRACERT command.

  • When the tracert operation is continuously performed, the first UDP packets in each round of tracert have the same destination port No..

  • In IPsec networking scenarios, if IPSec PreFragment Switch in the IKEPEER object is set to ON and DF Switch in the TRACERT object is also set to ON, the MTU of the fragment before encryption is not displayed in the TRACERT command output.

  • When the TRACERT command is executed, the destination IP address cannot set to the local IP address.

  • [Co-MPT,NodeB,eNodeB,gNodeB]If a source IP address is not specified or is 255.255.255.255, the base station searches the route closest to the destination IP address in the routing table according to the longest mask matching rule. If the masks have the same length, the base station selects the route with a higher priority and uses the most suitable IP address of the egress port corresponding to the route as the source IP address according to the longest mask matching rule. If the route tracing data flow matches the routes of both the source address and destination address, the base station may fail to select a route. It is recommended that a source IP address be specified for route tracing.

  • [Co-MPT,NodeB,eNodeB,gNodeB]When the TRACERT command is executed, the transmitted packets and received packets related to this command are UDP packets and ICMP packets, respectively.

  • [NodeB,eNodeB,gNodeB]If the route corresponding to the destination IP address is a tunnel route, the source IP address must be specified.

Example

To start route tracing with the parameters as follows: Slot No.: 6, Source IP: 192.168.164.11, Destination IP: 10.141.142.22, Continuing TRACERT: ENABLE, run the following command:
TRACERT: SN=6, SRCIP="192.168.164.11", DSTIP="10.141.142.22", CONTRACERT=ENABLE;
The result is shown as follows:
