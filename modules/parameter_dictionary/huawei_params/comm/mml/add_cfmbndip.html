Add Binding IP Address to CFMRMEP (ADD CFMBNDIP)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a binding relationship between an RMEP and an IP address. The binding relationship between an RMEP and an IP address can be used for route interlock.

Note

  • The RMEP must be configured before the IP address is bound to an RMEP.

  • A maximum of 4 IP addresses can be bound to each CFMRMEP.

  • Two CFMRMEPs of one maintenance association (MA) cannot be bound to the same IP address in the same routing domain.

  • The IP address bound to a CFMRMEP must be the next hop IP address of the device IP address in the same routing domain configured for the port of the CFMMEP in the corresponding MA. Otherwise, route association cannot be triggered.

  • System specifications: If the WMPT/GTMUb/GTMUc is the main control board, a maximum of 32 CFMBNDIP objects can be configured. If the LMPT/UMPT/UMDU is the main control board, a maximum of 256 CFMBNDIP objects can be configured.

  • [Co-MPT,NodeB,eNodeB,gNodeB]A CFM binding IP address cannot be used for source address route interlock.

  • [Co-MPT,NodeB,eNodeB,gNodeB]Board specifications: A maximum of 64 CFMBNDIP objects can be supported on a UMPT/LMPT/UMDU/UTRPc/UTRP (subboard type: UEOC/UQEC)/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UCCU/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9. A maximum of 16 CFMBNDIP objects can be supported on a WMPT. A maximum of 32 CFMBNDIP objects can be supported on a GTMUb/GTMUc.

  • [NodeB]When adding a CFMBNDIP MO, if an error message, indicating that the MO cannot be added because its dependent MO does not exit, is displayed, check whether the CFMRMEP MO exists.

BNDIP IP Address

Meaning: Indicates the IP address of the Ethernet port or Ethernet trunk corresponding to an RMEP. The binding IP address must be different from the existing local IP address or the IP address of any effective port (including the physical port and loopback port). The binding IP address must be different from the local IP address dynamically negotiated on the PPP or MLPPP link. During the binding of an IP address, an error messaged indicating IP address conflicts may be displayed. In this case, list the existing IP address in the system that conflicts with the IP address to be bound by running the related MML commands. Then, manually resolve the IP address conflicts. To list the IP address, run the LST DEVIP, DSP DEVIP, LST IPADDR4, or DSP IPADDR4 command. To list the local IP address of the remote maintenance channel, run the LST OMCH or DSP OMCH command. To list the local IP address of the PPP link, run the LST PPPLNK or DSP PPPLNK command. To list the local IP address of the MLPPP group, run the LST MPGRP or DSP MPGRP command. To list the IP address of the local maintenance channel, run the LST LOCALIP or DSP LOCALIP command.

GUI Value Range: Valid IP address

Unit: None

Actual Value Range: Valid IP address

MML Default Value: None

Recommended Value: None

Parameter Relationship:

-Configuration constraints:

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]BNDIP in a CFMBNDIP MO must be a valid IP address of class A, B, or C. In addition, it cannot be set to 0.x.x.x or 127.x.x.x (including 0.0.0.0).

Service Interrupted After Modification: N/A

Example

To bind an IP address to a CFM RMEP with the parameters as follows: MD Name: CHINA, MA Name: SHANGHAI, RMEP ID: 2000, IP Address: 192.168.2.2, run the following command: 
ADD CFMBNDIP: MDNAME="CHINA", MANAME="SHANGHAI", RMEPID=2000, BNDIP="192.168.2.2";
