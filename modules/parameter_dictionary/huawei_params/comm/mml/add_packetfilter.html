Add Packet Filter (ADD PACKETFILTER)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a packet filtering object. A packet filtering object binds an ACL to a physical port so that IP packets that are received on the physical port can be filtered by the ACL.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • After being added to an Ethernet trunk, the Ethernet port cannot be bound to a packet filtering object independently. After being bound to a packet filtering object, the Ethernet port cannot be added to the Ethernet trunk.

  • If ACTION in the ACL rule that is bound to a packet filtering object is set to DENY, the data that matches the rule will be discarded.

  • The L2 packet filtering function processes not only packets with VLAN tags but also packets without VLAN tags. If the L2 packet filtering function prohibits the admission of packets that have no VLAN tags, all packets without a VLAN tag are discarded, regardless of the protocol types.

  • If a base station cannot be maintained by the EMS, it will attempt to restore the OM channel. If user-defined configurations are valid at this time, the base station automatically starts DHCP detection at the currently available transmission link. In this case, if a packet filter is found to have been configured when the base station is in the LISTEN state, the base station will automatically modify the ACL rule that will filter out DHCP broadcast packets in the advanced ACL referenced by this packet filter, to ensure the successful DHCP detection. Alternatively, the base station will add an ACL rule that allows DHCP broadcast packets to pass through. After the OM channel has been successfully established and kept alive for 30 minutes, the base station restores the ACL rule according to the user-defined configurations.

  • When the DHCP procedure succeeds and the BS attempts to restore the remote maintenance channel, if the user has configured the packet filter but the TCP packets from MAE to the BS will be filtered, the BS automatically modifies the ACL rule that will filter out the TCP packets or adds a rule to the advanced ACL used by this packet filter to permit the packets from MAE to the OM IP of the BS.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering and the system automatically creates ACL rules, the created ACL rules are added to all the ACL groups referenced by the packet filtering that supports the ACL rule automatic setup and deletion function if the base station's IP address in the data flow is 0.0.0.0 or the IP address is configured on a loopback port. Otherwise, the created ACL rules are added only to the ACL groups referenced by the packet filtering of the port on which the local IP address is configured.

  • This operation may interrupt the services or OM channels. It is recommended that you determine whether to enable the automatic configuration data rollback function depending on scenarios. For details, see the help of the CFM CB command.

  • Board specifications: A maximum of 4 packet filters can be configured on a WMPT/UMPT/UMDU/LMPT/UTRPc/UTRP (subboard type: UQEC)/UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9. A maximum of 2 packet filters can be configured on a GTMUc/UTRP (subboard type: UEOC).

  • System specifications: If the LMPT/WMPT/GTMUb/GTMUc/UMDU is the main control board, a maximum of 4 packet filters can be configured. If the UMPT is the main control board, a maximum of 6 packet filters can be configured.

  • Only one packet filtering rule can be added on a port.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering, the Match Behavior parameter must be set to DENY(Deny) for packet filtering, that is, the whitelist mode must be used.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering, the ACL referenced by packet filtering cannot contain manually created ACL rules that are numbered from 50000 to 59999 (the value of the Auto Config Flag parameter is Manual Created when queried by running the LST ACLRULE command). If these ACL rules exist in the ACL, they must be manually deleted to enable the ACL rule automatic setup and deletion function.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering and if the required ACL rule has existed, the system will use the existing one.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering and if multiple data flows match the same ACL rule, the system will reuse the ACL rule for these data flows. In this case, the corresponding ACL rule whose CTRL MODE is AUTO_MODE can be deleted only when all data flows are deleted.

  • After the system starts, it checks the ACL rules created for packet filtering based on the ACL rules that are automatically created to ensure that the automatically created ACL rules match the configured data flows, and the unmatched ACL rules that are automatically created and have CTRL MODE set to AUTO_MODE will be deleted.

  • After the ACL rule automatic setup and deletion function is enabled for packet filtering, the system automatically creates 6 ACL rules for the active OM channels and 6 ACL rules for the standby OM channels in the ACL that supports auto-setup. The ACL that supports auto-setup refers to the one referenced by packet filtering that supports the ACL rule automatic setup and deletion function. The destination ports of the 6 ACL rules are as follows: 6007, 6006, 6000, 443, 4443, and 45300. As limited by the specifications of ACL rules, it is recommended that sufficient ACL rule numbers be reserved for OM channels data connection to ensure the OM channels connection.

  • When the ACL rule automatic setup and deletion function is disabled for a packet filter, the base station deletes the ACL rule created through the ACL rule automatic setup and deletion function and whose CTRLMODE is set to AUTO_MODE. To prevent services from being affected, it is recommended that users check which ACL rule is removed and manually add an ACL rule to ensure connectivity.

  • When a packet filtering object is added to a UTRP (subboard type: UEOC/UQEC) by running this command, the total number of ACL rules referenced by all packet filters cannot exceed 48. The same ACL rules in one ACL referenced by multiple packet filters are regarded as one ACL rule.

  • Before this command is executed, if the ACL on which packet filtering depends does not have a bearer object (packet filtering or IPSec policy group binding) on the board for which packet filtering is configured, the ACL will try to take effect on the board. If the ACL does not take effect, the packet filtering may also not take effect.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering, the system automatically creates an ACL rule for an FTP link which connects to the base station using the local IP address of the remote maintenance channel. If the FTP link is not used for more than 24 hours, the system automatically removes the ACL rule.

  • In FTP scenarios, the automatic ACL rule configuration and deletion function for packet filtering must be enabled before the FTP service is started. If automatic ACL rule configuration for packet filtering is enabled after the FTP service is started, the ACL rules used by the FTP service will not be automatically generated, and the FTP link in use will be disconnected. In this case, you need to restart the FTP upload and download services.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering, the system automatically creates advanced ACL rules and matches them with the following data flows: OM channels, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, PKI, and DNS server. If these data flows are added or deleted, the ACL rules whose CTRLMODE is AUTO_MODE will be added to or deleted from the ACL that supports the ACL rule automatic setup and deletion function, that is, the ACL referenced by the packet filtering that supports the ACL rule automatic setup and deletion function. If any of the preceding data flows is modified, the corresponding ACL rule that has been created automatically will be re-created.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering, the creation of ACL rules will be delayed, and the OM channels, manually created SCTP links, manually created IP paths, time services, clock services, IKE peers, PKI, and DNS server matching these ACL rules will be interrupted.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]When the switch for limiting the peer IP address for the remote maintenance channel is enabled, the peer IP address in the ACL rules for the automatically created OMCH is automatically restricted to the IP address for the MAE to log in to the base station when the base station is in the stable state. In this case, the destination port numbers of the ACL rules that have been automatically generated for the remote maintenance channel are 6007, 6006, 6000, 443, 4443, and 45300. If the OM service over these ports connecting the MAE or other tools to the base station does not use the IP address used for login of the MAE to the base station, ACL rules must be manually configured before access is allowed to the base station. For example, the MAE cluster may use multiple IP addresses to access the base station OM service, and the NetEco (6007), TraceServer (6007), or NIC (6000, 6006) that is independently deployed uses a non-MAE IP address to access the base station OM service.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple packet filters reference the same ACL, the ACL rule automatic setup and deletion switches must be either turned on or off for all these packet filters. If the ACL rule automatic setup and deletion switches for some packet filters are turned on while those for other packet filters are turned off, all the switches are regarded as having been turned on.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple packet filtering objects reference the same ACL, the OMCH peer IP limit switches must be either turned on or off for all these packet filters. If the OMCH peer IP limit switches for some packet filtering objects are turned on while those for other packet filters are turned off, all the switches are regarded as having been turned on.

  • [Co-MPT,NodeB,eNodeB,gNodeB]If a base station cannot be maintained by the EMS, it will attempt to restore the OM channel. If user-defined configurations are valid at this time, the base station automatically starts DHCP detection or DHCPv6 detection at the currently available transmission link. In this case, if a packet filter is found to have been configured when the base station is in the LISTEN state, the base station will automatically modify the ACL rule that will filter out DHCP broadcast packets or DHCPv6 packets in the advanced ACL referenced by this packet filter, to ensure the successful DHCP detection or DHCPv6 detection. Alternatively, the base station will add an ACL rule that allows DHCP broadcast packets or DHCPv6 packets to pass through. After the OM channel has been successfully established and kept alive for 30 minutes, the base station restores the ACL rule according to the user-defined configurations.

  • [Co-MPT,NodeB,eNodeB,gNodeB]When the MAE is deployed in distributed mode or uses the remote HA system, you are advised to manually configure access rules for all MAE addresses in advance. Otherwise, the base station may be disconnected during manager migration.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple PACKETFILTER objects reference the same ACL, the value of Match Behavior in these PACKETFILTER objects must be the same. IF any value is different, the value of Match Behavior in the PACKETFILTER objects that first takes effect prevails.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If the ACL rule automatic setup and deletion function is enabled for a packet filter when the configured ACL rules are about to reach the maximum number, the base station adopts a best effort solution. That is, the base station creates ACL rules first for OM channels, then for time services, clock services, manually created IKE peers, and PKI, and finally for the DNS server, manually created SCTP links, and manually created IP paths. When the maximum ACL rules have been configured, no ACL rule can be created for the OM channels, time services, clock services, manually created IKE peers, PKI data flows, DNS server, manually created SCTP links, or manually created IP paths. In this case, users need to properly plan the transport networking and allocate ACL rules.

  • [Co-MPT,eNodeB,gNodeB]If multiple PACKETFILTER objects reference the same ACL6, the value of Match Behavior in these PACKETFILTER objects must be the same.

  • [Co-MPT,eNodeB,gNodeB]When the DHCP procedure or DHCPv6 procedure succeeds and the BS attempts to restore the remote maintenance channel, if the user has configured the packet filter but the TCP packets from MAE to the BS will be filtered, the BS automatically modifies the ACL rule that will filter out the TCP packets or adds a rule to the advanced ACL used by this packet filter to permit the packets from MAE to the OM IP of the BS.

  • [Co-MPT,eGBTS]When the main control board is the GTMUc, the system does not support the ACL rule automatic setup and deletion function for packet filtering.

  • [eNodeB,gNodeB]If ACTION in the ACL rule that is bound to a packet filtering object is set to PERMIT, the data that matches the rule will be allowed to pass.

  • [NodeB]When the main control board is a WMPT, the system does not support the ACL rule automatic setup and deletion function for packet filtering.

  • [NodeB]When the main control board is a WMPT, the subboard type is BACK_BOARD, and the port type is TUNNEL, the base station does not support packet filtering.

  • [NodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering, the system automatically creates advanced ACL rules and matches them with the following data flows: OM channels, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, and PKI. If these data flows are added or deleted, the ACL rules with CTRLMODE set to AUTO_MODE will be added to or deleted from the ACL that supports the ACL rule automatic setup and deletion function, that is, the ACL referenced by the packet filtering that supports the ACL rule automatic setup and deletion function. If the configuration of any of these data flows is modified, the corresponding ACL rule that has been created automatically will be re-created.

  • [NodeB]If the ACL rule automatic setup and deletion function is enabled for a packet filter when the configured ACL rules are about to reach the maximum number, the base station adopts a best effort solution. That is, the base station creates ACL rules first for OM channels, then for time services, clock services, manually created IKE peers, and PKI, and finally for manually created SCTP links, and manually created IP paths. When the maximum ACL rules have been configured, no ACL rule can be created for the OM channels, time services, clock services, manually created IKE peers, PKI, manually created SCTP links, or manually created IP paths. In this case, users need to properly plan the transport networking and allocate ACL rules.

  • [NodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering, the creation of ACL rules will be delayed, and the OM channels, manually created SCTP links, manually created IP paths, time services, clock services, IKE peers, and PKI data flows matching these ACL rules will be interrupted.

Example

Example 1: To add a packet filter with the parameters as follows: Slot No.: 6, Subboard Type: BASE_BOARD, Port Type: ETH, Filter Mode: ADV_AND_L2, Advanced ACL ID: 3000, Layer 2 ACL ID: 4000, ACL Rule Automatic Setup and Deletion Switch: OFF, run the following command: 
ADD PACKETFILTER: SN=6, SBT=BASE_BOARD, PT=ETH, FM=ADV_AND_L2, ACLID=3000, ACLID2=4000, ACLAUTOSWITCH=OFF;
Example 2: To add a packet filter with the parameters as follows: Slot No.: 6, Subboard Type: BASE_BOARD, Port Type: ETH, Filter Mode: ADV_ACL, Advanced ACL ID: 3000, ACL Rule Automatic Setup and Deletion Switch: ON, run the following command: 
ADD PACKETFILTER: SN=6, SBT=BASE_BOARD, PT=ETH, FM=ADV_ACL, ACLID=3000, ACLAUTOSWITCH=ON;
