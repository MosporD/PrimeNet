Add IP Clock Link (ADD IPCLKLINK)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add an IP clock link. For a HW_DEFINED IP clock link or OC_SLAVE IP clock link compliant with IEEE 1588 V2, if the NE can properly obtain synchronization signals from the IP clock server, this link becomes available. For the OC_MASTER link, if the NE is configured with an external reference clock source for supplying reference clock signals, the external reference clock source is locked, and the clock link is set up, the NE can provide clock signals for lower-level NEs.

Note

  • The system supports a maximum of three IP clock links, and all the links must be compliant with the same type of protocol.

  • After an IP clock link is added, the IP clock is only an optional reference clock source for the system.

  • The client IP address must be configured on the same board as the physical link transmitting IP clock signals.

  • In non-hybrid clock synchronization mode, if two OC_SLAVE clock links comply with the IEEE 1588v2 protocol, Cabinet No., Subrack No., Slot No., Clock Net Mode, Profile Type, Compensation, Delay Type, Automatic Compensation Switch, and Priority must be set to the same values for these two links.

  • Any transmission network faults may lead to failures in executing this command.

  • When an OC_SLAVE clock link compliant with IEEE 1588 V2 uses the G.8265.1, 1588V2_16.1 or G.8275.2 protocol, the server needs to support the packet sending frequency requested by the NE so that the server can send synchronization packets at the requested frequency.

  • For a 1588 OC_SLAVE link, if layer 3 multicast networking is used for 1588, Port Type in the DEVIP MO or in the INTERFACE MO associated with the IPCLKLNK MO of the client cannot be set to LOOPINT.

  • The parameters for an IPv6 clock link can be configured only when IPv6 transmission is configured.

  • The OC_SLAVE IP clock link compliant with IEEE 1588 V2 is valid only configured in the default routing domain.

  • For an OC_SLAVE IP clock link compliant with IEEE 1588 V2, when the Profile Type parameter is set to IEEE1588V2_16.1, the value of the Announce Freq parameter is 1/16(1/16), 1/8(1/8), 1/4(1/4), 1/2(1/2), 1.0(1.0), 2.0(2.0), 4.0(4.0), or 8.0(8.0). The value 1/16(1/16) is not recommended in the protocol and can take effect only when the clock server supports this configuration.

  • For an OC_SLAVE IP clock link compliant with IEEE 1588 V2, when the Profile Type parameter is set to IEEE1588V2_16.1, the value range of the Negotiate Duration parameter is 60 to 1000, which is smaller than the range recommended in the protocol (10 to 1000).

  • If time synchronization is used, adding an IEEE 1588 V2 clock link to a UTRPc port interrupts all the services carried on the port for about 3s.

  • The priority is invalid for the OC_MASTER IP clock link compliant with IEEE 1588 V2.

  • The OC_MASTER clock link compliant with 1588 protocols is valid only if a UCCU, UBBPe, LCOP, UBBPf, UBBPg, UBBPfw1 or UBBPfw2 is configured.

  • The method of adding routes varies according to the setting of Transmission Configuration Mode in the GTRANSPARA MO if the following conditions are met: A link is compliant with the Huawei proprietary protocol, or a 1588 OC_SLAVE link complies with IPv4 and is configured in unicast networking; the client IPv4 address and the server IPv4 address are located in different network segments. The method of adding routes varies as follows: When Transmission Configuration Mode is set to OLD, routes are added through the ADD IPRT command. When Transmission Configuration Mode is set to NEW, routes are added through the ADD IPROUTE4 command.

  • If a 1588 OC_SLAVE link complies with IPv6 and is configured in unicast networking and the client IPv6 address and the server IPv6 address are located in different network segments, you need to run the ADD IPROUTE6 command to add a route.

  • If a board is configured with two IP clock links which comply with the Huawei proprietary protocol, the client IPv4 addresses must be the same.

  • An IP clock reference source needs to be configured for only one RAT on a board.

  • If Profile Type is set to G.8275.2(G.8275.2), Delay Freq must be set to the same value for the two links.

  • If CLKSYNCMODE is set to HYBRID, IPSYNCMODE cannot be simultaneously set to TIME for both IP clock links.

  • In hybrid clock synchronization mode, the following conditions must be met for two IP clock links: 1. Delay Type must be set to the same value for these IP clock links. 2. Device Type must be set to OC_SLAVE. 3. Protocol Type must be set to PTP. 4. Clock Net Mode must be set to UNICAST.

  • Domain of two IPCLKLINK MOs can be different only when Clock Synchronization Mode in the TASM MO is set to HYBRID, or when Clock Synchronization Mode in the TASM MO is set to FREQ, and Clock Net Mode is set to UNICAST and Profile Type is set to 1588V2_16.1 for the two IPCLKLINK MOs.

  • [NodeB,eNodeB,gNodeB]The setting of the domain to which the OC_SLAVE IP clock link in compliance with IEEE 1588 V2 belongs must be the same as the setting of the clock server.

  • [Co-MPT,eNodeB,gNodeB]When Transmission Configuration Mode in the GTRANSPARA MO is set to OLD, the port IP address must be added through the ADD DEVIP command before an IPv4 clock link is added. If the IPv4 clock link is compliant with the Huawei proprietary protocol, the value of Port Type in the DEVIP MO must be ETH, ETHTRK, or SUBIF. If the IP clock link is compliant with 1588, the value of Port Type in the DEVIP MO must be ETH, LOOPINT, ETHTRK, or SUBIF. When Transmission Configuration Mode in the GTRANSPARA MO is set to NEW, the port IP address must be added through the ADD IPADDR4 command before an IPv4 clock link is added. If the IPv4 clock link is compliant with the Huawei proprietary protocol, the value of Port Type in the INTERFACE MO associated with the IPADDR4 MO must be ETH or ETHTRK. If the IP clock link is compliant with 1588, the value of Port Type in the INTERFACE MO must be ETH, LOOPINT, or ETHTRK.

    When Transmission Configuration Mode in the GTRANSPARA MO is set to NEW, the port IP address must be configured through the ADD INTERFACE and ADD IPADDR6 commands before an IPv6 clock link is added.

  • [NodeB,eGBTS]When Transmission Configuration Mode in the GTRANSPARA MO is set to OLD, the port IP address must be added through the ADD DEVIP command before an IPv4 clock link is added. If the IPv4 clock link is compliant with the Huawei proprietary protocol, the value of Port Type in the DEVIP MO must be ETH, ETHTRK, or SUBIF. If the IP clock link is compliant with 1588, the value of Port Type in the DEVIP MO must be ETH, LOOPINT, ETHTRK, or SUBIF. When Transmission Configuration Mode in the GTRANSPARA MO is set to NEW, the port IP address must be added through the ADD IPADDR4 command before an IPv4 clock link is added. If the IPv4 clock link is compliant with the Huawei proprietary protocol, the value of Port Type in the INTERFACE MO associated with the IPADDR4 MO must be ETH or ETHTRK. If the IP clock link is compliant with 1588, the value of Port Type in the INTERFACE MO must be ETH, LOOPINT, or ETHTRK.

  • [eNodeB,gNodeB]If the configured IP clock protocol type is inconsistent with the actual one, the configuration takes effect only after the NE is reset.

PROFILETYPE Profile Type

Meaning: Indicates the type of protocol supported by the IEEE 1588 V2-compliant IP clock link, which can be ITU-T G.8265.1, IEEE 1588 V2, IEEE1588V2_16.1, ITU-T G.8275.1 or ITU-T G.8275.2. ITU-T G.8265.1 is defined by the International Telecommunication Union (ITU) for frequency synchronization of an IEEE 1588 V2-compliant IP clock link with the networking type of UNICAST. An IP clock link in compliant with ITU-T G.8265.1 supports interconnection with servers from other vendors. An IP clock link in compliant with IEEE 1588 V2 supports interconnection with clock service devices from other vendors only in L2 or L3 multicast networking. IEEE1588V2_16.1 can also be used for interconnection with clock service devices from other vendors when the other vendors do not support ITU-T G.8265.1.The content of IEEE1588V2_16.1 refer to the optional section 16.1 of IEEE1588V2 protocol. ITU-T G.8275.1 is defined by the International Telecommunication Union (ITU) for time synchronization of an IEEE 1588 V2-compliant IP clock link with the networking type of L2 multicast. An IP clock link in compliant with ITU-T G.8275.1 supports interconnection with clock service devices from other vendors. ITU-T G.8275.2 is defined by the International Telecommunication Union (ITU) for time synchronization of an IEEE 1588 V2-compliant IP clock link with the networking type of L3 unicast. An IP clock link in compliant with ITU-T G.8275.2 supports interconnection with clock service devices from other vendors.

DSTMLTMACTYPE Destination Multicast MAC Address Type

Meaning: Indicates the type of the destination multicast MAC address to which an NE sends G.8275.1 clock synchronization packets. Forwardable Multicast MAC Address (FMAC) means that the destination MAC address to which the NE sends clock synchronization packets is 01-1B-19-00-00-00. Non-Forwardable Multicast MAC Address (NFMAC) means that the destination MAC address to which the NE sends clock synchronization packets is 01-80-C2-00-00-0E. The NE can handle clock synchronization packets from both FMAC and NFMAC.

GUI Value Range: FMAC(Forwardable Multicast MAC Address), NFMAC(Non-Forwardable Multicast MAC Address)

Unit: None

Actual Value Range: FMAC, NFMAC

MML Default Value: FMAC(Forwardable Multicast MAC Address)

Recommended Value: None

Parameter Relationship:

-Configuration constraints:

The values of ICPT are both set to PTP; 2. The values of CNM are both set to L2_MULTICAST; 3. The values of PROFILETYPE are both set to G.8275.1.
