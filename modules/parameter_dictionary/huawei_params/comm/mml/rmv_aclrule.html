Remove ACL Rule (RMV ACLRULE)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to remove an ACL rule from an ACL.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • If an ACL is referenced by an IPSec policy or packet filter or a packet filtering policy, the last rule in the ACL cannot be removed.

  • For a UTRP (subboard type: UEOC/UQEC), if 48 IPv4 ACL rules have taken effect but more than 48 IPv4 ACL rules are referenced by packet filters, the system will automatically validate one ineffective IPv4 ACL rule after one effective IPv4 ACL rules is deleted by running this command. You can run the DSP ACLRULE command to query the currently valid IPv4 ACL rules.

  • This operation may interrupt the services or OM channels that references the ACL rule. It is recommended that you determine whether to enable the automatic configuration data rollback function depending on scenarios. For details, see the help of the CFM CB command.

RULEID Rule ID

Meaning: Indicates the ID of an ACL rule. The values 1 to 65535 indicate ACL rules manually configured by users or automatically generated for packet filtering. (When the value of ACL Rule Automatic Setup and Deletion Switch of packet filtering is ON, IDs from 50000 to 59999 cannot be used for manually configured ACL rules and are used for automatically generated ACL rules for packet filtering only.) The values 65431 to 65536 indicate the ACL rules automatically generated during DHCP detection. The values 70000 to 79999 indicate ACL rules automatically generated for packet filtering in endpoint configuration mode. The values 80000 to 89999 indicate ACL rules automatically generated for IPsec in endpoint configuration mode.

Unit: None

FORCEEXECUTE Support Forcible Execution

Meaning: Indicates whether a forcible change of an ACL rule is made. When this parameter is set to NO(No), the system checks whether the change affects upper-layer services. If the change affects upper-layer services, the forcible change will fail. When this parameter is set to YES(Yes), the system does not check whether the change affects upper-layer services. Upper-layer services include the following: active/standby OM channel (OMCH), DNS service (DNSSRV), certificate issuance (CA), CRL update (CRLTSK), IP clock link (IPCLKLINK), NTP (NTPC), ABIS CP/IUB CP/S1 CP/X2 CP/M2 CP/ECO CP/eX2 CP/SO CP/UX2 CP/XW CP/gNBCUX2 CP/gNBCUNg CP/gNBCUXn CP (SCTPLNK/SCTPHOST/SCTPPEER), and ABIS UP/IPPATH of unknown service type/IUB UP/UX2 UP/S1 UP/X2 UP/eX2 UP/XW UP/gNBCUX2 UP/gNBCUS1 UP/gNBCUNg UP/gNBCUXn UP (IPPATH/USERPLANEHOST/USERPLANEPEER). Only the change of the ACL rule that is manually configured with Protocol Type set to IP and Match DSCP set to NO in IPsec networking is checked. This parameter is invalid when a WMPT, LMPT, GTMUb, or GTMUc serves as the main control board.

Pay attention to the following when using this parameter:

1. The system checks whether a forcible change of an ACL rule affects upper-layer services based on the configuration data instead of based on the actual running status of these services.

2. If an NE is configured with an SRCIPRT, SRCIPROUTE4, PPPLNK, or MPGRP MO, the system does not check whether a forcible change of an ACL rule affects upper-layer services.

GUI Value Range: NO(No), YES(Yes)

Unit: None

Actual Value Range: NO, YES

MML Default Value: NO(No)

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N

Example

To remove an ACL rule with the parameter as follows: ACL ID: 3000, Rule ID: 10, run the following command:  
RMV ACLRULE: ACLID=3000, RULEID=10;
