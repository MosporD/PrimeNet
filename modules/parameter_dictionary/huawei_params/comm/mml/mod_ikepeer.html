Modify IKE Peer (MOD IKEPEER)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to modify the configuration of the IKE peer.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • If an IKEPEER can be queried by running the LST IKEPEER command and the value of Auto Config Flag is Auto Created, the IKE peer is automatically created by the system and cannot be modified by users.

  • Before modifying the master IKE peer to which the slave IKE peer corresponds, ensure that the master IKE peer specified by the Master Peer Name parameter exists.

  • The priorities of slave IKE peers corresponding to one master IKE peer must differ.

  • If a master IKE peer has been configured with slave IKE peers, this master IKE peer can be changed to neither slave IKE peer nor non-IPSec redundancy IKE peer.

  • If the slave IKE peer in use is modified, the system uses the slave IKE peer of a lower priority for negotiation.

  • If the only one slave IKE peer is being used, the following occurs when modifying this IKE peer: If the negotiation on the master IKE peer succeeds (no alarm related to IKE negotiation failure is reported), a back switchover is performed from the slave IKE tunnel to the master IKE tunnel. If the negotiation on the master IKE peer fails (the alarm related to IKE negotiation failure is reported), the slave IKE tunnel in use will still be used.

  • If the master IKE peer is modified, a switchover to the master IKE tunnel is performed regardless of whether the master or slave IKE peer is in use or whether back switchover is enabled.

  • If an IPsec policy group has been bound to a port, only one IPsec policy in the IPsec policy group takes effect (queried by using the DSP IPSECPOLICY command), and the IKE peer referenced by the IPsec policy is modified (excluding the situation where only the IPSECPREFRGSW parameter is modified when IPVERSION is set to IPV6), the system will unbind the IPsec policy group from the port (that is, the RMV IPSECBIND or RMV IPSECBINDITF command is executed) and then rebind it.

  • A master or slave IKE peer can be referenced by only one IPSec policy.

  • The Redundancy Flag parameter in the IKE peer referenced by the security host or security peer must be set to NONE(Non-redundancy).

  • After IKEv2 Redirect Switch is set to ON in an IKE peer, this IKE peer can be referenced by only one IPSECPOLICY MO.

  • The Remote IP Address parameter configured in an IKE peer cannot be the currently used redirection IP address sent by the peer to the base station.

  • After an IKE peer that supports IKEv2 redirection is configured, the IPSECDTNL MO cannot be configured, and vice versa.

  • If parameters in the IKE peer are modified when IPSec dual tunnels are configured, the primary tunnel is preferentially used, regardless of whether the services are carried on the primary or secondary tunnel before the modification.

  • If parameters in the IKE peer are modified , information about switchovers between the primary and secondary IPSec tunnels is cleared in the output of the DSP IPSECDTNL command.

  • IPSec tunnel pair cannot coexist with master/slave IKE peers.

  • [Co-MPT,NodeB,eNodeB,gNodeB]If multiple IPv4 addresses on the same network segment are configured on an interface, the local IPv4 address in the IKEPEER object must be configured. Otherwise, IKE negotiation may fail.

  • [Co-MPT,eNodeB,gNodeB]The IPv6 IPSec redundancy switchover is performed based on the configured IKE peer priorities, regardless of the route priorities.

IPSECPREFRGSW IPSec PreFragment Switch

Meaning: Indicates whether packets can be fragmented before being encrypted. If this parameter is set to OFF and the IPVERSION parameter is set to IPv4 for an IKE peer, the IPv4 traffic is not fragmented, and the IPv6 traffic is fragmented based on the maximum MTU capability of the internal ports. If IPVERSION is set to IPv6 for an IKE peer, the internal system sets the MTU used by IPv4 and IPv6 traffic to the board maximum capability and fragments packets based on the board maximum capability.

If this parameter is set to ON, packets are fragmented before being encrypted. If the IPVERSION parameter is set to IPv4 for an IKE peer, IPv4 and IPv6 packets are fragmented based on the MTU value of the IKE peer. If the IPVERSION of the IKE peer is set to IPv6, IPv4 and IPv6 traffic is fragmented based on the MTU4 and MTU6 values of the tunnel interface, respectively.

GUI Value Range: OFF(Off), ON(On)

Unit: None

Actual Value Range: OFF, ON

MML Default Value: None

Recommended Value: OFF(Off)

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: None

MTU Maximum Transmission Unit

Meaning: Indicates the MTU of IPv4 or IPv6 before packets are encrypted when the IP protocol version of an IKE peer is IPv4. This parameter takes effect for both IPv4 and IPv6 traffic when the ACL type of the IPsec policy that references the IKE peer is IPv4+IPv6.

If the length of a packet before encryption exceeds the value of this parameter, the system fragments the packet based on the value of this parameter and then encrypts the fragmented packet. If the length of the encrypted packet exceeds the value of MTU in the ETHPORT MO, ETHCIPORT MO, ETHTRK MO, IPRT MO, IPROUTE4 MO, and INTERFACE MO, the encrypted packet will be fragmented again based on the MTU of the ETHPORT MO, ETHCIPORT MO, ETHTRK MO, IPRT MO, IPROUTE4 MO, or INTERFACE MO.

GUI Value Range: 46~9000

Unit: byte

Actual Value Range: 46~9000

MML Default Value: None

Recommended Value: 1380

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: If this parameter is set to an excessively large value, a packet is segmented for a second time within the system, which reduces the transmission performance. If this parameter is set to an excessively small value, the number of fragmented packets increases, increasing the encryption times. Moreover, this also reduces the effective payload of transmission. As a result, the bandwidth cannot be efficiently used, and transmission performance decreases.

Applicable Mode: G, U, L, N
FORCEEXECUTE Support Forcible Execution

Meaning: Indicates whether forcible changes to IKEPEER objects are made. When this parameter is set to YES, forcible changes to the IKEPEER objects are made. When this parameter is set to NO, forcible changes to the IKEPEER objects that affect associated objects are not allowed.

The associated objects include CA and CERTREQ. This parameter is invalid when a WMPT, LMPT, GTMUb, or GTMUc serves as the main control board.

Pay attention to the following when setting this parameter:

1. The system checks whether forcible changes to IKEPEER objects affect associated objects based on the object configuration data instead of the actual object running status.

2. If the NE is configured with an SRCIPRT, SRCIPROUTE4, PPPLNK, or MPGRP MO, the system does not check whether the modification of the local IP address affects the associated MOs of the IKEPEER MO.

3. If the NE is configured with an SRCIPROUTE6 object, the system does not check whether the modification of the local IPv6 address affects the associated objects of the IKEPEER object.

Example

Example 1: To modify an IKE peer with the parameters as follows: IKE Peer Name: ike, Version: IKE_V1, Exchange Mode: AGGRESSIVE, Certificate Source: CERTMK, Certificate File Name: eNodeBCert.pem, run the following command:
MOD IKEPEER: PEERNAME="ike", IKEVERSION=IKE_V1, EXCHMODE=AGGRESSIVE, CERTSOURCE=CERTMK, CERTNAME="eNodeBCert.pem";

Example 2: To modify an IKE peer with the parameters as follows: IKE Peer Name: ikepeer, Version: IKE_V2, IP Version: IPV4, Local ID Type: IPV4, IKEv2 Redirect Switch: OFF, run the following command:
MOD IKEPEER: PEERNAME="ikepeer", IKEVERSION=IKE_V2, IPVERSION=IPV4, IDTYPE=IPV4, REDIRECTSW=OFF;

Example 3: To modify an IKE peer with the parameters as follows: IKE Peer Name: ikepeer2, Version: IKE_V2, IP Version: IPV4, Local ID Type: FQDN, NAT Traversal: DISABLE, run the following command:
MOD IKEPEER: PEERNAME="ikepeer2", IKEVERSION=IKE_V2, IPVERSION=IPV4, IDTYPE=FQDN, NATTRAV=DISABLE;

Example 4: To modify an IKE peer with the parameters as follows: IKE Peer Name: ikepeer6, Version: IKE_V2, IP Version: IPV6, Local ID Type: IPV6, Remote Name: segw, run the following command:
MOD IKEPEER: PEERNAME="ikepeer6", IKEVERSION=IKE_V2, IPVERSION=IPV6, IDTYPE=IPV6, REMOTENAME="segw";
