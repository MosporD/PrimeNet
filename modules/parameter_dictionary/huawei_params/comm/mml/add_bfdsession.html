Add BFD Session (ADD BFDSESSION)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a Bidirectional Forwarding Detection (BFD) session. BFD, a protocol for fast link fault detection, provides a low-overhead and short-duration method of detecting link failures.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Before running this command, ensure that the peer NE supports the BFD function. The peer end cannot be configured with more than one BFD session connected to the same BFD session of the local end. Otherwise, intermittent failures occur on the link.

  • The source and destination IP addresses of a BFD session must be different from each other.

  • The BS does not support inter-board BFD sessions.

  • Each BFD session must have a unique destination IP address in the same routing domain.

  • If the hop type is single hop and the source IP port is an Ethernet port in the BFD session to be added, the source and destination IP addresses must be on the same network segment.

  • The minimum TX and RX intervals in use may be different from the intervals set by running this command. To query the intervals in use, run the DSP BFDSESSION command.

  • If a single-hop reliability-type BFD session is inactive (including the session states specified by the values Admin Down and Down), the route with the next-hop IP address set to the same value as the destination IP address of the BFD session is disabled. If the BFD session is active, the route with the next-hop IP address set to the same value as the destination IP address of the BFD session is enabled.

  • If a multi-hop reliability-type BFD session is inactive, the routes whose destination IP address is the same as that of the BFD session and whose destination subnet mask has 32 bits are disabled one by one in descending order of priority. If the lowest-priority route is still unreachable, all disabled routes are enabled. If detection on low-priority routes is successful, the BFD detection is activated, and disabled high-priority routes of will not be enabled.

  • Configure a BFD session as a single-hop one if it is to facilitate BFD on two devices with no layer 3 network device in between.

  • Configure a BFD session as a multiple-hop one if it is to facilitate BFD on two devices with one or multiple layer 3 network devices in between.

  • System specifications: If the WMPT is the main control board, a maximum of 32 BFD sessions can be configured. If the LMPT/UMPT/UMDU is the main control board, a maximum of 96 BFD sessions can be configured. If the GTMUb/GTMUc is the main control board, a maximum of 16 BFD sessions can be configured.

  • Board specifications: A maximum of 4 BFD sessions can be configured on a WMPT and the session number must range from 0 to 3. A maximum of 96 BFD sessions can be configured on an LMPT/UMPT/UMDU/UTRPc/UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9. A maximum of 6 BFD sessions can be configured on a GTMUb/GTMUc and the session number must range from 0 to 5. A maximum of 4 BFD sessions can be configured on a UTRP (subboard type: UEOC/UQEC/UIEC/UAEC) and the session number must range from 0 to 3.

  • If a single-hop BFD session is faulty, the source-based IP route whose next hop IP address is the destination IP address of this BFD session will be disabled. This is not the case for a multi-hop BFD session.

  • The key with the minimum key ID is used for negotiation in BFD authentication. Ensure that the key ID and key are the same as those at the peer end; otherwise, the negotiation will fail.

  • Currently, the UMPT, UMDU, LMPT, UTRPc and GTMUc support BFD authentication.

  • [Co-MPT,NodeB,eGBTS,eNodeB]When the port type is set to PPP or MPGRP, BFD authentication is not supported.

  • [Co-MPT,NodeB,eGBTS,eNodeB]If a BFD session is carried on a PPP link or an MLPPP link, it is recommended that the minimum RX and TX intervals be both set to 300 ms. Otherwise, intermittent failures occur on the link.

SRCIP Source IP

Meaning: Indicates the source IP address of a BFD session. The source IP address of a BFD session must be a device IP address of a specified board (for example, the IP address of an Ethernet port or a port that carries a PPP link or MP group) or a logical IP address (for example, the IP address of a loopback port), but cannot be set to the same value as the IP address of a remote maintenance channel or a negotiated IP address. Note that a BFD session cannot be configured as a single-hope session if its source IP address is a logical IP address.

Disuse statement: This parameter will be deleted in later versions. In the current version, this parameter can be configured and takes effect when the Transmission Configuration Mode parameter in the GTRANSPARA MO is set to OLD, and this parameter cannot be configured and is replaced by the Source IP parameter in the BFD MO when the Transmission Configuration Mode parameter in the GTRANSPARA MO is set to NEW. Example

To add a BFD session with the parameters as follows: Slot No.: 6, Session ID: 0, Source IP: 192.168.2.24, Destination IP: 172.16.17.2, Hop Type: SINGLE_HOP, DSCP: 32, run the following command: 
ADD BFDSESSION: SN=6, BFDSN=0, SRCIP="192.168.2.24", DSTIP="172.16.17.2", HT=SINGLE_HOP, DSCP=32;
