Start Board Hardware Test (STR HWTST)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to start a hardware test on a board, which aims to locate or rectify the hardware faults on the board.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Starting a hardware test on a board causes the reset of the board.

  • Starting a hardware test on a board causes the board unavailable until the end of the test.

  • Before starting a hardware test on a board, ensure that the following conditions are met:

    1. No software or file is being uploaded or downloaded.

    2. The board must be configured. The sub-boards, if any, must be configured.

    3. The BBP, RRU, RFU, UBRI, MERC, AARU, GTMU, UMDU, and RMU must be blocked before a test starts. If the board type is MPMU, all the MPRFs in the same subrack must be blocked before a test starts. If the board type is WBBP, the board must be reset after it is blocked.

    4. No hardware test is being performed on the board.

    5. If a logical cell is carried on the baseband equipment that the service processing board belongs to, deactivate this logical cell before blocking the service processing board.

  • Starting a hardware test on the active main control board causes the reset of the BS.

  • Currently, the following boards of specific hardware versions support this command: MPT, BBP, UTRP, UCIU, RRU, RFU, UBRI, MERC, UMDU, UCCU, GTMU, CXU, AARU, and RHUB.

  • For an MBTS, running this command to start a hardware test on a multi-mode RF unit will interrupt services of the mode at the peer end.

  • If an MBTS works in co-communication mode and the shared outgoing transmission port is set on the UMTS side, starting a hardware test on the board housing the port will interrupt services of the mode at the peer end.

  • For a multi-mode BS in CPRI MUX/eCPRI MUX, if the local mode aggregates data, starting a hardware test on the main control board of the local mode or the baseband processing board that aggregates data will interrupt the services of the peer mode.

  • Do not unblock a board which is being tested. Otherwise, the test may fail.

  • The hardware test items vary with boards, so does the test duration. A hardware test takes 2 to 10 minutes on most boards and one and a half hours on some boards. You can learn whether the test is complete from the device panel. In addition, you can run the RST BRD command to reset the board. After the board is reset, necessary test items are tested and then the test is complete.

  • The system supports only one test instance.

  • Run the DSP HWTSTRESULT command to query the test result.

  • If an MPMU being tested enters the deep dormancy state, the hardware test results may be incorrect. It is recommended that a hardware test be performed when an MPMU is not in the deep dormancy state.

  • [eGBTS,eNodeB,gNodeB]The hardware test on the board lasts for 2 to 10 minutes. You can learn the progress of the test and whether the test is complete from the panel status.

  • [eNodeB,gNodeB]This command does not apply to RRU working in TDL_IR protocol.

Example

To start a hardware test on a board with the parameters as follows: Cabinet No.: 0, Subrack No.: 0, Slot No.: 1, run the following command:
STR HWTST: CN=0, SRN=0, SN=1;
