Modify Packet Filtering Policy (MOD PACKETFILTERING)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to modify the settings of packet filtering policy.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering policy, the Match Behavior parameter must be set to DENY(Deny) for packet filtering policy, which is the whitelist mode.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering policy, the ACL referenced by packet filtering policy must not contain manually created ACL rules that are numbered from 50000 to 59999 (the value of the Auto Config Flag parameter is Manual Created when queried by running the LST ACLRULE command). If these ACL rules exist in the ACL, they must be manually deleted to enable the ACL rule automatic setup and deletion function.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering policy and if the required ACL rule has existed, the system will use the existing one.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering policy and if multiple data flows match the same ACL rule, the system will reuse the ACL rule for these data flows. In this case, the corresponding ACL rule whose CTRL MODE is AUTO_MODE can be deleted only when all data flows are deleted.

  • After the system starts, it checks the ACL rules created for packet filtering policy according to the auto-setup rules to ensure that the automatically created ACL rules match with the configured data flows, and the unmatched automatically created ACL rules will be deleted.

  • After the ACL rule automatic setup and deletion function is enabled for packet filtering policy, the system automatically creates 6 ACL rules for the active O&M channel and 6 ACL rules for the standby O&M channel in the ACL that supports auto-setup. The ACL that supports auto-setup refers to the one referenced by packet filtering policy that supports the ACL rule automatic setup and deletion function. The destination ports of the 6 ACL rules are as follows: 6007, 6006, 6000, 443, 4443, and 45300. As limited by the specifications of ACL rules, it is recommended that sufficient ACL rule numbers be reserved for O&M data connection to ensure the O&M connection.

  • When the ACL rule automatic setup and deletion function is disabled for a packet filtering policy object, the base station deletes the ACL rule created through the ACL rule automatic setup and deletion function and whose CTRLMODE set to AUTO_MODE. To prevent services from being affected, it is recommended that users check which ACL rule is removed and manually add an ACL rule to ensure connectivity.

  • This operation may interrupt the services or OM channels carried on this port. It is recommended that you determine whether to enable the automatic configuration data rollback function depending on scenarios. For details, see the help of the CFM CB command.

  • In FTP scenarios, the automatic ACL rule configuration and deletion function for packet filtering must be enabled before the FTP service is started. If automatic ACL rule configuration for packet filtering is enabled after the FTP service is started, the ACL rules used by the FTP service will not be automatically generated, and the FTP link in use will be disconnected. In this case, you need to restart the FTP upload and download services.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If the ACL rule automatic setup and deletion function is enabled for a packet filtering policy object when the configured ACL rules are about to reach the maximum number, the base station adopts a best effort solution. That is, the base station creates ACL rules first for OM channels, then for time services, clock services, manually created IKE peers, and PKI, and finally for DNS server, manually created SCTP links, and manually created IP paths. When the maximum ACL rules have been configured, no ACL rule can be created for OM channels, time services, clock services, manually created IKE peers, PKI, DNS server, manually created SCTP links, or manually created IP paths. In this case, users need to properly plan the transport networking and allocate ACL rules.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering policy, the creation of advanced ACL rules will be delayed, and OM channels, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, PKI flows and DNS server matching these ACL rules will be interrupted.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]When the switch for limiting the peer IP address for the remote maintenance channel is enabled, the peer IP address in the ACL rules for the automatically created OMCH is automatically restricted to the IP address for the MAE to log in to the base station when the base station is in the stable state. In this case, if the NetEco (6007), TraceServer (6007), or NIC (6000, 6006) is independently deployed, the ACL rules must be manually configured before the preceding device can access the base station. The destination port numbers of the ACL rules that have been automatically generated for the remote maintenance channel are 6007, 6006, 6000, 443, 4443, and 45300.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple packet filters reference the same ACL, the ACL rule automatic setup and deletion switches must be either turned on or off for all these packet filtering policy objects. If the ACL rule automatic setup and deletion switches for some packet filters are turned on while those for other packet filters are turned off, all the switches are regarded as having been turned on.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple packet filters reference the same ACL, the OMCH peer IP limit switches must be either turned on or off for all these packet filtering policy objects. If the OMCH peer IP limit switches are turned on while those for other packet filters are turned off, all the switches are regarded as having been turned on.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]In packet filtering scenarios involving numerous configurations, do not frequently run this command to modify the interface bound to the PACKETFILTERING object. Otherwise, the modification may fail.

  • [Co-MPT,NodeB,eNodeB,gNodeB]When the MAE is deployed in distributed mode or uses the remote HA system, you are advised to manually configure access rules for all MAE addresses in advance. Otherwise, the base station may be disconnected during manager migration.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple PACKETFILTERING objects reference the same ACL, the value of Match Behavior in these PACKETFILTERING objects must be the same. IF any value is different, the value of Match Behavior in the PACKETFILTERING objects that first takes effect prevails.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple PACKETFILTERING objects reference the same ACL6, the value of Match Behavior in these PACKETFILTERING objects must be the same.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering policy, the system automatically creates advanced ACL rules and matches them with the following data flows: OM channels, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, PKI data flows, and DNS server. If these data flows are added or deleted, the ACL rules whose CTRLMODE is AUTO_MODE will be added to or deleted from the ACL that supports the ACL rule automatic setup and deletion function, that is, the ACL referenced by the packet filtering policy that supports the ACL rule automatic setup and deletion function. If any of the preceding data flows is modified, the corresponding ACL rule that has been created automatically will be re-created.

  • [NodeB]When the main control board is the WMPT, the system does not support the ACL rule automatic setup and deletion function for packet filtering policy.

  • [NodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering policy, the system automatically creates advanced ACL rules and matches them with the following data flows: OM channels, manually created SCTP links, manually created IPPATH, time services, clock services, manually created IKE peers, and PKI. If these data flows are added or deleted, the ACL rules whose CTRLMODE is AUTO_MODE will be added to or deleted from the ACL that supports the ACL rule automatic setup and deletion function, that is, the ACL referenced by the packet filtering policy that supports the ACL rule automatic setup and deletion function. If any of the preceding data flow is modified, the corresponding ACL rule that has been created automatically will be re-created.

  • [NodeB]If the ACL rule automatic setup and deletion function is enabled for a packet filtering policy object when the configured ACL rules are about to reach the maximum number, the base station adopts a best effort solution. That is, the base station creates ACL rules first for OM channels, then for time services, clock services, manually created IKE peers, and PKI, and finally for manually created SCTP links and manually created IP paths. When the maximum ACL rules have been configured, no ACL rule can be created for OM channels, time services, clock services, manually created IKE peers, PKI, manually created SCTP links, or manually created IP paths. In this case, users need to properly plan the transport networking and allocate ACL rules.

  • [NodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering policy, the creation of advanced ACL rules will be delayed, and OM channels, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, and PKI flows matching these ACL rules will be interrupted.

FM Filter Mode

Meaning: Indicates the packet filtering policy mode. The NE can filter packets based on the advanced ACL or layer-2 ACL.

GUI Value Range: ADV_ACL(Only Advanced ACL), L2_ACL(Only Layer 2 ACL)

Unit: None

Actual Value Range: ADV_ACL, L2_ACL

MML Default Value: None

Recommended Value: None

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When the FM in the PACKETFILTERING MO is ADV_ACL, the PT can only be set to INTERFACE or TUNNEL, and the range of ACLID must be from 3000 to 3999.

GUI Value Range: TUNNEL(Tunnel), INTERFACE(Interface), ETH(Ethernet Port), ETHTRK(Ethernet Trunk), ETHCI(Ethernet CI Port)

PORTID Port ID

Meaning: Indicates the port ID or interface ID. When Port Type is set to Interface, this parameter indicates the interface ID. When Port Type is set to other values, this parameter indicates the port ID. When Port Type is set to Interface, the following are true: if IPsec Policy Group Binding Mode in the IKECFG MO is set to ALL, packet filtering policies can be bound only to a normal interface and take effect on the normal interface and all VLAN subinterfaces in the default routing domain of the physical port to which the normal interface belongs; if IPsec Policy Group Binding Mode in the IKECFG MO is set to SINGLE, packet filtering policies take effect only on the interface bound to the IPsec policies.

GUI Value Range: 0~9999

Unit: None

Actual Value Range: 0~9999

MML Default Value: None

Recommended Value: None

Parameter Relationship:

-Others:

  • [Co-MPT, NodeB, eNodeB, gNodeB]In the PACKETFILTERING MO, if PT is set to ETH, PORTID ranges from 0 to 9999.
  • In the PACKETFILTERING MO, if PT is set to ETHTRK, PORTID ranges from 0 to 23.
  • In the PACKETFILTERING MO, if PT is set to TUNNEL, PORTID ranges from 0 to 14.
  • In the PACKETFILTERING MO, if PT is set to ETHCI, PORTID ranges from 0 to 9999.
  • In the PACKETFILTERING MO, if PT is set to INTERFACE, PORTID ranges from 0 to 1499.

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

ACLID ACL ID

Meaning: Indicates the ID of an ACL. The value of this parameter ranges from 3000 to 4999. A value in the range of 3000 to 3999 indicates that the ACL rules in this ACL are advanced ACL rules. A value in the range of 4000 to 4999 indicates that the ACL rules in this ACL are layer 2 ACL rules.

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When the FM in the PACKETFILTERING MO is ADV_ACL, the PT can only be set to INTERFACE or TUNNEL, and the range of ACLID must be from 3000 to 3999.

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

MB Match Behavior

Meaning: Indicates whether to permit or reject access of the data that does not match the ACL rule. If this parameter is set to PERMIT, data that does not match the ACL rule is allowed to pass. If this parameter is set to DENY, data that does not match the ACL rule is discarded.

GUI Value Range: PERMIT(Permit), DENY(Deny)

Unit: None

Actual Value Range: PERMIT, DENY

MML Default Value: None

Recommended Value: DENY(Deny)

Parameter Relationship:

-Others:

  • [Co-MPT, NodeB, eNodeB, gNodeB]In the PACKETFILTERING MO, if ACLAUTOSWITCH is set to ON, MB must be set to DENY.

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
ACLAUTOSWITCH ACL Rule Automatic Setup and Deletion Switch

Meaning: Indicates whether to enable automatic setup of advanced ACL rules for packet filtering policy. When this switch is turned on, the system creates advanced ACL rules that match the following items in the ACL group referenced by the packet filtering policy object: OM data flows, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, and PKI data flows. When the MOD PACKETFILTERING command is executed to change the value of this parameter from ON to OFF, the system will automatically delete the automatically created advanced ACL rules in the ACL group referenced by the packet filtering policy object.

GUI Value Range: OFF(OFF), ON(ON)

Unit: None

Actual Value Range: OFF, ON

MML Default Value: None

Recommended Value: None

Parameter Relationship:

-Configuration constraints:

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the PACKETFILTERING MO, if the ACLAUTOSWITCH parameter is set to ON, the MB parameter must be set to DENY.

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
OMPEERIPLIMITSW OMCH Peer IP Limit Switch

Meaning: Indicates whether the peer IP address is limited by the ACL rules that have been automatically generated for the OM channel when the ACL rule automatic setup and deletion function is enabled. When this parameter is set to ON(ON), the peer IP address must be the IP address of the MAE. In this case, if any one of the NetEco, TraceServer, and NIC is independently deployed, the ACL rules must be manually configured before the preceding device can access the base station.

GUI Value Range: OFF(OFF), ON(ON)

Unit: None

Actual Value Range: OFF, ON

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: No

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N

Example

To modify a packet filtering policy with the parameters as follows: Packet Filtering ID: 0, Filter Mode: Only Advanced ACL, ACL Type: IPv4, Port Type: Tunnel, Port ID: 1, ACL ID: 3000, Match Behavior: Permit, ACL Rule Automatic Setup and Deletion Switch: OFF, run the following command: 
MOD PACKETFILTERING: PACKETFILTERINGID=0, FM=ADV_ACL, ACLTYPE=IPV4, PT=TUNNEL, PORTID=1, ACLID=3000, MB=PERMIT, ACLAUTOSWITCH=OFF;
