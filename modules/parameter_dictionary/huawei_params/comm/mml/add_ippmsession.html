Add IP PM Session (ADD IPPMSESSION)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add an IP Performance Monitoring (PM) session.

Note

  • Before adding an IP PM session, ensure that the peer NE supports the IP PM function.

  • If the peer NE does not support bidirectional activation, only the UL IP PM session can be added to the local end. Otherwise, the IP PM session will be disconnected intermittently.

  • If TXBWASW or RXBWASW is set to ON in the RSCGRPALG object, and an IP PM session is bound to an IP path associated with a transmission resource group in the link model, the base station dynamically adjusts the TX or RX bandwidth of the transmission resource group based on the IP PM detection result. In the link model, if the IP PM session is not bound to any IP path, the IP PM detection result does not affect the TX or RX bandwidth of the transmission resource group. In the endpoint model, even if there is no IP path and the IP PM session is not bound to any IP path, the base station can also dynamically adjust the TX or RX bandwidth of the transmission resource group based on the IP PM detection result.

  • In VLAN group mode, if a triplet-based IP PM session is added, a VLANCLASS object with SRVPRIO of 0 must be added. Otherwise, the IP PM session will fail to be activated.

  • When a quadruplet-based IP PM session is used, the base station experiences probe errors if the intermediate device changes DSCP values.

  • If an IPPMSESSION MO with IP PM Type set to FOUR_TUPLE is bound to an IPPATH MO with Path Type set to FIXED(Fixed QoS), the DSCP value configured in the IPPMSESSION MO does not take effect, but the DSCP value configured in the IPPATH MO takes effect.

  • If a quadruplet-based IP PM session is bound to an any-type IP path, the DSCP value of the IP PM session takes effect, rather than that of the IP path.

  • An IPPMSESSION MO with IP PM Type set to Three_TUPLE cannot be bound to the IPPATH MO with Path Type set to FIXED(Fixed QoS).

  • IP PM sessions are not supported in scenarios where IP path routes are configured.

  • Before configuring IP PM triplets and bidirectionally activated IP PM sessions, ensure that the peer device supports IP PM triplets and bidirectionally activated IP PM sessions.

  • Board specifications: A maximum of 16 IP PM sessions can be configured on a WMPT/UTRP (subboard type: UEOC/UQEC/UIEC/UAEC). A maximum of 128 IP PM sessions can be configured on a UMPT/UMDU/LMPT/UTRPc/UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9. A maximum of 8 IP PM sessions can be configured on a GTMUb/GTMUc.

  • System specifications: If the WMPT/GTMUb/GTMUc is the main control board, a maximum of 128 IP PM sessions can be configured. If the LMPT/UMPT is the main control board, a maximum of 500 IP PM sessions can be configured. If the UMDU is the main control board, a maximum of 128 IP PM sessions can be configured.

  • If the UL IP PM session in the base station is activated on the peer device, the UL or round-trip IP PM session does not need to be activated on the base station. If the IP PM session is activated repeatedly, the IP PM session will fail to be activated.

  • When an IP PM session fails to be activated, ALM-25900 IP PM Activation Failure will not be reported under the following conditions: (1) The IP PM session is not bound to any IP path. (2) No IP path or user-plane link has the same local IP address, peer IP address, and DSCP as this IP PM session.

  • In the same routing domain, if a triplet-based IP PM session is not bound to an IP path, the local IP address of the IP PM session is the same as a device IP address. The type of sub-board on the board where the device IP address is established must be BASE_BOARD or ETH_COVERBOARD.

  • If a triplet-based IP PM session is bound to an IP path, the type of sub-board on the board where the IP path is established must be BASE_BOARD or ETH_COVERBOARD.

  • In security networking scenarios, the UCCU, UBBPe, UBBPei, UBBPep, UBBPem, LCOP, UBBPex2, UBBPf1, UBBPf0, UBBPg1, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7 and UBBPg9 boards do not support high-precision delay monitoring.

  • In the same routing domain, if IP PM sessions with both triplets and quadruples exist, and their local and peer IP addresses are the same, the system uses the last configured triplet or quadruplet to negotiate.

  • [Co-MPT,NodeB,eGBTS]A WMPT/UTRP (subboard type: UEOC/UQEC)/GTMUb board does not support a triplet or a bidirectionally activated IP PM session. If this command is executed to add a triplet or a bidirectionally activated IP PM session to a WMPT/UTRP (subboard type: UEOC/UQEC)/GTMUb board, the command will be executed successfully but the configuration will not take effect.

Parameters

ID Name Description
IPPMSN Session ID

Meaning: Indicates the ID of an IP PM session of an NE. An IP PM session with an ID ranging from 0 to 65535 is configured by users. An IP PM session with an ID ranging from 70000 to 79999 is configured by the system.

GUI Value Range: 0~65535,70000~79999

Unit: None

Actual Value Range: 0~65535,70000~79999

MML Default Value: None

Recommended Value: None

Parameter Relationship:

-Configuration constraints:

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The value of Session ID in a manually configured IPPMSESSION MO must range from 0 to 65535.

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
IPPMTYPE IP PM Type

Meaning: Indicates the type of IP PM session. A triplet consists of the local IP address, peer IP address, and protocol type; a quad bit consists of the local IP address, peer IP address, protocol type, and DSCP. The WMPT and UTRP do not support the triplets configuration mode.

GUI Value Range: FOUR_TUPLE(FOUR_TUPLE), THREE_TUPLE(THREE_TUPLE)

Unit: None

Actual Value Range: FOUR_TUPLE, THREE_TUPLE

MML Default Value: FOUR_TUPLE(FOUR_TUPLE)

Recommended Value: FOUR_TUPLE(FOUR_TUPLE)

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
BINDPATH Bind IP Path

Meaning: Indicates whether to bind the IP PM session to an IP path. If the IP PM session is bound to an IP path, the IP PM session uses the local and peer IP addresses of the IP path in data transmission. In addition, if TXBWASW or RXBWASW is set to ON and TCSW is set to ENABLE in the algorithm for the transmission resource group associated with the IP path, the system dynamically adjusts the TX or RX bandwidth of the transmission resource group based on the IP PM detection result. The IP PM dynamic bandwidth adjustment function is available for LTE but unavailable for UMTS. The function of binding the IP PM session to an IP path is unavailable for NR.

GUI Value Range: NO(No), YES(Yes)

Unit: None

Actual Value Range: NO, YES

MML Default Value: NO(No)

Recommended Value: NO(No)

Parameter Relationship:

-Configuration constraints:

  • [gNodeB]The value of BINDPATH in an IPPMSESSION MO cannot be set to YES.

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N

DIR Activate Direction

Meaning: Indicates that the activation direction of an IP PM session. For this parameter to be valid, the peer must also support the IP PM session. If this parameter is set to UP, the IP PM session initiated by the BS is activated. If this parameter is set to BIDIR, the IP PM sessions initiated by BS and the peer are activated. The activation direction is specified by the DIR parameter. The WMPT and UTRP do not support bidirectional activation. The DIR parameter determines the activation direction.

Example

To add an IP PM session with the parameters as follows: Session ID: 0, IP PM Type: FOUR_TUPLE, Bind IP Path: NO, Local IP: 192.168.11.110, Peer IP: 192.168.22.220, DSCP: 20, run the following command: 
ADD IPPMSESSION: IPPMSN=0, IPPMTYPE=FOUR_TUPLE, BINDPATH=NO, LOCALIP="192.168.11.110", PEERIP="192.168.22.220", IPPMDSCP=20;
