Reset IKE SA or IPSec SA (RST IKESA)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to reset an IKE SA or IPSec SA.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • [Co-MPT,NodeB,eNodeB,gNodeB]Exercise caution when running this command because this operation will reset the IKE SA or IPSec SA and ongoing services carried on the corresponding SA may be interrupted.

  • [Co-MPT,NodeB,eNodeB,gNodeB]"Operation succeeded" displayed in the command output only indicates that the command is successfully executed and does not necessarily mean that IKE SA and IPSec SA negotiations succeed. To query the negotiation result, run the DSP IKESA command.

  • [Co-MPT,NodeB,eNodeB,gNodeB]After this command is executed, a new IPSec SA may be generated, which is the same as the old one. In this case, the new IPSec SA is used to send data and the old one will be automatically removed later.

Parameters

ID Name Description
RSTTYPE Reset Type

Meaning: Indicates the reset mode for an IKE security association (SA) or IPSec SA. When this parameter is set to REAUTH, the reauthentication mode is applied. When this parameter is set to REKEY, the re-key mode is applied. Reauthentication is a reset mode exclusive to IKEv2. In this mode, the IKE SA is first renegotiated from the beginning and then the IPSec SA is renegotiated. During the renegotiation procedure, the original IKE SA and IPSec SA both work properly. Re-key is a reset mode for both IKEv1 and IKEv2 and is classified into IKE SA re-key and IPSec SA re-key. In IKE SA re-key mode, only the current IKE SA is renegotiated and none of IPSec SAs under the IKE SA are renegotiated. In IPSec SA re-key mode, only the current IPSec SA is renegotiated and none of other IPSec SAs are renegotiated.

SPSN IPSec Sequence No.

Meaning: Indicates the sequence number (SN) of an IPsec policy. IPsec policies with an SN ranging from 1 to 10000 are configured by users. IPsec policies with an SN ranging from 10001 to 20000 are automatically generated by the system. When Direct IPSec Priorities Match Switch is set to DISABLE(Disable), the IPsec policy with a smaller SN is preferentially matched. When Direct IPSec Priorities Match Switch is set to ENABLE(Enable), the IPsec policy of the directly connected IPsec tunnel is preferentially matched. For details about the IPsec policy of the directly connected IPsec tunnel, see the meaning of the Direct IPSec Priorities Match Switch parameter.

Example

Example 1: To reset IKE SA with the parameters as follows: Reset Type: REAUTH, Reauthentication IKE Peer Name: peer, run the following command:
RST IKESA: RSTTYPE=REAUTH, REAUTHPEERNAME="peer";

Example 2: To reset IKE SA with the parameters as follows: Reset Type: REKEY, Phase: PHASE1, Re-key IKE Peer Name: peer, run the following command: 
RST IKESA: RSTTYPE=REKEY, PHASE=PHASE1, REKEYPEERNAME="peer";

Example 3: To reset IPSec SA with the parameters as follows: Reset Type: REKEY, Phase: PHASE2, Policy Group Name: policy, IPSec Sequence No.: 1, Connection ID: 2, run the following command: 
RST IKESA: RSTTYPE=REKEY, PHASE=PHASE2, SPGN="policy", SPSN=1, CONNID=2;
