Add Binding from IPSec Policy Group to Port (ADD IPSECBIND)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to bind an IPSec policy group to a port. IPSec tunnels are negotiated to protect the data streams flowed through a port only after an IPSec policy group is bound to the port.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Before running this command, ensure that the associated IPSec policy group has been configured.

  • Before running this command, ensure that the name of the IPSec policy group to be bound is different from that of the IPSec policy group to which the IPSec policy of any IPSec tunnel pair belongs.

  • An IPSec policy can be bound to only one port.

  • Only one IPSec policy created by user and one IPSec policy created by the system can be bound to a port.

  • After an IPSec policy group is bound to a port, if packets comply with ACL rules in the group and IPSec SAs are available, the packets will be encapsulated by IPSec and be routed and forwarded based on the destination IP addresses after encapsulation.

  • System specifications: If the WMPT/LMPT/UMPT/UMDU is the main control board, a maximum of 12 IPSec policy groups can be configured. If the GTMUb/GTMUc is the main control board, a maximum of 6 IPSec policy groups can be configured.

  • Board specifications: A maximum of 4 IPSec policy groups can be configured on an LMPT. A maximum of 8 IPSec policy groups can be configured on a UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf0/UBBPf1/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9. A maximum of 6 IPSec policy groups can be configured on a UMPTa/UMPTb. A maximum of 10 IPSec policy groups can be configured on a UMPTe/UMPTg/UMPTga. A maximum of 4 IPSec policy groups can be configured on a UMDU. A maximum of 12 IPSec policy groups can be configured on a UTRPc.

  • If the master and slave IKE peers are configured in different IPSec policy groups, you must add the IPSECBIND MO of the master IKE peer to the board before adding the IPSECBIND MO of the slave IKE peer to this board.

  • Before this command is executed, if the IPSECPOLICY, IPSECPROPOSAL, ACL, IKEPEER and IKEPROPOSAL objects, which the IPSECBIND MO directly or indirectly depends on, do not have a bearer MO (PACKETFILTER, IPSECBIND), on the board for which the IPSECBIND MO is configured, the IPSECPOLICY, IPSECPROPOSAL, ACL, IKEPEER and IKEPROPOSAL objects will try to take effect. If these objects fail to take effect, the IPSECBIND MO will also fail to take effect.

FORCEEXECUTE Support Forcible Execution

Meaning: Indicates whether forcible changes to IPSECBIND objects are made. When this parameter is set to YES, forcible changes to IPSECBIND objects are made. When this parameter is set to NO, forcible changes to the IPSECBIND objects that affect associated objects are not allowed.

The associated objects include CA, CERTREQ, and IKEPEER. This parameter is invalid when a WMPT, LMPT, GTMUb, or GTMUc serves as the main control board.

Pay attention to the following when setting this parameter:

1. The system checks whether forcible changes to IPSECBIND objects affect associated objects based on the object configuration data instead of the actual object running status.

2. If the NE is configured with an SRCIPRT, PPPLNK, or MPGRP MO, the system does not check whether the modification of the local IP address affects the associated MOs of the IPSECBIND MO.

Example

To bind an IPSec policy group to a port with the parameters as follows: Slot No.: 6, Subboard Type: BASE_BOARD, Port Type: ETH, Port No.: 0, Policy Group Name: policy, run the following command:
ADD IPSECBIND: SN=6, SBT=BASE_BOARD, PT=ETH, PN=0, SPGN="policy";
