Modify Packet Filter (MOD PACKETFILTER)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to modify the settings of packet filtering.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering, the Match Behavior parameter must be set to DENY(Deny) for packet filtering, which is the whitelist mode.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering, the ACL referenced by packet filtering must not contain manually created ACL rules that are numbered from 50000 to 59999 (the value of the Auto Config Flag parameter is Manual Created when queried by running the LST ACLRULE command). If these ACL rules exist in the ACL, they must be manually deleted to enable the ACL rule automatic setup and deletion function.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering and if the required ACL rule has existed, the system will use the existing one.

  • When the ACL rule automatic setup and deletion function is enabled for packet filtering and if multiple data flows match the same ACL rule, the system will reuse the ACL rule for these data flows. In this case, the corresponding ACL rule whose CTRL MODE is AUTO_MODE can be deleted only when all data flows are deleted.

  • After the system starts, it checks the ACL rules created for packet filtering according to the auto-setup rules to ensure that the automatically created ACL rules match with the configured data flows, and the unmatched automatically created ACL rules will be deleted.

  • After the ACL rule automatic setup and deletion function is enabled for packet filtering, the system automatically creates 6 ACL rules for the active O&M channel and 6 ACL rules for the standby O&M channel in the ACL that supports auto-setup. The ACL that supports auto-setup refers to the one referenced by packet filtering that supports the ACL rule automatic setup and deletion function. The destination ports of the 6 ACL rules are as follows: 6007, 6006, 6000, 443, 4443, and 45300. As limited by the specifications of ACL rules, it is recommended that sufficient ACL rule numbers be reserved for O&M data connection to ensure the O&M connection.

  • When the ACL rule automatic setup and deletion function is disabled for a packet filtering object, the base station deletes the ACL rule created through the ACL rule automatic setup and deletion function and whose CTRLMODE set to AUTO_MODE. To prevent services from being affected, it is recommended that users check which ACL rule is removed and manually add an ACL rule to ensure connectivity.

  • This operation may interrupt the services or OM channels carried on this port. It is recommended that you determine whether to enable the automatic configuration data rollback function depending on scenarios. For details, see the help of the CFM CB command.

  • In FTP scenarios, the automatic ACL rule configuration and deletion function for packet filtering must be enabled before the FTP service is started. If automatic ACL rule configuration for packet filtering is enabled after the FTP service is started, the ACL rules used by the FTP service will not be automatically generated, and the FTP link in use will be disconnected. In this case, you need to restart the FTP upload and download services.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If the ACL rule automatic setup and deletion function is enabled for a packet filtering object when the configured ACL rules are about to reach the maximum number, the base station adopts a best effort solution. That is, the base station creates ACL rules first for OM channels, then for time services, clock services, manually created IKE peers, and PKI, and finally for DNS server, manually created SCTP links, and manually created IP paths. When the maximum ACL rules have been configured, no ACL rule can be created for OM channels, time services, clock services, manually created IKE peers, PKI, DNS server, manually created SCTP links, or manually created IP paths. In this case, users need to properly plan the transport networking and allocate ACL rules.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering, the creation of advanced ACL rules will be delayed, and OM channels, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, PKI flows and DNS server matching these ACL rules will be interrupted.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]When the switch for limiting the peer IP address for the remote maintenance channel is enabled, the peer IP address in the ACL rules for the automatically created OMCH is automatically restricted to the IP address for the MAE to log in to the base station when the base station is in the stable state. In this case, if the NetEco (6007), TraceServer (6007), or NIC (6000, 6006) is independently deployed, the ACL rules must be manually configured before the preceding device can access the base station. The destination port numbers of the ACL rules that have been automatically generated for the remote maintenance channel are 6007, 6006, 6000, 443, 4443, and 45300.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple packet filters reference the same ACL, the ACL rule automatic setup and deletion switches must be either turned on or off for all these packet filtering objects. If the ACL rule automatic setup and deletion switches for some packet filters are turned on while those for other packet filters are turned off, all the switches are regarded as having been turned on.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple packet filters reference the same ACL, the OMCH peer IP limit switches must be either turned on or off for all these packet filtering objects. If the OMCH peer IP limit switches are turned on while those for other packet filters are turned off, all the switches are regarded as having been turned on.

  • [Co-MPT,NodeB,eNodeB,gNodeB]When the MAE is deployed in distributed mode or uses the remote HA system, you are advised to manually configure access rules for all MAE addresses in advance. Otherwise, the base station may be disconnected during manager migration.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple PACKETFILTER objects reference the same ACL, the value of Match Behavior in these PACKETFILTER objects must be the same. IF any value is different, the value of Match Behavior in the PACKETFILTER objects that first takes effect prevails.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]If multiple PACKETFILTER objects reference the same ACL6, the value of Match Behavior in these PACKETFILTER objects must be the same.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering, the system automatically creates advanced ACL rules and matches them with the following data flows: OM channels, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, PKI data flows, and DNS server. If these data flows are added or deleted, the ACL rules whose CTRLMODE is AUTO_MODE will be added to or deleted from the ACL that supports the ACL rule automatic setup and deletion function, that is, the ACL referenced by the packet filtering that supports the ACL rule automatic setup and deletion function. If any of the preceding data flows is modified, the corresponding ACL rule that has been created automatically will be re-created.

  • [NodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering, the creation of advanced ACL rules will be delayed, and OM channels, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, and PKI flows matching these ACL rules will be interrupted.

  • [NodeB]When the main control board is the WMPT, the system does not support the ACL rule automatic setup and deletion function for packet filtering.

  • [NodeB]When the ACL rule automatic setup and deletion function is enabled for packet filtering, the system automatically creates advanced ACL rules and matches them with the following data flows: OM channels, manually created SCTP links, manually created IPPATH, time services, clock services, manually created IKE peers, and PKI. If these data flows are added or deleted, the ACL rules whose CTRLMODE is AUTO_MODE will be added to or deleted from the ACL that supports the ACL rule automatic setup and deletion function, that is, the ACL referenced by the packet filtering that supports the ACL rule automatic setup and deletion function. If any of the preceding data flow is modified, the corresponding ACL rule that has been created automatically will be re-created.

  • [NodeB]If the ACL rule automatic setup and deletion function is enabled for a packet filtering object when the configured ACL rules are about to reach the maximum number, the base station adopts a best effort solution. That is, the base station creates ACL rules first for OM channels, then for time services, clock services, manually created IKE peers, and PKI, and finally for manually created SCTP links and manually created IP paths. When the maximum ACL rules have been configured, no ACL rule can be created for OM channels, time services, clock services, manually created IKE peers, PKI, manually created SCTP links, or manually created IP paths. In this case, users need to properly plan the transport networking and allocate ACL rules.

ACLAUTOSWITCH ACL Rule Automatic Setup and Deletion Switch

Meaning: Indicates whether to enable the advanced ACL auto-setup function for packet filtering. After this switch is enabled, ACL rules in the ACL group referenced by a packet filtering object are automatically created and these ACL rules match the following data flows: OM channels, manually created SCTP links, manually created IP paths, time services, clock services, manually created IKE peers, and PKI. When the MOD PACKETFILTER command is executed to change the value of this parameter from ON(ON) to OFF(OFF), the system will automatically delete the advanced ACL rules that are automatically created in the ACL group referenced by the packet filtering object.

Disuse statement: This parameter will be deleted in later versions. In the current version, this parameter can be configured and takes effect when the Transmission Configuration Mode parameter in the GTRANSPARA MO is set to OLD, and this parameter cannot be configured and is replaced by the ACL Rule Automatic Setup and Deletion Switch parameter in the PACKETFILTERING MO when the Transmission Configuration Mode parameter in the GTRANSPARA MO is set to NEW. Therefore, avoid using this parameter.

GUI Value Range: OFF(OFF), ON(ON)

Unit: None

Actual Value Range: OFF, ON

MML Default Value: None

Recommended Value: None

Parameter Relationship:

-Configuration constraints:

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the PACKETFILTER MO, if the ACLAUTOSWITCH parameter is set to ON, the FM parameter cannot be set to L2_ACL.
  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]In the PACKETFILTER MO, if the ACLAUTOSWITCH parameter is set to ON, the MB parameter must be set to DENY.

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N
OMPEERIPLIMITSW OMCH Peer IP Limit Switch

Meaning: Indicates whether the peer IP address is limited by the ACL rules that have been automatically generated for the OM channel when the ACL rule automatic setup and deletion function is enabled. When this parameter is set to ON(ON), the peer IP address must be the IP address of the MAE. In this case, if any one of the NetEco, TraceServer, and NIC is independently deployed, the ACL rules must be manually configured before the preceding device can access the base station.

Disuse statement: This parameter will be deleted in later versions. In the current version, this parameter can be configured and takes effect when the Transmission Configuration Mode parameter in the GTRANSPARA MO is set to OLD, and this parameter cannot be configured and is replaced by the OMCH Peer IP Limit Switch parameter in the PACKETFILTERING MO when the Transmission Configuration Mode parameter in the GTRANSPARA MO is set to NEW. Therefore, avoid using this parameter.

Example

To modify a packet filter with the parameters as follows: Slot No.: 0, Subboard Type: ETH_COVERBOARD, Port Type: ETH, Port No.: 0, ACL Rule Automatic Setup and Deletion Switch: OFF, run the following command: 
MOD PACKETFILTER: SN=0, SBT=ETH_COVERBOARD, PT=ETH, PN=0, ACLAUTOSWITCH=OFF;
