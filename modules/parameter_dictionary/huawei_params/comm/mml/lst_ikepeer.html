List IKE Peer Configuration (LST IKEPEER)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to list the configuration of the IKE peer.

Note

None.

Parameters

ID Name Description
PEERNAME IKE Peer Name

Meaning: Indicates the name of the IKE peer.

GUI Value Range: 1~15 characters

Unit: None

Actual Value Range: 1~15 characters

MML Default Value: None

Recommended Value: None

Parameter Relationship:

-Configuration constraints:

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]When an IKEPEER MO is being added, the PEERNAME is case-insensitive; but when an IKEPEER MO is referenced, the PEERNAME is case-sensitive.
  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The value of PEERNAME in an IKEPEER MO must be comprised of ASCII characters.
  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The PEERNAME in a manually configured IKEPEER MO cannot be set to a value with the "SON_" prefix.

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N

To list the parameters of the IKEPEER MO, run the following command: 
LST IKEPEER:;

Output Description

Field Description

IKE Peer Name

Indicates the name of the IKE peer.

IKE Proposal ID

Indicates the ID of the IKE proposal in use.

Version

Indicates the IKE protocol version.

Exchange Mode

Indicates the IKE exchange mode. In main mode, keys are exchanged independently from identity authentications. This protects identity information and hence enhances security. The aggressive mode does not have identity authentication protection.

IP Version

Indicates the IP protocol version.

Local ID Type

Indicates the type of the identification payload that the local end transmits. The authentication can be performed based on IPv4 address, IPv6 address, fully qualified domain name (FQDN) or distinguished name (DN).

Remote IP Address

Indicates the IP address of the peer end.

Remote Name

Indicates the name of the peer end.

Pre-shared Key

Indicates the pre-shared key. The two negotiation ends must be configured with the same authenticator. This parameter takes effect only when Authentication Method in the corresponding IKEPROPOSAL is set to PRE_SHARED_KEY.

NAT Traversal

Indicates whether to enable the Network Address Translation (NAT) traversal function. The NAT traversal function is not supported by IKE SA in IPv6 scenarios.

DPD Mode

Indicates whether to enable the dead peer detection (DPD) function. When the IPSec redundancy function is enabled, it is recommended that the DPD detection function also be enabled. Otherwise, an active or standby IKE peer has to wait for a long time before the switchover.

DPD Idle Time(s)

Indicates the dead peer detection (DPD) idle time. If the total time during which the local end does not receive encrypted packets reaches the value specified by the DPD Idle Time parameter, the local end sends the DPD packet to perform DPD. However, the exact time at which the eNodeB sends DPD messages varies depending on network environment.

DPD Retransmission Interval(s)

Indicates the interval at which DPD detection frames are sent. The interval at which DPD detection frames are sent may slightly vary in various network environments such as network congestion, delay, and jitter.

DPD Retransmission Count

Indicates the number of retransmission attempts after a DPD detection fails.

Control Mode

Indicates whether the object can be modified or deleted by the system. The value MANUAL_MODE means that only the user can modify or delete the object. The value AUTO_MODE means only the system can modify or delete the object.

Local IP Address

Indicates the IP address of the local end, which is used in IKE negotiation. This IP address can be set to 0.0.0.0 or a configured interface IP address at the local end. If this parameter is set to 0.0.0.0, the BS automatically uses the interface IP address to negotiate with the peer. If multiple IP addresses are configured at the port, it is recommended that you specify one IP address for the negotiation. If the local BS uses the digital certificate and IP address for authentication in the negotiation, ensure that the IP address in the certificate is the same as the local IP address of the BS.

Auto Config Flag

Indicates whether the object is created by the system. MANUAL_CREATED means that the object is configured by the user manually. AUTO_CREATED means that the object is created by the system.

Redundancy Flag

Indicates the redundancy attribute of an IKE peer. If this parameter is set to NONE(Non-redundancy), the IKE peer does not use the IPSec redundancy function. If this parameter is set to MASTER(Master) or SLAVE(Slave), the IPSec policy group that references the IKE peer has been bound to an interface, the security configurations of the IPSec redundancy group to which the IKE peer belongs are modified, and the modified objects (IKEPROPOSAL, IKEPEER, IPSECPOLICY, IPSECPROPOSAL, IPSECBINDITF, and IPSECBIND) are reloaded, then the system unbinds the the IPSec policy group from the interface and then binds the IPSec policy group to the interface again. In the IPSec redundancy function, if the IKE SA of the slave IKE peer is available (you can run the DSP IKESA command to query the IKE SAs) or the slave IKE peer is being negotiated (you can check the negotiation status through IKE tracing), the slave IKE peer is being used. Otherwise, the master IKE peer is being used.

Master Peer Name

Indicates the name of the master IKE peer to which the current slave IKE peer corresponds.

Priority

Indicates the priority of the current slave IKE peer. A small value indicates a high priority of the slave IKE peer.

Certificate Source

Indicates the source of the certificate used for IKE negotiation in the multi-PKI scenario. When this parameter is set to APPCERT, the certificate configured by the APPCERT MO is used. When this parameter is set to CERTMK, the certificate configured by the CERTMK MO is used.

Certificate File Name

Indicates the name of the certificate file used in the IKE negotiation in the multi-PKI scenario.

IKEv2 Redirect Switch

Indicates whether to enable the IKEv2 redirection function. When this parameter is set to OFF, the base station does not support the IKEv2 redirection function, and will discard the redirection packets sent from the peer end. When this parameter is set to ON, the base station supports the IKEv2 redirection function. When the IKEv2 redirection function is enabled, the negotiation must be initiated by the base station. The IKEv2 redirection function is not supported by IKE SA in IPv6 scenarios.

IPSec PreFragment Switch

Indicates whether packets can be fragmented before being encrypted. If this parameter is set to OFF and the IPVERSION parameter is set to IPv4 for an IKE peer, the IPv4 traffic is not fragmented, and the IPv6 traffic is fragmented based on the maximum MTU capability of the internal ports. If IPVERSION is set to IPv6 for an IKE peer, the internal system sets the MTU used by IPv4 and IPv6 traffic to the board maximum capability and fragments packets based on the board maximum capability.

If this parameter is set to ON, packets are fragmented before being encrypted. If the IPVERSION parameter is set to IPv4 for an IKE peer, IPv4 and IPv6 packets are fragmented based on the MTU value of the IKE peer. If the IPVERSION of the IKE peer is set to IPv6, IPv4 and IPv6 traffic is fragmented based on the MTU4 and MTU6 values of the tunnel interface, respectively.

Maximum Transmission Unit(byte)

Indicates the MTU of IPv4 or IPv6 before packets are encrypted when the IP protocol version of an IKE peer is IPv4. This parameter takes effect for both IPv4 and IPv6 traffic when the ACL type of the IPsec policy that references the IKE peer is IPv4+IPv6.

If the length of a packet before encryption exceeds the value of this parameter, the system fragments the packet based on the value of this parameter and then encrypts the fragmented packet. If the length of the encrypted packet exceeds the value of MTU in the ETHPORT MO, ETHCIPORT MO, ETHTRK MO, IPRT MO, IPROUTE4 MO, and INTERFACE MO, the encrypted packet will be fragmented again based on the MTU of the ETHPORT MO, ETHCIPORT MO, ETHTRK MO, IPRT MO, IPROUTE4 MO, or INTERFACE MO.
