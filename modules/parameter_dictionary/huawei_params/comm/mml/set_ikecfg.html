Set Basic IKE Configuration (SET IKECFG)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to set the global parameters related to the basic IKE configurations.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • If IDType of the IKE Peer is set to FQDN and AUTHMETH of the IKE security proposal is set to PRE_SHARED_KEY, run this command to set Local Name, and keep Local Name as same as Remote Name of the IKE peer of other end if Remote Name exists.

  • The timeout duration within which the local end waits for keepalive packets must be at least three times the time interval at which the peer end sends the keepalive packets. Otherwise, keepalive negotiation fails.

  • If IKEVERSION of an IKE peer is set to IKE_V2, sending keep-alive messages is not allowed. Therefore in this case, IKEKLI and IKEKLT do not take effect.

  • Dead Peer Detection (DPD) is configured on a per IKE peer basis, whereas keep-alive message detection is configured for all IKE peers on a BS.

  • If a BS is enabled with keep-alive message detection and DPD is configured for an IKE peer, this IKE peer preferentially uses DPD. In this case, the keep-alive message of this IKE peer will not expire.

IPSECSWITCHBACK IPSec Redundancy Switch Back

Meaning: Indicates whether to allow a switchback to the master IKE peer after its negotiation recovers when the IPSec redundancy function is enabled.

If this parameter is set to OFF, the base station automatically stops the negotiation with the master IKE peer (IPv4 or IPv6) when the negotiation with the master IKE peer fails and the negotiation with a slave IKE peer succeeds. In this case, the IKE negotiation failure alarm for the master IKE peer is not cleared. If the negotiation with a slave IKE peer succeeds previously but fails now, and if the negotiation with the slave IKE peer with the lowest priority still fails, the negotiation with the master IKE peer is started immediately even if this parameter is set to OFF. After the negotiation with the master IKE peer succeeds, the system immediately switches back to the master IKE peer and clears the IKE negotiation failure alarm for the master IKE peer.

If this parameter is set to ON, the negotiation with the master IKE peer (IPv4 or IPv6) does not stop when the negotiation with the master IKE peer fails and services are switched to a slave IKE peer. In this case, the IKE negotiation failure alarm for the master IKE peer is cleared only when the negotiation with the master IKE peer succeeds. If the negotiation with the master IKE peer succeeds but the negotiation with a slave IKE peer fails, the system immediately switches services back to the master IKE peer. If the negotiation with a slave IKE peer succeeds, the system switches back to the master IKE peer after the specific timer expires. (The timer length is the sum of the IPSec switchback wait time and the random IPSec switchback delay.) If you run the SET IKECFG command to forbid the switchback when the master and slave IKE peers are being switched (in the switchback wait period), the system immediately stops the negotiation of the primary channel.

If this parameter is set to IPV4_ON+IPV6_OFF, the IPv4 switchback is enabled but the IPv6 switchback is disabled. This option is valid only for the UMPT/UMDU board that supports IPv6.

If this parameter is set to IPV4_OFF+IPV6_ON, the IPv4 switchback is disabled but the IPv6 switchback is enabled. This option is valid only for the UMPT/UMDU board that supports IPv6.

IPSECSBWAITTIME IPSec Redundancy Switch Back Wait Time

Meaning: Indicates the duration before a switchover from the slave IKE peer to the master IKE peer in the IPSec redundancy function. If the master IKE peer that has been switched over to the slave IKE peer due to failed negotiation succeeds in the negotiation again, the duration from the negotiation success to the back switchover equals the duration specified by this parameter plus a random delay generated with the IPSec Redundancy Switch Back Random Delay Time parameter specified. If the SET IKECFG command is executed to modify the value of this parameter during a back switchover, the modified value does not take effect until the next back switchover.

IPSECSBRANDTIME IPSec Redundancy Switch Back Random Delay Time

Meaning: Indicates the random delay before a switchover from the slave IKE peer to the master IKE peer in the IPSec redundancy function. IPSECBINDMODE IPSec Bind Mode

Meaning: Indicates the binding mode of an IPsec policy group, which can be global mode and single-interface mode. The two modes are mutually exclusive. In global mode, an IPsec policy group and packet filtering policies can be bound only to a normal interface, and the IPsec and packet filtering policies take effect on the normal interface and all VLAN subinterfaces in the default routing domain of the physical port to which the normal interface belongs. In single-interface mode, the IPsec policies take effect only on the interface bound to the IPsec policy group and packet filtering policies take effect only on the interface bound to the packet filtering policies. This parameter is valid only for IPv4 IPsec and packet filtering policies.

Example

To set the IKE basic configuration with the parameters as follows: Local Name: IKECFG1, Interval for Sending Keepalive Packets: 20, Keepalive Timeout: 60, Interval for Sending NAT Keepalive Packets: 20, DSCP: 48, IPSec Redundancy Switch Back: ON, IPSec Redundancy Switch Back Wait Time: 2, IPSec Redundancy Switch Back Random Delay Time: 30, IPSec Redundancy Switchover Wait Time: 5, IPSec Redundancy Switchover Random Delay Time: 60, IPSec Bind Mode: SINGLE, run the following command:
SET IKECFG: IKELNM="IKECFG1", IKEKLI=20, IKEKLT=60, NATKLI=20, DSCP=48, IPSECSWITCHBACK=ON, IPSECSBWAITTIME=2, IPSECSBRANDTIME=30, IPSECSOWAITTIME=5, IPSECSORANDTIME=60, IPSECBINDMODE=SINGLE;
