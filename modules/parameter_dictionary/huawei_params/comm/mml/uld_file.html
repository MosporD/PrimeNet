Upload File (ULD FILE)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to upload a file from an NE to a specified directory on the FTP server.

Note

  • Uploading files in non-compressed mode takes a longer time than uploading files in compressed mode. However, uploading files in compressed mode increases CPU usage by 10% to 50% and CPU overload may affect UE access. Therefore, it is recommended that files be uploaded in non-compressed mode with flow control performed.

  • Before running this command, ensure that the following conditions are met:

    The FTP server is functioning properly.

    The FTP port on the firewall between the FTP server and the NE is open.

    The entered user name and password for the FTP server are correct and the user has permission to write data into the specified directory.

    No file on the FTP server has the same name as the destination file. If there is such a file on the server, the file on the FTP server will be replaced after the upload.

  • The operations of uploading files to the base station are exclusive. If multiple clients upload the same type of files at the same time, the files probably fail to be uploaded and "Tasks associated with this type of file are running. Try it again later." is displayed. In this case, wait for a moment and run this command by following the displayed instructions.

  • When performing a one-click log upload for RRUs, ensure that the file type is set to BRDLOG and the cabinet number, subrack number, and slot number are specified.

  • If the File Type parameter is set to BRDLOG, one-click logs of the main control boards in the root and leaf BBUs are uploaded by default. If the File Type parameter is set to a value other than BRDLOG, the corresponding logs of the main control board in the root BBU are uploaded by default. The slot, subrack, and cabinet must be specified to upload other board logs.

  • The logs of a main control board or other boards are uploaded in a compressed package to the FTP server. Therefore, only a package file is generated on the FTP server. When setting the Destination File Name parameter, specify the destination file name, or the path as well as the destination file name.

  • When uploading a file, you need to select the correct function type.

  • Lower-level File Type can be selected only when the active main control board logs are uploaded and the source file type is one of the following: BRDLOG-GBTS, BRDLOG-NODEB, BRDLOG-ENODEB, BRDLOG-RFA, and BRDLOG-GNODEB.

  • Before uploading one-click logs, ensure that either of the following conditions is met if a device file must be included in the log: 1. An EXP DEVFILE command has been executed. 2. The NE with Maintenance Mode set to NORMAL has been once connected to the MAE.

  • The operation of uploading a BRDLOG file is mutually exclusive with that of uploading some files in the BRDLOG file. If you upload a BRDLOG file and a log file that is contained in the BRDLOG file at the same time, the latter file may fail to be uploaded and the "Tasks associated with this type of file are running. Try it again later." is displayed. In this case, wait a moment and run this command by following the displayed instructions.

  • The UCR log type is only supported by the UMPTe/UMPTga/UMPTg board.

  • [Co-MPT,NodeB,eGBTS,eNodeB]If a time range is specified for the one-click logs to be uploaded, operation logs (OPRLOG), running logs (RUNLOG), CHR logs (CHRLOG), enhanced CHR logs (ECRLOG), and UCR logs (UCRLOG) ,and others within this time range will be uploaded.

  • [Co-MPT,NodeB,eGBTS,eNodeB]If Lower-level File Type is not specified, all files in one-click logs will be uploaded.

  • [Co-MPT,NodeB]Files of the RRUIQDATA or RRURXPOWER type are uploaded to support interference detection. The corresponding RRUs must also support this function. Only RRUs such as the WRFU, RRU3801c, RRU3804, and RRU3801e support this function.

DSTF Destination File Name

Meaning: Indicates the name of the destination file.

For file uploading operations, this parameter indicates the name of the destination file saved to the FTP server, which can include the path of the file. If the path is not included in the file name, the file is saved in the default path on the FTP server. The maximum length of the file name plus the path cannot be greater than the maximum length of file name supported by the FTP server and cannot contain more than 248 characters. (Some servers do not support a full-path file name consisting of 248 characters. For details, see the related FTP server manual.)

For file downloading operations, this parameter indicates the name of the destination file downloaded to a board, which does not include any paths.

If the parameter contains only the file name, the length of the file name cannot exceed 64 characters.

GUI Value Range: 1~248 characters

Unit: None

CF Compression Flag

Meaning: Indicates whether to compress the source file before it is uploaded. If this parameter is set to COMPRESSED, a compressed file is generated after the source file is uploaded. The compressed file has a file name extension of .gz and can be decompressed using the WinRAR program. For example, if the source file is named "OPLOG.txt", the file will be compressed into a file named "OPLOG.txt.gz".

GUI Value Range: UNCOMPRESSED(Uncompressed), COMPRESSED(Compressed)

Unit: None

Actual Value Range: UNCOMPRESSED, COMPRESSED

MML Default Value: UNCOMPRESSED(Uncompressed)

Recommended Value: UNCOMPRESSED(Uncompressed)

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: The CPU usage increases by 10% to 50% if the source file is compressed before being uploaded. CPU overload will lead to access failure.

Applicable Mode: G, U, L, N, R

FLOWCTRL Flow Control Option

Meaning: Indicates whether to perform flow control during file upload. During busy hours, flow control obviously reduces CPU usage during file upload but slows file upload. During off-peak hours, flow control accelerates file upload. Except when flow control causes file upload to fail or to be slower than required despite an urgent requirement of log upload, flow control is recommended.

GUI Value Range: Y(Flow Control), N(Not to Flow Control)

Unit: None

Actual Value Range: Y, N

Example

Example 1: To upload a file with the parameters as follows: Source File Type: EXPT, Cabinet No.: 0, Subrack No.: 0, Slot No.: 3, Destination File Name: \expt, IP Mode: IPV4, FTP Server IP: 192.168.60.35, User Name: admin, Password: admin, run the following command: 
ULD FILE: FUNCTYPE=ALL, SRCF=EXPT, CN=0, SRN=0, SN=3, DSTF="\expt", MODE=IPV4, IP="192.168.60.35", USR="admin", PWD="*****";

Example 2:To upload a file with the parameters as follows: Source File Type: EXPT, Cabinet No.: 0, Subrack No.: 0, Slot No.: 3, Destination File Name: /export/home/sysm/ftproot/expt, IP Mode: IPV4, FTP Server IP: 192.168.60.35, User Name: admin, Password: admin, run the following command:
ULD FILE: FUNCTYPE=ALL, SRCF=EXPT, CN=0, SRN=0, SN=3, DSTF="/export/home/sysm/ftproot/expt", MODE=IPV4, IP="192.168.60.35", USR="admin", PWD="*****";

Example 3: To upload a file with the parameters as follows: Function Type: GBTS, Source File Type: BRDLOG-GBTS, Lower-level File Type: OPRLOG&DBGLOG, IP Mode: IPV4, FTP Server IP: 192.168.60.35, User Name: admin, Password: admin, run the following commands:
ULD FILE: FUNCTYPE=GBTS, SRCF=BRDLOG-GBTS, SUBTYPE=OPRLOG&DBGLOG, DSTF="\brdlog", MODE=IPV4, IP="192.168.60.35", USR="admin", PWD="*****";

Example 4: To upload a file with the parameters as follows: Function Type: GBTS, Source File Type: BRDLOG-GBTS, IP Mode: IPV4, FTP Server IP: 192.168.60.35, User Name: admin, Password: admin, run the following commands:
ULD FILE: FUNCTYPE=GBTS, SRCF=BRDLOG-GBTS, DSTF="\brdlog", MODE=IPV4, IP="192.168.60.35", USR="admin", PWD="*****";
