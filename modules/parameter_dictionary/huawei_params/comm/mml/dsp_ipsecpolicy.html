Display Effective Data of IPSec Policy (DSP IPSECPOLICY)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to query the IPSec policy configuration that takes effect.

Note

None.

Parameters

ID Name Description
SPGN Policy Group Name

Meaning: Indicates the name of the IPSec policy group.

GUI Value Range: 1~15 characters

Unit: None

Actual Value Range: 1~15 characters

MML Default Value: None

Recommended Value: None

Parameter Relationship:

-Configuration constraints:

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The value of the Policy Group Name parameter is not case sensitive when an IPSec policy is added. The values of the Policy Group Name parameters are case sensitive for IPSec policies that are added to the same group. When an IPSec policy is to be removed, modified, queried, or referenced by other MOs or commands, the value of the Policy Group Name parameter is case sensitive.
  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The Policy Group Name parameter in a manually configured IPSECPOLICY MO cannot be set to a value with the SON_ prefix.

-Others:

  • [Co-MPT, NodeB, eGBTS, eNodeB, gNodeB]The parameter is valid only when PHASE is set to PHASE2.

SPSN IPSec Sequence No.

When Direct IPSec Priorities Match Switch is set to ENABLE(Enable), the IPsec policy of the directly connected IPsec tunnel is preferentially matched. Output Description

Field Description

Cabinet No.

Indicates the cabinet number of the board that adopts the IPSec policy.

Subrack No.

Indicates the subrack number of the board that adopts the IPSec policy.

Slot No.

Indicates the slot number of the board that adopts the IPSec policy.

Policy Group Name

Indicates the name of the IPSec policy group.

IPSec Sequence No.

Indicates the sequence number (SN) of an IPsec policy. IPsec policies with an SN ranging from 1 to 10000 are configured by users. IPsec policies with an SN ranging from 10001 to 20000 are automatically generated by the system. When Direct IPSec Priorities Match Switch is set to DISABLE(Disable), the IPsec policy with a smaller SN is preferentially matched. When Direct IPSec Priorities Match Switch is set to ENABLE(Enable), the IPsec policy of the directly connected IPsec tunnel is preferentially matched. For details about the IPsec policy of the directly connected IPsec tunnel, see the meaning of the Direct IPSec Priorities Match Switch parameter.

ACL Type

Indicates the type of the ID of the access control list.

ACL ID

Indicates the ACL number when the type of the ACL is IPV4 or IPV6, or the ACL number corresponding to IPV4 when the type of the ACL is IPV4+IPV6.

ACL2 ID

Indicates the number of the ACL6 corresponding to IPV6 when the type of the ACL number that references the ACL is IPV4+IPV6.

IPSec Proposal Name

Indicates the name of the IPSec proposal.

IKE Peer Name

Indicates the name of the IKE peer that is referenced by the IPSec policy.

Perfect Forward Secrecy

Indicates the perfect forward secrecy (PFS) value. In the second phase of IPSec negotiation, PFS enables the BS to use a key that is not derived from the first-phase key, ensuring that the two keys are independent of each other. According to PFS, a key protects a unique set of data. The elements used to generate keys are not reusable. If a key is decrypted, other keys are still secure.

If the IPSec policy is used to initiate IPSec negotiation, a PFS exchange is launched, requiring consistent PFS values between the local and peer ends. If the PFS values are inconsistent, the following are true: when the IPsec policy uses the IKEv1 protocol, the IPsec SA negotiation will fail; when the IPsec policy uses the IKEv2 protocol, only one IPsec SA can be successfully negotiated and renegotiation of this IPsec SA will also fail. For details, see RFC2408, RFC5996, and RFC2409. The security levels specified by the values PFS_GROUP1, PFS_GROUP2, PFS_GROUP19, and PFS_GROUP20 are in ascending order. However, the processing durations are also in ascending order.

The values PFS_GROUP19(256-bit ECC Diffie-Hellman Group) and PFS_GROUP20(384-bit ECC Diffie-Hellman Group) are supported by the UMPTa, UMPTb, UMPTe, UMPTg, UMPTga, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7, UBBPg9 and UMDU boards.

SA Duration Mode

Indicates the configuration mode of the IPSec SA life cycle. If this parameter is set to GLOBAL, the default SA life cycle is used. In this case, LTS and LTKB are set to the default values 3600 and 69120000, respectively. If this parameter is set to LOCAL, the SA life cycle is configurable.

Lifetime Based On Time(s)

Indicates the life cycle of an IPSec SA. An IPSec SA becomes invalid once its life cycle specified by this parameter elapses. Before the life cycle of an IPSec SA elapses, the IPSec policy is used in an attempt to establish a new IPSec SA through negotiation to ensure secure transmission; before the negotiation is complete, the original IPSec SA is still used. After the negotiation is complete, the new SA is immediately used. IPSec SA negotiation takes a period. To prevent SA updating from affecting communication security, a life cycle longer than 900 seconds is recommended.

Lifetime Based On Traffic(kB)

Indicates the traffic volume threshold for the IPSec policy, above which negotiation for a new IPSec SA is started. The value 0 indicates that the function, which initiates negotiation for a new IPSec SA based on the traffic volume, is disabled. However, when BS acts as initiator in IKEv1 and this value is set to 0, if the responder insists or enforces the IPSec SA traffic lifetime to BS, BS will enable this function to avoid service breakdown.

Anti-Replay Window Size

Indicates the size of the IPSec packet anti-replay window. If the value of this parameter is set to 0, the IPSec packet anti-replay function is disabled. If the value of this parameter is set to 32, 64, 128, 256, 512, 1024, 2048 or 4096, the system checks whether the packets are duplicate in the window. A packet is discarded if it has a duplicate packet or its sequence number is smaller than any packet in the window. The window slides if the sequence number of the packet is larger than any packet that is received in the window.

Narrow Down Switch

Indicates whether to reduce the ACL rule scope. When this parameter is set to ON, if the ACL rule scope of the NE differs from that of the peer end, the NE attempts to reduce the range of data flows protected by the ACL rules. In this way, the NE and the peer end can successfully negotiate an IPSec SA. This parameter is invalid when the version of the IKE peer specified by IKE Peer Name in the IPSECPOLICY MO is IKE V1.
