Add ACL Rule (ADD ACLRULE)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a rule to an access control list (ACL).

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Before running this command, ensure that the associated ACL has been configured.

  • In the same ACL, the source or destination IP address range as well as the source or destination port number range of different ACL rules that have the same ACL ID and different ACL rule IDs cannot have any inclusion or overlapping relationships. Otherwise, the ACL rules conflict.

  • If multiple ACL rules exist, the ACL rules for automatically establishing SCTP links and IP paths are preferentially matched when data flows enter the base station for packet filtering by ACL rules. Then, other ACL rules are used for packet filtering based on ACL rule IDs in ascending order.

  • Board specifications: On a UMPTa/UMPTb/UMDU/UTRPc, a maximum of 1536 ACL rules can be used. Among the ACL rules, a maximum of 1000 ACL rules automatically configured for packet filtering and manually configured ACL rules can be used, a maximum of 1024 ACL rules automatically configured for packet filtering in end point configuration mode can be used, and a maximum of 256 ACL rules automatically configured for IPSec in end point configuration mode can be used. On a UMPTe, a maximum of 3072 ACL rules can be used. Among the ACL rules, a maximum of 1000 ACL rules automatically configured for packet filtering and manually configured ACL rules can be used, a maximum of 2048 ACL rules automatically configured for packet filtering in end point configuration mode can be used, and a maximum of 384 ACL rules automatically configured for IPSec in end point configuration mode can be used. On a UMPTg/UMPTga, a maximum of 6092 ACL rules can be used. Among the ACL rules, a maximum of 1000 ACL rules automatically configured for packet filtering and manually configured ACL rules can be used, a maximum of 4708 ACL rules automatically configured for packet filtering in end point configuration mode can be used, and a maximum of 384 ACL rules automatically configured for IPSec in end point configuration mode can be used. On an LMPT, a maximum of 512 ACL rules can be used. On a WMPT/UTRP (subboard type: UEOC/UQEC), a maximum of 48 ACL rules can be used. On a GTMUc, a maximum of 128 ACL rules can be used. In a single high-level rule, a maximum of 24 ACLRULEs can be used on a UTRP (subboard type: UEOC/UQEC). The number of layer-2 ACL rules based on the MAC layer must not exceed 64.

  • System specifications: If a WMPT is used as the main control board, a maximum of 48 ACL rules can be configured for a base station and a maximum of 24 ACL rules can be configured in each ACL. If a GTMUb/GTMUc is used as the main control board, a maximum of 128 ACL rules can be configured for a base station. If a UMPTa/UMPTb/UMDU is used as the main control board, a maximum of 1536 ACL rules can be configured for a base station. If a UMPTe is used as the main control board, a maximum of 3072 ACL rules can be configured for a base station. If a UMPTg/UMPTga is used as the main control board, a maximum of 6092 ACL rules can be configured for a base station. If an LMPT is used as the main control board, a maximum of 868 ACL rules can be configured for a base station. If a UMPT/UMDU is used as the main control board, the total number of manually configured ACL rules and ACL rules automatically configured for packet filtering must not exceed 1000. If a GTMUb/GTMUc/UMPT/UMDU/LMPT is used as the main control board, the maximum number of layer 2 ACLRULEs based on the MAC layer information is 64.

  • For successfully configured ACL rules that have not taken effect, you can query them only by running the LST ACLRULE command rather than the DSP ACLRULE command.

  • A maximum of 16 ACL rules can be configured in one layer 2 ACL.

  • If multiple ACL rules protect the same data flow, the SAs successfully negotiated by these ACL rules also protect this data flow. As a result, the encryption and decryption of this data flow may be performed by different SAs, resulting a fault. Therefore, data flows protected by multiple ACL rules should be exclusive, which can be configured by users.

  • If an ACL rule is manually configured with Action set to DENY(Deny), Protocol Type set to IP(IP) and both Source IP Address and Destination IP Address matching all IP addresses, the ACL rule will be changed to the last rule in the packet filtering ACL group during the validation of the ACL rule ID, that is, the ACL rule ID is changed to 90000. In addition, when Source IP Address or Destination IP Address is set to 0.0.0.0, the Source Wildcard or Destination Wildcard parameter that has actually taken effect is 255.255.255.255.

  • An ACL rule takes effect on the board where ACL takes effect. If the ACL MO does not take effect on any board because it does not have a bearer MO (packet filtering, packet filtering policy, IPsec policy group binding, or IPsec policy group binding interface), the ACL rule will also not take effect.

  • User-configured ACL rules count in the specifications of automatically setup ACL rules even if the user-configured ACL rules are not referenced by any bearer.

  • When packet filtering ACL rules are automatically configured by the system or manually configured by users, data forwarding performance fluctuates temporarily.

  • [Co-MPT,NodeB,eNodeB,gNodeB]If an ACL MO is referenced by an IPSECPOLICY MO, the ACL MO cannot be configured with multiple ACLRULE MOs of the permit type that have inclusive relationships. Otherwise, any of the following may occur: IPsec SA negotiation fails; IPsec SA negotiation succeeds but is deleted later; different IPsec SA negotiation results are obtained when the narrow down switch is turned on.

  • [Co-MPT,NodeB,eNodeB,gNodeB]If an ACLRULE MO is referenced by an IPSECPOLICY MO of the IPv4 type in IPsec scenarios, neither Source Port Operate nor Destination Port Operate in the ACLRULE MO can be set to OP_NEQ (Not Equivalent).

  • [Co-MPT,NodeB,eNodeB,gNodeB]If an ACLRULE MO is referenced by an IPSECPOLICY of the IPv4 type in IPsec scenarios, Match DSCP in the ACLRULE MO cannot be set to YES (Yes).

  • [Co-MPT,NodeB,eNodeB,gNodeB]In IPSec scenarios, if an ACL rule list with configuration conflicts described in the preceding two notes exists and is referenced by an IPSECPOLICY MO, exceptions such as IPSec SA negotiation failures and frequent switchovers may occur on the device (depending on the peer configurations).

  • [Co-MPT,eNodeB,gNodeB]On a BS, the total number of ACLRULE MOs and ACLRULE6 MOs must be less than or equal to 6092.

  • [Co-MPT,eNodeB,gNodeB]If the UMPTa/UMPTb/UMDU is the main control board, a maximum of 1536 ACLRULE MOs and ACLRULE6 MOs can take effect on a BS. If the UMPTe is the main control board, a maximum of 3072 ACLRULE MOs and ACLRULE6 MOs can take effect on a BS. If the UMPTg/UMPTga is the main control board, a maximum of 6092 ACLRULE MOs and ACLRULE6 MOs can take effect on a BS.

FORCEEXECUTE Support Forcible Execution

Meaning: Indicates whether a forcible change of an ACL rule is made. When this parameter is set to NO(No), the system checks whether the change affects upper-layer services. If the change affects upper-layer services, the forcible change will fail. When this parameter is set to YES(Yes), the system does not check whether the change affects upper-layer services. Upper-layer services include the following: active/standby OM channel (OMCH), DNS service (DNSSRV), certificate issuance (CA), CRL update (CRLTSK), IP clock link (IPCLKLINK), NTP (NTPC), ABIS CP/IUB CP/S1 CP/X2 CP/M2 CP/ECO CP/eX2 CP/SO CP/UX2 CP/XW CP/gNBCUX2 CP/gNBCUNg CP/gNBCUXn CP (SCTPLNK/SCTPHOST/SCTPPEER), and ABIS UP/IPPATH of unknown service type/IUB UP/UX2 UP/S1 UP/X2 UP/eX2 UP/XW UP/gNBCUX2 UP/gNBCUS1 UP/gNBCUNg UP/gNBCUXn UP (IPPATH/USERPLANEHOST/USERPLANEPEER). Only the change of the ACL rule that is manually configured with Protocol Type set to IP and Match DSCP set to NO in IPsec networking is checked. This parameter is invalid when a WMPT, LMPT, GTMUb, or GTMUc serves as the main control board.

Pay attention to the following when using this parameter:

1. The system checks whether a forcible change of an ACL rule affects upper-layer services based on the configuration data instead of based on the actual running status of these services.

2. If an NE is configured with an SRCIPRT, SRCIPROUTE4, PPPLNK, or MPGRP MO, the system does not check whether a forcible change of an ACL rule affects upper-layer services.

Example

To add an ACL rule with the parameters as follows: ACL ID: 3000, Rule ID: 10, Protocol Type: IP, Source IP Address: 192.168.5.5, Source Wildcard: 0.0.0.255, Destination IP Address: 192.168.5.6, Destination Wildcard: 0.0.0.255, Match DSCP: YES, DSCP: 25, run the following command: 
ADD ACLRULE: ACLID=3000, RULEID=10, PT=IP, SIP="192.168.5.5", SWC="0.0.0.255", DIP="192.168.5.6", DWC="0.0.0.255", MDSCP=YES, DSCP=25;
