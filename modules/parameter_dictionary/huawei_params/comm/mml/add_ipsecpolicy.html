Add IPSec Policy (ADD IPSECPOLICY)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add an IP Security (IPSec) policy. An IPSec policy group consists of IPSec policies with the same group name. An IPSec policy is identified by the group name (specified by the SPGN parameter) and the policy number (specified by the SPSN parameter).

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Before running this command, ensure that the associated ACL, IPSec proposal, and IKE peer have been configured. When an IPSec policy group is applied to a port, the policies in the group are all applied to the port. In this way, different data streams can be protected by different SAs.

  • If the encapsulation mode is transport mode for the IPSec proposal referenced by an IPSec policy, the following conditions related to the ACL rule referenced by the same IPSec policy must be all met: (1) The source IP address and destination IP address are both set to host IP addresses; (2) The source IP address is a configured device IP address; (3) The destination IP address is the same as the remote IP address (specified by the REMOTEIP parameter) in the IKEPEER object referenced by the same IPSec policy. If the preceding conditions are not met, encrypted packets will fail to be decrypted.

  • One IPSec policy can reference a maximum of one IPSec proposal.

  • Before running this command, ensure that the IPSec policy to be added references an ACL that is different from that referenced by either IPSec policy of any configured IPSec tunnel pair.

  • If a slave IKE peer is referenced by an IPSec policy, the master IKE peer of this slave IKE peer must have been referenced by an IPSec policy.

  • It is recommended that different IPSec policy groups use different IKE peers. It is recommended that different IPSec policies use different ACLs if these policies are not in an IPSec tunnel pair or IPSec redundancy function. Otherwise, services are interrupted.

  • System specifications: If a WMPT/LMPT/GTMUb/GTMUc is used as the main control board, a maximum of 100 IPSec policies can be configured for a base station. If a UMPTa/UMPTb/UMDU is used as the main control board, a base station supports a maximum of 264 IPsec policies. If a UMPTe is used as the main control board, a base station supports a maximum of 392 IPsec policies. If a UMPTg/UMPTga is used as the main control board, a base station supports a maximum of 520 IPsec policies. If a UMPT/UMDU is used as the main control board, a maximum of 256 IPv4 IPsec policies and a maximum of 128 IPv6 IPsec policies can be manually configured for a base station.

  • Board specifications: A UMPTa/UMPTb/UMDU supports the IPsec policy specifications of 264. A UMPTe supports the IPsec policy specifications of 392. A UMPTg/UMPTga supports the IPsec policy specifications of 520. A UMPTa/UMPTb/UMDU supports a maximum of 128 IPv6 IPsec policies. A UMPTe supports a maximum of 392 IPv4 IPsec policies and 392 IPv6 IPsec policies. A UMPTg/UMPTga supports a maximum of 392 IPv4 IPsec policies and 520 IPv6 IPsec policies. A UTRPc supports a maximum of 264 IPSec policies. An LMPT/UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9 supports a maximum of 100 IPSec policies.

  • The numbers of the ACLs referenced by the IPSec policy of the master and slave IKE peers in the same group must be the same.

  • A master or slave IKE peer can be referenced by only one IPSec policy.

  • The Encapsulation Mode parameter must be set to TUNNEL for the IPSec proposal that is referenced by the IPSec policy of the master or slave IKE peer.

  • After IKEv2 Redirect Switch is set to ON in an IKE peer, this IKE peer can be referenced by only one IPSECPOLICY MO.

  • The IPSECPOLICY MO takes effect on the board together with the IPSECBIND MO. That is, the IPSECPOLICY MO does not take effect on any board when being configured, and takes effect on the board when the bearer MO (IPSECBIND) is configured.

  • A new IPSECPOLICY MO takes effect on the board where the IPSec policy group takes effect. When the IPSECPOLICY MO takes effect, if the IPSECPROPOSAL, ACL, IKEPEER and IKEPROPOSAL objects, which the IPSECPOLICY MO depends on, do not have a bearer MO (PACKETFILTER, PACKETFILTERING, IPSECBIND or IPSECBINDITF) on the board where the IPSECPOLICY takes effect, the IPSECPROPOSAL, ACL, IKEPEER and IKEPROPOSAL objects will try to take effect on the board. If these objects fail to take effect, the IPSECPOLICY MO will also fail to take effect.

  • If the security protocol used by an IPSec proposal that is referenced by an IPSec policy is AH_ESP, a maximum of two IPSec SAs can be obtained from negotiation for the ACL rule with ACTION set to PERMIT that uses the IPSec policy. If the security protocol used by an IPSec proposal that is referenced by an IPSec policy is AH or ESP, a maximum of one IPSec SA can be obtained from negotiation for the ACL rule with ACTION set to PERMIT that uses the IPSec policy.

  • User-configured IPSec policies count in the specifications of automatically setup IPSec policies even if the user-configured IPSec policies are not referenced by any bearer.

  • The LMPT/UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4 supports a maximum of 128 IPv4 IPsec SAs. The UTRPc supports a maximum of 264 IPv4 IPsec SAs. The UMPTa/UMPTb/UMDU supports a maximum of 264 IPv4 IPsec SAs and 256 IPv6 IPsec SAs. If both IPv4 IPsec SAs and IPv6 IPsec SAs exist, a maximum of 264 IPv4 IPsec SAs and IPv6 IPsec SAs are allowed. The UMPTe supports a maximum of 512 IPv4 IPsec SAs and 392 IPv6 IPsec SAs. If both IPv4 IPsec SAs and IPv6 IPsec SAs exist, a maximum of 512 IPv4 IPsec SAs and IPv6 IPsec SAs are allowed. The UMPTg/UMPTga supports a maximum of 512 IPv4 IPsec SAs and 520 IPv6 IPsec SAs. If both IPv4 IPsec SAs and IPv6 IPsec SAs exist, a maximum of 520 IPv4 IPsec SAs and IPv6 IPsec SAs are allowed. The IP version of an IPsec SA is determined by the IP version of the IKE peer referenced by the IPsec policy that generates the IPsec SA.

  • If the ACLTYPE, ACLID, and ACL2ID referenced by the IPSec policies used by the active and standby IKEPEERs in the DR scenario are different, the DR function cannot be used.

  • When the TRANMODE in the associated IPSECPROPOSAL MO is ESP and ESPAUTHALG is NULL, the anti-replay function does not take effect.

PFS Perfect Forward Secrecy

Meaning: Indicates the perfect forward secrecy (PFS) value. In the second phase of IPSec negotiation, PFS enables the BS to use a key that is not derived from the first-phase key, ensuring that the two keys are independent of each other. According to PFS, a key protects a unique set of data. The elements used to generate keys are not reusable. If a key is decrypted, other keys are still secure.

If the IPSec policy is used to initiate IPSec negotiation, a PFS exchange is launched, requiring consistent PFS values between the local and peer ends. If the PFS values are inconsistent, the following are true: when the IPsec policy uses the IKEv1 protocol, the IPsec SA negotiation will fail; when the IPsec policy uses the IKEv2 protocol, only one IPsec SA can be successfully negotiated and renegotiation of this IPsec SA will also fail. For details, see RFC2408, RFC5996, and RFC2409. The security levels specified by the values PFS_GROUP1, PFS_GROUP2, PFS_GROUP19, and PFS_GROUP20 are in ascending order. However, the processing durations are also in ascending order.

The values PFS_GROUP19(256-bit ECC Diffie-Hellman Group) and PFS_GROUP20(384-bit ECC Diffie-Hellman Group) are supported by the UMPTa, UMPTb, UMPTe, UMPTg, UMPTga, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7, UBBPg9 and UMDU boards.

Disuse statement: In later versions, the values PFS_GROUP1(768-bit Diffie-Hellman Group) and PFS_GROUP2(1024-bit Diffie-Hellman Group) will be removed from the value range of this parameter. In the current version, these values can still be configured and take effect. Therefore, you are not advised to use the values PFS_GROUP1(768-bit Diffie-Hellman Group) and PFS_GROUP2(1024-bit Diffie-Hellman Group).

GUI Value Range: DISABLE(Disable), PFS_GROUP1(768-bit Diffie-Hellman Group), PFS_GROUP2(1024-bit Diffie-Hellman Group), PFS_GROUP14(2048-bit Diffie-Hellman Group), PFS_GROUP15(3072-bit Diffie-Hellman Group), PFS_GROUP19(256-bit ECC Diffie-Hellman Group), PFS_GROUP20(384-bit ECC Diffie-Hellman Group)

Unit: None

Actual Value Range: DISABLE, PFS_GROUP1, PFS_GROUP2, PFS_GROUP14, PFS_GROUP15, PFS_GROUP19, PFS_GROUP20

MML Default Value: PFS_GROUP19(256-bit ECC Diffie-Hellman Group)

Recommended Value: PFS_GROUP19(256-bit ECC Diffie-Hellman Group)

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: When this parameter is set to PFS_GROUP19 or PFS_GROUP20, the CPU usage temporarily increases during IPSec negotiation.

Applicable Mode: G, U, L, N

LTS Lifetime Based On Time

Meaning: Indicates the life cycle of an IPSec SA. An IPSec SA becomes invalid once its life cycle specified by this parameter elapses. Before the life cycle of an IPSec SA elapses, the IPSec policy is used in an attempt to establish a new IPSec SA through negotiation to ensure secure transmission; before the negotiation is complete, the original IPSec SA is still used. After the negotiation is complete, the new SA is immediately used. IPSec SA negotiation takes a period. To prevent SA updating from affecting communication security, a life cycle longer than 900 seconds is recommended.

REPLAYWND Anti-Replay Window Size

Meaning: Indicates the size of the IPSec packet anti-replay window. If the value of this parameter is set to 0, the IPSec packet anti-replay function is disabled. If the value of this parameter is set to 32, 64, 128, 256, 512, 1024, 2048 or 4096, the system checks whether the packets are duplicate in the window. A packet is discarded if it has a duplicate packet or its sequence number is smaller than any packet in the window. The window slides if the sequence number of the packet is larger than any packet that is received in the window.

GUI Value Range: WND_DISABLE(0), WND_32(32), WND_64(64), WND_128(128), WND_256(256), WND_512(512), WND_1024(1024), WND_2048(2048), WND_4096(4096)

Unit: None

Actual Value Range: WND_DISABLE, WND_32, WND_64, WND_128, WND_256, WND_512, WND_1024, WND_2048, WND_4096

MML Default Value: WND_512(512)

Recommended Value: If the network disorder is serious, it is recommended that the anti-replay function be disabled by setting this parameter to WND_DISABLE(0).

If the anti-replay function is enabled, it is recommended that this parameter be set to WND_512(512).

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: 1) After the IPsec anti-replay function is enabled, the transmission processing capability decreases and service performance deteriorates. 2) In certain scenarios, for example, when network congestion occurs or packets experiences QoS processing, the sequence of service data packets may be different from the normal sequence. Although these packets are not intended for replay attacks, the anti-replay detection considers them as replay packets and discards them. In this case, you are advised to disable the IPSec anti-replay function to prevent packets from being discarded incorrectly. If the anti-replay function is enabled, it is recommended that this parameter be set to WND_512(512).

Applicable Mode: G, U, L, N

Meaning: Indicates whether forcible changes to IPSECPOLICY objects are made. When this parameter is set to YES, forcible changes to IPSECPOLICY objects are made. When this parameter is set to NO, forcible changes to the IPSECPOLICY objects that affect associated objects are not allowed.

3. If the NE is configured with an SRCIPROUTE6 object, the system does not check whether the modification of the local IPv6 address affects the associated objects of the IPSECPOLICY object.

Example

Example 1: To add an IPSec policy with the parameters as follows: Policy Group Name: policy4, IPSec Sequence No.: 1, ACL TYPE: IPV4, ACL ID: 3400, IPSec Proposal Name: prop4, IKE Peer Name: ikep4, SA Duration Mode: LOCAL, run the following command:
ADD IPSECPOLICY: SPGN="policy4", SPSN=1, ACLTYPE=IPV4, ACLID=3400, PROPNAME="prop4", PEERNAME="ikep4", LTCFG=LOCAL;

Example 2: To add an IPSec policy with the parameters as follows: Policy Group Name: policy6, IPSec Sequence No.: 1, ACL TYPE: IPV6, ACL ID: 3600, IPSec Proposal Name: prop6, IKE Peer Name: ikep6, SA Duration Mode: LOCAL, run the following command:
ADD IPSECPOLICY: SPGN="policy6", SPSN=1, ACLTYPE=IPV6, ACLID=3600, PROPNAME="prop6", PEERNAME="ikep6", LTCFG=LOCAL;

Example 3: To add an IPSec policy with the parameters as follows: Policy Group Name: policy46mix, IPSec Sequence No.: 1, ACL TYPE: IPV4+IPV6, ACL ID: 3000, ACL2 ID:3001, IPSec Proposal Name: prop, IKE Peer Name: ike, SA Duration Mode: LOCAL, run the following command:
ADD IPSECPOLICY: SPGN="policy46mix", SPSN=1, ACLTYPE=IPV4+IPV6, ACLID=3000, ACL2ID=3001, PROPNAME="prop", PEERNAME="ike", LTCFG=LOCAL;
