List Security Parameters Template Configuration (LST SECURITYTEMPLATE)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to list the configuration of the security parameter templates.

Note

None.

Parameters

ID Name Description
SECURITYTEMPLATEID Security Parameters Template ID

Meaning: Indicates the ID of the security parameter template.

GUI Value Range: 0~65535

Unit: None

Actual Value Range: 0~65535

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N

Example

To list the configuration of a security parameter template, run the following command:
LST SECURITYTEMPLATE:;
The result is as follows:

Output Description

Field Description

Security Parameters Template ID

Indicates the ID of the security parameter template.

SeGW Switch

Indicates whether to enable the peer end to perform IPSec negotiation with the local end through an SeGW. When this parameter is set to DISABLE, the peer end performs IPSec negotiation with the local end directly. When this parameter is set to ENABLE, the peer end establishes an IPSec tunnel to the local end through the SeGW.

IKE Proposal ID

Indicates the ID of the IKE proposal.

IPSec Proposal Name

Indicates the name of the IPSec proposal.

IKE Version

Indicates the IKE protocol version.

Exchange Mode

Indicates the IKE V1 exchange mode. There are two exchange modes: main mode and aggressive mode. In main mode, keys are exchanged separately from identity information, which protects identity information and hence enhances security. In aggressive mode, identity information is not protected, but requirements of specific network environments can be met.

Pre-shared Key

Indicates the preshared key. Both ends must use the same preshared key in negotiation.

DPD Mode

Indicates whether to enable the dead peer detection (DPD) function. When this parameter is set to DISABLE, the local end does not perform DPD. When this parameter is set to PERIODIC, the local end periodically sends DPD packets to perform DPD if the total time during which the local end does not receive encrypted packets reaches the value specified by the DPD Idle Time parameter.

DPD Idle Time(s)

Indicates the dead peer detection (DPD) idle time. If the total time during which the local end does not receive encrypted packets reaches the value specified by the DPD Idle Time parameter, the local end sends the DPD packet to perform DPD. However, the exact time at which the eNodeB sends DPD messages varies depending on network environment.

DPD Retransmission Interval(s)

Indicates the interval at which the eNodeB sends DPD frames. However, the exact interval at which the eNodeB sends DPD frames varies depending on the network environment.

DPD Retransmission Count

Indicates the maximum allowed number of DPD frame retransmissions after a dead peer detection (DPD) failure.

Perfect Forward Security

Indicates the perfect forward secrecy (PFS) value.

In the second phase of an IPSec negotiation, PFS enables the system to use a key that is not derived from the first-phase key. Therefore, the two keys are independent of each other. According to PFS, each key protects a unique set of data. The elements used to generate a key cannot be reused, preventing the disclosure of a key from affecting security of other keys.

If the parameter is set to PFS_GROUP1 or PFS_GROUP2 at the local end, the peer end must launch a PFS exchange when initiating an IPSec negotiation. requiring consistent PFS values between the local and peer ends. If the PFS values are inconsistent, the following are true: when the IPsec policy uses the IKEv1 protocol, the IPsec SA negotiation will fail; when the IPsec policy uses the IKEv2 protocol, only one IPsec SA can be successfully negotiated and renegotiation of this IPsec SA will also fail. The security levels specified by the values PFS_GROUP1, PFS_GROUP2, PFS_GROUP19, and PFS_GROUP20 are in ascending order. However, the processing durations are also in ascending order.

The values PFS_GROUP19(256-bit ECC Diffie-Hellman Group) and PFS_GROUP20(384-bit ECC Diffie-Hellman Group) are supported by the UMPTa, UMPTb, UMPTe, UMPTg, UMPTga, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7, UBBPg9 and UMDU boards.

SA Duration Mode

Indicates the configuration mode of the IPSec SA life cycle. If this parameter is set to GLOBAL, the default SA life cycle is used. In this case, LTS and LTKB are set to the default values 3600 and 69120000, respectively. If this parameter is set to LOCAL, the SA life cycle is configurable.

Lifetime Based On Time(s)

Indicates the life cycle of an IPSec SA. An IPSec SA becomes invalid when its life cycle elapses. Before an IPSec SA becomes invalid, IKE establishes a new IPSec SA based on negotiation. Before a new IPSec SA is established, the old IPSec SA is still used to ensure communication security. Once the negotiation is complete, the new IPSec SA is immediately used. IPSec SA negotiation takes a period of time. To prevent SA update from affecting communication security, a life cycle longer than 900 seconds is recommended.

Lifetime Based On Traffic(kB)

Indicates the traffic volume threshold for the IPSec policy. The value 0 indicates that the function, which initiates negotiation for a new IPSec SA based on the traffic volume, is disabled. However, when BS acts as initiator in IKEv1 and this value is set to 0, if the responder insists or enforces the IPSec SA traffic lifetime to BS, BS will enable this function to avoid service breakdown.

Anti-Replay Window Size

Indicates the size of the IPSec packet anti-replay window. If the value of this parameter is set to 0, the IPSec packet anti-replay function is disabled. If the value of this parameter is set to 32, 64, 128, 256, 512, 1024, 2048 or 4096, the system checks whether the packets are duplicate in the window. A packet is discarded if it has a duplicate packet or its sequence number is smaller than any packet in the window. The window slides if the sequence number of the packet is larger than any packet that is received in the window.

Narrow Down Switch

Indicates whether to reduce the ACL rule scope. When this parameter is set to ON, if the ACL rule scope of the NE differs from that of the peer end, the NE attempts to reduce the range of data flows protected by the ACL rules. In this way, the NE and the peer end can successfully negotiate an IPSec SA. This parameter is invalid when the version of the IKE peer specified by IKE Peer Name in the IPSec policy is IKE V1.

IPv6 Route Preference

Indicates the priority of a static IPv6 route. A smaller value indicates a higher priority. This parameter applies only to IPv6.
