Reset Board Through Power-off (RST BRDPWROFF)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to power off a board. The board is automatically powered on and is reset. This helps to rectify some hardware faults of the board. Currently, only the boards (excluding the FAN unit, UPEU, and UEIU) in the BBU and the boards on the RRU chain/ring support such reset.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Resetting a board by powering it off causes loss of all services carried on the board.

  • If a board is reset by power-off, the board is reinitialized, and it is unavailable before initialization is completed.

  • A power-off reset of an RRU or RFU on an RRU chain interrupts services carried on the lower-level boards.

  • To prevent service interruption of the lower-level RRUs or RFUs, run the RST BRD command to reset the RRU or RFU.

  • This command can be executed on a board in the BBU regardless of whether the board is configured. If this command is executed on an RRU, the RRU must be configured first.

  • In a dual-mode BS, common components of the two sides can be reset by running this command on either side. The services carried on those components are interrupted temporarily and then resumed after the reset.

  • For an MBTS, services of the mode at the peer end will be interrupted after a multi-mode RF unit is reset.

  • For a multimode base station using CPRI MUX/eCPRI MUX, if the local mode aggregates data, resetting the main control board of the local mode or the baseband processing board that aggregates data by powering it off will interrupt the services of the peer mode.

  • You are not advised to reset the board when the board is being downloading, supplementing, or activating software. If the board needs to be reset at this time, set the FOCRST parameter to YES.

  • You are not advised to reset the main active board when the NE is being downloading, supplementing, or activating software. If the main active board needs to be reset at this time, set the FOCRST parameter to YES.

  • When the IR protocol is used, you can perform a power-off rest on a non-first-level RRU only when the status of the upper-level RRU is normal. Otherwise, this non-first-level RRU cannot be powered off and reset.

  • It is recommended that this command be not executed when ALM-26101 Inter-Board CANBUS Communication Failure is reported, as the user fails to power on/off the board or obtain the board electronic label.

  • Resetting a board through a power cycle causes losses of the board logs. If Forced Reset Flag is set to NO, the board will make preparations before reset. In this case, the board reset takes a longer time than that if Forced Reset Flag is set to YES.

  • Forced Reset Flag of the USCU can be set only to YES.

  • A power-off reset of a CXU interrupts services carried on all boards behind the CXU.

  • [Co-MPT,NodeB,eNodeB,gNodeB]The MPRF cannot reset independently. When you run this command to reset an MPRF, the MPMU and other MPRFs in the same subrack as this MPRF will be reset at the same time.

  • [Co-MPT,NodeB,eNodeB,gNodeB]A power-off reset of an RHUB interrupts services carried on all boards behind the RHUB.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]In a multi-mode base station, the boards of the peer mode in the BBU can be reset. For example, a GTMU can be reset on the LTE LMT.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]For a multi-mode base station that applies common transmission and the LTE provides the co-transmission port, running this command on the board where the co-transmission port is located interrupts services on the peer mode.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]In a multi-mode base station, the reset of RF modules working in multi-mode interrupts the services of the peer mode. The reset of MPT and UTRP may interrupt the services of the peer mode.

  • [Co-MPT,NodeB,eGBTS]If an MBTS works in co-communication mode and the shared outgoing transmission port is set on the UMTS side, services of the mode at the peer end will be interrupted after the board housing the port is reset.

FOCRST Forced Reset Flag

Meaning: Indicates whether to forcibly reset an NE. When this parameter is set to NO, an NE cannot be forcibly reset if the NE is downloading, supplementing, or activating software, and if the command is RST BRDPWROFF, the system performs a security exit and then a power-off reset on the board. When this parameter is set to YES, an NE is forcibly reset no matter what kind of operations this NE is performing.

GUI Value Range: NO(NO), YES(YES)

Unit: None

Actual Value Range: NO, YES

MML Default Value: NO(NO)

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, R, N

Example

To reset a board with the parameters as follows: Cabinet No.: 0, Subrack No.: 0, Slot No.:2, run the following command:
RST BRDPWROFF: CN=0, SRN=0, SN=2;
