Confirm CB (CFM CB)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to confirm the active version, including the software version and data configuration file. After the active version is confirmed, a new configuration baseline (CB) is generated. A CB can be manually activated or automatically rolled back:

(1) If configuration data about OMCH connecting to the NE (such as the IP address and route) is incorrectly modified at the remote end, the OMCH may be interrupted and cannot be restored for a long period of time. To eliminate the need to handle this type of fault onsite, users can run this command with the Automatic Roll Back Switch parameter set to ENABLE(ENABLE) to enable automatic rollback before modifying configuration data. It is recommended that the automatic rollback function be disabled during local modification. Otherwise, an interruption in the OM channel may cause an unexpected rollback.

(2) You are advised to set Automatic Roll Back Switch to DISABLE(DISABLE) if you only need to back up software version and configuration data of the system for future manual activation or rollback.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • The storage space of a base station is limited. Therefore, if configuration date needs to be backed up, it is recommended that you use the automatic configuration backup function on the MAE or run the BKP CFGFILE and ULD CFGFILE command to back up the configuration data to the MAE or a third-party server. It is recommended that you back up as few CBs as possible.

  • Generally, this command is executed when the configuration data of the current system needs to be backed up and the current CB is not confirmed. It is recommended that this command be not executed frequently.

  • When a CB is being confirmed, it is not recommended that configuration operations be performed.

  • If a CB has been confirmed for the active version (can be queried by DSP CB command), the CB confirmation fails in unforced mode and can succeed only when MODE is set to FORCED(FORCED).

  • If the output of the DSP CB command shows that a CB whose Automatic Roll Back Switch parameter is set to ENABLE(ENABLE) exists in the current system, you cannot create a CB whose Automatic Roll Back Switch parameter is set to ENABLE(ENABLE).

  • When the automatic configuration data rollback is being enabled by running this command, the timer specified by RBKTIME starts. The data modification must have been completed before the timer expires. For the existing configuration baseline (CB), you can also run the MML command MOD CB to enable the automatic configuration data rollback function. You can run the MML command DSP CB to query the remaining rollback time.

  • Before the period of time specified by RBKTIME expires, if the OMCH is normal after its configuration data is modified or recovers to its normal state after an interruption, and users do not require rollback in spite of an OMCH interruption, run the MML command MOD CB to disable the automatic configuration data rollback function. This prevents the rollback of the configuration data in the case of an OMCH interruption.

  • If automatic rollback is enabled, the system is reset and restores the CB confirmed by this command at the end of rollback duration specified by RBKTIME when the link is continuously interrupted and rollback conditions specified by the parameter RBKCONDITION are met. After the rollback is performed, the system reports ALM-26255 Automatic Version Rollback alarm, and automatically disables automatic rollback.

  • When the period of time specified by RBKTIME expires, if the rollback conditions are not met, the system waits five minutes before making a decision again. The remaining rollback time is five minutes and the timing restarts. After the five minutes expire, if rollback conditions specified by the parameter RBKCONDITION are met, the base station resets, data configuration is rolled back to the corresponding CB used to enable this function. If the rollback succeeds, the base station disables this function. If rollback conditions are not met (for example, the OMCH is normal or has recovered to its normal state), the base station disables this function.

  • Before the period of time specified by RBKTIME expires, if the base station resets and related conditions are met, the automatic configuration data rollback function still takes effect after the reset.

  • When the configuration data of base stations is being modified, the configuration data of peripheral NEs may also be modified. After the configuration data of base stations is rolled back successfully, the data of peripheral NEs may also need to be rolled back to ensure a normal OMCH.

  • If Name of CB is set to OSS_AUTO_CFM_CB and Mode of CB is set to FORCED(FORCED), the CB with the same name on the NE will be replaced.

  • Command execution will fail if the MAE is periodically saving configuration data. Please run this command later.

  • OSS_TASK_AUTO_CB is the dedicated name for automatic backup of the NMS. This name cannot be used for manual backup.

  • If the CB file backed up before an upgrade is named OSS_TASK_AUTO_CB (the same as the CB file used for automatic backup in the target version), the target version regards this file as the automatic backup CB file after the upgrade. The file is overwritten during a periodic backup.

  • Check that all applications(Integrated Deployment Mode) are available before you confirm a CB. If any application is unavailable, a CB will fail to be confirmed.

  • A maximum of 10 CBs can be confirmed in a base station(The CB named OSS_TASK_AUTO_CB is not included). The actual number of CBs that can be confirmed in a base station varies depending on the remaining storage space and configurations of the base station. If a failure prompt is displayed when you run the CFM CB command, manually delete CBs on the base station.

  • If the RBKCONDITION parameter is set to OMCH_AND_SERVICE_FAULT(OMCH_AND_SERVICE_FAULT), the automatic configuration data rollback function will be triggered only when the OMCH and all service channels are faulty.

  • [Co-MPT,NodeB,eNodeB,gNodeB]When a WMPT, LMPT, or GTMUb/GTMUc (used as the main control board of independent NE) is used, the CB file cannot be automatically backed up on the EMS due to limited storage space.

Example

Example 1: To confirm a CB with the parameters as follows: Mode of CB: UNFORCED, Name of CB: "CB1", Comment of CB: "Launch", Automatic Roll Back Switch: "ENABLE", Roll Back Time:"30minutes", Roll Back Condition:"OMCH FAULT", run the following command:
CFM CB: MODE=UNFORCED, NAME="CB1", COMMENT="Launch", AUTORBKSW=ENABLE, RBKTIME=30, RBKCONDITION=OMCH_FAULT;

Example 2: To confirm a CB with the parameters as follows: Mode of CB: FORCED, Name of CB: "CB1", Comment of CB: "Launch", Automatic Roll Back Switch: "DISABLE", run the following command:
CFM CB: MODE=FORCED, NAME="CB1", COMMENT="Launch", AUTORBKSW=DISABLE;
