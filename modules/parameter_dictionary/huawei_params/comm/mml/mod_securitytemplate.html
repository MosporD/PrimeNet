Modify Security Parameters Template (MOD SECURITYTEMPLATE)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to modify a security parameter template.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Modifying any parameters of the security template interrupts service that references this security template.

  • If one or more of the parameters in a SECURITYTEMPLATE object are modified, the following security link objects that reference the SECURITYTEMPLATE object will be removed and then added: ACL, ACL6, ACLRULE, ACLRULE6, IKEPEER, IPSECBIND or IPSECBINDITF, IPSECPOLICY, TUNNELITF, INTERFACE and IPROUTE6.

  • When the TRANMODE in the associated IPSECPROPOSAL MO is ESP and ESPAUTHALG is NULL, the anti-replay function does not take effect.

PFS Perfect Forward Security

Meaning: Indicates the perfect forward secrecy (PFS) value.

In the second phase of an IPSec negotiation, PFS enables the system to use a key that is not derived from the first-phase key. Therefore, the two keys are independent of each other. According to PFS, each key protects a unique set of data. The elements used to generate a key cannot be reused, preventing the disclosure of a key from affecting security of other keys.

If the parameter is set to PFS_GROUP1 or PFS_GROUP2 at the local end, the peer end must launch a PFS exchange when initiating an IPSec negotiation. requiring consistent PFS values between the local and peer ends. If the PFS values are inconsistent, the following are true: when the IPsec policy uses the IKEv1 protocol, the IPsec SA negotiation will fail; when the IPsec policy uses the IKEv2 protocol, only one IPsec SA can be successfully negotiated and renegotiation of this IPsec SA will also fail. The security levels specified by the values PFS_GROUP1, PFS_GROUP2, PFS_GROUP19, and PFS_GROUP20 are in ascending order. However, the processing durations are also in ascending order.

The values PFS_GROUP19(256-bit ECC Diffie-Hellman Group) and PFS_GROUP20(384-bit ECC Diffie-Hellman Group) are supported by the UMPTa, UMPTb, UMPTe, UMPTg, UMPTga, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7, UBBPg9 and UMDU boards.

Disuse statement: In later versions, the values PFS_GROUP1(768-bit Diffie-Hellman Group) and PFS_GROUP2(1024-bit Diffie-Hellman Group) will be removed from the value range of this parameter. In the current version, these values can still be configured and take effect. Therefore, you are not advised to use the values PFS_GROUP1(768-bit Diffie-Hellman Group) and PFS_GROUP2(1024-bit Diffie-Hellman Group).

GUI Value Range: DISABLE(Disable), PFS_GROUP1(768-bit Diffie-Hellman Group), PFS_GROUP2(1024-bit Diffie-Hellman Group), PFS_GROUP14(2048-bit Diffie-Hellman Group), PFS_GROUP15(3072-bit Diffie-Hellman Group), PFS_GROUP19(256-bit ECC Diffie-Hellman Group), PFS_GROUP20(384-bit ECC Diffie-Hellman Group)

Unit: None

Actual Value Range: DISABLE, PFS_GROUP1, PFS_GROUP2, PFS_GROUP14, PFS_GROUP15, PFS_GROUP19, PFS_GROUP20

MML Default Value: None

Recommended Value: PFS_GROUP19(256-bit ECC Diffie-Hellman Group)

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: When this parameter is set to PFS_GROUP19 or PFS_GROUP20, the CPU usage temporarily increases during IPSec negotiation.

Applicable Mode: G, U, L, N

LTS Lifetime Based On Time

Meaning: Indicates the life cycle of an IPSec SA. An IPSec SA becomes invalid when its life cycle elapses. Before an IPSec SA becomes invalid, IKE establishes a new IPSec SA based on negotiation. Before a new IPSec SA is established, the old IPSec SA is still used to ensure communication security. Once the negotiation is complete, the new IPSec SA is immediately used. IPSec SA negotiation takes a period of time. To prevent SA update from affecting communication security, a life cycle longer than 900 seconds is recommended.

REPLAYWND Anti-Replay Window Size

Meaning: Indicates the size of the IPSec packet anti-replay window. If the value of this parameter is set to 0, the IPSec packet anti-replay function is disabled. If the value of this parameter is set to 32, 64, 128, 256, 512, 1024, 2048 or 4096, the system checks whether the packets are duplicate in the window. A packet is discarded if it has a duplicate packet or its sequence number is smaller than any packet in the window. The window slides if the sequence number of the packet is larger than any packet that is received in the window.

GUI Value Range: WND_DISABLE(0), WND_32(32), WND_64(64), WND_128(128), WND_256(256), WND_512(512), WND_1024(1024), WND_2048(2048), WND_4096(4096)

Unit: None

Actual Value Range: WND_DISABLE, WND_32, WND_64, WND_128, WND_256, WND_512, WND_1024, WND_2048, WND_4096

MML Default Value: None

Recommended Value: If the network disorder is serious, it is recommended that the anti-replay function be disabled by setting this parameter to WND_DISABLE(0).

If the anti-replay function is enabled, it is recommended that this parameter be set to WND_512(512).

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: 1) After the IPsec anti-replay function is enabled, the transmission processing capability decreases and service performance deteriorates. 2) In certain scenarios, for example, when network congestion occurs or packets experiences QoS processing, the sequence of service data packets may be different from the normal sequence. Although these packets are not intended for replay attacks, the anti-replay detection considers them as replay packets and discards them. In this case, you are advised to disable the IPSec anti-replay function to prevent packets from being discarded incorrectly. If the anti-replay function is enabled, it is recommended that this parameter be set to WND_512(512).

Applicable Mode: G, U, L, N

Example

To modify a security parameter template with the parameters as follows: Security Parameters Template ID: 0, SeGW Switch: ENABLE, Perfect Forward Security: 768-bit Diffie-Hellman Group, SA Duration Mode: Local Configuration, Lifetime Based On Time: 4000, Lifetime Based On Traffic: 700000000, run the following command:
MOD SECURITYTEMPLATE: SECURITYTEMPLATEID=0, SEGWSWITCH=ENABLE, PFS=PFS_GROUP1, LTCFG=LOCAL, LTS=4000, LTKB=700000000;
