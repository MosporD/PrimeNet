Add Mapping from Traffic Type to VLAN (ADD VLANCLASS)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a mapping from traffic types to VLANs.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • This command must be used together with the ADD VLANMAP command.

  • ARP requests belong to the "OTHER" type of data. Correct VLAN settings must be added for ARP messages before Ethernet ports can communicate with each other properly.

  • The TRACERT packet and the TWAMP measurement packet belong to user data.

  • If ICMP packets are local traffic stream, ICMP packets are preferentially mapped to a VLAN priority in a VLANCLASS with TRAFFIC set to USERDATA. If there is no VLANCLASS with TRAFFIC set to USERDATA, ICMP packets are mapped to a VLAN priority in a VLANCLASS with TRAFFIC set to OTHER. If ICMP packets are passing-by data flow, ICMP packets of the WMPT and UTRP boards are mapped to a VLAN priority in a VLANCLASS with TRAFFIC set to OTHER, whereas ICMP packets of the UMPT, UMDU, LMPT, UTRPc, UCCU, UBBPe (excluding UBBPe15), UBBPei, UBBPep, UBBPem, LCOP, UBBPex2, UBBPf0, UBBPf1, UBBPg1, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7, UBBPg9, GTMUb and GTMUc boards are preferentially mapped to a VLAN priority in a VLANCLASS with TRAFFIC set to USERDATA. If the VLAN priority mapping with TRAFFIC set to USERDATA is not configured, the BS attaches a VLAN tag to packets based on the default VLANCLASS rules.

  • For local signaling packets, if the VLAN priority mapping with TRAFFIC set to SIG is not configured, the BS attaches a VLAN tag to these signaling packets based on the VLAN priority of the USERDATA whose SRVPRIO is the same as the DSCP of the signaling data. The BS attaches a VLAN tag to passing-by signaling packets on the WMPT and UTRP with TRAFFIC set to SIG. If the VLANCLASS with TRAFFIC set to SIG is not configured, no VLAN tag will be attached to these packets. The BS attaches a VLAN tag to passing-by signaling packets on the LMPT, UMPT, UMDU, UTRPc, UCCU, UBBPe (excluding UBBPe15), UBBPei, UBBPep, UBBPem, LCOP, UBBPex2, UBBPf1, UBBPf0, UBBPg1, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7, UBBPg9, GTMUb and GTMUc with TRAFFIC set to USERDATA. If the VLANCLASS is not configured for the USERDATA whose SRVPRIO is the same as the DSCP of these passing-by signaling packets, the BS attaches a VLAN tag to packets based on the default VLANCLASS rules.

  • The WMPT and UTRP do not support IPSec encryption. In the cascading scenario, the BS attaches a VLAN tag to encrypted passing-by packets on the WMPT and UTRP with TRAFFIC set to OTHER, and the BS attaches a VLAN tag to encrypted passing-by packets on the LMPT, UMPT, UMDU, UTRPc, UCCU, UBBPe (excluding UBBPe15), UBBPei, UBBPep, UBBPem, LCOP, UBBPex2, UBBPf1, UBBPf0, UBBPg1, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7, UBBPg9, GTMUb and GTMUc with TRAFFIC set to USERDATA. If the VLAN priority mapping with TRAFFIC set to USERDATA is not configured, the BS attaches a VLAN tag to packets based on the default VLANCLASS rules.

  • In the cascading scenario, if VLANs are configured, passing-by low-priority OM packets on the WMPT and UTRP must have the same DSCP as the local low-priority OM data and be mapped to a VLAN priority in a VLANCLASS with TRAFFIC set to OM_LOW. Passing-by low-priority OM packets on the LMPT, UMPT, UMDU, UTRPc, UCCU, UBBPe (excluding UBBPe15), UBBPei, UBBPep, UBBPem, LCOP, UBBPex2, UBBPf1, UBBPf0, UBBPg1, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7, UBBPg9, GTMUb and GTMUc are mapped to a VLAN priority in a VLANCLASS with TRAFFIC set to USRDATA and SRVPRIO set to the same DSCP as the passing-by low-priority OM packets. If the VLAN priority mapping with TRAFFIC set to USERDATA is not configured, the BS attaches a VLAN tag to packets based on the default VLANCLASS rules.

  • If VLANs are planned for SCTP signaling packets, the VLAN must be configured with TRAFFIC set to SIG.

  • If VLANs are planned for user data packets, the VLAN whose user data priority is the same as the DSCP of the user data packets must be configured. It is recommended that the user data priorities in the VLANCLASS be fully configured for the LMPT, UMPT, UMDU, UTRPc, UCCU, UBBPe (excluding UBBPe15), UBBPei, UBBPep, UBBPem, LCOP, UBBPex2, UBBPf1, UBBPf0, UBBPg1, UBBPg2, UBBPg3, UBBPg4, UBBPg5, UBBPg6, UBBPg7, UBBPg9, GTMUb and GTMUc from 0 to 63 (totally 64 priorities).

  • OM_LOW TRAFFIC in the VLANCLASS includes TCP packets except high-priority data, such as FTP packets.

  • SIG TRAFFIC in the VLANCLASS includes all SCTP packets.

  • System specifications: If the WMPT/UMPT/UMDU/LMPT/GTMUb/GTMUc is the main control board, a maximum of 272 VLANCLASSes can be configured.

  • Board specifications: A maximum of 272 VLANCLASSes can be configured on a WMPT/UMPT/UMDU/LMPT/GTMUb/GTMUc/UTRPc/UTRP (subboard type: UEOC/UQEC)/UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9.

  • If VLANs are planned for high-priority OM packets, the BS must attach a VLAN tag to these packets with TRAFFIC set to OM_HIGH. For an LMPT /UMPT/UMDU/UTRPc/UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9/GTMUb/GTMUc, if the VLAN priority mapping with TRAFFIC set to OM_HIGH is not configured, the BS attaches a VLAN tag to high-priority OM packets based on the VLAN priority mapping with TRAFFIC set to USERDATA whose DSCP is the same as that of the high-priority OM packets. For a WMPT/UTRP, if the VLAN priority mapping with TRAFFIC set to OM_HIGH is not configured, the BS attaches no VLAN tag to TCP packets in the high-priority OM packets but attaches a VLAN tag to UDP packets in the high-priority OM packets based on the VLAN priority mapping with TRAFFIC set to USERDATA whose DSCP is the same as that of the high-priority OM packets.

  • If VLANs are planned for OM low-priority data, the BS must attach a VLAN tag to these packets with TRAFFIC set to OM_LOW. For an LMPT /UMPT/UMDU/UTRPc/UCCU/UBBPe (excluding UBBPe15)/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9/GTMUb/GTMUc, if the VLAN priority mapping with TRAFFIC set to OM_LOW is not configured, the BS attaches a VLAN tag to low-priority OM packets based on the VLAN priority mapping with TRAFFIC set to USERDATA whose DSCP is the same as that of the low-priority OM packets. For a WMPT/UTRP, if the VLAN priority mapping with TRAFFIC set to OM_LOW is not configured, the BS attaches no VLAN tag to these low-priority OM packets.

  • If VLAN tags are not attached to packets transmitted by an LMPT/UMPT/UMDU/UTRPc/UCCU/UBBPe/UBBPei/UBBPep/UBBPem/LCOP/UBBPex2/UBBPf1/UBBPf0/UBBPg1/UBBPg2/UBBPg3/UBBPg4/UBBPg5/UBBPg6/UBBPg7/UBBPg9 according to the agreed rules, the following rules are supplemented:

    1. If the DSCP of packets is the same as the local signaling data priority, the BS attaches a VLAN tag to these packets based on the VLAN priority mapping with TRAFFIC set to SIG.

    2. If the BS fails to attach a VLAN tag to packets on the preceding rule and the DSCP of these packets is the same as the DSCP set for the local VLAN priority mapping with TRAFFIC set to OM_HIGH or OM_LOW, the BS attaches a VLAN tag to these packets based on the VLAN priority mapping with TRAFFIC set to OM_HIGH or OM_LOW.

    3. If the BS fails to attach a VLAN tag based on any one of the preceding rules, the BS attaches a VLAN tag to these packets based on the VLAN priority mapping with TRAFFIC set to OTHER.

    4. If the BS fails to attach a VLAN tag based on any one of the preceding rules, the BS attaches no VLAN tag to packets.

  • This operation may interrupt the services or OM channels. It is recommended that you determine whether to enable the automatic configuration data rollback function depending on scenarios. For details, see the help of the CFM CB command.

  • [Co-MPT,NodeB,eNodeB,gNodeB]High-priority OM data consists of OM data and OM-related packets. OM UDP packets include DHCP relay packets, packets over the NTP (default port), and OM channel switchover packets at the remote end. OM TCP packets include packets related to MML commands, alarms, events, tracing tasks, tests, monitoring tasks, certificate downloading, and TWAMP.

  • [Co-MPT,NodeB,eNodeB,gNodeB]USERDATA TRAFFIC in the VLANCLASS includes user data packets, user channel maintenance and test packets (such as ICMP packets whose DSCP is the same as any user data priority and packets related to TRACERT request, TWAMP measurement, IP PM, UDP-ECHO, and GTP-U ECHO), and encrypted packets.

  • [NodeB,eNodeB,gNodeB]The execution result of this command takes effect at all Ethernet ports of a BS.

  • [Co-MPT,eNodeB,gNodeB]OTHER TRAFFIC in the VLANCLASS includes layer 3 and higher transmission protocol packets except OM packets, signaling packets, and user data packets. OTHER TRAFFIC consists of packets related to ARP, BFD, IKE, DNS, PTP control, IP clock control and ICMP packets whose DSCP differs from any user data priority.

  • [eNodeB,gNodeB]A GTP-U frame is a type of user data packet. If the VLAN is planned, you need to configure the VLAN priority mapping with Traffic Type set to USERDATA(User Data) and User Data Service Priority set to the same value as the GTP-U DSCP. If the VLAN priority mapping with TRAFFIC set to USERDATA is not configured, the BS attaches a VLAN tag to packets based on the default VLANCLASS rules. If an IP path with Path Type set to FIXED(Fixed QoS) is configured, you also need to configure the VLAN priority mapping with Traffic Type set to USERDATA(User Data) and User Data Service Priority set to the DSCP of this IP path.

  • [NodeB]OTHER TRAFFIC in the VLANCLASS includes layer 3 and higher transmission protocol packets except OM packets, signaling packets, and user data packets. OTHER TRAFFIC consists of packets related to ARP, BFD, IKE, PTP control, IP clock control and ICMP packets whose DSCP differs from any user data priority.

Parameters

ID Name Description
VLANGROUPNO VLAN Group No.

Meaning: Indicates the VLAN group that the added VLAN mapping belongs to. Multiple VLAN groups are used in the scenario in which telecom operators share transport resources and use different VLAN policies.

GUI Value Range: 0~3

Unit: None

Actual Value Range: 0~3

MML Default Value: 0

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N, R
TRAFFIC Traffic Type

Meaning: Indicates the traffic type. Traffic of different types is transmitted through different VLANs. OTHER data is the data except the user data, signaling, high-priority OM data, and low-priority OM data. OTHER data includes the data of the IEEE 1588 V2 clock, clock over IP, and Address Resolution Protocol (ARP) services. OM_HIGH data includes the data of the NTP, switchover between remote maintenance channels, and TCP services.

GUI Value Range: USERDATA(User Data), SIG(Signaling Data), OM_HIGH(High Level Maintenance Data), OM_LOW(Low Level Maintenance Data), OTHER(Other Data)

Unit: None

Actual Value Range: USERDATA, SIG, OM_HIGH, OM_LOW, OTHER

MML Default Value: None

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N, R
SRVPRIO User Data Service Priority

Meaning: Indicates the DSCP priority of user data.

GUI Value Range: 0~63

Unit: None

Actual Value Range: 0~63

MML Default Value: None

Recommended Value: It is recommended that the value of this parameter be consistent with the implementation of the differentiated service.

Parameter Relationship: None

Service Interrupted After Modification: N/A

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N, R
VLANID VLAN ID

Meaning: Indicates the VLAN ID that the service data belongs to.

GUI Value Range: 1~4094

Unit: None

Actual Value Range: 1~4094

MML Default Value: 1

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: None

Applicable Mode: G, U, L, N, R
VLANPRIO VLAN Priority

Meaning: Indicates the VLAN priority. A greater parameter value indicates a higher priority.

GUI Value Range: 0~7

Unit: None

Actual Value Range: 0~7

MML Default Value: 0

Recommended Value: None

Parameter Relationship: None

Service Interrupted After Modification: Yes

Impact on Radio Network Performance: A smaller parameter value indicates a lower priority of the data transmission in layer 2 and affects the QoS.

Applicable Mode: G, U, L, N, R

Example

To add a VLAN group mapping with the parameters as follows: VLAN Group No.: 0, Traffic Type: USERDATA, User Data Service Priority: 46, VLAN ID: 1024, VLAN Priority: 3, run the following command: 
ADD VLANCLASS: VLANGROUPNO=0, TRAFFIC=USERDATA, SRVPRIO=46, VLANID=1024, VLANPRIO=3;
