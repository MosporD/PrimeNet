Add RRU Chain/Ring (ADD RRUCHAIN)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add an RRU chain/ring before adding an RRU to the chain/ring. There are two types of RRU chains/rings: TRUNK and BRANCH. TRUNK indicates that RRUs or RFUs are located on the main chain/ring connected to the optical port on the baseband processing board. BRANCH indicates that RRUs or RFUs are connected to an RHUB or RMU.

Note

  • Before adding an RRU chain/ring, ensure that the needed CPRI port on the baseband processing board or the needed port on the RHUB or RMU is not used by any other RRU chain/ring.

  • If Topo Type is set to RING or LOADBALANCE, the information of an RRU or RFU can be queried only on one connected CPRI port.

  • The backup mode of a ring can be hot backup only when the head and tail of the ring are different interface boards.

  • When an RRU chain/ring is added, the number of breakpoints is zero by default. Before adding an RRU or RFU, breakpoints must be configured on the chain/ring. For details, see the MOD RRUCHAIN command.

  • CPRI-related alarms are generated when the actual CPRI line rate is inconsistent with the preset CPRI line rate. If the entire link supports the preset CPRI line rate, rate synchronization is performed within two minutes and the CPRI-related alarms are cleared. Run the DSP CPRIPORT command to check whether the preset CPRI line rate takes effect. If the preset CPIR line rate fails to take effect or the queried CPRI line rate is not the expected one, check the capabilites of optical modules, baseband processing boards, and boards on the RRU chain/ring and then reconfigure the CPRI line rate.

  • If Topo Type is set to CHAIN, the board specified by the Head Cabinet No., Head Subrack No., and Head Slot No. must have been configured.

  • If Topo Type is set to RING or LOADBALANCE, the board specified by the Head Cabinet No., Head Subrack No., and Head Slot No. must have been configured, and the board specified by the Tail Cabinet No., Tail Subrack No., and Tail Slot No. must have been configured.

  • In single-mode scenarios, only LTE allows load sharing, including intra- and inter-board load sharing, whereas GSM or UMTS do not.

  • In multimode scenarios, load sharing is implemented only between boards of different modes. Additionally, LTE services are shared between two fiber optic cable, whereas GSM or UMTS services are allocated to only one fiber optic cable.

  • For CPRI MUX in co-MPT scenario, only the WBBPf, LBBPd, UBRIb, UBBPd, UBBPe, and UBBPg can serve as the converging party.

  • In the scenario where the access type of an RRU chain/ring is the peer port, baseband processing boards cannot aggregate each other's data.

  • When a CPRI fault occurs, services of all modes carried on the CPRI port will be interrupted.

  • The LPMP board supports the RRU chain in the chain topology only and the RRU chain can be configured only on port 0, 1, or 2.

  • On a branch chain/ring which connects to an RMU, the CPRI line rate must be set to AUTO or a fixed rate.

  • A trunk chain complies with the CPRI protocol by default.

  • RRU chains cannot be configured on an LCOP board.

  • In auto-negotiation mode, if the rate change period is set longer, rate negotiation requires more time.

  • If the converging party and the converged party of CPRI MUX are deployed in the same subrack, the main control board of the converged party and that of the converging party must be both UMPT boards.

  • The converging party and the converged party of CPRI MUX/eCPRI MUX are deployed in the same subrack if Access Type is set to PEERPORT and Local Cabinet No. and Local Subrack No. are both set to 255 or are set to the cabinet number and subrack number of the optical port that is connected to the chain/ring.

  • The converging party and the converged party of CPRI MUX are deployed in different subracks if the following conditions are met: Access Type is set to PEERPORT; Local Cabinet No. and Local Subrack No. are neither set to 255 nor set to the cabinet number and subrack number of the optical port that is connected to the chain/ring.

  • When the protocol type of the chain/ring is IR, the chain/ring does not support automatic rate negotiation.

  • In LampSite scenarios, a baseband processing board can be configured with a maximum of 96 RF modules. In CPRI MUX scenarios, a baseband processing board of the converged party can be simultaneously converged to a maximum of 96 RRUs of the converging party.

  • Only the RMU, AIRU, and RHUB boards can be configured in the trunk chain topology.

  • The reserved bandwidth can be configured only on the chain/ring connected to the local end. In CPRI MUX scenarios, the reserved bandwidth must be configured on the RHUB and RRU chain/ring of the converging party.

  • [Co-MPT,NodeB,eNodeB,gNodeB]When the RHUB port connecting to an RRU is an electrical port and the CPRI line rate of the branch chain connecting to the RHUB is automatically negotiated, the negotiated CPRI line rate can only be 1.25 Gbit/s.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]The backup mode of CHAIN is cold standby, and the backup mode of LOADBALANCE is null.

  • [Co-MPT,eGBTS,eNodeB,gNodeB]A multi-level RRU CHAIN, networking of combined RRUs/RFUs, and RRU channel cross-connection under MIMO cannot coexist on a BBP.

  • [Co-MPT,NodeB,eNodeB,gNodeB]A branch chain/ring can be configured on only one RHUB or RMU.

  • [Co-MPT,NodeB,eNodeB,gNodeB]The line rates of all UBBPei ports must be the same due to the hardware capability limitations. If the line rate of a UBBPei port is set to a fixed rate, all the UBBPei ports work at the fixed rate.

  • [Co-MPT,NodeB,eNodeB,gNodeB]In a separate-MPT base station deployed with CPRI MUX, when the converged board is an LBBP or WBBP and the CPRI line rates of the ports connecting to a trunk chain on the converging party are set to AUTO:

    - If the converging board is not a UBBPei, the CPRI line rates must not exceed 9.8 Gbit/s.

    - If the converging board is a UBBPei, the CPRI line rates must not exceed 39.2 Gbit/s.

    If links cannot be set up for the associated boards or links cannot work at the expected CPRI line rate, a negotiation for the CPRI line rate should be manually started. For details, see the help of the STR CPRILBRNEG command.

  • [Co-MPT,NodeB,eNodeB,gNodeB]If multiple modes of a separate-MPT base station share an RMU, the chains/rings connecting to the RMU work at the same line rate as the chain/ring with the maximum number of board cascading levels. If links cannot be set up for the associated boards or links cannot work at the expected CPRI line rate, run the STR CPRILBRNEG command to initiate a CPRI line rate negotiation.

  • [Co-MPT,NodeB,eNodeB,gNodeB]When the RRU chain/ring is configured on the UBBPei, UBBPem, UBBPf1, or UBBPf0 board, the networking mode must be the trunk chain. The trunk chain must be configured on the UBBP, UBBP-W, or UBRI. When the trunk chain is configured on the UBRI, only the UBRIb is supported. When the trunk chain is configured on the UBBP-W, it must be configured on port 3, 4, or 5 (except in QSA or QDA conversion scenarios).

  • [Co-MPT,NodeB,eNodeB,gNodeB]When a trunk chain connects to a UBBP and the CPRI port type is XCI_QSFP or CPRI_QSFP, the CPRI line rate must be set to a value greater than or equal to 39.2 Gbit/s if a fixed rate is required. When a trunk chain connects to a UBBP or UBRI and the CPRI port type is CPRI_SFP, the CPRI line rate must be set to a value less than 39.2 Gbit/s if a fixed rate is required.

  • [Co-MPT,NodeB,eNodeB,gNodeB]In CPRI MUX networking, convergence from one BBP of the converged party to two BBPs of the converging party is not supported if the converged base station uses the TDL_IR protocol.

  • [Co-MPT,NodeB,eNodeB,gNodeB]If the protocol type of the chain/ring where the RF module is located is inconsistent with the protocol type supported by the RF module, the RF module cannot work properly. In this case, you need to change the protocol type of the chain/ring where the RF module is located according to the specifications. After the modification, the board on the chain/ring may not work at the highest CPRI line rate. In this case, you need to run the STR CPRILBRNEG command to initiate negotiation manually.

  • [Co-MPT,eNodeB,gNodeB]When the actual protocol type of an RRU chain/ring is the IR protocol, this RRU chain/ring cannot be in the ring topology.

  • [Co-MPT,eNodeB,gNodeB]If an RRU chain/ring connects to an LBBP and the configured protocol of the RRU chain/ring is changed, the protocol used by the LBBP may change. If the protocol used by the LBBP changes, the LBBP is reset.

  • [Co-MPT,eNodeB,gNodeB]When the CPRI Extension parameter for a BBP is set to ON, an RRU chain cannot be configured on optical ports 3 to 5 of the BBP.

  • [Co-MPT,eGBTS]The GBBP, GTMU, and UBRI in GSM mode supports the intra-board cold backup ring topology and do not support inter-board cold backup and hot backup ring topologies.

  • [gNodeB]Only the AIRU or RHUB board can be configured in the trunk chain topology.

BM Backup Mode

Meaning: Indicates the backup mode of the RRU chain/ring. There are two modes: cold backup and hot backup. Cold backup indicates that when the link on one end of the chain/ring fails, services are interrupted for a short period of time, and then re-established on the other end of the chain/ring. Hot backup indicates that when the link on one end of the chain/ring fails, services are taken over by the other end of the chain/ring immediately. There is only one RRU on the chain/ring in hot backup mode. In the RRUCHAIN MO, if TT is set to RING and BM is set to HOT, the head CPRI port and the tail CPRI port of the RRU ring must be on different baseband processing boards.
