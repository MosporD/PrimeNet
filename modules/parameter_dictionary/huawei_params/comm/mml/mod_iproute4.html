Modify IPv4 Route (MOD IPROUTE4)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to modify the configuration of a static IPv4 route.

Note

This is a high-risk MML command. Pay attention to the following precautions before running this command:

  • Active/standby routes indicate routes with the same destination IP address and subnet mask but different priorities in the same routing domain.

  • This operation may interrupt the services or OM channels carried on this IPv4 route. It is recommended that you determine whether to enable the automatic configuration data rollback function depending on scenarios. For details, see the help of the CFM CB command.

  • [Co-MPT,NodeB,eNodeB,gNodeB]After an IPADDR4 MO is configured, the system automatically generates a direct gateway route. A direct gateway route takes precedence over other routes. Therefore, after an IPROUTE4 MO is configured, if the network address part of the destination IP address of the IPROUTE4 MO is the same as that of the direct gateway route, the IPROUTE4 MO is invalid.

  • [Co-MPT,NodeB,eNodeB]Equal-cost routes indicate routes with the same destination IP address, subnet mask, and priority in the same routing domain.

  • [Co-MPT,eNodeB,gNodeB]When changing the priority of an IPv4 route on a base station, ensure that the relative priority of the IPv4 route remains unchanged.

FORCEEXECUTE Support Forcible Execution

Meaning: Indicates whether a forcible change of an IPv4 route is made. When this parameter is set to NO(No), the system checks whether the change affects upper-layer services. If the change affects upper-layer services, the forcible change will fail. When this parameter is set to YES(Yes), the system does not check whether the change affects upper-layer services. Upper-layer services include the following: active/standby OM channel (OMCH), DNS service (DNSSRV), security link (IKEPEER), certificate issuance (CA), CRL update (CRLTSK), IP clock link (IPCLKLINK), NTP (NTPC), Abis CP/Iub CP/S1 CP/X2 CP/M2 CP/ECO CP/eX2 CP/SO CP/uX2 CP/Xw CP/gNBCUX2 CP/gNBCUNg CP/gNBCUXn CP (SCTPLNK/SCTPPEER), and Abis UP/IP path of an unknown service type/Iub UP/uX2 UP/S1 UP/X2 UP/eX2 UP/Xw UP/gNBCUX2 UP/gNBCUS1 UP/gNBCUNg UP/gNBCUXn UP (IPPATH/USERPLANEPEER). This parameter is invalid when a WMPT, LMPT, GTMUb, or GTMUc serves as the main control board.

Pay attention to the following when using this parameter:

1. The system checks whether a forcible change of an IP route affects upper-layer services based on the configuration data instead of based on the actual running status of these services.

2. If an NE is configured with an SRCIPROUTE4, PPPLNK, or MPGRP MO, the system does not check whether a forcible change of an IPv4 route affects upper-layer services.

3. If Port Type is set to IPOA(IP Over ATM Interface) or AIRLNK(Air Link) for the IPv4 route to be added or removed, the system does not check whether the addition or removal affects upper-layer services.

4. If Port Type is set to IPOA(IP Over ATM Interface) or AIRLNK(Air Link) for both the IPv4 routes before and after the modification, the system does not check whether the modification affects upper-layer services.

5. If Port Type is set to IPOA(IP Over ATM Interface) or AIRLNK(Air Link) for an IPv4 route, the system does not check whether the IPv4 route forms a pair of equal-cost routes with another route and whether the IPv4 route is included in the network segment of another route.

Example

To modify an IPv4 Route with the parameters as follows: RTIDX:1, DSTIP:"192.168.0.0", DSTMASK:"255.255.0.0", RTTYPE:NEXTHOP, NEXTHOP:"192.168.100.254", run the following command:
MOD IPROUTE4: RTIDX=1, DSTIP="192.168.0.0", DSTMASK="255.255.0.0", RTTYPE=NEXTHOP, NEXTHOP="192.168.100.254";
