Add OM Channel (ADD OMCH)

Network Element: BTS3900, BTS3900 WCDMA, BTS3900 LTE, BTS3900 5G, BTS5900, BTS5900 WCDMA, BTS5900 LTE, BTS5900 5G

Function

Use this command to add a remote maintenance channel.

Note

  • If both active and standby channels are configured and the one in use becomes faulty, the BS will switch over to the other remote maintenance channel according to MAE instructions. This enhances the reliability of remote maintenance channels.

  • If a remote maintenance channel is added as an active channel and no maintenance channel is being used in the BS, this channel is considered to be the currently active maintenance channel. If the remote maintenance channel and services are both abnormal, the BS starts the procedure for automatically establishing a remote maintenance channel. The procedure ends upon the recovery of the remote maintenance channel.

  • A remote maintenance channel must have been configured before a BS is running normally. Otherwise, the BS may need to establish the OM channel when the BS is reset or the network experiences intermittent connectivity. This affects ongoing services.

  • The local IP address for the remote maintenance channel on the BS side must be the same as the BS maintenance IP address on the network management system side. Otherwise, uploading and downloading files or upgrading the BS may fail.

  • After a BS starts, the active channel takes effect. If no active channel is configured, the standby channel cannot work as the active channel automatically. The standby channel takes effect as the standby one.

  • If an error message indicating an IP address conflict is displayed when you configure a remote maintenance channel and configure IPv4 or ATM type of OMCH, search existing IP addresses that may conflict with the local IP address of the remote maintenance channel by running the following commands: LST OMCH, DSP OMCH, LST LOCALIP, DSP LOCALIP, LST IPRT, DSP IPRT, LST IPROUTE4, DSP IPROUTE4, and so on. Then, manually resolve the IP address conflict. The conflicting IP address may be a local IP address of a remote maintenance channel, IP address for local maintenance, next hop IP address of an IP route, next hop IP address of an IPv4 route, and so on.

  • An NE can be configured with a maximum of two remote maintenance channels, which are the active and standby remote maintenance channels. Configuring only one remote maintenance channel is allowed. The configured channel may be an active or standby channel, depending on the data configuration.

  • Board specifications: A maximum of 2 remote maintenance channels can be configured on a WMPT/UMPT/UMDU/LMPT/GTMUb/GTMUc.

  • The ID of UDP session/UDP session group bound to the remote maintenance channel must be added by running the ADD UDPSESSION command.

  • If master/slave remote maintenance channels exist, and no UDP detection mechanism is bound to the remote maintenance channel or the UDP detection detects that all remote maintenance channels are faulty, the base station switches to the other remote maintenance channel based on the request from the MAE when one channel is faulty. If the UDP detection mechanism is bound to both the master and slave remote maintenance channels and UDP detection detects that one of the channels is faulty and the other is functional, the base station switches to the functional remote maintenance channel. When OMCH Switch Back is set to ENABLE(Enable) and the base station is using the slave remote maintenance channel, the base station will automatically switch to the master remote maintenance channel after the UDP detection detects that the master remote maintenance channel resumes functional and keeps functional for a period of time specified by Switch Back Time.

  • If the remote HA system is applied to the MAE, and the routes from the base station to the primary and secondary MAEs are different and master/slave remote maintenance channels exist, the information about standby routes needs to be added to the master/slave remote maintenance channel configurations. The standby route is the route to the secondary MAE.

  • If the active and standby routes are bound to the remote maintenance channel, the active and standby routes do not take effect when the remote maintenance channel does not take effect.

  • One route cannot be bound to the master remote maintenance channel and slave remote maintenance channel at the same time. The active route of the master remote maintenance channel cannot be the same as the active or standby route of the slave remote maintenance channel, and the standby route of the master remote maintenance channel cannot be the same as the active route or standby route of the slave remote maintenance channel.

  • The active and standby routes of one remote maintenance channel cannot be the same.

  • One UDP session/ UDP session group cannot be bound to the master and slave remote maintenance channels at the same time.

  • If BEAR of the remote maintenance channel is set to IPv4 and RTTYPE for the route is set to IF, IFT cannot be IPOA.

  • In the same routing domain, the route to be bound to a remote maintenance channel should be on a different network segment from any other route that is not bound to any remote maintenance channel.

  • The CHECKTYPE parameters of two O&M channels must be set to UDPSESSIONGRP simultaneously.

  • [Co-MPT,eNodeB,gNodeB]System specifications: If the UMPT/UMDU/LMPT is used as the main control board, a base station supports a maximum of two OM channels. The LMPT does not support IPv6.

  • [Co-MPT,NodeB,eGBTS]If BEAR of the remote maintenance channel is set to ATM and a route is bound to the channel, the RTTYPE must be set to IF and IFT must be set to IPOA, and CN, SRN, and SN of the local route must be the same as those of the remote maintenance channel.

  • [Co-MPT,eNodeB,gNodeB]If the bearer type of an OM channel in active/standby mode is IPv4 and the local and peer IP addresses of the OM channel are on different network segments, a route must be bound to the channel. Only the route bound to the active channel takes effect. Ensure that each remote maintenance channel uses an exclusive route so that the services along the route will not be interrupted after a remote maintenance channel switchover (except when an OMCH whose bearer type is IPv4 and an OMCH whose bearer type is IPv6 form an active/standby relationship). In this case, if this route is used by another channel, the channel is disconnected. To ensure that a route is used exclusively by a remote maintenance channel, the destination network segment of the route must be different from that of other route in the same routing domain added by running the ADD IPRT or ADD IPROUTE4 command.

  • [Co-MPT,eGBTS,eNodeB]The local IP address of a remote maintenance channel must be on a different network segment from the IP address for local maintenance, but it can be on the same network segment as the IP address configured for any Ethernet port or any port that carries a PPP link or MP group. The local IP address of a remote maintenance channel must be different from the local IP address of any PPP link or MLPPP group configured on a non main control board(except GTMUb/GTMUc evolution scenario). The local IP addresses of two remote maintenance channels must be on different network segments.

  • [Co-MPT,NodeB,eGBTS]When BEAR of the remote maintenance channel is set to ATM and no route is bound to the channel, the BS automatically makes the default route (with both the destination IP address and subnet mask be set to 0.0.0.0) on the IPoA link take effect if the remote maintenance channel is in the active state.

  • [Co-MPT,NodeB,eGBTS]In dual-stack scenarios where the OMCH is in ATM mode, it is recommended that an IPoA route be bound, instead of no route be bound.

  • [Co-MPT,eNodeB,gNodeB]If the bearer type of an OM channel in active/standby mode is IPv6 and the local and peer IPv6 addresses of the OM channel are on different network segments, a route must be bound to the channel. Only the route bound to the active channel takes effect. Ensure that each remote maintenance channel uses an exclusive route so that the services along the route will not be interrupted after a remote maintenance channel switchover (except when an OMCH whose bearer type is IPv4 and an OMCH whose bearer type is IPv6 form an active/standby relationship). In this case, if this route is used by another channel, the channel is disconnected. To ensure that a route is used exclusively by a remote maintenance channel, the destination network segment of the route must be different from that of other route in the same routing domain added by running the ADD IPROUTE6 command.

  • [Co-MPT,eNodeB,gNodeB]After a remote maintenance channel with the IPv6 bearer type is configured, a route to the peer IPv6 address must be added by running the ADD IPROUTE6 or ADD SRCIPROUTE6 command so that the BS can communicate with the peer end.

  • [Co-MPT,eNodeB,gNodeB]If an error message indicating an IPv6 address conflict is displayed when you configure a remote maintenance channel, search existing IPv6 addresses that may conflict with the local IPv6 address of the remote maintenance channel by running the following commands: LST OMCH, DSP OMCH, LST IPADDR6, DSP IPADDR6, LST IPROUTE6, DSP IPROUTE6, and so on. Then, manually resolve the IPv6 address conflict. The conflicting IPv6 address may be local IPv6 address of a remote maintenance channel, IPv6 address, next hop IPv6 address of an IPv6 route, and so on.

  • [Co-MPT,eNodeB,gNodeB]If Check Type for an OMCH is set to AUTO_UDPSESSION, the system automatically creates a UDP session detection when the active OMCH is faulty and the EMS sets up a standby OMCH (If the active OMCH whose bearer type is IPv4 and the standby OMCH whose bearer type is IPv6 form an active/standby relationship, the automatic UDP session detection function is not supported.). In the UDP session, the local IP address is the local IP address of the active OM channel, the peer IP address is the IP address of the EMS, the destination port number is 31252, the source port number is 65043, and the DSCP value is the value of OM High Priority in the DIFPRI object. When the automatic UDP session detects that the active OMCH recovers and remains normal for a period longer than the OMCH switchback wait time, the system disables the standby OMCH and switches back to the active OMCH. If the switchback fails, the system disables the switchback function within 24 hours. During this time, if parameters such as the local IP address of the active OMCH, the switchback wait time in the GTRANSPARA MO, and the OM high priority in the DIFPRI MO are changed, the switchback function is reactivated.

  • [NodeB,eNodeB,gNodeB]If the OM channel switchback function is required, CHECKTYPE for the active OM channel needs to be set to AUTO_UDPSESSION.

  • [Co-MPT,eNodeB,gNodeB]The route or secondary route bound to the OM channel with the bearer type of IPv6 must be a route added by running the ADD IPROUTE6 command. This route must be in the same routing domain.

  • [Co-MPT,eNodeB,gNodeB]If an OMCH whose bearer type is IPv4 and an OMCH whose bearer type is IPv6, or two OMCHs whose bearer type is IPv6 form an active/standby relationship, an OMCH active/standby switchover can be performed only on the active main control board, not across boards, and can be triggered only by the NMS, not by the base station (for example, UDP-related detection cannot trigger an OMCH active/standby switchover).

  • [Co-MPT,NodeB]The sum of the following numbers cannot exceed 200: (1) Twice the number of the Tree Link PVC objects configured on this board (2) Total number of the following objects configured on this board: OMCH in which the Bearer Type parameter is set to ATM(ATM), AAL2PATH, and SAALLNK.

  • [NodeB,eGBTS]The route or secondary route bound to the OM channel with the bearer type of IPv4 must be a route added by running the ADD IPRT or ADD IPROUTE4 command. This route must be in the same routing domain and the Port Type parameter for this route cannot be set to AIRLNK(Air Link).

  • [Co-MPT,eGBTS]If the OM channel switchback function is required, CHECKTYPE for the active OM channel needs to be set to AUTO_UDPSESSION. For a GSM base station, it is recommended that CHECKTYPE for the OM channel be set to UDPSESSION or UDPSESSIONGRP.

  • [NodeB,eGBTS]System specifications: If the WMPT/UMPT/UMDU/GTMUb/GTMUc is the main control board, a maximum of 2 remote maintenance channels can be configured.

  • [Co-MPT,NodeB]If OMIPSWITCH is set to ON, the OMIP parameter must be the same as the DEVIP or IPADDR4 parameter for an Ethernet port on the active main control board and the Ethernet port must be activated.

  • [NodeB,eGBTS]If the bearer type of an OM channel in active/standby mode is IPv4 and the local and peer IP addresses of the OM channel are on different network segments, a route must be bound to the channel. Only the route bound to the active channel takes effect. Ensure that each remote maintenance channel uses an exclusive route so that the services along the route will not be interrupted after a remote maintenance channel switchover. In this case, if this route is used by another channel, the channel is disconnected. To ensure that a route is used exclusively by a remote maintenance channel, the destination network segment of the route must be different from that of other route in the same routing domain added by running the ADD IPRT or ADD IPROUTE4 command.

  • [NodeB]If Check Type for an OM channel is set to AUTO_UDPSESSION, the system automatically creates a UDP session detection when the active OM channel is faulty and the EMS sets up a standby OM channel. In the UDP session, the local IP address is the local IP address of the active OM channel, the peer IP address is the IP address of the EMS, the destination port number is 31252, the source port number is 65043, and the DSCP value is the value of OM High Priority in the DIFPRI object. When the automatic UDP session detects that the active OMCH recovers and remains normal for a period longer than the OMCH switchback wait time, the system disables the standby OMCH and switches back to the active OMCH. If the switchback fails, the system disables the switchback function within 24 hours. During this time, if parameters such as the local IP address of the active OMCH, the switchback wait time in the GTRANSPARA MO, and the OM high priority in the DIFPRI MO are changed, the switchback function is reactivated.

  • [NodeB]The IP addresses of the remote maintenance channel and local maintenance channel must be on different network segments. The local IP addresses of two remote maintenance channels must be on different network segments.

  • [gNodeB]The local IP address of a remote maintenance channel must be on a different network segment from the IP address for local maintenance, but it can be on the same network segment as the IP address configured for any Ethernet port. The local IP addresses of two remote maintenance channels must be on different network segments.

CHECKTYPE Check Type

Meaning: Indicates the type of detection mechanism bound to the remote maintenance channel. If this parameter is set to NONE, no detection mechanism is bound to the remote maintenance channel and an active/standby remote maintenance channel switchover is triggered by switchover message sent by the MAE. If this parameter is set to UDPSESSION, the UDP ping detection is bound to the remote maintenance channel and an active/standby remote maintenance channel switchover depends on the UDP session detection, only GSM currently supports this function. If this parameter is set to UDPSESSIONGRP, the UDP ping detection is bound to the remote maintenance channel and an active/standby remote maintenance channel switchover depends on the UDP session group detection, only GSM currently supports this function. If this parameter is set to AUTO_UDPSESSION, automatic UDP session detection is performed on the OM channel. When the standby OM channel is connected to the EMS, the base station automatically creates a UDP session from the local IP address of the active OM channel to the EMS. If the OM channel switchback function is required, set CHECKTYPE for the active OM channel to AUTO_UDPSESSION.

Disuse statement: In later versions, the values UDPSESSION and UDPSESSIONGRP of this parameter will be deleted from UMTS/LTE/NR single-mode base stations.
