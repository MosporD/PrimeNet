GLOCELLALGPARA

+-NE
  +-GBTSFUNCTION
    +-GLOCELL
      +-GLOCELLALGPARA

Description

The GLOCELLALGPARA MO manages algorithm parameters for a local cell, including parameters for the frequency-based power control algorithm.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    GLOCELL

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
LST GLOCELLALGPARA

Use this command to query the algorithm parameters for a local cell.
SET GLOCELLALGPARA

Use this command to set algorithm-related parameters for a local cell.

Related Parameters

Table 2 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Local Cell ID

Indicates the identity of a local cell. It uniquely identifies a local cell served by a GBTS function.
Frequency-based Power Control

Indicates whether to enable the frequency-based power control algorithm. If the frequency spacing between the GSM and UMTS networks is less than or equal to 2.2 MHz, the frequency-based power control algorithm can be enabled to reduce the power on GSM interfering frequencies and therefore reduce the interference on the UMTS network.
Interference Coordination Policy

Indicates the frequency-based power control policy. If this parameter is set to GSM(GSM), the policy preferentially ensures the GSM network quality when minimizing the interference on the UMTS network. If this parameter is set to UMTS(UMTS), the policy preferentially ensures the UMTS network quality.
Max. Power Decrease for GU2.0 MHz Interfering Frequency

Indicates the maximum power decrease for the GSM interfering frequencies when there is a 2.0 MHz frequency spacing between the GSM and UMTS networks. The related formula is as follows: Expected transmit power of the interfering frequency on the GSM side = Maximum TRX transmit power - GU2000KHZMAXVAL.
Max. Power Decrease for GU2.2 MHz Interfering Frequency

Indicates the maximum power decrease for the GSM interfering frequencies when there is a 2.2 MHz frequency spacing between the GSM and UMTS networks. The related formula is as follows: Expected transmit power of the interfering frequency on the GSM side = Maximum TRX transmit power - GU2200KHZMAXVAL.
UMTS Center Frequency 1

Indicates the UMTS downlink frequency that has a 2.0 MHz or 2.2 MHz spacing with the frequency in the logical cell bound to the local cell.
UMTS Center Frequency 2

Indicates the UMTS downlink frequency that has a 2.0 MHz or 2.2 MHz spacing with the frequency in the logical cell bound to the local cell. 65535 indicates UMTS center frequency 2 is not used.
Non-AHR Power Compensation Proportion

Indicates the proportion of power compensation on the GSM non-interfering frequencies to the power decrease on the interfering frequencies for EFR, FR, HR, and AMR FR services. When this parameter is set to 0, power compensation is not performed on the GSM non-interfering frequencies.
Non-AHR Power Compensation Offset

Indicates the offset of power compensation for GSM non-interfering frequencies in EFR, FR, HR, and AMR FR services.

Power compensation offset for GSM non-interfering frequencies = Power decrease on interfering frequencies x NAHRCOMPCOEFF + NAHRCOMPOFFVAL.
AHR Power Compensation Proportion

Indicates the proportion of power compensation on the non-interfering frequencies on the GSM side to the power decrease on the interfering frequencies for AMR HR services. When this parameter is set to 0, power compensation is not performed on the non-interfering frequencies.
AHR Power Compensation Offset

Indicates the offset of power compensation for the non-interfering frequencies on the GSM side for AMR HR services.

Power compensation for non-interfering frequencies on the GSM side = Power decrease on interfering frequencies x AHRCOMPCOEFF + AHRCOMPOFFVAL.
Diversity Transmitter GMSK Delay

Indicates the delay of transmit diversity when GMSK is used. Generally, the parameter is used in general fading environments. The transmit diversity can bring a gain of 3 dB to 5 dB. The fading degrees vary with environments. With a fixed delay, different UEs obtain different gains. In addition, a fixed delay has negative impacts on some EDGE service coding. Therefore, the delay of transmit diversity must be configurable and can be separately set for GMSK and 8PSK.
Diversity Transmitter 8PSK Delay

Indicates the delay of transmit diversity when 8PSK is used. Generally, the parameter is used in general fading environments. The transmit diversity can generally bring a gain of 3 dB to 5 dB. The fading degrees vary with environments. With a fixed delay, different UEs obtain different gains. In addition, a fixed delay has negative impacts on some EDGE service coding. Therefore, the delay of transmit diversity must be configurable and can be separately set for GMSK and 8PSK.
Diversity Transmitter 16QAM Delay

Indicates the delay of transmit diversity when 16QAM is used. Generally, the parameter is used in general fading environments. The transmit diversity can generally bring a gain of 3 dB to 5 dB. The fading degrees vary with environments. With a fixed delay, different UEs obtain different gains. In addition, a fixed delay has negative impacts on some EDGE service coding. Therefore, the delay of transmit diversity must be configurable and can be separately set for GMSK and 16QAM.
Diversity Transmitter 32QAM Delay

Indicates the delay of transmit diversity when 32QAM is used. Generally, the parameter is used in general fading environments. The transmit diversity can generally bring a gain of 3 dB to 5 dB. The fading degrees vary with environments. With a fixed delay, different UEs obtain different gains. In addition, a fixed delay has negative impacts on some EDGE service coding. Therefore, the delay of transmit diversity must be configurable and can be separately set for GMSK and 32QAM.
Dynamic GMSK Delay Adjustment Switch

Indicates Whether to enable dynamic adjustment of the transmit diversity GMSK delay. If this parameter is set to ON, the dynamic change of delay between timeslots is supported. If this parameter is set to OFF, this function is disabled.
