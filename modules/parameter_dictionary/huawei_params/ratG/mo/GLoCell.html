GLOCELL

+-NE
  +-GBTSFUNCTION
    +-GLOCELL
      +-GLOCELLALGPARA[1~1]
      +-GLOCELLENERGYMGTPARA[1~1]
      +-GLOCELLOTHPARA[1~1]
      +-GLOCELLRLALMPARA[1~1]
      +-GLOCELLRSVDPARA[1~1]

Description

The GLOCELL MO manages basic parameters for a local cell.

Effective Scenario

Immediately

Relations Between MOs

  • Possible parents:

    GBTSFUNCTION

  • Possible children:

    GLOCELLALGPARA[1~1];GLOCELLENERGYMGTPARA[1~1];GLOCELLOTHPARA[1~1];GLOCELLRLALMPARA[1~1];GLOCELLRSVDPARA[1~1]
  • Relation with the GLOCELL MO:
    • GLOCELL served by GTRXGROUP cannot be deleted.
    • When LOCELLTYPE in GLOCELL is set to NORMAL_CELL, the sector equipment cannot be bound to different GTRXGROUP MOs bound to GLOCELL using GTRXGROUPSECTOREQM under which SERVETYPE is set to NORMAL.
    • BASEBANDEQMTYPE for BASEBANDEQM used by GLOCELL must be set to ULDL.
    • The GLOCELLRLALMPARA, GLOCELLRSVDPARA, GLOCELLALGPARA, GLOCELLENERGYMGTPARA and GLOCELLOTHPARA corresponding to the GLOCELL must exist.
    • If LOCELLTYPE for GLOCELL is set to MULTISITE_CELL, WORKMODE for GTRXGROUP under GLOCELL must be set to INDEPENDENT.
    • If LOCELLTYPE for GLOCELL is set to MULTISITE_CELL, MAXPOWER for GTRXGROUPSECTOREQM bound to GTRXGROUP must be set to 65535.
    • If LOCELLTYPE for GLOCELL is set to MULTISITE_CELL, sector equipment bound to all GTRXGROUPs under GLOCELL cannot be used by GBTSPWRSHRGRP.
    • If LOCELLTYPE for GLOCELL is set to MULTISITE_CELL, RCVMD for GTRXGROUP under GLOCELL cannot be set to FOURDIVERSITY.
    • Different BASEBANDEQM bound to different GLOCELL must use different board.
    • If LOCELLTYPE under GLOCELL is set to MULTISITE_CELL, the sector equipment bound to GTRXGROUP under GLOCELL cannot be used by other GLOCELL.
  • Relation with the GTRXGROUP and GTRXGROUPSECTOREQM MOs:
    • No more than two pieces of sector equipment can be bound to the GTRXGROUP MO using the GTRXGROUPSECTOREQM MO under which SERVETYPE is set to NORMAL if both the following conditions are met:
    • LOCELLTYPE in GLOCELL is set to NORMAL_CELL.
    • WORKMODE in GTRXGROUP bound to GLOCELL is set to INDEPENDENT.
    • When LOCELLTYPE in the GLOCELL MO is set to NORMAL_CELL, if WORKMODE in the GTRXGROUP MO referenced by the GLOCELL MO is set to INDEPENDENT and the GTRXGROUPSECTOREQM MO with SERVETYPE set to NORMAL is bound to two sets of sector equipment, SNDMD must be set to DIVERSITY and RCVMD must be set to FOURDIVERSITY in the GTRXGROUP MO.
  • Relation with the BASEBANDEQM MO:
    • BASEBANDEQM used by GLOCELL must have been configured.
  • Relation with the GTRXGROUP MO:
    • If LOCELLTYPE under GLOCELL is set to MULTISITE_CELL, SNDMD of GTRXGROUP under GLOCELL must be set to SINGLESND.
  • Relation with the GTRXGROUPSECTOREQM, GTRXGROUP, and SECTOREQM MOs:
    • The four RX antennas must be configured on the same RF module if all of the following conditions are met:
    • BASEBANDPOLICY in GLOCELL is set to EMBEDBBONLY.
    • RCVMD in GTRXGROUP bound to GLOCELL is set to FOURDIVERSITY.
    • Four RX antennas are configured on SECTOREQM referenced by GTRXGROUP using GTRXGROUPSECTOREQM under which SERVETYPE is set to NORMAL.
    • The four RX antennas must be configured on the same RF module, or two RX antennas are configured on one RF module and the other two are configured on another RF module if all of the following conditions are met:
    • BASEBANDPOLICY in GLOCELL is set to BBEQMFST.
    • RCVMD in GTRXGROUP bound to GLOCELL is set to FOURDIVERSITY.
    • Four RX antennas are configured on SECTOREQM referenced by GTRXGROUP using GTRXGROUPSECTOREQM under which SERVETYPE is set to NORMAL.
  • Relation with the BASEBANDEQM and BBP MOs:
    • If BBPs are used by BASEBANDEQMs in GLOCELLs, TYPE is set to UBBP, and BBWS includes GSM, those BBPs must reside in a BBU subrack.
  • Relation with the BASEBANDEQM and MDU MOs:
    • If MDUs are used by BASEBANDEQMs in GLOCELLs, TYPE is set to UMDU, and BBWS includes GSM, those MDUs must reside in a BBU subrack.
  • Relation with the MPT and GTMU MOs:
    • TYPE is set to GTMU, and there is no MPT MO under which TYPE is set to UMPT. If in this situation, BASEBANDPOLICY under the GLOCELL MO is set to BBEQMFST, BBEQMPOLICY under this MO must be set to ALLBBEQM.
  • Relation with the GTRXGROUPSECTOREQM and GTRXGROUP MOs:
    • When LOCELLTYPE in GLOCELL is set to MULTISITE_CELL, GTRXGROUP bound to GLOCELL cannot be bound to GTRXGROUPSECTOREQM under which SERVETYPE is set to AUX.
  • Relation with the GTRXGROUPSECTOREQM, SECTOREQM, and GTRXGROUP MOs:
    • If one transmit antenna is bound to two SECTOREQM MOs, and the SECTOREQM MO is referenced by the GTRXGROUPSECTOREQM MO under which SERVETYPE is set to NORMAL, LOCELLTYPE under the GLOCELL MO referencing the SECTOREQM MO must be set to NORMAL_CELL.
  • Relation with the GTRXGROUP, GTRXGROUPSECTOREQM, and SECTOREQM MOs:
    • When LOCELLTYPE in the GLOCELL MO is set to NORMAL_CELL, if WORKMODE in the GTRXGROUP MO referenced by the GLOCELL MO is set to INDEPENDENT and the GTRXGROUPSECTOREQM MO with SERVETYPE set to NORMAL is bound to two sets of sector equipment, all antennas bound to GTRXGROUP must belong to the same RF module.
    • When LOCELLTYPE in the GLOCELL MO is set to NORMAL_CELL, if WORKMODE in the GTRXGROUP MO referenced by the GLOCELL MO is set to INDEPENDENT and the GTRXGROUPSECTOREQM MO with SERVETYPE set to NORMAL is bound to two sets of sector equipment, the sector equipment bound to GTRXGROUP must be configured with two TX antennas.
    • When LOCELLTYPE in the GLOCELL MO is set to NORMAL_CELL, if WORKMODE in the GTRXGROUP MO referenced by the GLOCELL MO is set to INDEPENDENT and the GTRXGROUPSECTOREQM MO with SERVETYPE set to NORMAL is bound to two sets of sector equipment, the sector equipment bound to GTRXGROUP must be configured with four RX antennas.
    • When LOCELLTYPE in the GLOCELL MO is set to NORMAL_CELL, if WORKMODE in the GTRXGROUP MO referenced by the GLOCELL MO is set to INDEPENDENT and the GTRXGROUPSECTOREQM MO with SERVETYPE set to NORMAL is bound to two sets of sector equipment, the two sets of sector equipment bound to GTRXGROUP must belong to different sectors.

Related MML Commands

Table 1 describes the MML commands related to this MO.

Table 1 Related MML commands

MML Command

Function
ADD GLOCELL

Use this command to add a local cell for a GBTS function.
BLK GLOCELL

Use this command to block a local cell.
DSP GLOCELL

Use this command to query the status for local cells, such as local cell status, local cell administration status, status of the logical cell corresponding to the local cell, cell baseband deployment, and cell aid status.
LST GCELLFREQSCAN

Use this command to query the configuration information about the frequency scan in the specified or all local cells.
LST GLOCELL

Use this command to query the configuration information of local cells.
MOD GLOCELL

Use this command to modify the configuration information of local cells.
RMV GLOCELL

Use this command to remove a specified local cell.
SET GCELLFREQSCAN

Use this command to start the uplink frequency scan test in a specified local cell. In the uplink frequency scan test, the uplink receive levels of specified frequencies are scanned when the TCH/F is idle. The interference of uplink frequencies can be obtained from this test. Therefore, the test provides a reference for selecting appropriate working frequencies in network optimization.
STP GCELLFREQSCAN

Use this command to stop the uplink frequency scan test in a specified local cell.
UBL GLOCELL

Use this command to unblock a local cell.

Related Parameters

Table 2 and Table 3 describes the parameters related to this MO.

Table 2 Configuration parameters

Parameter

Description
Local Cell ID

Indicates the identity of a local cell. It uniquely identifies a local cell served by a GBTS function.
Baseband Policy

Indicates the policy used by a baseband processing unit serving the local cell. When this parameter is set to EMBEDBBONLY, the local cell can use only the baseband processing unit (BPU) in an RF module. When this parameter is set to BBEQMFST, the local cell preferentially uses the baseband processing unit in the baseband equipment
Baseband Equipment ID

Indicates the ID of the baseband equipment deployed in the local cell. This parameter identifies the physical deployment for the baseband processing unit (BPU) in the local cell. 255 is an invalid value, indicating that the BPU is deployed on the RF module.
User Label

Indicates a user-defined message. Users can add remarks for the local cell using this parameter.
Local Cell Type

Indicates the local cell type. NORMAL_CELL indicates a common cell, and MULTISITE_CELL indicates a multi-site cell.
Baseband Equipment Policy

Indicates the policy used by the baseband equipment serving the local cell. When this parameter is set to ALLBBEQM, the local cell can use only the baseband processing unit in the baseband equipment. When this parameter is set to LOWFREQBBEQMONLY, only low-frequency TRXs (PGSM, EGSM, RGSM, GSM850, and GT810) of the local cell can use the baseband processing unit in the baseband equipment. TRXs at other frequency bands use the baseband processing unit in the RF module. When this parameter is set to HIGHFREQBBEMONLY, only high-frequency TRXs (DSC1800 and PSC1900) of the local cell can use the baseband processing unit in the baseband equipment. TRXs at other frequency bands use the baseband processing unit in the RF module.
Table 3 Dynamic parameters

Parameter

Description
Local Cell Status

Indicates the state of the local cell: AVAILABLE and UNAVAILABLE. Note: AVAILABLE indicates that the baseband and RF resource of the local cell are normal and can provide services. UNAVAILABLE indicates that the baseband and RF resource of the local cell cannot provide services.
Local Cell Administration Status

Indicates the administration status of a local cell: LOCK and UNLOCK. Note: LOCK indicates that both the local cell and its logical cell are unavailable. MSs that have accessed the logical cell bound to the local cell are forcibly handed over to other normal cells. UNLOCK indicates that the local cell is available.
Cell Index

Indicates the index of the logical cell corresponding to the local cell. If the local cell is not bound to a logical cell, this parameter displays as NULL.
Cell No.

Indicates the number of the logical cell corresponding to the local cell. If the local cell is not bound to a logical cell, this parameter displays as NULL.
Cell Status

Indicates the status of a logical cell: AVAILABLE and UNAVAILABLE. If the local cell is not bound to a logical cell, this parameter displays as NULL. Note: AVAILABLE indicates that the logical cell is normal. UNAVAILABLE indicates that users cannot access the logical cell.
Cell Administration Status

Indicates the administration status of a logical cell: LOCK and UNLOCK. If no logical cell is bound to the local cell, this parameter displays as NULL. Note: LOCK indicates that the logical cell is blocked and unavailable, and MSs that have accessed the cell are forcibly handed over to other normal cells. UNLOCK indicates that the logical cell is available.
Baseband Deployment

Indicates the actual baseband deployment in the local cell. It falls into three types: embedded baseband deployment, baseband equipment deployment and baseband equipment and embedded baseband deployment.
Cell TRX Cooperation Supported

Indicates whether the TRX cooperation has been enabled in the logical cell. The parameter values are YES and NO.
Frequency Band

Indicates the frequency band supported by a cell. A cell supports a maximum of two frequency bands. The frequency bands include PGSM, RGSM, GSM850, DCS1800, PCS1900, and GT810. When a cell supports two frequency bands, use & between the two frequency bands.
Frequency List

Indicates the list of frequencies on which the scan test is started.
Frequency

Indicates the cell frequency list.
Receiving Frequency

Indicates the uplink frequencies of the cell working frequencies. The unit is 0.1MHz.
Sector List

Indicates the sector list for a local cell. When multiple sector IDs are specified, use & between two sector IDs. A maximum of 30 sectors can be configured for a local cell.
